СОХРАНЯЕМЫЙ СТЕНД GRAFANA · OSS13.3.0 · 1 ноября 2026

Публичный набор не содержит бинарных файлов, рабочей базы, паролей и ключей.
Полную поставку получают по главе grafana-02-install, проверяют SHA-256 и
распаковывают вне книги. На рабочем Windows без установки — чтение и браузер
к личной VM. Основной сервер — собственный процесс Linux без root или своя VM.
Он слушает только127.0.0.1; этот адрес относится к машине процесса Grafana.

Сначала выбрать постоянный GRAFANA_WORK, задать GRAFANA_HOME на проверенную
поставку и прочитать установку. Для сервера достаточно labs/. Переносимый
набор portable/Pages сохраняет лабораторные файлы и тесты, но исключает
sources/ и корневой volume_config.py: это не полный исходный checkout.
Два зависимых от исходников теста ниже выделены отдельно. Рабочий каталог
далее — grafana/labs; обычный пользователь, остановка после каждого отказа:

# Рабочий каталог: скопированный grafana/labs, обычный пользователь Linux.
# Только НОВЫЙ пустой state; для продолжения смотрите отдельный блок README.
(
  set -euo pipefail
  python3 labctl.py init "$GRAFANA_WORK/state" --port 13000
  python3 labctl.py argv "$GRAFANA_WORK/state" --grafana-home "$GRAFANA_HOME"
  exec "$GRAFANA_HOME/bin/grafana" server --homepath "$GRAFANA_HOME" --config "$GRAFANA_WORK/state/config/grafana.ini"
)

init отказывает при любом непустом каталоге. Маркер O_EXCL исключает двух
владельцев начала; private/0700 и файлы0600 создаются до записи. Прерванное
состояние исследуют отдельно с сохранением базы/ключа. Это не команда сброса
или продолжения. Единственную копию учебного состояния не держат в /tmp.
Ctrl+C завершает свой процесс; база и файлы сохраняются. init не повторяют.

ОБЫЧНОЕ ПРОДОЛЖЕНИЕ СУЩЕСТВУЮЩЕГО СТЕНДА (init исключён):
(
  set -euo pipefail
  python3 labctl.py argv "$GRAFANA_WORK/state" --grafana-home "$GRAFANA_HOME"
  exec "$GRAFANA_HOME/bin/grafana" server --homepath "$GRAFANA_HOME" --config "$GRAFANA_WORK/state/config/grafana.ini"
)
При отказе argv exec не выполняется. После Ctrl+C повторяют только этот блок.

Соседний prometheus/ уже описывает Go18080,Prometheus9090,job=go-lab,
environment=lab,сбор15s. Источник prom-local, доска go-service-lab, папка
handbook-go. Loopback подходит при совместном размещении процессов на одной
VM/ОС. Другое размещение требует явных адресов, доверия и доступа. Соседние
файлы этот том не меняет. Метрики Kubernetes ledger-api имеют иной договор.

Начальная конфигурация выключает анонимный вход, самостоятельную регистрацию,
аналитику, проверки обновлений, автоматическую установку модулей, Alerting и
SMTP. Файл правила приостановлен и init его не копирует. Доска использует
встроенные модули, allowUiUpdates=false,disableDeletion=true. Её владелец —
файлы, не временная правка интерфейса. VM-INSTALL.txt — отдельный невыполненный
рецепт пакетной установки и HTTPS только в новой собственной Ubuntu24.04 VM.

ЗАКРЫТЫЙ КЛИЕНТ API
Сначала создать служебную запись и ограниченный токен по главе12. Затем:
python3 make_api_client.py "$GRAFANA_WORK/state/private"
Токен вводится через getpass без эха, не в argv. api.curl создаётся0600
и никогда не перезаписывается. Файл не публикуют. После опыта токен отзывают.

ПРОВЕРКИ ИЗ PORTABLE/PAGES ИЛИ ПОЛНОГО ИСХОДНОГО ДЕРЕВА
Из grafana/labs при уже доступном Python3:
python3 ../tests/test_labctl.py
python3 check_samples.py
python3 ../tests/test_api_client.py
Последнему нужен уже доступный curl для своего loopback-приёмника. Он
проверяет перенос искусственного значения Bearer...,не пригодность токена
для Grafana и не эхо терминала. Основные скрипты labctl.py и make_api_client.py
также самодостаточны относительно sources/ и volume_config.py.

Настоящие отдельные процессы требуют заранее проверенную полную поставку:
python3 native_check.py --grafana-home "$GRAFANA_HOME" --output "$GRAFANA_WORK/native-result.json"
python3 native_alerting_check.py --grafana-home "$GRAFANA_HOME" --output "$GRAFANA_WORK/alert-result.json"
native_check дополнительно использует уже доступный PyYAML; native_alerting_check
использует стандартную библиотеку Python и YAML-парсер самой Grafana.
Эти опыты читают файлы labs/,но не требуют sources/ или volume_config.py.

ТОЛЬКО ПОЛНЫЙ ИСХОДНЫЙ CHECKOUT: ПРОВЕРКИ ИСХОДНИКОВ
В portable/Pages следующие две команды не выполняют. Из grafana/labs полного
checkout,где сохранены sources/,tests/ и volume_config.py,при уже доступном
Python3/PyYAML:
python3 ../tests/test_guards.py
python3 ../tests/check_sources.py
test_guards извлекает исполняемые Bash-блоки из sources/grafana-02-install.html;
check_sources читает HTML,reference.py,diagrams.py и volume_config.py.
Их отсутствие в portable/Pages предусмотрено экспортом,а не является отказом
labctl,панели или native-опытов. Ради этих тестов не копируют sources в labs
и не меняют экспортёр. Исторический PASS source/guard в ПРОВЕРКИ.txt получен
на полном исходном checkout и не заявляет повторение этих тестов из portable.

Первый фактический опыт создаёт временный каталог и HTTP-имитатор Prometheus,
запускает настоящий Grafana, проверяет25условий API/SQLite/provisioning/ролей,
запросы15s/30s, API-секрет после запуска и отдельного восстановления. Приёмник
источника отвечает401 без правильного искусственного заголовка. Подключение
секрета создаётся API вне provisioning, поэтому повторное внесение открытого
значения файлом не объясняет успешную расшифровку. Источник не исполняет PromQL.

Второй опыт включает настоящий Alerting только в собственной временной базе.
Источник и приёмник сообщений находятся на127.0.0.1. SMTP выключен, разрешена
только интеграция webhook. За примерно2–3минуты проверяются17условий:
приостановленный YAML,переходы Pending/Alerting/Recovering/Normal,ожидание
NoData/Error и отдельные локальные сообщения DatasourceNoData/DatasourceError.
Время каждой фазы ограничено; finally завершает свои процесс и оба HTTP-порта.
Это не отправка людям и не проверка внешней почты, HA или inhibition.

Оба опыта не используют постоянный учебный state, не устанавливают пакеты,
службы и модули, не изменяют сеть хоста. Временные базы/ключи/журналы удаляются.
Выходной JSON содержит только искусственные данные. При ошибке команда
возвращает ненулевой код; частичный запуск нельзя считать успешной проверкой.
check_samples — ограниченная арифметика, не движок Grafana/Prometheus.

АРИФМЕТИЧЕСКИЕ МОДЕЛИ РЕДАКЦИИ 2 НОЯБРЯ
Из этого же каталога labs, обычный пользователь и уже доступный Python3:
python3 check_review_models.py

Помощник только читает fixtures/review-models.json и печатает JSON. Он сверяет
выравнивание двух исторических запросов, inner/outer по уникальному instance
на одном времени и новый числовой путь20s/for30s/keep30s. Это не Grafana,
PromQL или браузерный transformer; HTTP и файлы состояния не изменяются.
Для изменения входа скопируйте JSON в свой state/evidence, предскажите новый
список expected и передайте --fixture ПУТЬ. Несовпадение прогноза даёт отказ.
Точные ограничения модели перечислены в самом JSON и выводе помощника.

ОФЛАЙН И ВОССТАНОВЛЕНИЕ
Сохранить полный архив+сумму/источник, лицензии, скрипты, шаблоны, JSON доски.
Секреты, ключ и согласованный резерв личной базы хранят отдельно и закрыто.
Не включать private state в экспорт книги. До обновления принять восстановление
на другом каталоге/порте с выключенными уведомлениями. Офлайн HTML не заменяет
запущенные Grafana/Prometheus, их данные и ресурсы модулей.
