Доверие к запросу, прокси, пользователю и публичной ссылке

Скрытая панель не скрывает источник от пользователя, которому разрешены запросы. Права и сетевые ограничения должны соответствовать реальному пути данных.

Границы редакций

В OSS есть администратор сервера, базовые роли организации и разрешения папок/досок. Enterprise/Cloud добавляют расширенный RBAC, права запросов источников и другие возможности по лицензии. RBAC, role-based access control, — управление разрешениями через роли, действия и область. Это не синоним любой выпадающей роли интерфейса. Вкладка подробных прав Enterprise не предполагается в OSS-рецепте.

Фактический тест подтвердил: новый Viewer отправил собственный /api/ds/query к доступному источнику и получил таблицу; сохранение доски получило 403. Значит, ограничение папки защищает сохранённые доски, но не обязательно отдельные метрики источника. Строгое разделение данных требует ограниченной внешней учётной записи/арендатора, отдельной организации с ограниченным подключением либо реально доступной функции Enterprise/Cloud. Список instance, скрытый редактор и регулярное выражение доски не являются политикой безопасности.

Серверный запрос и SSRF

HTTP-клиент Grafana имеет сетевое положение сервера. Разрешив произвольный URL источника или запрос модуля, администратор позволяет серверу обращаться туда, куда браузер клиента не может. SSRF, server-side request forgery, — злоупотребление серверными запросами для обращения к нежелательным внутренним ресурсам. Защита включает права изменения подключения, ограничения исходящих соединений, область внешней учётной записи и проверку URL. Enterprise request security не обещается OSS. Разрешение localhost нашего теста не универсально для рабочей системы, где localhost может содержать административные адреса.

Skip TLS verify отключает проверку личности сервера и не исправляет 401/403. Пароль/заголовок отправляют только доверенному выбранному источнику; перенаправления и правила прокси рассматривают отдельно. Cookie входа пользователя нельзя автоматически пересылать источнику. В цепочке расшифровки важны память процесса, права хоста и журналы. secureJsonData защищает определённый путь хранения и скрывает значение API, но захваченная серверная часть с правом запросов может обращаться к данным в рамках сохранённых полномочий.

Публичная доска и снимок

Внешнее предоставление доски и snapshot имеют разные договоры версии/редакции. Снимок способен включать сохранённые данные панелей, метки и ссылки: это уже публикация содержимого, даже без пароля источника. Анонимный доступ даёт аудитории соответствующие возможности Viewer. «Только ссылка» не является аутентификацией. До экспорта проверяют метки, выражения, аннотации, внутренние URL, пользователей и реальные данные. Данный практикум не вызывает внешнюю публикацию или API снимков.

Поставщики входа и служебные записи

OAuth/SSO/LDAP/auth proxy — отдельные интеграции входа с перенаправлениями, группами, сопоставлением ролей и границами редакций. Наличие кнопки OAuth не устанавливает поставщика удостоверений. При auth proxy внешний клиент не должен сам задать заголовок, принимаемый за личность. Cookie secure/samesite, root_url, TLS и разрешённые браузерные источники согласуют с внешним доступом. Токен служебной записи ограничивают и отзывают по доступной модели; в переменной доски ему не место.

Прикладная проверка

В своём сервере создайте Viewer и Editor, проверьте чтение папки, собственный запрос, сохранение нового объекта и изменение управляемого. Записывайте конкретные HTTP-коды и личность, а не название роли на снимке. Встроенный администратор фактического теста существует только во временном стенде. Расширенный аудит и сроки хранения проверяют по лицензии; stdout процесса по умолчанию не является полным достоверным журналом аудита.

Накладные расходы защиты измеряют предметно: задержку входа, SQL-хранилища сеансов, запроса источника и TLS. Нельзя выключать проверки ради неразделённого общего p95. Сначала найдите этап задержки. Ограничение максимального диапазона запроса защищает и данные, и доступность источника.
