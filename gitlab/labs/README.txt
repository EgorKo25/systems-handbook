Это оригинальный Go-проект и локальные CI-команды. Здесь нет исходников,
заданий, секретов или инфраструктуры платного курса.

Подготовьте Go >= 1.24, Python 3 и отдельную копию service. Установка программ
и запуск GitLab автоматически не выполняются. На домашнем Linux:

  cd service
  python3 tools/ci.py test
  python3 tools/ci.py build
  python3 tools/ci.py verify

Если Go не в PATH, передайте HANDBOOK_GO с полным путём к подготовленному Go.
Проект не имеет внешних Go-зависимостей. GOTOOLCHAIN=local и GOPROXY=off
пригодны для заранее подготовленного автономного опыта. Первый Go-cache
может потребовать заметного времени; это не обращение к GitLab.

Проверки книги (временные копии, настоящий Go):

  python3 check.py

Проверяются: успешные тесты, намеренно сломанный тест и ненулевой код,
сохранение JUnit, реальный бинарник, manifest/SHA, отказ на подмене,
встроенная версия, ошибочное значение версии, оборванные/не-JSON события,
отказ пакета без именованного теста, XML-экранирование, маленькая модель rules,
независимое чтение Git HEAD/dirty, несовпадение заявленного CI_COMMIT_SHA,
недопустимая подмена истории родительским репозиторием вложенного проекта.
Для настоящего CI service должен быть корнем чистого собственного Git-репозитория;
CI_COMMIT_SHA сверяется с его наблюдаемым HEAD, а не принимается на веру.
Manifest записывает также фактические флаги и хеш tools/ci.py.
Build обнуляет унаследованный GOFLAGS: дополнительные параметры не должны
незаметно менять сборку при прежнем записанном argv. Исходный JSONL сохраняется
отдельно; запрещённые XML 1.0 символы тестового вывода (например ANSI ESC)
заменяются в представлении JUnit на U+FFFD, чтобы отчёт оставался читаемым XML.
Модель policy.py демонстрирует только явно описанный workflow и не является
парсером .gitlab-ci.yml или заменой GitLab CI Lint.

Для настоящего собственного GitLab:
1. Создайте приватный личный проект, отправьте только содержимое service.
2. Подготовьте отдельный личный Runner с меткой personal-go.
3. Для Docker executor задайте несекретную project variable
   LAB_GO_PYTHON_IMAGE: полный закреплённый образ с Go и Python 3.
4. Проверьте YAML через CI Lint своего GitLab и запустите pipeline.
5. Проверьте unit/vet -> build -> verify и скачайте manifest и бинарник.
6. Проверьте неуспех теста, артефакт отчёта, ожидание при остановленном Runner,
   правила MR/branch/tag и доступ без полномочий.

Live GitLab/Runner в этой редакции здесь не разворачивались. Локальная проверка
не подтверждает регистрацию Runner, серверную семантику YAML, UI JUnit или
права API. Именно эти границы нужно подтвердить отдельно на личном экземпляре.

Запуск приложения, если нужен настоящий локальный HTTP:
  ./dist/echo -listen 127.0.0.1:18081
Остановите процесс после опыта. По умолчанию он слушает только loopback.
На другом целевом GOOS/GOARCH используйте соответствующий нативный исполнитель.
