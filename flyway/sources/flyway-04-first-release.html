Первая миграция и первое приложение

Сначала принимаем состояние базы, затем допускаем Go-процесс к прикладным операциям.

Что создаёт V1

В migrations/V1__create_notes.sql таблица notes получает числовой первичный ключ id — уникальное ненулевое имя строки; PostgreSQL создаёт identity-последовательность, выдающую новые номера. Поле body хранит текст, created_at — момент вставки. Приложению нужны SELECT/INSERT/UPDATE и доступ к последовательности. Оно не получает владение таблицей и не запускает миграции при каждом HTTP-запросе.

Конфигурация уже существует в скопированном flyway.conf. Она перечисляет только app и flyway_meta, с defaultSchema=flyway_meta, требует корректные имена файлов, запрещает clean и автоматический baseline. Пароли не включены. Wrapper lab.py читает частный runtime.json и передаёт URL/user/password в окружение только дочернего процесса. Окружение — не идеальное хранилище секретов: владелец процесса/администратор может его прочесть. Здесь это личная VM; в CI нужны собственные защищённые переменные и ограничение доступа к runner.

Принять версию 1

Блок: Bash обычного владельца, cwd $HOME/handbook-lab/flyway. PostgreSQL запущен и bootstrap принят. Читаются существующие migrations/, flyway.conf и .private/runtime.json; новых учётных записей блок не создаёт.

set -euo pipefail
cd "$HOME/handbook-lab/flyway"
python3 lab.py flyway info -target=1
python3 lab.py flyway validate '-ignoreMigrationPatterns=*:pending'
python3 lab.py flyway migrate -target=1
python3 lab.py sql --file inspect.sql
python3 lab.py sql --role app --file seed.sql

Wrapper исполняет настоящий flyway -configFiles=… migrate -target=1. info читает доступные/применённые действия; ничего не накатывает. validate сверяет историю с файлами; обычный самостоятельный validate отвергает ещё не применённые Pending. Здесь локальное исключение *:pending разрешает подготовленные следующие действия, сохраняя проверку checksum уже принятых. Оно заменяет default-список исключений, поэтому Future здесь не игнорируется. target=1 ограничивает следующие versioned-миграции сверху и оставляет V2–V6 Above Target. Repeatable view выполняется после V1. Ожидаются код 0, успешные V1/R и две отрицательные проверки прав приложения. Последний шаг добавляет 1000 записок от app_local. Повтор seed намеренно добавит ещё 1000; это нагрузочный ввод, не идемпотентная миграция. Ошибка в любом шаге прекращает цепочку до зависимой записи.

Приложение не требует Java

Файл app/main.go использует database/sql и закреплённый драйвер pgx v5.11.0. Перед первой сборкой должны быть локальный Go 1.27.3, сеть к Go proxy либо подготовленный module cache. go.sum фиксирует ожидаемые суммы зависимостей. Вычисленный checksum SQL с этим механизмом не связан.

Блок подготовки: тот же пользователь и cwd, приложение ещё не запущено; исходники и go.sum уже скопированы. Загрузка пишет в личный Go module cache, сборка — в app/bin/. go -C app выполняет команду из существующего каталога app; mod download получает закреплённые зависимости. GOTOOLCHAIN=local запрещает автоматический выбор скачиваемого toolchain, GOWORK=off исключает посторонний workspace. Helper app-build также задаёт эти две переменные и -mod=readonly: он не должен молча менять go.mod/go.sum. При недостающем module cache offline-сборка откажет до запуска Go-процесса.

set -euo pipefail
export PATH="$HOME/opt/go/bin:$PATH"
GOTOOLCHAIN=local GOWORK=off go -C app mod download
python3 lab.py app-build
python3 lab.py app-run v1

Go должен уже находиться в указанном PATH: блок его не устанавливает. Сборка возвращает 0; долгоживущий app-run v1 занимает терминал и слушает 127.0.0.1:18080. В другой оболочке с тем же cwd выполните чтение/вставку ниже. HTTP 200/201 допускают продолжение; отказ подключения означает, что процесс не готов; HTTP 503 после неопределённого результата записи нельзя слепо повторять — здесь нет ключа идемпотентности.

set -euo pipefail
cd "$HOME/handbook-lab/flyway"
python3 lab.py request
python3 lab.py request --text 'Первая собственная записка'

POST /notes принимает ровно один JSON-объект с непустой строкой text. Общий предел тела — 8192 байта, включая пробелы после объекта. Decoder после объекта требует EOF — конца входа; вторая JSON-ценность, мусор или превышение бюджета дают HTTP 400 до запроса к PostgreSQL. Завершающие пробелы в пределах бюджета допустимы. Проверка только первого Decode пропустила бы хвост, поэтому в сервисе чтение доведено до EOF.

Первая команда возвращает не более 100 строк; порядок задаёт id. Вторая создаёт новую строку и печатает id. Остановите приложение Ctrl-C в его терминале: обработчик SIGINT завершает HTTP с бюджетом 5 секунд. Это останавливает Go, но сохраняет PostgreSQL, строки и history. Сетевой пароль не появляется в аргументах Go; для сообщения об ошибке код не печатает DSN.
