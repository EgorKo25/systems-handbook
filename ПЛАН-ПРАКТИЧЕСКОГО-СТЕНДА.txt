ПРОЕКТ ПРАКТИЧЕСКОГО СТЕНДА
28 октября 2026. Проект, а не установленная песочница.

ЗАДАЧА
Один учебный мир продолжается между главами. На клиенте настраиваем
сеть, на маршрутизаторе исследуем доставку и NAT, на сервере запускаем
службы и PostgreSQL. Упражнения используют уже сделанное: вместо нового
пустого стенда появляются новые задачи для знакомых машин.

Пример окружения: Ubuntu 24.04 и 14 ГиБ памяти для практики;
Windows и флешка для автономного чтения.
Поэтому полноценный домашний стенд и рабочий режим имеют разные границы.

ДОМАШНЯЯ ОСНОВА
Три небольшие виртуальные машины QEMU с ускорением KVM в Linux:

клиент — учебная сетьA — маршрутизатор — учебная сетьB — сервер

Виртуальная машина имеет своё ядро, загрузку, устройства и диски.
Это подходит для маршрутизации, NAT, SSH, systemd, разделов, файловых
систем и LVM. Docker использует ядро той Linux-системы, внутри которой
работает; контейнеры полезны для отдельных приложений и сравнений
способов развёртывания. Для упражнений с ядром и дисками основной
границей остаётся виртуальная машина. Docker можно добавлять внутри
учебного сервера, когда он нужен по теме.

Начальный бюджет для испытаний: клиент 512 МиБ, маршрутизатор 512 МиБ,
сервер 1024 МиБ гостевой памяти; вместе с расходами эмуляторов ориентир
2–3 ГиБ. Это проектное предположение, не результат измерения готового
стенда. Состав и настройки серверных процессов ещё надо проверить.
Больше реплик и служб запускаются по необходимости. Выключенные узлы
не держат гостевую RAM. Программа запуска проверяет доступную память,
но не закрывает приложения пользователя и не меняет настройки хоста.

На домашнем компьютере при осмотре свободный запас был около 1,1 ГиБ,
а swap занят. В этой сессии машины не запускались и ПО не устанавливалось.
Наличие /dev/kvm отмечено; фактический запуск с ускорением не проверен.

ЧТО ЗНАЧИТ «СОХРАНИТЬ МИР»
У каждой машины — неизменяемый исходный диск и отдельный рабочий файл
изменений. QCOW2 — формат виртуального диска, позволяющий хранить
изменённые блоки отдельно от исходного образа. Удаление упражнения не
должно затрагивать файлы ДО, документы пользователя или исходные образы.

Обычная остановка и последующий запуск сохраняют записанные данные.
Контрольная точка сохраняет диски всех связанных машин и описание сети
после корректного выключения. Возврат к ней запускает машины заново.
Это предсказуемый базовый вариант для переноса между компьютерами.

Открытые SSH-сеансы, память процессов и временное сетевое состояние в
такой точке не сохраняются. Маршрут, заданный только командой ip route,
после загрузки не появится сам: постоянную настройку ученик записывает
самостоятельно. Сохранение RAM работающей VM возможно как отдельный
режим на совместимом хосте; переносимый комплект не должен обещать его.

Для PostgreSQL, реплик и управляющего сервиса точка охватывает согласованно
весь связанный мир. Откат одной старой реплики в продолжающую работать
группу — отдельное упражнение восстановления. Простая копия работающего
PGDATA не становится корректной резервной копией. Docker commit также
не включает данные подключённых volumes — их надо сохранять отдельно.

Возврат к началу конкретного упражнения должен быть явным выбором.
По умолчанию при переходе к следующей главе данные не сбрасываются.
Полезно иметь личную основную ветку и отдельную копию для разрушительного
опыта. Возврат меняет только выбранный учебный мир.

ПОДКЛЮЧЕНИЕ И СВЯЗЬ С КНИГОЙ
В главе — одна кнопка «Открыть практику». Она показывает нужные машины,
продолжение текущего мира либо копию контрольной точки и требования к
ресурсам. Выполнение команд не происходит от простого открытия HTML.
Домашняя программа управления запускается пользователем отдельно.

Внутри практики достаточно карты машин, подключения/консоли, остановки
и контрольных точек. Объяснения и проверка результата раскрываются
по желанию. Проверка должна читать состояние гостя, а не сравнивать
введённую строку с единственным «правильным» написанием команды.

SSH означает настоящий клиент и сервер внутри гостя. Порты управления
слушают только localhost. Учебные Ethernet-соединения не присоединяются
к рабочей локальной сети по умолчанию. Для опытов с NAT достаточно двух
виртуальных сегментов и учебного сервера на другой стороне; интернет
для этих опытов не требуется. Образы заранее содержат нужные пакеты.

Пример последовательности:
1. Назначить адреса и исследовать доставку клиент→сервер.
2. Разобрать захват на двух сторонах маршрутизатора и настроить NAT.
3. Развернуть службу на знакомом сервере и проверить её с клиента.
4. Добавить отдельный виртуальный диск, создать ФС/LVM, перенести данные.
5. Поставить PostgreSQL, разобраться с сокетом, TCP, доступом и копиями.
6. При достаточных ресурсах добавить реплику и разбирать отказы.

Состав урока: исходные условия, задача, наблюдаемый результат, подсказки,
проверка, разбор, безопасная точка возврата. Не каждый урок требует новой VM.

РАБОЧИЙ WINDOWS
Базовый режим — нынешняя офлайн книга, схемы и учебный терминал в браузере.
Он не требует установки Docker, WSL, гипервизора, драйвера или изменения
сетевых настроек Windows. При строгом запрете запуска дополнительного ПО
на этом режиме и следует остановиться.

Запуск с USB не равен отсутствию следов. Браузер и Windows могут сохранять
свои данные и журналы; браузерные заметки/прогресс книги тоже сохраняются
локально. Гарантию «нулевой след» проект не даёт. Политика рабочего ПК
имеет приоритет; средства обхода ограничений не предусматриваются.

Если запуск одобренного ПО с USB разрешён, можно отдельно испытать QEMU
с программной эмуляцией TCG. Она не требует аппаратного ускорителя,
но обычно медленнее него. На Windows ускоритель WHPX требует включённого
компонента Windows Hypervisor Platform — это не базовое условие проекта.
Официальный сайт QEMU указывает источники Windows-сборок; готовый
подходящий переносимый комплект ещё предстоит выбрать и проверить.

В проекте такого варианта: виртуальные связи через loopback, гостевые
диски и записи стенда на USB, явный SSH-порт 127.0.0.1, запрет внешней сети
по умолчанию. Не следует обещать, что временные данные ОС всегда останутся
на флэшке. Это дополнительный разрешённый режим, а не основной сценарий.

ПЕРЕНОС ДОМАШНЕГО МИРА
Выключенные диски QCOW2 могут быть общим форматом для Ubuntu и Windows.
Нужно фиксировать архитектуру CPU, тип машины, контроллеры дисков,
сетевые устройства, версии и все исходные образы цепочки. Поэтому
перенос — отдельная команда экспорта целого комплекта с проверкой
контрольных сумм, а не копирование одного случайного рабочего файла.
RAM-снимки и прозрачная миграция Docker↔VM в обещание не входят.

Перед обновлением формата/образов сохраняется предыдущая рабочая версия.
Флэшка хранит транспортную копию; единственный экземпляр ценных настроек
не должен зависеть от случайного извлечения накопителя во время записи.

ВОЗМОЖНЫЙ БРАУЗЕРНЫЙ ПРОТОТИП
v86 эмулирует настоящий 32-разрядный x86-компьютер внутри браузера.
Есть экспорт состояния и обмен Ethernet-кадрами между экземплярами без
внешнего сервера. Это перспективный опыт для маленького Linux-гостя,
Bash, прав, процессов и части сетевых задач на рабочем Windows.

Но поддерживаются только 32-разрядный x86 и один процессор; обычный
64-разрядный домашний образ туда не переносится. Штатная загрузка
ресурсов рассчитана на HTTP. Для нашей книги нужен специальный полностью
автономный комплект и отдельная проверка file:// в разрешённых браузерах.
Две сетевые стороны маршрутизатора, увеличение диска, LVM и подходящий
PostgreSQL пока не проверены. Цифры скорости эмуляции не характеризуют
производительность настоящего сервера. Это отдельный исследовательский
прототип, который нельзя показывать читателю как готовую возможность.

ПОРЯДОК РЕАЛИЗАЦИИ
Сначала один домашний Linux-гость: SSH, постоянный диск, выключенная
контрольная точка и откат. Затем три машины и настоящий путь пакета/NAT.
После проверки ресурсов — продолжение мира между двумя главами,
дисковая практика и установка PostgreSQL. В последнюю очередь — HA,
перенос на разрешённый Windows и браузерный прототип.

Критерий готовности: человек без интернета открывает комплект, видит
понятные требования, запускает практику, меняет данные, закрывает стенд,
продолжает позже и может воспроизводимо вернуться к своей точке.
Такой сценарий ещё не испытан; эта редакция сохраняет проект решений.
