Jenkinsfile: описание конвейера, которое можно объяснить

Составим последовательность получения исходников, тестирования, упаковки и сохранения результата. У каждой директивы будет причина, а у примера — обозначенная среда, чтобы его можно было перенести без догадок о скрытых плагинах.

Предпосылки перед копированием файла

Пример использует Declarative Pipeline — декларативную форму описания конвейера Jenkins. Нужны Jenkins с совместимыми установленными компонентами Pipeline, включая поддержку Declarative, шагов SCM и долговременного запуска команд, а также Git plugin для checkout scm. Задание создаётся как Multibranch Pipeline: Jenkins обнаруживает ветки репозитория и даёт контекст, по которому работает условие branch. Нужен Linux amd64-агент с меткой linux-go, Git, Go и Python 3 и доступом к репозиторию. Метку назначает администратор; Jenkins не создаёт подходящую машину по самому слову в файле.

Репозиторием задания является самостоятельная закоммиченная копия Go-службы из go/labs/service, а не корень всей энциклопедии. В ней есть go.mod, исходники и тесты Go, а tools/build.py создаёт dist/handbook-service и dist/manifest.json. Python нужен только для понятной записи и проверки метаданных; приложение и тесты написаны на Go. Внешних модулей нет. Файл ниже использует checkout scm в контексте Multibranch. Отдельный локальный вариант автономной лаборатории Jenkins получает свою копию репозитория через явный Git clone и не требует ослабления глобальной политики SCM.

На агенте нужен известный Go; проверяемая поставка использует 1.27.3, а директива go 1.25.0 задаёт минимальное требование языка. Цель примера — Linux amd64 с CGO_ENABLED=0, чтобы собранную программу можно было тут же запустить на соответствующем агенте. Для другой ОС или архитектуры меняют контракт и проверку; имя метки само не эмулирует процессор. Нужные плагины устанавливают заранее. Отчёт реального лабораторного прогона вынесен в проверку Jenkins; он не означает испытание любого сервера и любого плагина.

Полный пример

pipeline {
    agent { label 'linux-go' }
    options {
        timeout(time: 15, unit: 'MINUTES')
        disableConcurrentBuilds()
        skipDefaultCheckout(true)
        buildDiscarder(logRotator(numToKeepStr: '20'))
    }
    environment {
        PYTHONDONTWRITEBYTECODE = '1'
        PYTHONUTF8 = '1'
        GOENV = 'off'
        GOTOOLCHAIN = 'local'
        GOWORK = 'off'
        GOPROXY = 'off'
        GOTELEMETRY = 'off'
        GOFLAGS = ''
        CGO_ENABLED = '0'
        GOOS = 'linux'
        GOARCH = 'amd64'
        GOAMD64 = 'v1'
        GOEXPERIMENT = ''
    }
    stages {
        stage('Снимок исходников') {
            steps {
                deleteDir()
                checkout scm
                sh 'go version'
            }
        }
        stage('Тесты без повторного использования результата') {
            steps {
                sh '''
                    export GOCACHE="$PWD/.lab-cache/build"
                    export GOPATH="$PWD/.lab-cache/gopath"
                    export GOMODCACHE="$PWD/.lab-cache/modules"
                    go test -count=1 ./...
                '''
            }
        }
        stage('Сборка') {
            steps {
                sh 'python3 tools/build.py --version 1.0.0'
            }
        }
        stage('Проверка комплекта') {
            steps {
                sh '''python3 - <<'PY'
import hashlib, json, subprocess
from pathlib import Path

def require(condition, message):
    if not condition:
        raise SystemExit(message)

output = Path('dist')
manifest = json.loads((output / 'manifest.json').read_text(encoding='utf-8'))
require(manifest['format'] == 1 and manifest['binary'] == 'handbook-service',
        'Неверный формат или имя бинарного файла')
binary = output / manifest['binary']
data = binary.read_bytes()
require(len(data) == manifest['bytes'], 'Размер бинарного файла изменился')
require(hashlib.sha256(data).hexdigest() == manifest['sha256'], 'SHA-256 не совпал')
require(manifest['version'] == '1.0.0', 'Неожиданная версия приложения')
require(manifest['target'] == dict(GOOS='linux', GOARCH='amd64', GOAMD64='v1',
                                  CGO_ENABLED='0', GOEXPERIMENT=''),
        'Неожиданная целевая среда')
require(manifest['flags'] == ['-mod=readonly', '-trimpath', '-buildvcs=false',
                             '-ldflags=-X main.Version=1.0.0'],
        'Неожиданные параметры сборки')
head = subprocess.check_output(['git', 'rev-parse', '--verify', 'HEAD'], text=True).strip()
require(manifest['source_revision'] == head and manifest['source_dirty'] is False,
        'Происхождение не соответствует чистому текущему снимку')
require(manifest['build_script_sha256'] == hashlib.sha256(Path('tools/build.py').read_bytes()).hexdigest(),
        'Изменился сценарий сборки')
toolchain = subprocess.check_output(['go', 'version'], text=True).strip()
require(manifest['toolchain'] == toolchain, 'Сведения о Go отличаются от инструмента агента')
version = subprocess.check_output([str(binary.resolve()), '-version'], text=True).strip()
require(version == '1.0.0', 'Запущен другой выпуск')
PY
'''
                sh 'go version -m dist/handbook-service'
                sh 'go tool buildid dist/handbook-service'
            }
        }
        stage('Сохранение основной ветки') {
            when { branch 'main' }
            steps {
                archiveArtifacts(
                    artifacts: 'dist/handbook-service,dist/manifest.json',
                    allowEmptyArchive: false,
                    onlyIfSuccessful: true,
                    fingerprint: true
                )
            }
        }
    }
    post {
        always {
            echo "Итог: ${currentBuild.currentResult}"
        }
        cleanup {
            deleteDir()
        }
    }
}

Где выделяется агент и где начинается таймер

Один верхнеуровневый agent даёт стадиям общую выделенную среду и рабочий каталог. Это простая схема для небольшого проекта. timeout задаёт предел времени выполнения после выделения верхнеуровневого агента; ожидание этого агента в общий лимит данного варианта не входит. При агенте и options на уровне отдельной стадии таймер может включать выделение её агента. Поэтому перенос одинаковых строк на другой уровень способен изменить наблюдаемую длительность до прерывания.

disableConcurrentBuilds() запрещает одновременно исполнять несколько запусков данного задания; следующий ждёт. Это помогает с общей инфраструктурой, но не заменяет корректную изоляцию. В Multibranch каждая ветка представлена своим заданием, поэтому настройка не является глобальным замком для всех веток и всех проектов. buildDiscarder с numToKeepStr: '20' ограничивает историю по политике ротации; существенные выпуски следует хранить в предназначенном для них хранилище, а не рассчитывать на бесконечность истории задания.

skipDefaultCheckout(true) отключает неявное получение исходников. Мы делаем его явно после deleteDir(), чтобы старые файлы не участвовали в тестах. checkout scm использует настройку SCM и ревизию контекста задания; самостоятельно вставленная команда «клонировать последнюю main» могла бы проверить другой код, чем тот, из-за которого начался запуск. Очистка удаляет содержимое текущего workspace; она не очищает домашний каталог агента, общий кэш пакетов и внешнюю базу.

Что проверяют команды и что попадает в архив

go test -count=1 ./... выбирает пакеты текущего дерева и принудительно исполняет тесты вместо использования сохранённого успешного результата. Кэш компиляции остаётся допустимым. Каталоги GOCACHE, GOPATH и GOMODCACHE размещены внутри рабочей копии; правила игнорирования исключают их из происхождения исходников. python3 tools/build.py --version 1.0.0 запускает наш сценарий, где --version задаёт метку приложения. Это не флаг версии интерпретатора Python. Сценарий явно фиксирует целевую среду и параметры Go build.

Для проверки комплекта аргумент Python - читает программу со стандартного ввода, а <<'PY' передаёт текст до отдельной строки PY без подстановок оболочки. require — наша функция, завершающая действие ошибкой при нарушении условия. Проверяются формат, имя, размер и SHA-256 бинарного файла; версия, цель, набор флагов, фактический HEAD, чистота дерева, хеш сценария и идентичность Go. В конце запускается именно созданный бинарный файл с -version, и его ответ сравнивается с ожидаемой меткой. Это короткий запуск без слушающего порта, а не полная проверка HTTP-интеграции.

Параметр --verify у git rev-parse требует корректного разрешения ссылки HEAD. chr(10) в многоязычных фрагментах удобно обозначает LF без лишнего уровня обратных косых черт; каждый текст проходит сначала Groovy, затем оболочку, затем Python. Для этого проверяющего кода нужны стандартные библиотеки Python, сторонние пакеты не используются. Ошибки JSON, отсутствующего файла и дочерней команды не подавляются.

go version -m показывает доступные встроенные сведения о модулях и параметрах сборки. go tool buildid показывает внутренний идентификатор Go build. Они помогают объяснить файл, но не заменяют полный внешний SHA-256 и доверенное происхождение. При -buildvcs=false автоматическая запись VCS-сведений отключена; исходная ревизия сохраняется во внешнем манифесте. Мы проверяем согласованность этого конкретного контракта, а не объявляем любое совпадение хеша доказательством безопасности.

PYTHONDONTWRITEBYTECODE=1 запрещает обычную запись Python-кэша .pyc при импорте; это уменьшает мусор рабочего дерева. PYTHONUTF8=1 включает режим UTF-8 интерпретатора. Ни одна переменная не фиксирует версию Python и не делает преобразования пользовательского кода автоматически воспроизводимыми. Среда агента всё равно должна иметь известный интерпретатор, а бинарные входы читают как байты.

Условие when { branch 'main' } выбирает политику сохранения: остальные ветки проходят проверки и упаковку, но в этой схеме не архивируются. Это поведение опирается на контекст Multibranch. В обычном Pipeline нельзя ожидать, что такая проверка сама определит ветку по произвольному локальному репозиторию. archiveArtifacts сохраняет два перечисленных через запятую файла: бинарный файл и манифест. allowEmptyArchive: false делает отсутствие совпадений ошибкой, но само по себе не требует присутствия каждого из двух имён; для этого перед архивированием и выполнена отдельная проверка комплекта. onlyIfSuccessful: true ограничивает архивирование успешным состоянием; fingerprint: true добавляет механизм отслеживания Jenkins. Fingerprint Jenkins не следует выдавать за криптографическую подпись выпуска или современный SHA-256-манифест.

Ошибки и завершающие действия

Окружение Go фиксирует область опыта

GOTOOLCHAIN=local оставляет установленный инструмент вместо автоматического получения другого; GOENV=off исключает пользовательский файл постоянных настроек Go; GOWORK=off отключает поиск внешнего рабочего пространства модулей. GOFLAGS очищен, чтобы скрытый набор параметров не изменял команду. GOPROXY=off допустим здесь благодаря отсутствию внешних модулей. Эти настройки нельзя без подготовки перенести на проект, которому действительно нужны зависимости: отказ их получить будет ожидаемой ошибкой, а не доказательством автономности.

GOOS, GOARCH и GOAMD64 выбирают целевую ОС, архитектуру и уровень требований amd64. CGO_ENABLED=0 исключает C-интеграцию для этой сборки; код, которому она нужна, потребовал бы другого контракта. GOEXPERIMENT очищен, чтобы не включить экспериментальные режимы извне. Эти переменные объясняют цель опыта и фиксируются в манифесте. Они не гарантируют одинаковые байты между разными версиями Go или разными исходниками.

Поскольку цель Linux amd64, короткий запуск -version выполняется на соответствующем агенте. Кросс-компиляция для Windows может успешно создать EXE на Linux, но это не позволяет исполнить его обычным Linux-процессом. Проверку пакета и проверку запуска на целевой платформе тогда разделяют. Выбор agent any без проверки совместимости мог бы сделать один и тот же Jenkinsfile случайно успешным или падающим в зависимости от свободного узла.

Скрипт сборки намеренно не включает автоматические VCS-метаданные в бинарный файл: -buildvcs=false оставляет их во внешнем JSON. -trimpath уменьшает зависимость встроенных путей от рабочего каталога. Линкерный -X main.Version=1.0.0 задаёт значение строковой переменной версии. Такие условия удобны для независимого сравнения; полноценное утверждение о воспроизводимости всё равно требует повторной сборки и сравнения полного файла. Совпадение значения Version является лишь одной проверкой.

Ненулевой код обычного sh завершает шаг ошибкой; последующие обычные стадии не продолжаются как успешные. В post условие always выполняет завершающее действие при разных исходах, а cleanup предназначено для окончательной уборки после остальных условий. Если агент потерян, операция, требующая его workspace, тоже может оказаться невыполнимой; нельзя обещать абсолютную очистку удалённой машины одним блоком. В рабочем варианте нужные диагностические файлы сохраняют перед удалением и контролируют срок жизни временных агентов.

Не добавляйте || true к тестам ради зелёного интерфейса: это меняет договорённость об ошибке. Если требуется получить код вручную, у sh есть returnStatus: true; после этого автор обязан сам сравнить результат и вызвать error при недопустимом исходе. Когда одно действие повторяется, проверьте его побочные эффекты. Повтор компиляции обычно безопаснее повторной публикации под изменяемым именем.

Где уместны credentials

Основной конвейер не обращается к закрытому сервису публикации, поэтому ему не нужен такой секрет. Если позднее появляется отдельный издатель, секрет передают только на время соответствующего шага через Credentials Binding. Минимальная форма выглядит так:

withCredentials([string(credentialsId: 'release-token', variable: 'TOKEN')]) {
    sh '''
        set +x
        python3 tools/publish.py dist/handbook-service
    '''
}

Это фрагмент интеграции, а не часть автономного стенда: publish.py потребуется отдельно реализовать для выбранного хранилища и он должен читать TOKEN из окружения, проверять ответ и возвращать ошибку при неуспехе. string связывает запись типа secret text с переменной; credentialsId — идентификатор записи Jenkins, не сам токен. Тройные одинарные кавычки передают текст оболочке без подстановки Groovy. set +x отключает трассировку команд оболочки. Маскирование журнала не защищает от программы, которая сама отправит секрет наружу, и от другого недоверенного процесса под тем же пользователем. Недоверенный код не запускают на агенте с секретами выпуска.

Чего именно достиг основной пример

Контракт этого файла — получить определённый чистый снимок Go-службы, выполнить тесты, собрать известную цель, проверить согласованность бинарного файла и метаданных и сохранить комплект для основной ветки. HTTP-доставка в рабочую сеть сюда не включена. Локальный маршрут лаборатории проверен отдельно; многоветочная интеграция зависит от вашего источника SCM. При переносе сначала воспроизведите короткий успешный и намеренно неуспешный запуск на своём тестовом задании.

Первичные источники

Declarative Pipeline: структура, условия и таймеры; Работа с Jenkinsfile и окружением; archiveArtifacts; sh и коды завершения; Credentials Binding; Команды Go; Выбор toolchain Go. Набор и совместимость плагинов сверяются с установленным сервером; конкретные номера версий здесь не выдуманы.
