Свой локальный Jenkins: Go-служба, агент и сохраняемое состояние

Поднимем небольшой настоящий контроллер и отдельный агент, соберём собственную Go-службу, проверим отказ и сохранённый артефакт. Всё состояние останется в выделенной папке между упражнениями; внешняя сеть после подготовки не требуется.

Границы и предварительная подготовка

Маршрут рассчитан на домашний Linux amd64 с Bash, Git 2.28 или новее, Python 3 и подходящим Go. Проверяемый набор использует Jenkins LTS 2.580.2 и Java 21; для данного Jenkins поддерживается также Java 25. Java 17 не подходит. Go-служба объявляет минимальную версию языка 1.25.0, а зафиксированный инструмент опыта — Go 1.27.3. Здесь нужен установленный toolchain, а не только текст go.mod. Python выполняет небольшой сценарий записи метаданных; сервер приложения написан на Go.

Контроллер ограничен кучей 512 MiB, агент — 128 MiB. Фактическая память JVM больше этих куч; Go-компилятор и тесты расходуют свою память. Это экономный учебный режим с одним executor, не конфигурация рабочего сервера. На компьютере с 8 GiB закройте ненужные тяжёлые приложения и наблюдайте общий расход. На рабочем Windows, где нельзя устанавливать программы и запускать фоновые службы, используйте чтение и встроенные модели; этот Linux-маршрут там выполнять не требуется.

До отключения интернета подготовьте WAR, Go, Java и совместимые плагины Pipeline с зависимостями. Один WAR не содержит всю функциональность Declarative. Для задания нужны поддержка Pipeline, Declarative, базовых шагов и запуска процессов; Git в данном маршруте вызывается командой ОС, без настройки Git plugin на локальный источник. JUnit и Lockable Resources для основного опыта не нужны. Дополнительные упражнения соответствующих глав требуют своих компонентов.

Каталоги и проверенные исходники

Откройте Bash в корне копии библиотеки, где находятся тома git, linux и остальные. Переменные ниже относятся к этой сессии и не меняют домашнюю настройку Git или Go. Выберите новый отдельный каталог; используйте его последовательно во всех терминалах лаборатории.

HANDBOOK_BOOK_ROOT="$(pwd)"
export JENKINS_LAB_ROOT="$HOME/jenkins-handbook"
umask 077
mkdir -p -- "$JENKINS_LAB_ROOT/downloads" "$JENKINS_LAB_ROOT/logs" \
  "$JENKINS_LAB_ROOT/agent-home" "$JENKINS_LAB_ROOT/snapshots"
git --version
python3 --version
java -version
go version

pwd получает текущий путь; двойные кавычки сохраняют его одним аргументом. umask 077 ограничивает доступ к вновь создаваемым файлам и каталогам в этой сессии. mkdir -p создаёт недостающие родительские каталоги, -- завершает параметры. Проверки версий завершаются без запуска службы. Если нужной программы нет, подготовку надо закончить до автономной работы; сценарий не устанавливает её незаметно.

Положите официальный WAR в downloads/jenkins-2.580.2.war. Зафиксированный SHA-256 учебной поставки: d98032d2401c540a35613a82ed358921fcf3166d5e6eaaaf60a7941845be3251. Приложенный launcher сравнивает полный хеш перед запуском. Файл можно заранее получить с официального адреса Jenkins или перенести из своей подготовленной автономной поставки. Хеш должен происходить из доверенного описания выпуска, а не из случайного текста рядом с неизвестным WAR.

python3 - "$HANDBOOK_BOOK_ROOT/go/labs/service" \
  "$JENKINS_LAB_ROOT/go-workshop" <<'PY'
import shutil
import sys
shutil.copytree(sys.argv[1], sys.argv[2])
PY
cd "$JENKINS_LAB_ROOT/go-workshop"
git init --initial-branch=main
git config --local user.name "Handbook Student"
git config --local user.email "student@example.invalid"
git config --local commit.gpgSign false
git add --all
git commit -m "Start the Go build laboratory"

copytree требует отсутствующий каталог назначения: повтор не должен смешивать шаблон с вашими изменениями. При ошибке сначала разберите состояние, а не продолжайте следующую строку. --initial-branch задаёт имя первой ветки; config --local меняет только новый репозиторий. Учебные имя и адрес не являются настройкой личного Git. add --all готовит файлы, commit -m сохраняет сообщение без редактора. Существование собственного коммита нужно для достоверной проверки происхождения.

Проверяем Go-проект до Jenkins

go test -count=1 ./...
python3 tools/build.py --version 1.0.0
./dist/handbook-service -version
go version -m dist/handbook-service
go tool buildid dist/handbook-service

./... — шаблон пакетов Go внутри текущего дерева, а не подстановка Bash. -count=1 требует выполнить тесты вместо использования сохранённого успешного результата; кэш компиляции при этом остаётся допустимым. Тесты обработчиков используют httptest без общего слушающего порта. --version у Python-сценария задаёт метку выпуска, а -version у готовой службы печатает её и выходит. Порт приложения этим запуском не открывается.

go version -m показывает доступные сведения сборки внутри бинарного файла; go tool buildid печатает внутренний build ID. Они полезны для исследования, но не заменяют внешний SHA-256 и описание происхождения. Сборщик создаёт бинарный файл и dist/manifest.json, фиксируя цель, параметры, инструмент, коммит и признак изменённого рабочего дерева. В проекте нет внешних модулей, а сборщик запрещает сетевой прокси и автоматическую загрузку другого Go.

Запуск контроллера и настройка владельца

bash "$HANDBOOK_BOOK_ROOT/jenkins/labs/start-controller.sh" \
  "$JENKINS_LAB_ROOT" 18080

Команда работает в переднем плане первого терминала. Скрипт выбирает controller-home, проверяет WAR, задаёт память JVM и привязывает HTTP только к 127.0.0.1:18080. Откройте этот адрес в браузере и дождитесь готовности. Начальный пароль получите из локального файла controller-home/secrets/initialAdminPassword, не публикуя его. Пройдите мастер, создайте собственную учебную учётную запись и оставьте анонимному пользователю запрет управления.

Заранее установите необходимый набор плагинов либо используйте свою проверенную автономную подготовку. После возможного перезапуска подтвердите наличие типа задания Pipeline. В управлении узлами задайте встроенному узлу контроллера ноль executor. Jenkins URL установите http://127.0.0.1:18080/. Отдельный TCP-порт inbound-агентов в этом маршруте не нужен: используется WebSocket.

Создаём и подключаем агент

В Nodes создайте Permanent Agent с именем handbook-agent, одним executor и меткой handbook-local. Укажите полный путь к своему agent-home как удалённый корень. Выберите запуск подключением агента к контроллеру и WebSocket. Имя регистрации и метка имеют разный смысл: имя нужно для аутентификации подключения, метка — для размещения работы. Откройте страницу узла, чтобы получить его секрет и актуальную команду.

Во втором терминале снова задайте JENKINS_LAB_ROOT. Агент и контроллер работают обычными процессами одного домашнего пользователя; это обучение протоколу, а не защитная виртуальная машина. Для чужого кода такая граница недостаточна.

export JENKINS_LAB_ROOT="$HOME/jenkins-handbook"
umask 077
curl --fail --silent --show-error \
  --output "$JENKINS_LAB_ROOT/agent.jar" \
  http://127.0.0.1:18080/jnlpJars/agent.jar
read -r -s -p 'Секрет своего учебного агента: ' JENKINS_AGENT_SECRET
printf '\n'
printf '%s' "$JENKINS_AGENT_SECRET" > "$JENKINS_LAB_ROOT/agent-secret.txt"
unset JENKINS_AGENT_SECRET
java -Xms32m -Xmx128m -jar "$JENKINS_LAB_ROOT/agent.jar" \
  -url http://127.0.0.1:18080/ -name handbook-agent \
  -secret "@$JENKINS_LAB_ROOT/agent-secret.txt" \
  -webSocket -workDir "$JENKINS_LAB_ROOT/agent-home"

У curl --fail делает ошибочный HTTP-статус неуспехом команды, --silent убирает прогресс, --show-error сохраняет диагностические ошибки, --output задаёт файл. У Bash read -r сохраняет обратные косые черты, -s скрывает ввод, -p задаёт приглашение. printf '%s' записывает значение без добавочного перевода строки; unset убирает временную переменную. Префикс @ у секрета агента заставляет Remoting прочитать файл. Подробное назначение остальных параметров разобрано в главе об агентах.

Первый Pipeline и параметры запуска

Создайте отдельное задание типа Pipeline и вставьте содержимое готового учебного Jenkinsfile в редактор Pipeline script с включённым sandbox. Это локальный вариант с явным clone через команду Git; вариант Multibranch из основной главы использует checkout scm. Плагин локального SCM-доступа глобально не ослабляется. Источником служит только ваш репозиторий go-workshop.

При первом сохранении Jenkinsfile определения параметров могут появиться лишь после начального запуска. Если SOURCE_REPO ещё пуст или осталось показательное значение, конвейер останавливается с понятной ошибкой. После этого выберите Build with Parameters и введите полный путь к своему go-workshop. Значение читается из params, проверяется и передаётся оболочке через отдельную переменную; случайное отсутствие переменной не превращается в непонятный пустой URL Git.

Агент должен видеть путь источника, Git, Go и Python в своей среде. Если Go установлен в отдельном каталоге, его bin добавляют в PATH процесса агента до запуска. Переменная HANDBOOK_GO поддерживается сборщиком, но команды go test и go version тоже должны находить тот же инструмент. Согласованность проверяется, а не предполагается по имени агента.

Положительный и отрицательный результаты

Успешный маршрут получает чистый снимок, выполняет тесты, строит бинарный файл, сверяет манифест и сохраняет оба результата. Скачайте артефакт и сравните полный SHA-256 с манифестом; число байтов также должно совпасть. Workspace после завершающей уборки очищается, а сохранённый комплект остаётся в истории задания. Исходный go-workshop и домашний каталог контроллера не удаляются.

Затем в своём исходном репозитории сделайте намеренно неверное ожидание одного теста и сохраните отдельный коммит. Новый запуск обязан завершиться неуспехом до стадии сохранения выпуска. Не исправляйте результат добавлением || true. Верните правильное ожидание новым коммитом и повторите: проверяться должны новые входы с новым идентификатором. Так исследуется реальный барьер, а не только удачный путь.

Очередь, перезапуск и продолжение на следующий день

Остановите только агент, оставив контроллер. Запустите задание и убедитесь, что оно ждёт метку handbook-local, а команда не выполняется на встроенном узле. Верните агент той же командой: работа должна получить слот. Для опыта восстановления создайте отдельное безопасное задание с sleep time: 60, unit: 'SECONDS', выполните штатный перезапуск контроллера и исследуйте продолжение. Не используйте для этого настоящую доставку или изменение базы.

На время завершения дня дождитесь окончания нужных запусков, остановите JVM контроллера и агента, сохраните согласованную копию по главе о восстановлении Jenkins. В следующий раз запускайте те же каталоги: учётная запись, задания, параметры и история сохранятся. Новый controller-home означает новый экземпляр. Удалять состояние для каждого следующего упражнения не требуется; сброс делают отдельным осознанным действием после сохранения нужных результатов.

Проверенная область этого стенда ограничена локальным Linux, своим кодом, указанными версиями и выбранными штатными отказами. Работа с удалённым SCM, TLS-прокси, Windows-агентами, аварией питания и реальными секретами доставки требует отдельных опытов. Смысл лаборатории в том, что каждый наблюдаемый переход можно объяснить и повторить, а сделанные настройки остаются вашими между главами.

Что подтверждено исполнением

В поставке книги выполнены девять реальных проверок на Jenkins 2.580.2, Java 21.0.11 и Go 1.27.3: успешный Go-конвейер с совпадением SHA-256 и чистой исходной ревизией; отдельный WebSocket-агент при нуле исполнителей контроллера; наблюдаемая очередь при одном executor; штатное продолжение того же CPS-запуска после SIGTERM во время sleep без повторной метки BEFORE; намеренно неуспешный тест с отказом Pipeline и отсутствием архивированного бинарного выпуска. Полный перечень и ограничения находятся в связанном машинном отчёте.

Фактически загружено 48 плагинов вместе с зависимостями. Их точный список сохранён отдельно; сами бинарные файлы WAR и расширений не включены в публичный репозиторий. После проверок процессы контроллера и агента остановлены. Отчёт документирует выполненный опыт, а для вашей автономной работы всё равно требуется заранее подготовить свои разрешённые программы и файлы.
