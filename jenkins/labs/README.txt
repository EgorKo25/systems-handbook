Локальная лаборатория Jenkins

Полный маршрут и объяснения — глава 45 самостоятельного тома VIII Jenkins.
Основной проект — Go-служба из go/labs/service в корне библиотеки.
Практикум Git с Python-шаблоном — отдельный маршрут со своим состоянием.

Файлы:
- start-controller.sh: foreground-запуск проверенного WAR на 127.0.0.1;
  аргумент 1 — отдельный каталог лаборатории, аргумент 2 — порт (по умолчанию 18080).
- Jenkinsfile: основной Declarative Pipeline Go-службы для отдельного задания
  Pipeline из UI. Требуется агент Linux amd64 с меткой handbook-local,
  установленными Git, Go и Python3. SOURCE_REPO указывает собственный чистый
  локальный репозиторий, созданный из go/labs/service. Изменения надо закоммитить.
  После первого запуска определения параметров могут только появиться в задании:
  используйте Build with Parameters и задайте свой абсолютный путь.
- Jenkinsfile.python-example: дополнительный прежний пример для Python-проекта
  Git-тренажёра. Он не является основным маршрутом книги Jenkins.

На Linux нужны Bash, Git, Go, Python3, Java 21 и подготовленный WAR Jenkins 2.580.2.
Для Pipeline отдельно нужны совместимые плагины и их зависимости; WAR их не
заменяет. Их устанавливают до автономной работы. Java17 для этого Jenkins не подходит.
Порядок подготовки агента и сохранения состояния подробно изложен в автономной лаборатории Jenkins.
На рабочей машине, где запрещены установки и фоновые программы, используйте чтение
и встроенные схемы книги. Windows-вариант реального стенда здесь не проверялся.

Лаборатория — несколько обычных процессов под вашим пользователем, не виртуальная
машина и не защитная песочница для чужого кода. Контроллер и агент на одном домашнем
компьютере показывают протокол взаимодействия, но не создают изоляции прав ОС.

Основной Jenkinsfile проверяет Go-тесты, сборку, бинарный файл, манифест, версию и HEAD;
архивирует бинарный файл и manifest.json. Jenkinsfile хранится в конфигурации UI;
основная глава19 отдельно показывает вариант checkout scm для Multibranch.

Фактические версии и девять проверок описаны в runtime-check.json;
полный набор 48 загруженных плагинов — plugins.lock.txt. Результат штатного
перезапуска во время sleep не распространяется на power loss, потерю диска,
сетевое разделение, Windows и внешние SCM webhooks.
