Язык и интерфейсы

Для типов/преобразований нужны types и constraints; для knowledge propagation — references. Для адресов и масштаба — for_each, count, dynamic. Каждая глава языка связывает это с собственным конфигом и возможным отказом.

В модульной книге используются composition, providers/aliases, refactoring/moved и sources. Настройки provider и library interface не выводятся из похожего имени ресурса.

Исполнение и память

Граф, Plugin Protocol и JSON view ограничивают точность модели: нарисованные сообщения — логические переходы, не дамп network packets. Для exact RPC fields смотрите versioned definitions. Встроенный terraform_data не подтверждает запуск внешнего plugin process.

State-линия опирается на purpose, locking, push checks, local backend и S3 backend. Import/removed/lifecycle уточняются по import, removed, lifecycle. Secrets-линия сверяется с sensitive, ephemeral и write-only.

Зависимости и VM-адаптер

Lock file, installation methods/cache, mirror описывают поставку пакетов. VM-рецепт привязан к dmacvicar/libvirt 0.9.9 и его domain schema. Это первичный проект community provider, не встроенная универсальная VM-функция Terraform.

Что именно проверено

При перечитывании 2 ноября 2026 года выполнены только вычисления в памяти: fixed-model переходы, сравнение сохранённого JSON view и файлов на искусственных входах, HTML/ID/ARIA, AST, точные source-splices и bash -n нового сценария установки. Terraform init/apply и внешние API повторно не запускались. Два встроенных рисунка показывают конкретные записи и условные переходы; визуальные размеры телефона, восемь тем и реальная печать ожидают браузерной приёмки интегратора. Исторические CLI-результаты ниже относятся к исходной редакции; новая null-диагностика пока проверена статически.

labs/check-results.json содержит 15 настоящих CLI-проверок одной цепочки, labs/language-results.json — 10 дополнительных HCL/state проверок с реальным CLI, labs/benchmark-results.json — реальные локальные wall-time/state-size наблюдения. labs/adapters/libvirt/schema-check.json фиксирует успешные init/validate/schema, включая повтор с mirror без прямого registry-источника и без plan/apply к гипервизору. Статический QA проверяет структуру CONFIG, command cards, diagrams и локальные links. Промышленное API, удалённый backend, гостевые машины и приёмка Go-сервиса не объявляются выполненными. Подробные команды и ограничения сохранены в ПРОВЕРКИ.txt и READY.txt.
