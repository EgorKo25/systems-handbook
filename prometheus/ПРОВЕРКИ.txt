6. Loopback/TSDB acceptance — РЕАЛЬНО ВЫПОЛНЕН

Безопасная повторная команда (заменить пути на подготовленные binaries):
python3 prometheus/labs/check.py \
  --prometheus /path/to/prometheus-3.13.5/prometheus \
  --promtool /path/to/prometheus-3.13.5/promtool \
  --go /path/to/go/bin/go --module-cache /path/to/prepared-modules

Итоговый результат: exit0,
STATIC/MODEL/CLI HELP/NEGATIVE PASS и native SUCCESS;
LIVE PASS: Go200/500 → exposition lint → scrape/up → sample → WAL restart
→ snapshot → independent restore query.

Runner использует TemporaryDirectory и только127.0.0.1 с выбранными
свободными портами, временную TSDB, собственные процессы Popen.
Завершает только свои процессы, никогда не killall/systemctl/sudo.
Копирует исходники Go и подготовленный module cache в temp;
GOPATH/GOCACHE/GOMODCACHE временные; GOENV=off/GOWORK=off,
GOTELEMETRY=off/GOTOOLCHAIN=local/GOPROXY=off/GOSUMDB=off;
go test/build выполняются с -mod=readonly. Проверенные go.mod/go.sum
не изменяются, сеть для dependency lookup не требуется.

Отказ admin snapshot без флага в3.13.5 подтверждён как HTTP500
с сообщением admin APIs disabled. Первый запуск runner ошибочно ожидал503,
нашёл несоответствие и был исправлен; после исправления полный live PASS.
Приёмка включает штатный SIGTERM restart, не аварию питания.
Исторический counter query до/после restart и в отдельном restore-data
с пустым scrape config имеет прежнее значение1 для500-series.

7. ЧТО НЕ ИСПОЛНЯЛОСЬ

Systemd/useradd/install на хосте, несколько VM, подключение node_exporter,
рабочая сеть, TLS proxy, native histogram live transport от Go,
многосуточное retention/compaction stress, power-loss/disk corruption,
HA/dedup, внешний remote receiver/read/write и Alertmanager delivery.
Эти действия — описанные рецепты/контракты, не подтверждённые результаты.

Четыре пошаговые схемы — явно фиксированные модели, не настоящий сервер.
Браузерного «движка PromQL» нет; реальная семантика проверяется promtool.
Полная общая сборка, wrapper build.py, регистрация, export, commit/push
не выполнялись. Изолированный рендер/reader QA выполняет координатор.
