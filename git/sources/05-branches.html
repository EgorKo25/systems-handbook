Ветки, HEAD и несколько рабочих деревьев

Что перемещается при commit и switch и почему отдельный каталог ещё не означает отдельную историю

Ветка — имя вершины

Ветка Git — изменяемая ссылка на коммит. Имя main обычно соответствует полному имени refs/heads/main. В простом формате хранения ссылка может выглядеть как файл с идентификатором, но Git умеет упаковывать ссылки, а новые версии поддерживают и другие служебные представления. Программа должна читать их через команды Git. Отсутствие отдельного файла .git/refs/heads/main не доказывает отсутствие ветки.

HEAD отвечает на вопрос «из какого состояния работает этот рабочий каталог». В обычном случае это символическая ссылка, содержащая имя текущей ветки. Коммит читает подготовленное дерево, создаёт новый объект с текущим коммитом в качестве родителя и перемещает текущую ветку к новому объекту. Остальные ветки остаются на прежних вершинах. Создание ветки не копирует файлы и всю историю: достаточно добавить ещё одно имя существующему коммиту.

До фиксации:  HEAD → refs/heads/topic → B → A
                                    ↑
                            refs/heads/main
После:        HEAD → refs/heads/topic → C → B → A
                                         ↑
                                 refs/heads/main

Создание и переключение — разные операции

git branch topic
git switch topic
git symbolic-ref --short HEAD
# topic
git rev-parse HEAD
git show-ref --heads

git branch topic создаёт ссылку на текущий коммит, но не переключает рабочий каталог. git switch topic выбирает ветку и приводит индекс и необходимые рабочие файлы к выбранному снимку. git switch -c other совмещает создание новой ветки other и переключение: -c означает create, создать. symbolic-ref читает символическую ссылку; --short сокращает полное имя. show-ref --heads перечисляет локальные ветки и их идентификаторы, не обращаясь к серверу.

Переключение не является безусловным уничтожением текущих правок. Git может перенести незакоммиченные изменения в новый контекст, если операция не должна перезаписать их конфликтующим содержимым. В противном случае команда откажет и перечислит мешающие пути. Следовательно, «я переключился на main» ещё не означает «каталог в точности равен main». Сразу посмотрите статус. Для воспроизводимой проверки нужен чистый снимок, а не только ожидаемая подпись ветки в приглашении оболочки.

Отсоединённый HEAD

git switch --detach HEAD~1 выбирает конкретный предыдущий коммит, не локальную ветку. Флаг --detach означает отсоединение HEAD: он непосредственно указывает на объект. Можно читать файлы, собирать программу и даже создавать новые коммиты. Новые объекты будут нормальными, но при переходе на другую ветку привычного имени у получившейся линии может не остаться.

git switch --detach HEAD~1
# работа и, при необходимости, учебный commit
git switch -c investigation

Последняя команда создаёт имя investigation на текущем состоянии, сохраняя удобную достижимость этой линии. Отсоединённый режим часто возникает в автоматической сборке: системе нужен конкретный неизменный коммит, а не имя ветки, способное сдвинуться во время работы. Ошибка не в самом режиме, а в предположении, что новый коммит уже прикреплён к известной ветке.

Удаление имени не равняется удалению объектов

git branch -d topic удаляет локальное имя с проверкой предусмотренного Git условия слитости. -d — обычное удаление, -D — принудительное, обходящее эту проверку. Это не команда немедленного стирания коммитов. Пока на объекты указывает другая ветка, метка, журнал ссылок или иная учитываемая точка достижимости, они могут оставаться доступными. И наоборот, удаление ветки не удаляет одноимённую ветку на сервере: пространства имён разных репозиториев независимы.

Перед удалением линия может быть проверена через git log main..topic --oneline: если есть вывод, у topic есть коммиты, недостижимые из main. Это характеристика графа. Даже если одинаковое изменение перенесено другим коммитом, идентичность объектов не появилась. Поэтому «изменения уже есть» и «ветка является предком» — разные формулировки с разными проверками.

Worktree: вторая рабочая область с общим хранилищем

Связанное рабочее дерево, linked worktree, даёт отдельный каталог, индекс и HEAD при общем хранилище объектов и большинстве ссылок. Это удобно, когда в одном каталоге находится незаконченная работа, а в другом надо проверить выпуск. Отдельный клон тоже решает изоляцию рабочих файлов, но создаёт отдельное хранилище и собственные отслеживаемые ссылки. Worktree экономит место и делает общие ветки сразу видимыми.

git worktree add -b release-check ../release-check main
git worktree list
git -C ../release-check status --short
git worktree remove ../release-check

У worktree add флаг -b release-check создаёт новую ветку на коммите main и выбирает её в новом каталоге. list показывает зарегистрированные рабочие деревья. Параметр самого Git -C выполняет команду после перехода в указанный каталог, не меняя текущий каталог вашей оболочки. remove удаляет чистое связанное дерево и его регистрацию; при оставшихся правках команда обычно откажет. Исходное основное дерево этой командой не удаляют.

Одну ветку Git обычно не позволяет одновременно выбрать в двух рабочих деревьях: два независимых индекса не должны незаметно конкурировать за одну текущую ветку. Конфигурация по умолчанию общая, поэтому изменение локального параметра в одном каталоге может повлиять на другой. При этом незакоммиченные правки и индекс у каждого свои. Перед перемещением основного каталога или копированием worktree на флэшку нужно учитывать служебные связи путей; самостоятельный клон переносится иначе. Для чтения учебника Git вообще не нужен: готовые HTML-файлы остаются обычными файлами.

Три имени одного состояния

Создайте две ветки на текущем коммите и сделайте новый коммит только в одной. Изменится ли идентификатор второй ветки? Изменится ли её прошлое?

Разбор

Нет: вторая ссылка останется на старом объекте. Общие предки сохранятся общими. Новый коммит не дописывает данные в старый объект и не рассылается автоматически всем веткам.

Первоисточники: branch, switch, symbolic-ref, разделение служебных данных worktree.
