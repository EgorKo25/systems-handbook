Воспроизводимая сборка: одинаковые исходники, одинаковые байты

Два приложения могут вести себя одинаково и при этом иметь разные контрольные суммы. Научимся различать полезную повторяемость, функциональную эквивалентность и побайтовую воспроизводимость; затем сами получим одинаковый ZIP в разных каталогах.

Что именно мы обещаем повторить

Повторяемая команда — ещё не воспроизводимый результат. «Два раза выполнили без ошибки», «два раза прошли тесты» и «два раза получили один SHA-256» отвечают на разные вопросы. Тесты наблюдают выбранные свойства поведения. Побайтовое сравнение устанавливает равенство конкретных выходных файлов. Утверждение о воспроизводимой сборке всегда содержит область: какие входы зафиксированы, какие различия среды допускаются и какие выходы сравниваются. Нельзя распространить опыт с одним архивом на все версии упаковщика и все операционные системы без проверки.

Например, две страницы HTML отличаются только пробелом в комментарии. Браузер показывает их одинаково, но файлы различаются. Два ZIP содержат одинаковый app.py, но разное время записи элемента — снова разные байты. Это не обязательно ошибка приложения; это помеха проверке происхождения результата. Если независимая сборка должна подтвердить доставленный артефакт, шум от часов, путей и случайного порядка мешает отличить ожидаемое изменение от постороннего.

Где появляется недетерминированность

Детерминированное действие при одинаковых определённых входах выдаёт одинаковый результат. Нарушение часто приходит через неучтённый вход. Генератор вставил текущее время, перечисление каталога вернуло файлы в другом порядке, компилятор записал абсолютный путь в отладочную информацию, утилита сортировала строки по другой локали. Случайный идентификатор запуска, имя пользователя, режим доступа, перевод строки и версия сжимающей библиотеки способны изменить сохранённый файл без видимого изменения деловой логики.

Архив особенно нагляден: в нём есть содержимое каждого элемента и метаданные контейнера. Наивное добавление файла переносит время и платформенные свойства с файловой системы. Даже исправив время, можно оставить другой порядок записей или отличающиеся атрибуты прав. Сжатие добавляет ещё один алгоритм и его реализацию. Поэтому наш первый опыт вообще не сжимает данные: размер будет больше, зато проще увидеть причинную связь между входами и байтами.

Минимальный детерминированный ZIP

Следующий самостоятельный файл stable_zip.py рассчитан на обычный Python 3 со стандартной библиотекой. Он упаковывает только app.py и README.txt из текущего каталога. Выход задаётся аргументом. Создайте два своих небольших входных файла заранее; для изучения самого ZIP им не обязательно принадлежать лабораторной службе. Это отдельный минимальный опыт, а не файл из поставки практикума. В примере намеренно нет обхода всех файлов: временный мусор, секреты и сам предыдущий архив не должны незаметно попасть в результат.

from pathlib import Path
import stat
import sys
import zipfile

members = ("README.txt", "app.py")
with zipfile.ZipFile(sys.argv[1], "w") as archive:
    for name in sorted(members):
        payload = Path(name).read_bytes()
        info = zipfile.ZipInfo(name, (2000, 1, 1, 0, 0, 0))
        info.create_system = 3
        info.external_attr = (stat.S_IFREG | 0o644) << 16
        info.compress_type = zipfile.ZIP_STORED
        info.extra = b""
        info.comment = b""
        archive.writestr(info, payload)
    archive.comment = b""

read_bytes() читает исходные байты: программа не меняет кодировку и окончания строк. sorted фиксирует порядок имён. ZipInfo явно задаёт имя и дату; 2000 год попадает в допустимый традиционным ZIP диапазон. Значение create_system = 3 объявляет Unix-формат атрибутов независимо от машины сборки. Старшая половина external_attr получает тип обычного файла и права 0644: владелец читает и пишет, остальные читают. Сдвиг на 16 помещает эти биты в соответствующую часть поля. Это описание внутри архива, а не изменение прав исходного файла.

ZIP_STORED сохраняет данные без сжатия; пустые дополнительные поля и комментарии исключают ещё один канал различий. Режим "w" создаёт новый архив вместо дописывания к старому. Здесь нет текущего времени, абсолютных путей и обращения к сети. Не следует, однако, обещать этими строками воспроизводимость произвольного приложения: генератор, который заранее создал разные app.py, останется источником отличий. Мы нормализовали контейнер, а не все возможные входные данные.

В главе с автономной лабораторией эта идея расширена в другом файле — tools/build.py. Он ищет входы относительно расположения проекта, требует существующий Git-коммит и создаёт dist/handbook-demo.zip, dist/manifest.json и dist/source-commit.txt. В ZIP остаются только два объявленных файла; сведения о происхождении находятся рядом. Не заменяйте лабораторный сборщик сокращённым примером выше: у них разные интерфейсы. В частности, stable_zip.py принимает имя выхода аргументом, а лабораторный tools/build.py выбирает его сам и аргумент не требует.

python3 stable_zip.py first.zip
python3 stable_zip.py second.zip
python3 -c 'import hashlib,pathlib; a=pathlib.Path("first.zip").read_bytes(); b=pathlib.Path("second.zip").read_bytes(); print(a == b); print(hashlib.sha256(a).hexdigest())'

-c выполняет переданную строку как Python-код. Ожидается True, затем шестнадцатеричный SHA-256. Само значение зависит от содержимого двух исходных файлов. Существеннее повторить упаковку в двух независимых каталогах с одинаковыми входными байтами, но разными временем файлов и правами. Для данного упаковщика результат должен совпасть. Если изменится хотя бы один байт app.py, совпадения требовать уже нельзя. Прямая проверка a == b в маленьком опыте сравнивает сами байты; хеш удобен для передачи идентификатора большого файла.

Время происхождения вместо времени запуска

Иногда продукту действительно нужна дата. Тогда выбирают осмысленный фиксированный вход: время утверждённого снимка исходников либо дату выпуска. Соглашение SOURCE_DATE_EPOCH передаёт число секунд от начала Unix-эпохи. Оно действует только на инструменты, которые его поддерживают; объявление переменной не перехватывает произвольные обращения к часам. Свой генератор должен явно прочитать её и согласованно использовать UTC. Записывать текущее время «для удобства», а затем ожидать одинаковый файл противоречиво.

Традиционное время ZIP имеет ограничения представления, включая допустимые годы и двухсекундную точность. Если переносите произвольную дату в такой формат, заранее определите проверку диапазона и нормализацию. Молчаливая подстановка сегодняшнего дня после ошибки уничтожит ожидаемое свойство. Фиксированная дата в учебном примере честно означает техническую нормализацию; фактическое время запуска сохраняют в отдельном отчёте CI, который не объявляют воспроизводимым артефактом.

Как расследовать различие

Сначала убедитесь, что сравниваются одинаковые категории выходов: архив приложения с архивом приложения, а не с журналом запуска. Затем сравните перечень элементов, их содержимое и метаданные. Если содержимое одинаково, ищите порядок, время, комментарии, права и сжатие. Если отличается сам текст, ищите генерацию, кодировки, путь или окружение. Изменяйте по одному фактору: временной каталог, часовой пояс, порядок создания файлов. Такой опыт превращает случайное несовпадение в проверяемую гипотезу.

Чистый контейнер облегчает фиксацию инструментов, но не гарантирует результата: внутри него остаются часы, сетевые ответы и случайность. И наоборот, два обычных каталога на одной машине могут успешно подтвердить ограниченную воспроизводимость простой упаковки. В протоколе опыта укажите фактические версии, входы и изменённые факторы. Равенство двух сборок с общим отравленным кэшем также слабее независимого повторения: оба запуска могли взять один и тот же чужой выход, ничего не пересобрав.

Побайтовое равенство не является полной проверкой безопасности. Детерминированно собираемая ошибочная программа остаётся ошибочной; одинаковый вредоносный компилятор способен дать одинаковый вредоносный выход. Сила воспроизводимости в дополнительном проверяемом отношении между утверждёнными входами и доставленным файлом. Для этого нужны известные входы, доверенная процедура их получения и независимость проверки, а не только красивая строка контрольной суммы.
