Команды технической библиотеки: подробная справка

:
Двоеточие — настоящая встроенная пустая команда Bash: принимает аргументы, ничего с ними не делает и возвращает 0. До её выполнения оболочка всё равно раскрывает аргументы и выполняет перенаправления, поэтому вся запись с : может иметь побочные эффекты или завершиться ошибкой открытия файла. Модель учебного терминала поддерживает саму пустую команду и простые перенаправления.
Синтаксис: : [АРГУМЕНТЫ...] [ПЕРЕНАПРАВЛЕНИЯ]

без аргументов
Выполнить явный пустой успешный шаг. Само двоеточие возвращает ноль.
Когда: Ветке конструкции нужна команда, но никакое действие в ней не требуется.
Пример:
false || :; printf '%s\n' "$?"
Результат: Печатает 0: false привела к выполнению правой части ||, а : успешно завершила эту цепочку. Так можно намеренно принять конкретный отказ, но исходный ненулевой статус после этого уже потерян.

АРГУМЕНТЫ...
Дать оболочке раскрыть аргументы, затем проигнорировать полученные значения. Двоеточие не печатает их в stdout.
Когда: Понять отличие пустой команды от отсутствия всех раскрытий.
Пример:
unset lesson_cache; : "${lesson_cache:=/tmp/cache}"; printf '%s\n' "$lesson_cache"
Результат: Печатает /tmp/cache: присваивание выполнило раскрытие ${...:=...} до вызова :. Знак : в имени команды и двоеточие внутри оператора параметра — разные части языка. Это расширенное раскрытие не реализовано в учебной модели и там будет явно отклонено.

ПЕРЕНАПРАВЛЕНИЕ
Выполнить открытие или усечение файла средствами оболочки даже без печатающей команды. Вся запись имеет ненулевой статус, если открыть файл не удалось.
Когда: Намеренно создать пустой учебный файл или обнулить существующий файл.
Пример:
printf 'old' > scratch.txt; : > scratch.txt; wc -c < scratch.txt
Результат: Печатает 0: scratch.txt существует, но его прежнее содержимое удалено оператором >. Само двоеточие байты в файл не записывало. : >> scratch.txt открывает файл на добавление и существующее содержимое не усекает.

[[
Составная проверочная конструкция Bash. Не выполняет обычное разбиение слов и glob внутри; правая часть == может быть шаблоном.
Синтаксис: [[ ВЫРАЖЕНИЕ ]]

-n ЗНАЧЕНИЕ
Успех при непустоте.
Когда: Проверка строки без изменения границ.
Пример:
[[ -n $value ]]
Результат: Пробелы внутри value не создадут новые операнды.

== ОБРАЗЕЦ
Сопоставление с шаблоном справа.
Когда: Проверить префикс или суффикс.
Пример:
[[ $file == *.log ]]
Результат: Успех для строки с суффиксом .log. Для буквального образца заключите правую часть в кавычки.

=~ ВЫРАЖЕНИЕ
Сопоставление с расширенным regex.
Когда: Проверить форму и захватить группы.
Пример:
re='^port=([0-9]+)$'; [[ port=5432 =~ $re ]]; printf '%s' "${BASH_REMATCH[1]}"
Результат: Напечатает 5432. Неправильный regex отличается от отсутствия совпадения.

-v ИМЯ
Проверить заданность параметра.
Когда: Различить unset и заданную пустую строку.
Пример:
x=; [[ -v x ]]
Результат: Успех, хотя x пустая.

Шаблон стал буквальным текстом
Правая сторона == или =~ целиком защищена кавычками.
Выберите намеренный режим: буквальное значение или язык образцов; не применяйте одно правило кавычек механически.

awk
Обрабатывает записи и поля: для каждой записи проверяет условия и выполняет действия. $1 внутри программы awk означает поле, а не аргумент Bash.
Синтаксис: awk [ПАРАМЕТРЫ] 'ПРОГРАММА' [ФАЙЛЫ...]

-F РАЗДЕЛИТЕЛЬ
Задать разделение полей.
Когда: Обработать известный простой табличный формат.
Пример:
printf 'alpha:3\nbeta:5\n' | awk -F ':' '{s += $2} END {print s}'
Результат: Выведет 8. Это не разбор CSV с кавычками.

-v ИМЯ=ЗНАЧЕНИЕ
Задать переменную awk до обработки.
Когда: Передать числовой порог без вклейки в программу.
Пример:
awk -v limit=10 '$2 > limit {print $1}' input.txt
Результат: Выберет первое поле строк со вторым числом больше 10. Значение проходит правила awk, включая escape-последовательности.

-f ФАЙЛ
Прочитать программу из отдельного файла.
Когда: Программа длиннее удобной однострочной записи.
Пример:
awk -f report.awk input.txt
Результат: Команды обработки берутся из report.awk; данные — из input.txt.

END { ... }
Выполнить блок после окончания входа.
Когда: Вывести итог накопленного счётчика.
Пример:
printf 'a\nb\n' | awk 'END {print NR}'
Результат: Выведет 2 — число обработанных записей.

Bash раскрыла $1 в программе awk
Код awk был заключён в двойные кавычки.
Держите постоянную программу awk в одинарных кавычках, значения передавайте отдельным интерфейсом.

bash
Запускает интерпретатор Bash. Способ запуска выбирает режим, файлы настройки, язык и область состояния.
Синтаксис: bash [ПАРАМЕТРЫ] [ФАЙЛ [АРГУМЕНТЫ...]]

-n
Проверить синтаксис без обычного выполнения.
Когда: Раннее обнаружение незакрытых конструкций.
Пример:
bash -n task.sh
Результат: Нулевой статус подтверждает разбор, но не существование команд и правильность алгоритма.

-c ТЕКСТ
Прочитать программу из аргумента.
Когда: Постоянная короткая программа с отдельными параметрами.
Пример:
bash -c 'printf "%s\n" "$1"' bash 'two words'
Результат: Слово bash становится $0; значение two words — $1.

--noprofile --norc
Отключить соответствующие обычные стартовые файлы.
Когда: Контролируемый запуск без личных настроек.
Пример:
bash --noprofile --norc -c 'printf ready'
Результат: Не очищает уже унаследованное окружение; BASH_ENV рассматривается отдельно.

--login
Режим чтения файлов входа.
Когда: Изучить профиль и способ создания сеанса.
Пример:
bash --login
Результат: Не является новой аутентификацией и не меняет права пользователя.

Sh не понимает массив
Запущен другой язык или режим, расширение .sh не выбирает Bash.
Укажите Bash и проверьте версию/зависимости; source также не следует shebang.

break
Выходит из охватывающего цикла for, while или until. По умолчанию затрагивает один цикл. Это не возврат из функции и не завершение оболочки; выполнение продолжается после цикла. При нормальном выходе break имеет статус 0, но последующие команды могут изменить общий статус функции или сценария.
Синтаксис: break [N]

без аргумента
Прекратить ближайший охватывающий цикл. Оставшиеся команды его тела и следующие итерации этого цикла не выполняются.
Когда: Условие поиска достигнуто или продолжать перебор больше не требуется.
Пример:
bash -c 'for item in a b c; do printf "%s\n" "$item"; break; done; printf "%s\n" after'
Результат: Печатает a и after. Цикл закончился после первой итерации, а оболочка продолжила работу. break предназначен для тела действующего цикла; вне него Bash сообщает о неверном контексте.

N
Выйти сразу из N охватывающих циклов, считая ближайший первым. N — положительное целое, не флаг.
Когда: Событие во внутреннем цикле должно закончить также внешний перебор.
Пример:
bash -c 'for outer in A B; do for inner in 1 2; do printf "%s%s\n" "$outer" "$inner"; break 2; done; printf BAD; done; printf "%s\n" after'
Результат: Печатает A1 и after: закончились оба цикла, BAD и остальные сочетания не выполняются. Недопустимое N, например 0, вызывает диагностику и ненулевой статус.

cat
Читает файлы по очереди и передаёт байты в stdout. Без имён файлов читает stdin. Не разбирает структуру JSON или CSV.
Синтаксис: cat [ПАРАМЕТРЫ] [ФАЙЛ...]

-n
Добавить номера всех строк в вывод.
Когда: Сопоставить текст с номером строки.
Пример:
cat -n -- config.txt
Результат: Номера появятся в stdout; исходник не изменится.

-A
Показать непечатаемые знаки, TAB и концы строк: сочетание -vET.
Когда: Искать CRLF и скрытые разделители.
Пример:
cat -A -- script.sh
Результат: LF отмечен $, TAB — ^I, CR — ^M. Это визуальное представление байтов.

--
Закончить параметры.
Когда: Прочитать имя с начальным дефисом.
Пример:
cat -- -notes.txt
Результат: -notes.txt станет именем, а не набором флагов.

-b / --number-nonblank
Нумеровать только непустые строки, начиная с единицы.
Когда: Нужны номера содержательных строк; пустые строки сохраняются без номера.
Пример:
printf 'alpha\n\nbeta\n' > sample.txt; cat -b sample.txt
Результат: alpha получает номер 1, пустая строка остаётся без номера, beta — 2. -b имеет преимущество перед -n.

-s / --squeeze-blank
Сжать каждую серию соседних пустых строк до одной.
Когда: Слишком длинные пустые промежутки мешают читать поток.
Пример:
printf 'alpha\n\n\nbeta\n' | cat -s
Результат: Между alpha и beta останется одна пустая строка. Строка из пробелов непустая и не равна пустой строке.

cd
Меняет текущий каталог самой Bash. Отдельная дочерняя команда не может изменить каталог родителя.
Синтаксис: cd [-L|-P] [--] КАТАЛОГ

--
Завершить параметры.
Когда: Путь может начинаться с дефиса.
Пример:
cd -- "$directory" || exit
Результат: Каталог меняется либо дальнейшая опасная работа не выполняется.

-P
Использовать физическую структуру без логического прохода по ссылкам.
Когда: Нужен реальный путь каталога.
Пример:
cd -P -- "$directory"; pwd -P
Результат: Покажет физическое положение после успешного cd.

-
Перейти в предыдущий каталог OLDPWD.
Когда: Удобство интерактивной навигации.
Пример:
cd /tmp; cd -
Результат: Вернётся к прежнему каталогу и обычно напечатает его.

После ошибки cd обработаны не те файлы
Относительные пути остались привязаны к старому каталогу.
Всегда проверяйте критичный cd; группируйте временный переход в подоболочке.

chmod
Меняет режим доступа существующего объекта. Проверка удаления имени относится к каталогу; ACL и дополнительные политики также влияют на фактический доступ.
Синтаксис: chmod [ПАРАМЕТРЫ] РЕЖИМ ФАЙЛ...

u+x
Форма режима: добавить владельцу исполнение.
Когда: Разрешить непосредственный запуск своего сценария.
Пример:
chmod u+x -- task.sh
Результат: Добавится x владельца; shebang и интерпретатор проверяются отдельно.

640
Числовая форма: владелец rw, группа r, остальные без прав.
Когда: Задать конкретный режим обычного файла.
Пример:
chmod 640 -- report.txt
Результат: Обычные биты станут rw-r----- с учётом взаимодействия расширенной ACL.

-R
Рекурсивно применить изменение к дереву.
Когда: Изменить выбранное своё дерево.
Пример:
chmod -R u+rwX -- own-work
Результат: Владелец получит r/w; X добавляет проход каталогам и исполнение уже исполняемым файлам по правилам режима.

--reference=ФАЙЛ
Взять режим из эталона.
Когда: Согласовать права нового файла с образцом.
Пример:
chmod --reference=template.txt -- result.txt
Результат: Изменится режим result.txt; данные и владелец не копируются.

chown
Меняет UID владельца и при указании GID группы с проверкой полномочий. Изменение имени пользователя в выводе и назначение числового владельца — разные уровни.
Синтаксис: chown [ПАРАМЕТРЫ] ВЛАДЕЛЕЦ[:ГРУППА] ФАЙЛ...

ВЛАДЕЛЕЦ:ГРУППА
Форма операнда: назначить владельца и группу.
Когда: Подготовить владение для выбранной службы.
Пример:
chown appuser:appgroup -- report.txt
Результат: При достаточных полномочиях и найденных именах изменятся UID/GID, а не содержимое.

-h
Изменить саму символическую ссылку вместо цели.
Когда: Назначить владельца ссылке как объекту.
Пример:
chown -h appuser -- current-link
Результат: Владелец целевого файла этим действием не назначается.

-R
Рекурсивно обработать дерево с выбранными правилами обхода ссылок.
Когда: Назначить владение определённому своему дереву.
Пример:
chown -R appuser:appgroup -- own-data
Результат: Изменятся многие объекты; правила перехода по ссылкам задаются отдельно.

--reference=ФАЙЛ
Взять владельца и группу из эталона.
Когда: Согласовать владение нового файла.
Пример:
chown --reference=reference.txt -- result.txt
Результат: При достаточных полномочиях UID/GID будут взяты из reference.txt.

command
Встроенная команда Bash обходит поиск функции при вызове и умеет сообщать разрешение имени. Она не является очисткой окружения или общей защитой от вложенных языков.
Синтаксис: command [-pVv] ИМЯ [АРГУМЕНТЫ...]

ИМЯ АРГУМЕНТЫ
Вызвать команду без выбора одноимённой shell-функции.
Когда: Обёртка должна обратиться к настоящей встроенной или внешней команде.
Пример:
printf() { command printf 'prefix: '; command printf '%s\n' "$*"; }; printf hello
Результат: Напечатает prefix: hello. Без command функция могла бы вызвать саму себя.

-v
Кратко показать, как имя доступно в текущей оболочке, и вернуть статус проверки.
Когда: Проверить зависимость до начала изменений.
Пример:
if command -v python3 >/dev/null 2>&1; then printf available; fi
Результат: Available печатается, если имя разрешается. Наличие не доказывает нужную версию программы.

-V
Показать более подробное описание разрешения.
Когда: Диагностика человеком, включая встроенные и функции.
Пример:
command -V cd
Результат: Сообщит, что cd — встроенная команда в этой Bash; точное оформление зависит от версии/локали.

-p
Для поиска использовать стандартный PATH, рассчитанный на стандартные утилиты.
Когда: Намеренно обойти пользовательский PATH для известной стандартной команды.
Пример:
command -p getconf PATH
Результат: Напечатает системный стандартный путь через getconf при его наличии. Не очищает окружение и не меняет учётные данные.

Command не убрала псевдоним в уже прочитанном тексте
Подстановка alias принадлежит более раннему этапу чтения; command в первую очередь изменяет разрешение функции при выполнении.
Не стройте автоматизацию на личных псевдонимах. Для конкретного внешнего файла используйте проверенный путь.

Command -v вернула функцию, а нужен файл
Доступность имени шире наличия внешнего исполняемого файла.
Используйте type -P и проверяйте конкретный файл/версию, если именно это входит в договор.

continue
Пропускает оставшуюся часть текущей итерации цикла и переходит к следующей. Сам цикл сохраняется: for берёт следующий элемент, while/until заново проверяет своё условие. По умолчанию затрагивает ближайший цикл; число N выбирает внешний охватывающий цикл. Успешная continue имеет статус 0.
Синтаксис: continue [N]

без аргумента
Начать следующую итерацию ближайшего цикла, пропустив команды после continue в текущем проходе.
Когда: Текущий элемент не подходит, но остальные ещё нужно обработать.
Пример:
bash -c 'for item in a skip b; do if [[ $item == skip ]]; then continue; fi; printf "%s\n" "$item"; done'
Результат: Печатает a и b. Элемент skip пропущен, однако цикл не закончен. В while изменение счётчика после continue будет пропущено — это может случайно создать бесконечный цикл.

N
Перейти к следующей итерации N-го охватывающего цикла. Внутренние текущие итерации при этом прекращаются. N — положительное целое, не флаг.
Когда: Результат внутренней проверки означает, что нужно пропустить остаток обработки всего внешнего элемента.
Пример:
bash -c 'for outer in A B; do for inner in 1 2; do printf "%s%s\n" "$outer" "$inner"; continue 2; done; printf BAD; done'
Результат: Печатает A1 и B1. После каждого continue 2 начинается следующая итерация outer, а inner=2 и BAD не выполняются. Вне действующего цикла команда неприменима; недопустимое N диагностируется.

cp
Копирует данные и выбранные метаданные. Копирование в существующий файл не даёт тех же гарантий видимости, что публикация подготовленного файла через rename.
Синтаксис: cp [ПАРАМЕТРЫ] ИСТОЧНИК НАЗНАЧЕНИЕ

-a
Рекурсивно копировать с сохранением предусмотренных атрибутов и ссылок.
Когда: Скопировать своё дерево.
Пример:
cp -a -- source-tree copy-tree
Результат: Будет создана копия; сохранение владения и атрибутов зависит от полномочий и ФС.

-i
Спрашивать перед перезаписью.
Когда: Вручную проверить замену назначения.
Пример:
cp -i -- source.txt result.txt
Результат: При отрицательном ответе существующий result.txt не перезаписывается.

-P
Не следовать ссылкам источника.
Когда: Копировать ссылку как ссылку.
Пример:
cp -P -- current-link saved-link
Результат: saved-link будет хранить текст ссылки, а не копию содержимого цели.

-n / --no-clobber
Сохранить уже существующее назначение, пропустив его перезапись.
Когда: Нужно избежать замены, но заранее определена версия утилиты и трактовка статуса.
Пример:
printf 'keep\n' > copy.txt; cp -n notes.txt copy.txt
Результат: copy.txt сохраняет keep. В модели выбран результат GNU coreutils 9.4 — код 0; сама опция непереносима по кодам завершения и в современных GNU помечена устаревшей. Для точной политики изучите --update=none/none-fail установленной версии.

-r / -R / --recursive
Рекурсивно скопировать каталог с его содержимым.
Когда: Источник — дерево, а не один обычный файл.
Пример:
mkdir -p work; touch work/item.txt; cp -r work other
Результат: В новом other появляется item.txt. Слияние с существующим каталогом, ссылки, права и особые файлы требуют отдельного разбора; учебный стенд явно ограничивает эти случаи.

createdb
Клиентская оболочка SQL-команды CREATE DATABASE. Подключается к уже работающему серверу и создаёт новую базу; не создаёт новый кластер и не запускает PostgreSQL.
Синтаксис: createdb [ПАРАМЕТРЫ] НОВАЯ_БАЗА

-T ШАБЛОН
Указать базу-основу создаваемой базы.
Когда: Нужна чистая основа template0 вместо изменённой template1.
Пример:
createdb -T template0 book_restore
Результат: На выбранном сервере появится новая база book_restore с копией шаблона; команда требует соответствующих прав.

-O РОЛЬ
Назначить владельца новой базы.
Когда: Владение должно принадлежать отдельной прикладной или административной роли.
Пример:
createdb -T template0 -O book_owner book_restore
Результат: Создаст базу с владельцем book_owner, если роль существует и вызывающий вправе так назначить владельца.

-h УЗЕЛ_ИЛИ_КАТАЛОГ
Выбрать сервер по имени/адресу либо каталогу Unix-сокета.
Когда: Создавать учебную базу именно в отдельном кластере.
Пример:
createdb -h /tmp/book-socket -T template0 book_restore
Результат: Использует сокет выбранного каталога; book_restore — имя создаваемой базы, а не имя сервера.

createdb сработала, а новая база не видна
Следующий клиент мог выбрать другой сервер или порт.
Сверьте строку подключения обоих вызовов и pg_database выбранного кластера.

curl
Выполняет прикладной запрос по URL. Тело ответа обычно выводит в stdout, сообщения прогресса и ошибки — в stderr; TLS-проверка зависит от имени URL и доверенных сертификатов.
Синтаксис: curl [ПАРАМЕТРЫ] URL

--resolve ИМЯ:ПОРТ:АДРЕС
Задать адрес соединения для конкретной пары имени и порта.
Когда: Проверить локальный HTTPS, сохранив правильные SNI и проверяемое имя.
Пример:
curl --resolve app.lab.test:18443:127.0.0.1 --cacert ca.pem https://app.lab.test:18443/
Результат: TCP идёт к 127.0.0.1, имя остаётся app.lab.test; файл hosts не меняется.

--cacert ФАЙЛ
Задать PEM-файл доверенных центров для проверки TLS.
Когда: Доверять отдельному учебному центру только в данном вызове.
Пример:
curl --cacert ca.pem https://app.lab.test/
Результат: Проверит сертификат по выбранному доверию и имени URL; это не отключение проверки как -k.

--noproxy СПИСОК
Исключить перечисленные адресаты из использования прокси; * исключает все.
Когда: Локальная проверка должна идти напрямую независимо от переменных прокси.
Пример:
curl --noproxy "*" http://127.0.0.1:7000/
Результат: Запрос пойдёт непосредственно к loopback; тело ответа окажется в stdout.

-o ФАЙЛ
Сохранить тело ответа в указанный файл вместо stdout.
Когда: Отделить полученный документ от сообщений диагностики.
Пример:
curl --noproxy "*" -o response.txt http://127.0.0.1:7000/
Результат: Создаст или перезапишет response.txt. Успех передачи сам по себе не означает статус HTTP 200: тело ошибки тоже можно сохранить.

-I
Для HTTP отправить HEAD и вывести заголовки вместо обычного получения тела GET.
Когда: Проверить статус и метаданные ответа без загрузки тела ресурса.
Пример:
curl --noproxy "*" -I http://127.0.0.1:7000/
Результат: Заголовки окажутся в stdout. Сервер может поддерживать HEAD иначе, поэтому результат не заменяет полный GET той же страницы.

-v
Показать подробности соединения и обмена заголовками в stderr.
Когда: Понять выбранный адрес, TLS-проверку и ответ HTTP.
Пример:
curl --noproxy "*" -v http://127.0.0.1:7000/
Результат: Тело остаётся в stdout, диагностика — отдельно; строки с > обычно относятся к отправке, с < — к ответу.

--connect-timeout СЕКУНДЫ
Ограничить фазу установления соединения, включая разрешение имени и необходимые транспортные/защитные согласования.
Когда: Служба недоступна, а ждать начала обмена долго нельзя.
Пример:
curl --noproxy "*" --connect-timeout 2 http://127.0.0.1:7000/
Результат: Не даст фазе подключения ждать дольше установленного предела; это не общий предел получения большого тела.

--max-time СЕКУНДЫ
Ограничить полное время операции curl.
Когда: Нужна граница всего запроса, включая ожидание и передачу ответа.
Пример:
curl --noproxy "*" --connect-timeout 2 --max-time 5 http://127.0.0.1:7000/
Результат: Подключение ограничено двумя секундами, вся операция — пятью. При истечении вывод или файл могут уже содержать неполную часть ответа.

-f / --fail
Считать HTTP-ответ 400 или выше неуспехом команды и не выводить его тело.
Когда: Сценарий должен отличить HTTP-ошибку от успешной передачи страницы ошибки.
Пример:
curl -f http://app.lab.test:7000/absent
Результат: При обычном HTTP 404 curl без -f может вернуть статус0, а с -f —22. Это не запрет самой серверной ошибки; её преобразует в код завершения клиент.

Обращение к IP даёт ошибку имени сертификата
Проверяется имя из URL; заголовок Host сам по себе не меняет TLS-проверку.
Используйте нужное имя URL и --resolve для адреса соединения; добавьте --cacert для учебного доверия.

cut
Выбирает байтовые или разделённые поля из простого формата. Не является CSV-парсером.
Синтаксис: cut [ПАРАМЕТРЫ] [ФАЙЛЫ...]

-d СИМВОЛ
Задать разделитель полей.
Когда: Формат запрещает этот разделитель внутри поля.
Пример:
printf 'alpha:3\n' | cut -d ':' -f 1
Результат: Выведет alpha.

-f СПИСОК
Выбрать номера полей.
Когда: Извлечь известные столбцы простой таблицы.
Пример:
printf 'a:b:c\n' | cut -d ':' -f 1,3
Результат: Выведет a:c.

-b СПИСОК
Выбрать байтовые позиции.
Когда: Формат определён в байтах, а не Unicode-символах.
Пример:
printf 'abcdef\n' | cut -b 2-4
Результат: Выведет bcd; для UTF-8 можно разрезать многобайтовый символ.

-s
Не печатать строки без разделителя.
Когда: Исключить непохожие на ожидаемую таблицу записи.
Пример:
printf 'plain\na:b\n' | cut -s -d ':' -f 2
Результат: Выведет только b.

Поле с запятой в кавычках разобрано неверно
Cut не понимает грамматику CSV.
Используйте CSV-парсер; разделитель и кавычки — разные уровни.

declare
Объявляет переменные и их атрибуты: например массив, ссылка по имени или экспорт. Атрибут — свойство переменной, влияющее на её хранение или последующие присваивания. Внутри функции обычный declare создаёт локальную привязку; declare -g явно выбирает глобальную. Это встроенная команда Bash.
Синтаксис: declare [ПАРАМЕТРЫ] [ИМЯ[=ЗНАЧЕНИЕ] ...]

-p [ИМЯ...]
Показать атрибуты и значения выбранных переменных в форме объявлений Bash. Без имён показывает переменные, подходящие остальным заданным фильтрам.
Когда: Проверить тип, наличие и точное представление значения при отладке.
Пример:
bash -c 'value="two words"; declare -p value'
Результат: Печатает объявление вида declare -- value="two words". Для отсутствующего имени выдаёт диагностику и ненулевой статус. При выводе могут оказаться видны секретные значения.

-a
Объявить индексированный массив. Индексы — неотрицательные целые; наличие индекса и его значение проверяются отдельно.
Когда: Нужен упорядоченный набор значений, каждое из которых сохраняется как отдельная строка.
Пример:
bash -c 'declare -a names=(anna "bob smith"); printf "<%s>\n" "${names[@]}"'
Результат: Печатает <anna> и <bob smith>. Пробел внутри второго элемента не разбивает его, поскольку раскрытие массива заключено в двойные кавычки.

-A
Объявить ассоциативный массив: элементы адресуются строковыми ключами вместо обычных числовых индексов.
Когда: Нужна таблица настроек по известным именам.
Пример:
bash -c 'declare -A settings=([host]=localhost [port]=5432); printf "%s:%s\n" "${settings[host]}" "${settings[port]}"'
Результат: Печатает localhost:5432. Порядок обхода ключей ассоциативного массива не следует считать порядком объявления.

-n
Сделать переменную ссылкой на другую переменную по имени. Это атрибут nameref, то есть «ссылка по имени».
Когда: Функции или вспомогательному коду требуется работать с заранее определённой переменной через другое имя.
Пример:
bash -c 'value=old; declare -n ref=value; ref=new; printf "%s\n" "$value"'
Результат: Печатает new: присваивание ref изменило value. declare +n ref снимает атрибут ссылки; unset -n ref удаляет саму ссылку, а не её цель.

dig
Отправляет DNS-вопрос выбранному серверу и показывает его ответ. Не повторяет автоматически весь системный путь приложения через NSS и локальные файлы.
Синтаксис: dig [@СЕРВЕР] ИМЯ [ТИП] [ПАРАМЕТРЫ]

@СЕРВЕР
Направить вопрос конкретному DNS-серверу.
Когда: Проверить внутреннюю зону у её обслуживающего узла.
Пример:
dig @10.77.10.1 app.lab.test A
Результат: Вопрос типа A пойдёт к 10.77.10.1; ответ и SERVER покажут источник, если он ответил.

-p ПОРТ
Использовать указанный порт DNS вместо 53.
Когда: Обратиться к отдельному учебному экземпляру.
Пример:
dig @127.0.0.1 -p 1053 app.lab.test A
Результат: Проверит службу на порту 1053, не меняя системный resolv.conf.

+tcp
Выполнить DNS-обмен через TCP.
Когда: Сравнить доступность DNS через UDP и TCP либо исследовать усечённый ответ.
Пример:
dig @10.77.10.1 app.lab.test A +tcp
Результат: Передаст DNS-вопрос внутри TCP; успех отличается от проверки UDP того же сервера.

+short
Сократить вывод до основных данных ответа.
Когда: Получить адреса после того, как подробный результат уже понятен.
Пример:
dig @10.77.10.1 app.lab.test A +short
Результат: Может напечатать адреса или цепь псевдонимов. Пустой stdout без подробного статуса не объясняет причину.

dig работает, приложение не находит имя
Они могут обращаться к разным источникам или дополнять имя разными суффиксами.
Сравните getaddrinfo/NSS, выбранный сервер, search/ndots и буквальный вопрос с завершающей точкой.

dnsmasq
Лёгкий сервер DNS и DHCP. Здесь используется только как отдельный учебный экземпляр с явно выбранными интерфейсами и файлами; вывод запросов и выдача аренды зависят от конфигурации.
Синтаксис: dnsmasq [ПАРАМЕТРЫ]

--test
Проверить синтаксис конфигурации и завершиться.
Когда: Убедиться, что подготовленный файл разобран до запуска службы.
Пример:
dnsmasq --test --conf-file=./dnsmasq.conf
Результат: Напечатает результат проверки; служба не остаётся работать и аренды этой командой не выдаются.

--conf-file=ФАЙЛ
Использовать выбранный файл вместо стандартного /etc/dnsmasq.conf.
Когда: Не смешивать учебный пример с настройками действующей службы.
Пример:
dnsmasq --test --conf-file=./dnsmasq.conf
Результат: Прочитает указанный файл; относительные пути внутри настроек требуют отдельного понимания.

--no-resolv
Не брать вышестоящие DNS-серверы из resolv.conf.
Когда: Изолированный стенд должен отвечать только по своим источникам и явным правилам.
Пример:
dnsmasq --test --no-resolv --conf-file=./dnsmasq.conf
Результат: Проверка пройдёт с этим режимом; он не отменяет явные server= или локальный hosts сам по себе.

--keep-in-foreground
Оставить сервер на переднем плане без обычного ухода в фон.
Когда: Наблюдать жизненный цикл отдельного учебного процесса.
Пример:
dnsmasq --keep-in-foreground --conf-file=./dnsmasq.conf
Результат: При запуске занимает терминал до остановки; это запуск сервера, а не только просмотр. Проверку файла отдельно выполняет --test.

Сервер выдаёт неожиданные ответы
Он мог прочитать стандартный файл, resolv.conf, hosts или дополнительные настройки.
Установите фактический набор источников и запустите отдельную конфигурацию внутри предусмотренного изолированного стенда.

echo
Выводит аргументы через пробел и обычно добавляет LF. Правила обратных черт и параметров различаются по реализации и настройкам; для произвольных данных удобнее printf.
Синтаксис: echo [-neE] [АРГУМЕНТ...]

-n
Не добавлять завершающий LF.
Когда: Продолжить ту же строку следующим выводом.
Пример:
echo -n ready
Результат: Появится ready без конечного перевода строки.

-e
В Bash интерпретировать предусмотренные последовательности обратной черты.
Когда: Намеренно представить перевод строки через \n.
Пример:
echo -e 'a\nb'
Результат: Появятся две строки: a и b.

-E
В Bash отключить интерпретацию последовательностей обратной черты.
Когда: Показать буквальное a\nb.
Пример:
echo -E 'a\nb'
Результат: Обратная черта и n останутся видимыми. Это не универсальное решение для аргумента -n.

env
Запускает программу с изменённым окружением. Не меняет автоматически остальные свойства процесса: каталог, права и дескрипторы.
Синтаксис: env [ПАРАМЕТРЫ] [ИМЯ=ЗНАЧЕНИЕ...] ПРОГРАММА...

-i
Начать с пустого набора строк окружения.
Когда: Найти неявные зависимости запуска.
Пример:
env -i PATH=/usr/bin:/bin HOME="$HOME" bash --noprofile --norc -c 'printf %s "$PATH"'
Результат: Дочерняя среда получает явно перечисленные строки; это не песочница прав.

-u ИМЯ
Удалить одну переменную перед запуском.
Когда: Исключить нежелательный hook запуска.
Пример:
env -u BASH_ENV bash -c 'printf ready'
Результат: Дочерняя Bash не получает BASH_ENV от этой команды.

Чистая среда не исправила права
Окружение — строки, а права определяются учётными данными ядра.
Диагностируйте пользователя, группы, политики и доступ отдельно.

ethtool
Читает параметры сетевого устройства и аппаратных возможностей. Набор полей зависит от адаптера и драйвера; показанная скорость линии не равна измеренной скорости приложения.
Синтаксис: ethtool [ПАРАМЕТРЫ] ИНТЕРФЕЙС

ИНТЕРФЕЙС
Без изменяющих параметров запросить основные сведения линии.
Когда: Проверить согласованную скорость, дуплекс и наличие связи.
Пример:
ethtool enp1s0
Результат: В stdout появятся поддерживаемые поля, например Speed, Duplex и Link detected; имя заменяют своим интерфейсом.

-k
Показать состояния аппаратных и программных возможностей offload.
Когда: Объяснить необычно большие пакеты или непосчитанную сумму в местном захвате.
Пример:
ethtool -k enp1s0
Результат: Выведет признаки segmentation/checksum/GRO и доступность изменения; сама команда настройки не меняет.

-S
Показать расширенные счётчики адаптера и драйвера.
Когда: Искать потери по очередям и аппаратные ошибки при нагрузке.
Пример:
ethtool -S enp1s0
Результат: Напечатает поддерживаемые именованные счётчики. Их смысл уточняется у драйвера, поэтому одинаковые названия не всегда переносимы.

Link detected: yes, сервер недоступен
Подтверждён физический канал, а не адресация и работа приложения.
Дальше проверяйте VLAN, адреса, маршрут, соседей и слушающий сокет.

eval
Соединяет свои аргументы пробелами, затем читает и выполняет полученную строку как новый исходный код текущей оболочки. Это явный второй разбор языка: текст снова получает смысл кавычек, подстановок и операторов. Обычное раскрытие "$value" так не делает. Для набора аргументов предназначены массивы; eval требуется только при осознанном построении самого кода.
Синтаксис: eval [АРГУМЕНТЫ...]

АРГУМЕНТЫ...
Соединить аргументы в одну строку программы и выполнить её в текущей оболочке. Статус eval определяется последней выполненной командой этой программы.
Когда: Исследовать границу между текстом и кодом на полностью известной строке.
Пример:
name=world; eval 'printf "%s\n" "$name"'
Результат: Печатает world. Одинарные кавычки сохранили запись $name при первом разборе; eval затем прочитал полученный текст заново и выполнил раскрытие. Кавычки вокруг переменной-аргумента eval защищают лишь первый разбор, а не произвольные данные внутри второго.

без аргументов
При отсутствии аргументов либо при пустой результирующей программе ничего не выполнять и вернуть статус 0.
Когда: Проверить, почему пустой сгенерированный код может скрыть предшествующий ненулевой статус.
Пример:
false; eval; printf '%s\n' "$?"
Результат: Печатает 0: у пустой eval свой успешный статус, а не статус предшествующей false. Для передачи прежнего результата нужно сохранять его отдельно, а не рассчитывать на пустую команду.

Строка данных превращается в программу
Повторный разбор eval интерпретирует операторы и подстановки в полученном тексте. Даже передача строки одним аргументом не отменяет этот второй разбор.
Храните известную команду и её аргументы в массиве: args=(printf "%s\n" "$value"); "${args[@]}". Для выбора заранее известных действий используйте функции и case.

exec
С программой заменяет текущую Bash этой программой; без программы оставляет перенаправления у текущей оболочки.
Синтаксис: exec [ПРОГРАММА АРГУМЕНТЫ...] [ПЕРЕНАПРАВЛЕНИЯ]

ПРОГРАММА
Заменить исполняемый образ с сохранением PID процесса.
Когда: Простой запускающий сценарий больше не нужен после старта.
Пример:
bash -c 'exec printf ready'
Результат: Дочерняя Bash становится printf; возврата к её следующим строкам нет.

{fd}>ФАЙЛ
Открыть выделенный Bash номер и сохранить его в переменной.
Когда: Не занимать вручную номер чужой библиотеки.
Пример:
exec {fd}>result.txt; printf data >&"$fd"; exec {fd}>&-
Результат: Данные записаны через отдельный номер, затем ссылка закрыта.

n>&m
Дублировать текущее назначение m в n.
Когда: Сохранить исходный канал до перенаправления.
Пример:
exec 3>&1; exec >log; printf notice >&3
Результат: Notice идёт в прежний stdout, дальнейший обычный вывод — в log.

-c
Запустить заменяющую программу с пустым окружением.
Когда: Редкая контролируемая среда, где нужные параметры переданы иначе.
Пример:
bash -c 'exec -c /usr/bin/env'
Результат: На обычной системе env не увидит унаследованных строк окружения.

Окно закрылось после exec
Exec заменил интерактивную оболочку.
Экспериментируйте в отдельном bash -c, когда нужно сохранить основное окно.

exit
Завершает текущую оболочку, а не только функцию или цикл. В дочерней Bash завершится этот дочерний процесс; в запущенном обычным способом сценарии — процесс сценария. Если файл подключён через source, exit затронет вызывающую оболочку. Для возврата из функции или подключённого файла служит return.
Синтаксис: exit [КОД]

КОД
Завершить оболочку с явно заданным целочисленным статусом. Ноль означает успех, ненулевое значение — выбранный программой исход. Это аргумент, а не флаг.
Когда: Сценарий закончил работу либо обнаружил условие, после которого продолжение невозможно.
Пример:
bash -c 'exit 7'; printf '%s\n' "$?"
Результат: Дочерняя Bash завершается с кодом 7, родитель печатает 7. Следующие команды внутри завершившегося процесса уже не исполняются. Для предсказуемого интерфейса используют коды 0–255; большие числовые значения Bash сводит к младшему байту.

без аргумента
Завершить оболочку со статусом последней выполненной команды. Промежуточная команда может уже изменить этот статус.
Когда: Нужно передать последний результат непосредственно вызывающей программе.
Пример:
bash -c 'false; exit'; printf '%s\n' "$?"
Результат: Печатает 1. Если перед exit выполнить успешный printf, безаргументный exit получит уже его статус 0. Для сохранения исходного кода заранее записывают status=$?.

export
Отмечает параметр для окружения последующих дочерних программ. Не обновляет уже запущенных потомков и не передаёт изменения вверх.
Синтаксис: export [ИМЯ[=ЗНАЧЕНИЕ]...]

ИМЯ
Пометить существующую переменную для наследования.
Когда: Дочерняя программа должна получить настройку.
Пример:
mode=check; export mode; bash -c 'printf %s "$mode"'
Результат: Ребёнок напечатает check.

-n ИМЯ
Снять атрибут export, сохранив переменную Bash.
Когда: Ограничить последующее наследование.
Пример:
export -n mode
Результат: В текущей Bash mode остаётся, новые внешние команды обычно не получат её.

-p
Показать экспортируемые параметры.
Когда: Выборочная диагностика собственной среды.
Пример:
export -p
Результат: Может раскрыть секреты: вывод не следует слепо прикладывать к отчёту.

Export в ребёнке не изменил родителя
Окружение передаётся снимком при запуске.
Верните данные по оговорённому потоку, файлу или другому каналу.

false
Встроенная команда с неуспешным статусом 1. Позволяет проверить ветвь отказа без изменения файлов или служб.
Синтаксис: false

false
Базовая форма: вернуть 1.
Когда: Смоделировать ненулевой результат.
Пример:
false; printf "%s\n" "$?"
Результат: При обычном продолжении выведется 1; errexit меняет условия продолжения.

false || КОМАНДА
Форма списка: правый участник || выполнится после отказа.
Когда: Проверить обработку ненулевого статуса.
Пример:
false || printf '%s\n' failed
Результат: Будет failed. || — оператор Bash, не параметр false.

find
Обходит дерево и применяет выражение выбора и действий к объектам. При частичном обходе может уже вывести имена и затем вернуть отказ. Режимы следования ссылкам задаются перед путями; выражение имеет собственные приоритеты И/ИЛИ.
Синтаксис: find НАЧАЛЬНЫЙ_ПУТЬ [ВЫРАЖЕНИЕ]

-type f
Выбирать обычные файлы.
Когда: Исключить каталоги и специальные объекты.
Пример:
find ./data -type f -print
Результат: Покажет выбранные пути; для машинной обработки имён предпочтительнее -print0.

-name ШАБЛОН
Сопоставить имя с шаблоном find.
Когда: Оставить определённый суффикс.
Пример:
find ./data -type f -name '*.log' -print0
Результат: Звёздочка защищена от Bash и читается find; выход разделён NUL.

-print0
Завершать имена нулём.
Когда: Передать произвольные допустимые имена программе.
Пример:
find ./data -type f -print0 >names.bin
Результат: LF внутри имени не превращается в границу записи.

-exec КОМАНДА {} +
Запускать команду с группами найденных путей.
Когда: Не строить промежуточный текстовый список.
Пример:
find ./data -type f -exec printf '<%s>\n' {} +
Результат: Find соберёт допустимые по размеру группы argv.

-maxdepth N
Ограничить глубину обхода.
Когда: Рассмотреть только ближайшие записи.
Пример:
find ./data -maxdepth 1 -type f -print
Результат: Не войдёт в подкаталоги глубже первого уровня.

-print
Вывести путь с LF в конце.
Когда: Показать результат человеку, когда границы имён понятны.
Пример:
find ./data -type f -print
Результат: Для имён с LF результат визуально неоднозначен. Машинному получателю нужен -print0.

-mindepth N
Не применять проверки и действия на уровнях мельче N.
Когда: Исключить начальный каталог из результата.
Пример:
find ./data -mindepth 1 -maxdepth 1 -print
Результат: Выведет непосредственные записи, не сам ./data.

-type d
Выбирать каталоги. Проверяемый тип определяется режимом -P/-L/-H: при следовании доступной ссылке проверяется её цель.
Когда: Нужны именно каталоги, например для отдельного списка структуры дерева.
Пример:
find -P ./data -type d -print
Результат: Печатает ./data и найденные внутри реальные каталоги, если они доступны. В режиме -P ссылки на каталоги сами не становятся каталогами и не обходятся.

-type l
Выбирать символические ссылки при обычном режиме -P. Символическая ссылка хранит путь к цели; это отдельный объект файловой системы.
Когда: Проверить ссылки, включая те, цель которых больше не существует.
Пример:
find -P ./data -type l -print
Результат: Печатает пути ссылок, а не их целей. При -L доступная ссылка обычно проверяется по типу цели, поэтому -type l остаётся истинным для сломанных ссылок; режим следования нужно выбирать явно.

-P
Не следовать символическим ссылкам: проверки используют сведения о самой ссылке, а обход не входит в каталог через неё. Это режим GNU find по умолчанию.
Когда: Границей обхода должно быть само дерево, без переходов по содержащимся в нём ссылкам.
Пример:
find -P ./data -type f -print0
Результат: Обычные файлы выводятся с NUL между именами. Ссылка на файл не проходит -type f, а ссылка на каталог не расширяет обход. -P ставится перед начальным путём.

-L
Следовать символическим ссылкам как в начальных путях, так и при дальнейшем обходе. Проверки обычно относятся к доступной цели ссылки.
Когда: Ссылки являются намеренными переходами к данным, и содержимое их целей должно участвовать в обходе.
Пример:
find -L ./data -type f -print0
Результат: В результат могут войти файлы, достигнутые через ссылки, в том числе вне исходного дерева. Ссылки на каталоги обходятся; циклы обнаруживаются и диагностируются. Для сломанной ссылки сведения о цели получить нельзя. -L ставится перед путём.

-H
Следовать ссылкам, указанным непосредственно как начальные пути, но не переходить по ссылкам, найденным глубже при обходе.
Когда: Начальный путь current-release является ссылкой на нужное дерево, а внутренние ссылки не должны расширять поиск.
Пример:
find -H ./current-release -type f -print0
Результат: Если current-release ведёт на доступный каталог, его содержимое исследуется. Вложенная ссылка на другой каталог сама по себе не запускает обход цели. -H ставится перед начальным путём; последний из -H/-L/-P определяет режим.

-iname ШАБЛОН
Сопоставить имя без учёта регистра в GNU find.
Когда: Искать .LOG и .log.
Пример:
find ./data -type f -iname '*.log' -print0
Результат: Маску читает find, а не Bash; регистр сравнивается по правилам локали.

-path ШАБЛОН
Сопоставить весь путь с образцом find.
Когда: Выделить или исключить расположение, не только имя.
Пример:
find ./data -path './data/archive/*' -type f -print
Результат: Сопоставляется путь в форме, которую строит данный стартовый операнд.

-prune
Не входить в текущий каталог; действие также возвращает истину.
Когда: Исключить поддерево в выражении с -o.
Пример:
find ./data -path './data/cache' -prune -o -type f -print
Результат: Cache не обходится; -print относится только к правой ветке.

-xdev
Не спускаться в каталоги на другой файловой системе.
Когда: Ограничить обход одной файловой системой.
Пример:
find ./data -xdev -type f -print0
Результат: Точка монтирования может быть увидена как объект, но её дерево не обходится. Это не то же, что запрет ссылок.

-mtime N / +N / -N
Сравнить возраст изменения данных в округлённых вниз периодах по 24 часа.
Когда: Выбрать старые или свежие файлы по точному договору времени.
Пример:
find ./logs -type f -mtime +7 -print
Результат: Выберет более семи полных округлённых периодов: фактически возраст не менее восьми 24-часовых периодов.

-mmin N / +N / -N
Аналогичная проверка возраста в минутах GNU find.
Когда: Нужна более мелкая шкала, чем сутки.
Пример:
find ./logs -type f -mmin -10 -print
Результат: Выберет файлы моложе десяти минут с учётом округления возрастных интервалов.

-size N[СУФФИКС]
Сравнить размер в выбранных единицах; + больше, - меньше.
Когда: Ограничить набор крупных файлов.
Пример:
find ./data -type f -size +1048576c -print
Результат: Выберет размер строго больше 1 048 576 байт. Суффикс c задаёт байты; другие единицы могут округляться.

-empty
Выбрать пустой обычный файл или пустой каталог.
Когда: Найти пустые объекты без удаления.
Пример:
find ./data -type f -empty -print
Результат: Выведет обычные файлы размера ноль.

-exec КОМАНДА {} \;
Один запуск команды на каждый найденный объект.
Когда: У команды индивидуальный статус участвует в выражении.
Пример:
find ./data -type f -exec printf '<%s>\n' {} \;
Результат: Точка с запятой защищена от Bash. В отличие от + запускается много отдельных процессов.

-execdir КОМАНДА {} +
Групповой запуск из каталога найденных объектов в GNU find.
Когда: Уменьшить некоторые риски обработки путей при осознанном PATH.
Пример:
find ./data -type f -execdir /usr/bin/printf '<%s>\n' {} +
Результат: Пути подаются относительно каталога запуска. PATH должен быть безопасным: без пустых/относительных элементов.

-o / -a / ! / \( ... \)
ИЛИ, И, отрицание и группировка выражения find.
Когда: Выразить несколько типов выбора без ошибочного приоритета.
Пример:
find ./data -type f \( -name '*.log' -o -name '*.txt' \) -print0
Результат: Имеющийся -type f применяется к обеим маскам благодаря скобкам, защищённым от Bash.

-delete
Удалить выбранный объект; в GNU find включает обход -depth.
Когда: Только специально спроектированная операция с проверенным множеством целей.
Пример:
# Сначала только просмотр, без удаления:
find ./own-temp -type f -name '*.tmp' -print
Результат: Реальное добавление -delete изменит файлы. Не сочетайте с -prune: подразумеваемый -depth меняет логику и может расширить последствия.

Пути с LF разбились на две строки
Выход -print является строковым отображением.
Используйте -print0 и получателя нулевых записей; проверяйте итоговый статус find.

Найдены каталоги, хотя указан -type f
В выражении A -o B -print действие может относиться только к B; И связывает сильнее ИЛИ.
Группируйте маски: -type f \( -name ... -o -name ... \) -print0.

-mtime +7 не означает ровно старше 7×24 часов
Возраст сначала округляется вниз, а +7 сравнивает округлённое число с 7.
Для точных границ времени используйте понятную исходную точку и соответствующую проверку, проверяя её на контрольных датах.

Имена с кавычками изменили sh -c в -exec
Путь был вклеен в код вместо позиционного параметра.
Передавайте {} как аргументы после постоянной программы: bash -c 'for f in "$@"; do ...; done' bash {} +.

На минимальной системе нет -printf, -maxdepth или -execdir
Набор и детали find различаются у GNU, BSD и BusyBox.
Проверьте find --version/локальную помощь. Справочник указывает GNU-возможности, не все они являются общим POSIX.

flock
Получает согласительную блокировку открытого объекта. Участники должны соблюдать один протокол и не заменять lock-файл во время работы.
Синтаксис: flock [ПАРАМЕТРЫ] FD  или  flock ФАЙЛ КОМАНДА...

-x
Эксклюзивная блокировка.
Когда: Защитить весь участок чтение→вычисление→публикация.
Пример:
exec {fd}>report.lock; flock -x "$fd"
Результат: Следующий согласованный писатель ждёт освобождения того же объекта.

-n
Не ждать занятый объект.
Когда: Один активный запуск, второй должен сразу отказать.
Пример:
flock -n report.lock bash -c 'printf running; sleep 1'
Результат: Если занято, команда не запускается и возвращается ненулевой статус.

-w СЕКУНДЫ
Ограничить ожидание блокировки.
Когда: Не блокировать автоматику бесконечно.
Пример:
flock -w 5 report.lock ./task.sh
Результат: Ждёт до пяти секунд получения, затем запускает task либо отказывает.

-u
Явно освободить блокировку.
Когда: Открытый дескриптор нужен дальше без критического участка.
Пример:
flock -u "$fd"
Результат: Блокировка снята; закрытие последнего соответствующего дескриптора тоже освобождает её.

Два процесса оба получили lock
Имя lock-файла было удалено/создано заново или протокол различается.
Держите стабильный объект. На сетевых ФС отдельно проверяйте поддерживаемые гарантии.

gcc
Организует препроцессор, компилятор, ассемблер и связывание. Сам не запускает полученный исполняемый файл.
Синтаксис: gcc [ПАРАМЕТРЫ] ИСХОДНИК...

-std=c11
Выбрать режим языка C11.
Когда: Собирать пример с атомарными операциями C11.
Пример:
gcc -std=c11 atomic_counter.c -o atomic-counter
Результат: Исходник обрабатывается по выбранному режиму при доступности зависимостей.

-O2
Включить набор оптимизаций уровня 2.
Когда: Проверить механизм на оптимизируемом коде.
Пример:
gcc -std=c11 -O2 atomic_counter.c -o atomic-counter
Результат: Машинный код может измениться; гонка данных от выбора оптимизации корректной не становится.

-o ФАЙЛ
Назначить выходной файл.
Когда: Получить определённое имя результата.
Пример:
gcc page_faults.c -o page-faults
Результат: При успешной полной сборке появится page-faults вместо a.out.

-Wall
Включить распространённый набор предупреждений, но не все возможные.
Когда: Найти подозрительные места исходника.
Пример:
gcc -Wall -Wextra -std=c11 page_faults.c -o page-faults
Результат: Предусмотренные предупреждения будут показаны; их отсутствие не доказывает корректность.

-Wextra
Добавить предупреждения сверх обычного набора -Wall.
Когда: Уточнить диагностику учебного кода.
Пример:
gcc -Wall -Wextra -std=c11 atomic_counter.c -o atomic-counter
Результат: Дополнительные предупреждения зависят от версии GCC и исходника.

getent
Запрашивает системные базы через NSS. Ответ зависит от /etc/nsswitch.conf и настроенных источников, а не обязательно только от DNS.
Синтаксис: getent [ПАРАМЕТРЫ] БАЗА [КЛЮЧ...]

hosts ИМЯ
Форма запроса базы адресных записей hosts.
Когда: Проверить системное разрешение имени.
Пример:
getent hosts localhost
Результат: Будут доступные записи; это не доказательство обращения именно к DNS.

ahosts ИМЯ
Форма запроса адресов через getaddrinfo.
Когда: Посмотреть результат для сокетных интерфейсов.
Пример:
getent ahosts localhost
Результат: Возможны несколько строк с одним адресом для разных типов сокета.

-s ИСТОЧНИК
Выбрать поддерживаемый источник NSS вместо обычного порядка.
Когда: Сравнить файлы с общим разрешением.
Пример:
getent -s files hosts localhost
Результат: Запрос пойдёт источнику files; доступные источники зависят от системы.

grep
Выбирает строки по буквальному образцу или регулярному выражению. Статус 0 — найдено, 1 — не найдено, иной ненулевой обычно означает ошибку. Карточка ориентирована на GNU grep; точное число совпадений и полнота обхода требуют отдельного договора.
Синтаксис: grep [ПАРАМЕТРЫ] -- ОБРАЗЕЦ [ФАЙЛЫ...]

-F
Рассматривать образец буквально.
Когда: Искать пользовательский текст с точками, скобками и звёздочками.
Пример:
printf 'aXb\na.b\n' | grep -F -- 'a.b'
Результат: Выберет только a.b.

-E
Использовать расширенные регулярные выражения.
Когда: Нужны группы, +, | и явная грамматика образца.
Пример:
grep -E -- '^[0-9]+$' input.txt
Результат: Выберет строки, полностью состоящие из цифр.

-n
Показывать номер исходной строки.
Когда: Найти место в журнале для чтения человеком.
Пример:
grep -n -F -- 'ERROR' service.log
Результат: Каждая выбранная строка получит номер.

-q
Не выводить выбранные строки, вернуть статус проверки.
Когда: Ответить на вопрос о наличии без захвата текста.
Пример:
if grep -q -F -- 'READY' service.log; then printf ready; fi
Результат: Печать ready произойдёт при найденном совпадении; статус ошибки надо отличать от отсутствия.

-i
Не учитывать регистр по правилам локали.
Когда: Найти варианты error, ERROR и Error.
Пример:
printf 'error\nERROR\nok\n' | grep -i -F -- 'error'
Результат: Выведет первые две строки. Для национальных букв результат зависит от локали.

-v
Выбирать строки, которые НЕ совпали с образцом.
Когда: Исключить известные записи.
Пример:
printf 'INFO\nDEBUG\n' | grep -v -F -- 'DEBUG'
Результат: Выведет INFO. Сочетание -vc считает строки без совпадения.

-w
Требовать границы слова вокруг совпадения.
Когда: Искать самостоятельное техническое слово.
Пример:
printf 'cat\nscatter\n' | grep -w -F -- 'cat'
Результат: Выведет cat. Понятие слова включает буквы, цифры и подчёркивание с учётом локали.

-x
Требовать совпадение всей строки.
Когда: Сравнить полную запись без ручных якорей.
Пример:
printf 'READY\nNOT READY\n' | grep -x -F -- 'READY'
Результат: Выведет только READY.

-c
Напечатать число выбранных строк, а не число отдельных совпадений.
Когда: Сосчитать записи с признаком.
Пример:
printf 'x x\ny\nx\n' | grep -c -F -- 'x'
Результат: Выведет 2: в первой строке два x, но строка считается один раз.

-o
Печатать только непустые совпавшие фрагменты, каждый отдельно.
Когда: Извлечь значения по регулярному выражению.
Пример:
printf 'id=12 id=345\n' | grep -oE '[0-9]+'
Результат: Выведет 12 и 345 на отдельных строках. -o меняет формат вывода по сравнению с обычными строками.

-l
Печатать имена файлов с выбранными строками вместо самих строк.
Когда: Найти файлы с заданным текстом.
Пример:
grep -l -F -- 'READY' ./a.log ./b.log
Результат: Вывод содержит только имена подходящих файлов. Для произвольных имён добавьте -Z.

-L
Печатать имена файлов без выбранных строк.
Когда: Выделить файлы без обязательной отметки.
Пример:
grep -L -F -- 'READY' ./a.log ./b.log
Результат: Выведет имена файлов, в которых READY не найдена. Ошибки чтения отдельно требуют проверки.

-H
Всегда добавлять имя источника перед выбранной строкой, даже при поиске в одном файле.
Когда: Номер строки без имени не позволит понять, из какого файла получен результат.
Пример:
grep -Hn -F -- 'anna' names.txt
Результат: При учебном names.txt получатся names.txt:1:anna и names.txt:3:anna. -H управляет именем, -n отдельно добавляет номер.

-h
Убирать имя файла из префикса вывода, в том числе при поиске в нескольких файлах.
Когда: Объединить текст совпадений из нескольких известных источников; происхождение каждой строки больше не требуется.
Пример:
grep -hn -F -- 'anna' names.txt notes.txt
Результат: При учебных файлах получатся 1:anna и 3:anna без names.txt:. Номера остаются, поскольку задан -n; одинаковые номера из разных файлов могут стать неоднозначными.

-A N
Печатать до N строк после каждой выбранной строки. A — after, «после». Пересекающиеся участки контекста объединяются.
Когда: Причина записана в строке ошибки, а подробности или продолжение находятся ниже.
Пример:
printf 'before\nERROR\nafter\nend\n' | grep -n -A 1 -F -- 'ERROR'
Результат: Печатает 2:ERROR и 3-after. Двоеточие отмечает совпавшую строку, дефис — контекст при -n. Раздельные группы отделяются строкой --. С -o контекст не выводится.

-B N
Печатать до N строк перед каждой выбранной строкой. B — before, «перед». Пересекающиеся участки контекста объединяются.
Когда: Нужно увидеть действия, которые предшествовали событию.
Пример:
printf 'before\nERROR\nafter\n' | grep -n -B 1 -F -- 'ERROR'
Результат: Печатает 1-before и 2:ERROR. Первая строка — контекст, вторая совпала. Если перед событием меньше N строк, недостающие строки не создаются.

-C N
Печатать до N строк с каждой стороны выбранной строки. C — context, «окружение». Это одновременно контекст до и после.
Когда: Нужен фрагмент журнала целиком вокруг события.
Пример:
printf 'before\nERROR\nafter\n' | grep -n -C 1 -F -- 'ERROR'
Результат: Печатает 1-before, 2:ERROR и 3-after. Общие участки соседних совпадений не дублируются; раздельные группы отделяются --. Само совпадение по-прежнему определяет шаблон.

-m N
Остановить чтение файла после N выбранных строк.
Когда: Достаточно первых совпадений.
Пример:
printf 'x\nx\nx\n' | grep -m 2 -F -- 'x'
Результат: Выведет две строки. Ранний выход может вызвать SIGPIPE у большого производителя; это учитывают при pipefail.

-r
Рекурсивно читать каталоги; в GNU grep следовать ссылкам из командной строки, пропуская найденные внутри ссылки.
Когда: Обычный поиск по дереву.
Пример:
grep -rinF --include='*.log' -- 'error' ./logs
Результат: Ищет без учёта регистра, показывает номера, читает только имена по маске .log. Образец -F буквальный.

-R
Рекурсивно читать с обходом символических ссылок.
Когда: Намеренно включить цели ссылок при известной структуре.
Пример:
grep -RnF -- 'READY' ./logs
Результат: Может выйти за логические границы исходного дерева. Для обычного поиска часто достаточно -r.

-Z
После выводимого имени файла использовать NUL.
Когда: Передать результат -l в xargs -0.
Пример:
grep -lZ -F -- 'READY' ./*.log | xargs -0 -r printf '<%s>\n'
Результат: Имена с LF сохраняются целиком. Это разделитель имён, а не входных текстовых записей.

-z
Считать записи разделёнными NUL вместо LF в GNU grep.
Когда: Искать по нулевому потоку записей.
Пример:
printf 'a\0b\0' | grep -z -F -- 'a'
Результат: Выдаст a и NUL. -z и -Z решают разные задачи; большой вход без NUL может потребовать большой памяти.

-a
Обрабатывать вход как текст, даже если GNU grep обнаруживает двоичные данные. Эквивалент --binary-files=text.
Когда: Осознанно искать по текстовым фрагментам двоичного файла и сохранить результат для дальнейшего разбора.
Пример:
grep -aF -- 'READY' ./data.bin > matches.bin
Результат: Выбранные строки записываются в matches.bin с исходными байтами, включая возможные NUL и управляющие коды. Это не преобразование кодировки; вывод такого содержимого прямо в терминал может изменить его состояние.

-I
Обрабатывать распознанный двоичный файл как источник без совпадений. Эквивалент --binary-files=without-match.
Когда: При рекурсивном поиске нужны текстовые файлы, а двоичное содержимое следует пропускать.
Пример:
grep -rInF -- 'READY' ./data
Результат: Печатает совпадения в текстовом содержимом; при обнаружении NUL GNU grep считает остаток двоичного файла не совпадающим. Это политика поиска, а не проверка расширения имени и не доказательство отсутствия байтов READY.

--include=ШАБЛОН
Выбирать для поиска файлы, чьи базовые имена соответствуют шаблону GNU grep. Звёздочку должен получить grep, поэтому её защищают от раскрытия Bash.
Когда: В большом дереве требуется искать, например, только конфигурационные файлы.
Пример:
grep -rnF --include='*.conf' -- 'listen' ./project
Результат: Рекурсивно исследует выбранные .conf и печатает совпадения с номерами. Каталоги по этому параметру не отбрасываются: обход дерева продолжается. При сочетании с --exclude учитываются порядок и последнее подходящее правило.

--exclude-dir=ШАБЛОН
Не обходить подходящие каталоги при рекурсивном поиске. Для найденных подкаталогов сопоставляется базовое имя; для каталога из аргументов GNU grep проверяет суффикс пути.
Когда: Исключить служебный каталог .git или большое дерево зависимостей.
Пример:
grep -rnF --exclude-dir='.git' -- 'listen' ./project
Результат: Не входит в подкаталоги с именем .git, но продолжает поиск по другим именам файлов. Это исключение каталогов, а не ограничение расширений файлов; для расширений нужен отдельный --include.

--line-buffered
Сбрасывать stdout после каждой выходной строки в GNU grep.
Когда: Уменьшить задержку видимости совпадений в длинном конвейере.
Пример:
producer | grep --line-buffered -F -- 'READY' | consumer
Результат: Меняет буферизацию grep; не заставляет producer немедленно выталкивать собственный буфер.

Точка нашла любой символ
По умолчанию образец является регулярным выражением.
Для буквального поиска выберите -F; кавычки Bash сами не меняют язык grep.

Склеены -rinF: что означает каждая буква?
Это -r (рекурсия), -i (регистр), -n (номер), -F (буквальный образец). -A/-B/-C/-m требуют значения.
Читайте сочетание как набор отдельных правил. После -- остаются образец и пути; не путайте образец find и регулярное выражение grep.

-q вернула успех, хотя другой файл недоступен
В GNU grep при -q найденное совпадение может определить нулевой статус даже при некоторых ошибках чтения. Это проверка наличия, не полного обхода.
Если нужно доказать чтение всех файлов, не используйте -q как такую гарантию; отдельно спроектируйте полноту обхода и обработку ошибок.

-c и -o дают разные числа
-c считает выбранные строки; -o выводит отдельные совпавшие фрагменты. Это разные единицы.
Заранее назовите, что нужно считать. Для полного структурированного формата используйте парсер.

На другой системе часть длинных параметров отсутствует
Справочник описывает GNU grep. BSD и BusyBox могут иметь другой набор, а -P зависит от поддержки PCRE.
Проверьте grep --version и локальную помощь. Для автономной работы заранее закрепите требуемую реализацию.

head
Выводит начало входа. После нужного объёма закрывает канал, и предыдущая стадия может получить SIGPIPE.
Синтаксис: head [ПАРАМЕТРЫ] [ФАЙЛ...]

-n ЧИСЛО
Показать первые указанное число строк вместо десяти.
Когда: Ограничить обзор журнала.
Пример:
head -n 3 -- service.log
Результат: Появятся первые три LF-записи или весь более короткий файл.

-c ЧИСЛО
Вывести первые указанное число байтов.
Когда: Исследовать начало двоичного файла.
Пример:
head -c 16 -- payload.bin
Результат: Не более 16 исходных байтов; UTF-8-символ может оказаться разрезан.

-z
Считать разделителем записи NUL.
Когда: Ограничить нулевой список имён.
Пример:
find . -type f -print0 | head -z -n 2
Результат: В stdout будут первые две NUL-записи без потери внутренних LF.

help
Настоящая встроенная команда Bash показывает локальную справку о встроенных командах и конструкциях оболочки. Это не man для внешних программ. В учебном виртуальном терминале одноимённая команда help без аргументов показывает список моделей и их ограничения; она не воспроизводит справочник установленной Bash. Примеры здесь запускают настоящую Bash.
Синтаксис: help [-d|-m|-s] [ТЕМА...]

ТЕМА
Показать подробную встроенную справку по выбранной теме. Имя сопоставляется с темами установленной версии Bash.
Когда: Нужно уточнить точные параметры встроенной команды без интернета.
Пример:
bash -c 'help read'
Результат: Показывает назначение read, допустимые параметры и сведения о статусе. При отсутствии подходящей темы статус ненулевой. Для внешних grep или find нужен их собственный --help либо установленный man.

-s
Показать только краткую строку синтаксиса выбранной темы.
Когда: Требуется быстро вспомнить порядок аргументов и допустимые формы.
Пример:
bash -c 'help -s read'
Результат: Показывает синтаксис read без развёрнутого описания каждого параметра. Квадратные скобки в синтаксисе обычно обозначают необязательную часть, а не буквальные символы команды.

-m
Представить справку в формате с разделами, похожем на страницу man.
Когда: Удобнее читать разделы назначения, синтаксиса, параметров и статуса.
Пример:
bash -c 'help -m read'
Результат: Показывает сведения о read с оформленными разделами. Это тот же встроенный источник Bash, а не запуск программы man и не загрузка страницы из сети.

-d
Показать короткое описание выбранной темы без полного справочного текста.
Когда: Нужно быстро проверить назначение встроенной команды.
Пример:
bash -c 'help -d read'
Результат: Показывает короткое описание read. Параметры установленной версии при необходимости уточняются обычным help read.

hostname
Читает имя узла и производные сведения. Имя UTS, полное DNS-имя и адрес интерфейса могут различаться.
Синтаксис: hostname [ПАРАМЕТРЫ]

без параметров
Базовая форма: прочитать текущее имя узла.
Когда: Осмотреть имя в текущем пространстве UTS.
Пример:
hostname
Результат: Будет системное имя; его регистрация в DNS этим не доказана.

-s
Показать короткую часть имени.
Когда: Сопоставить краткую метку с полным именем.
Пример:
hostname -s
Результат: Будет короткая форма, которая не обязана быть уникальной.

-f
Запросить полное имя через системное разрешение.
Когда: Проверить дополнение текущего имени резолвером.
Пример:
hostname -f
Результат: Результат зависит от NSS/DNS/hosts; отказ не доказывает поломку физической сети.

-I
Показать адреса настроенных интерфейсов с исключениями реализации.
Когда: Осмотреть адреса машины.
Пример:
hostname -I
Результат: Порядок не гарантирован; это не внешний адрес NAT и не проверка доступности извне.

id
Показывает идентификаторы пользователя и групп. Эффективные и реальные идентификаторы могут различаться; имя в приглашении терминала не заменяет эту проверку.
Синтаксис: id [ПАРАМЕТРЫ] [ПОЛЬЗОВАТЕЛЬ]

-u
Показать эффективный UID по умолчанию.
Когда: Проверить текущую личность.
Пример:
id -u
Результат: Появится одно число UID; capabilities этим не перечислены.

-g
Показать эффективный основной GID.
Когда: Проверить основную группу.
Пример:
id -g
Результат: Будет один GID, без полного списка дополнительных групп.

-G
Показать все учитываемые группы.
Когда: Сопоставить доступ с членством.
Пример:
id -G
Результат: Появятся идентификаторы групп; принадлежность группе не обещает любые права.

-n
С -u/-g/-G выводить имена вместо чисел.
Когда: Сделать вывод читаемым.
Пример:
id -Gn
Результат: Будут системно разрешённые имена групп; ядро проверяет числовые значения.

-r
С поддерживаемой формой запросить реальные идентификаторы.
Когда: Сравнить реальную и эффективную личность.
Пример:
id -ru
Результат: Будет реальный UID; он может отличаться после предусмотренного перехода полномочий.

initdb
Создаёт новый кластер PostgreSQL в отдельном каталоге. Не является способом обновления версии и не разворачивает логический дамп; запускать нужно от владельца будущего сервера.
Синтаксис: initdb [ПАРАМЕТРЫ] [-D] КАТАЛОГ

-D КАТАЛОГ
Выбрать каталог нового кластера.
Когда: Отделить лабораторные файлы от существующего PGDATA.
Пример:
initdb -D ./book-pgdata --encoding=UTF8 --locale=C
Результат: Создаст системные каталоги и настройки нового кластера в пустом месте; сервер этой командой ещё не запущен.

--encoding=КОДИРОВКА
Задать кодировку по умолчанию создаваемых баз.
Когда: Явно использовать UTF8 в учебных данных.
Пример:
initdb -D ./book-pgdata --encoding=UTF8 --locale=C
Результат: Новый кластер получит выбранную совместимую кодировку; это не перекодировка уже существующих файлов.

--locale=ЛОКАЛЬ
Задать исходные настройки локали нового кластера.
Когда: Условия сортировки и классификации должны быть воспроизводимы.
Пример:
initdb -D ./book-pgdata --encoding=UTF8 --locale=C
Результат: Выберет локаль C; текстовый порядок отличается от правил русского словаря и от иных ICU/libc-локалей.

--auth=МЕТОД
Задать метод для создаваемых начальных правил pg_hba.conf; --auth-local и --auth-host позволяют разделить Unix- и TCP-подключения.
Когда: Отдельный изолированный опыт явно задаёт свою начальную политику.
Пример:
initdb -D ./book-pgdata --encoding=UTF8 --locale=C --auth=trust
Результат: Создаёт правила trust: подходящий подключившийся клиент может заявить роль без пароля. Такая форма относится к изолированному стенду; доступность сервера и HBA проектируются отдельно.

initdb не принимает непустой каталог
Он создаёт новый кластер, а не чинит или обновляет существующий.
Выберите новое пустое место; для переноса существующих данных используйте совместимый путь копирования или миграции.

ip
Показывает и изменяет устройства, адреса, соседей и маршруты Linux. Сначала выбирается объект, затем действие; приведённые формы show/get только исследуют состояние.
Синтаксис: ip [ОБЩИЕ ПАРАМЕТРЫ] ОБЪЕКТ ДЕЙСТВИЕ [АРГУМЕНТЫ]

-br
Сократить представление адресов или интерфейсов до компактной строки.
Когда: Быстро сопоставить имя, состояние и адрес.
Пример:
ip -br address
Результат: В stdout появятся интерфейсы, состояния и адреса с префиксами; конфигурация не меняется.

-s
Добавить счётчики статистики подходящего объекта.
Когда: Проверить накопленные ошибки и потери интерфейса.
Пример:
ip -s link show dev enp1s0
Результат: Покажет RX/TX, байты, пакеты и доступные счётчики; нулевые потери здесь не исключают потерь дальше по пути.

route get АДРЕС
Спросить ядро о пути к конкретному назначению.
Когда: Установить выбранные интерфейс, шлюз и исходный адрес до ping.
Пример:
ip route get 198.51.100.20
Результат: Покажет решение поиска маршрута либо ошибку; сам диагностический IP-пакет этой командой не отправляется.

neigh show
Показать таблицу соседей, связывающую сетевые адреса с канальными.
Когда: Отличить отсутствие маршрута от незавершённого ARP/NDP.
Пример:
ip neigh show
Результат: В stdout появятся адреса, интерфейсы, lladdr и состояния; STALE само по себе не означает отказ.

-n ИМЯ
Выполнить последующую команду ip в именованном сетевом пространстве.
Когда: Исследовать клиента или шлюз стенда с отдельными адресами и маршрутами.
Пример:
ip -n "$C" route show
Результат: Читает маршруты пространства, имя которого заранее записано стендом в C; рабочая таблица маршрутов компьютера не выбирается вместо него.

-4
Ограничить объект или операцию семейством IPv4.
Когда: Не смешивать маршруты или адреса двух семейств.
Пример:
ip -4 address show
Результат: Покажет IPv4-адреса; не отключает IPv6 и не удаляет его настройки.

-6
Ограничить объект или операцию семейством IPv6.
Когда: Исследовать отдельный путь IPv6, NDP и префиксы.
Пример:
ip -6 route show
Результат: Покажет маршруты IPv6 выбранной таблицы; исправность IPv4 по этому выводу не проверяется.

link show
Показать интерфейсы, их флаги, MTU и канальные адреса.
Когда: Установить фактические имена и административное состояние перед настройкой.
Пример:
ip link show
Результат: Выведет интерфейсы текущего пространства; UP и наличие физического сигнала являются разными признаками.

link set
Изменить параметры выбранного интерфейса, например административное включение.
Когда: Включить loopback ранее созданного учебного пространства.
Пример:
ip -n "$C" link set dev lo up
Результат: Меняет состояние lo внутри пространства C. Это изменяющая форма; она не назначает IP-адрес и не создаёт маршрут сама по себе.

address show
Показать присвоенные интерфейсам IP-адреса с префиксами и состояниями.
Когда: Проверить адрес источника, область и допустимость использования адреса.
Пример:
ip -br address show
Результат: Сокращённый вывод показывает назначенные адреса; это не проверка DNS и не список всех достижимых узлов.

route show
Показать записи выбранной таблицы маршрутов.
Когда: Понять готовые правила выбора следующего шага.
Пример:
ip -4 route show
Результат: Обычно покажет main для IPv4. При policy routing нужно также исследовать ip rule и другие таблицы; route get уточняет решение для конкретной цели.

netns exec ИМЯ КОМАНДА
Запустить произвольную программу в именованном сетевом пространстве.
Когда: Проверить путь глазами клиента стенда либо выполнить там nft, ping или сервер.
Пример:
ip netns exec "$C" ip route show
Результат: Дочерний ip увидит маршруты пространства C. В отличие от общего -n, netns exec применим не только к подкомандам ip; нужны существующее пространство и соответствующие права.

-o
Вывести каждую запись одной строкой; внутренние переводы строки заменяются обратной косой чертой.
Когда: Нужно обработать многострочный обычный вывод построчным фильтром.
Пример:
ip -o address show
Результат: Состав адресов сохраняется, но одна запись теперь занимает одну строку; это изменение представления, не настройки сети.

-j
Вывести объекты в формате JSON.
Когда: Нужны явные ключи объектов вместо разбора выровненных столбцов.
Пример:
ip -j -4 address show
Результат: Получится массив интерфейсов с addr_info; -4 ограничит адреса IPv4. Это не JavaScript-код для выполнения.

address add АДРЕС/ПРЕФИКС dev ИМЯ
Назначить адрес указанному интерфейсу.
Когда: Настраивается собственный учебный интерфейс; существующий адрес и маршрут уже исследованы.
Пример:
ip address add 192.0.2.11/24 dev eth0
Результат: Реальная команда меняет конфигурацию интерфейса и связанные маршруты ядра. В учебном терминале меняется только виртуальный адрес; новые connected-маршруты нужно добавлять явно.

route add ПРЕФИКС via ШЛЮЗ dev ИМЯ
Добавить запись выбора следующего узла.
Когда: В учебной таблице отсутствует маршрут к нужному префиксу.
Пример:
ip route add 198.51.100.0/24 via 192.0.2.1 dev eth0
Результат: Следующий поиск route get выберет более длинный совпавший префикс; команда не проверяет успешную доставку до сервера.

route del ПРЕФИКС dev ИМЯ
Удалить выбранную запись маршрута.
Когда: В собственном стенде исследуется влияние отсутствующего пути.
Пример:
ip route del default dev eth0
Результат: Удалённый путь больше не участвует в выборе. В учебном терминале последующие ping и curl используют изменённую виртуальную таблицу.

Маршрут виден, но связь не работает
Таблица маршрутов описывает следующий шаг, а не успешную доставку.
Сопоставьте route get, neigh show, состояние линии и захваты по пути.

journalctl
Читает доступные записи журнала systemd. Время, PID и единица связывают сообщения с событием; фильтр и права влияют на видимость.
Синтаксис: journalctl [ПАРАМЕТРЫ] [ПОЛЕ=ЗНАЧЕНИЕ...]

-u ЕДИНИЦА
Отобрать сообщения, связанные с единицей.
Когда: Исследовать конкретную службу.
Пример:
journalctl -u example.service --no-pager
Результат: Будут доступны сообщения выбранной единицы по правилам отбора journalctl.

-b
Ограничить текущей загрузкой; аргумент выбирает другую доступную.
Когда: Не смешивать разные загрузки.
Пример:
journalctl -b -u example.service --no-pager
Результат: Останутся подходящие записи этой загрузки.

-n ЧИСЛО
Показать указанное число последних записей.
Когда: Получить короткий хвост журнала.
Пример:
journalctl -u example.service -n 50 --no-pager
Результат: Не более 50 записей; многострочная запись может занимать несколько экранных строк.

--since=ВРЕМЯ
Задать нижнюю временную границу.
Когда: Сопоставить сообщения с началом отказа.
Пример:
journalctl -u example.service --since="2026-10-28 09:00:00" --no-pager
Результат: Останутся записи не ранее границы в применяемом часовом представлении.

--no-pager
Не запускать просмотрщик.
Когда: Сохранить выбранные сообщения как поток.
Пример:
journalctl -b -n 30 --no-pager
Результат: Данные пойдут в stdout; сам параметр не ограничивает число записей.

kill
Отправляет сигнал процессу или заданию. В Bash есть встроенная kill с поддержкой jobspec; внешняя /bin/kill может иметь другой набор параметров. Успешная отправка не подтверждает завершение.
Синтаксис: kill [-s СИГНАЛ | -n НОМЕР | -СИГНАЛ] PID...; kill -l [НОМЕР...]

-TERM / -s TERM
Отправить перехватываемый запрос завершения; TERM — сигнал по умолчанию.
Когда: Корректная остановка собственного ребёнка с последующим ожиданием.
Пример:
sleep 30 & child=$!; kill -TERM "$child"; wait "$child"; printf 'status=%s\n' "$?"
Результат: Обычный sleep завершится по TERM; в Linux Bash обычно покажет 143. Цель принадлежит этому примеру.

-INT / -s INT
Отправить SIGINT.
Когда: Программа документирует такое прерывание, и известна нужная цель.
Пример:
# Только известному собственному процессу:
kill -s INT "$worker_pid"
Результат: Реакция зависит от программы и исходной обработки сигнала. Это не универсальный эквивалент Ctrl-C группе терминала.

-KILL / -s KILL
Отправить неперехватываемый SIGKILL.
Когда: Последняя предусмотренная ступень остановки, когда чистое завершение не удалось.
Пример:
# Последняя ступень для собственного ребёнка:
kill -s KILL "$worker_pid"
Результат: Цель не выполнит cleanup/trap после KILL; несохранённое и частичное состояние требует восстановления.

-n НОМЕР
Выбрать сигнал по номеру в Bash.
Когда: Изучить числовое обозначение на конкретной системе.
Пример:
kill -n 0 "$$"
Результат: Номер 0 ничего не доставляет: проверяет существование/право сигнала для собственной оболочки. Для переносимой логики предпочитайте смысловые имена сигналов.

-0
Проверить возможность обращения к процессу без доставки сигнала.
Когда: Ограниченная проверка известного PID, не проверка готовности службы.
Пример:
kill -0 "$$"; printf '%s' "$?"
Результат: Для своей живой Bash вернёт 0. Это не исключает zombie и не защищает от повторного использования PID.

-l [НОМЕР] / -L
В Bash показать имена сигналов или перевести номер/определённый статус в имя; -L — её синоним.
Когда: Понять 15 или обычный код 143 в Linux.
Пример:
kill -l 15
Результат: В Linux Bash 5.2 выведет TERM. Внешняя kill может по-другому понимать -L и формат списка.

%ЗАДАНИЕ
Во встроенной Bash kill выбрать известное задание, а не произвольный PID.
Когда: Осознанное интерактивное управление jobs.
Пример:
# После просмотра jobs в той же интерактивной Bash:
kill -TERM %1
Результат: Ссылка %1 относится к таблице заданий данной оболочки, а не к процессу PID 1.

Kill вернула успех, но приложение продолжает работу
TERM мог быть обработан или отложен; подтверждена отправка, а не окончание.
Для собственного ребёнка используйте wait и протокол таймаута; для службы — её менеджер.

Kill 0 и kill -0 перепутаны
0 как цель означает текущую группу процессов; -0 — отсутствие доставки сигнала известной цели. Отрицательные цели тоже связаны с группами.
Не экспериментируйте с групповыми целями в рабочем окне. Для опытов сохраняйте только свой $! и проверяйте адресата.

Послан сигнал не тому процессу
PID мог быть повторно использован или найден только по совпавшему имени.
Управляйте собственными детьми через сохранённый $!/wait, а сервисами через систему надзора. Поиск имени не даёт владения.

ln
Создаёт новое имя-ссылку. По умолчанию делает жёсткую ссылку; -s создаёт отдельный объект с текстом пути.
Синтаксис: ln [ПАРАМЕТРЫ] ЦЕЛЬ ИМЯ_ССЫЛКИ

-s
Создать символическую ссылку.
Когда: Сослаться на путь, в том числе в другой ФС.
Пример:
ln -s -- versions/v1 current
Результат: current хранит versions/v1; относительная цель разрешается от каталога самой ссылки.

-r
С -s вычислить относительный путь цели от расположения ссылки.
Когда: Сохранить переносимость связанного дерева каталогов.
Пример:
ln -sr -- /srv/app/versions/v1 /srv/app/current
Результат: Текст current будет относительным путём к цели, вычисленным из расположений.

-T
Считать последний путь именем ссылки, а не каталогом назначения.
Когда: Не создать случайно дополнительную ссылку внутри каталога.
Пример:
ln -sT -- versions/v1 current
Результат: Невозможность создать именно current даст отказ вместо обычного помещения внутрь каталога.

local
Объявляет переменную локальной для выполняемой функции Bash. После выхода из функции прежняя привязка имени восстанавливается. В Bash область видимости динамическая: локальную переменную видит и другая функция, вызванная из этой функции. Отдельным процессам переменная передаётся только по правилам export. Вне функции local неприменима.
Синтаксис: local [ПАРАМЕТРЫ DECLARE] ИМЯ[=ЗНАЧЕНИЕ] ...

ИМЯ[=ЗНАЧЕНИЕ]
Создать локальную переменную в текущем вызове функции и при необходимости присвоить ей значение. Это форма объявления, а не флаг.
Когда: Функции нужно своё временное значение, не меняющее одноимённую переменную вызывающего кода.
Пример:
bash -c 'value=outer; f() { local value=inner; printf "%s\n" "$value"; }; f; printf "%s\n" "$value"'
Результат: Печатает inner внутри функции и outer после её возврата. При рекурсивном вызове каждый вызов получает собственную локальную переменную.

-a
Объявить локальный индексированный массив: значения хранятся в элементах с целочисленными индексами.
Когда: Функция собирает список отдельных аргументов, включая строки с пробелами.
Пример:
bash -c 'f() { local -a args=(one "two words"); printf "<%s>\n" "${args[@]}"; }; f'
Результат: Печатает <one> и <two words>. Раскрытие "${args[@]}" сохраняет каждый элемент отдельным аргументом.

-n
Создать локальную ссылку по имени: значение переменной задаёт имя другой переменной. Чтение и присваивание обычно обращаются к указанной цели.
Когда: Контролируемая функция возвращает результат в переменную, имя которой явно передал вызывающий код.
Пример:
bash -c 'write_result() { local -n target=$1; target=ready; }; result=old; write_result result; printf "%s\n" "$result"'
Результат: Печатает ready: target ссылается на result. Имена target и result намеренно различны; ссылка на саму себя создаёт ошибку. Имена переменных не следует брать из непроверенного ввода.

Присваивание через подстановку команды скрывает её отказ
local является отдельной встроенной командой. В local value=$(false) итоговый статус обычно принадлежит успешному объявлению local, а не false.
Разделяйте операции: local value; value=$(producer) || return. Второй статус относится к присваиванию с подстановкой и может быть проверен.

ls
Показывает имена и метаданные для человека. Вывод ls не подходит для восстановления произвольных имён в сценарии.
Синтаксис: ls [ПАРАМЕТРЫ] [ПУТЬ...]

-l
Показать тип, права, ссылки, владельца, группу, размер и время.
Когда: Осмотреть метаданные конкретного объекта.
Пример:
ls -l -- report.txt
Результат: Появится подробная строка; её оформление зависит от среды и настроек.

-a
Включить скрытые имена с точкой, в том числе . и ...
Когда: Найти скрытые файлы настройки.
Пример:
ls -a -- .
Результат: Будут показаны также скрытые имена; рекурсивный обход не включается.

-d
Показать сам каталог вместо его содержимого.
Когда: Посмотреть права прохода по каталогу.
Пример:
ls -ld -- /srv
Результат: Будут метаданные /srv, а не список его детей.

-i
Добавить номер inode.
Когда: Сопоставить имена внутри одной файловой системы.
Пример:
ls -li -- a.txt b.txt
Результат: Одинаковый inode у обычных файлов одной ФС означает тот же объект; номер без устройства не уникален глобально.

-F / --classify
Добавить к именам признаки типа объекта.
Когда: Нужно отличать каталог от обычного файла по короткому выводу.
Пример:
ls -F
Результат: У каталога добавляется /; у других типов возможны свои признаки. Имена на диске при этом не меняются. Указание исполнимости зависит от прав; учебная модель прав не хранит.

mapfile
Загружает записи потока в массив Bash. Сохраняет структуру, но весь набор занимает память.
Синтаксис: mapfile [ПАРАМЕТРЫ] МАССИВ

-t
Удалять завершающий разделитель записи.
Когда: Получить значения без LF или NUL-разделителя.
Пример:
mapfile -t lines <input.txt
Результат: Каждая строка — отдельный элемент без завершающего LF.

-d ''
Использовать NUL как разделитель.
Когда: Загрузить заранее проверенный нулевой список имён.
Пример:
mapfile -d '' -t files <names.bin
Результат: LF внутри имени сохраняется, разделитель NUL не хранится.

-n N
Читать не более N записей.
Когда: Ограничить объём одной загрузки.
Пример:
mapfile -n 10 -t lines <input.txt
Результат: В массив попадут максимум первые десять записей.

Mapfile успешна, но список неполный
Производитель подстановки процесса мог отказать отдельно.
Для критичного списка сначала проверьте производство файла, затем загружайте его.

mkdir
Создаёт каталоги. Доступ к конечному пути зависит также от владельцев и прав всех родительских каталогов.
Синтаксис: mkdir [ПАРАМЕТРЫ] КАТАЛОГ...

-p
Создать отсутствующих родителей; существующий каталог не считать ошибкой.
Когда: Подготовить рабочее дерево.
Пример:
mkdir -p -- work/reports/2026
Результат: Недостающие компоненты появятся; существующие сохранят свои прежние права.

-m РЕЖИМ
Задать режим нового целевого каталога.
Когда: Сразу ограничить доступ к новому каталогу.
Пример:
mkdir -m 700 -- private-work
Результат: Новый каталог предназначен для r/w/x владельца; существующий эта форма не перенастраивает.

-v
Сообщать о созданных каталогах.
Когда: Увидеть реально созданные компоненты.
Пример:
mkdir -pv -- work/reports
Результат: Сообщения появятся для новых каталогов, а не как подтверждение будущей работы.

mktemp
Безопасно создаёт новый временный файл или каталог. Возвращённый путь принимают только после успешного статуса.
Синтаксис: mktemp [ПАРАМЕТРЫ] [ШАБЛОН]

-d
Создать собственный временный каталог.
Когда: Нужны несколько независимых рабочих файлов.
Пример:
tmp=$(mktemp -d) || exit
Результат: Tmp получает реально созданный новый каталог с ограниченным доступом.

ШАБЛОН
Создать объект по шаблону с X в нужном каталоге.
Когда: Временный файл должен быть на той же ФС, что цель.
Пример:
pending=$(mktemp -- "$parent/.report.XXXXXXXX") || exit
Результат: Новый объект находится в каталоге назначения для последующей атомарной замены.

Rm получил пустой или чужой путь
Создание не проверено либо переменная изменена.
Проверяйте mktemp, храните путь неизменным и удаляйте только собственный объект.

mv
Перемещает имя или заменяет назначение. Между разными файловыми системами копирование с удалением имеет другие свойства, чем rename внутри одной.
Синтаксис: mv [ПАРАМЕТРЫ] ИСТОЧНИК НАЗНАЧЕНИЕ

-T
Считать назначение именно целевым именем, а не каталогом для помещения внутрь.
Когда: Определённо заменить ожидаемое имя.
Пример:
mv -T -- pending.txt result.txt
Результат: При допустимой операции изменится result.txt; неожиданный каталог не получит файл внутрь обычным способом.

-i
Спрашивать перед перезаписью.
Когда: Вручную подтвердить замену.
Пример:
mv -i -- new.txt current.txt
Результат: Отрицательный ответ сохраняет назначение; положительный разрешает замену.

-n
Не перезаписывать существующее назначение.
Когда: Сохранить ранее созданный результат.
Пример:
mv -n -- pending.txt result.txt
Результат: Если result.txt существует, pending.txt может остаться; один нулевой статус не доказывает перемещение.

-v
Показать сведения о перемещении.
Когда: Проследить конкретный шаг публикации.
Пример:
mv -v -- pending.txt result.txt
Результат: Сообщение относится к действию; устойчивость после аварии требует отдельного протокола.

nft
Управляет правилами nftables в текущем сетевом пространстве Linux. Формы list исследуют состояние; загрузка файла способна менять действующий межсетевой экран и NAT.
Синтаксис: nft [ПАРАМЕТРЫ] КОМАНДА

list ruleset
Показать весь доступный набор правил.
Когда: Установить реальные таблицы, цепочки, hook и приоритеты.
Пример:
nft list ruleset
Результат: Напечатает конфигурацию в stdout; чтение может требовать административных прав данного пространства.

-a
Добавить идентификаторы handle к выводимым правилам.
Когда: Точно сопоставить наблюдаемое правило с последующей адресной правкой на стенде.
Пример:
nft -a list ruleset
Результат: Вывод дополнится handle; это идентификаторы правил, а не порядковые номера пакетов.

-f ФАЙЛ
Прочитать команды nft из файла.
Когда: Проверить подготовленный набор либо применить его в учебном пространстве.
Пример:
nft -c -f ./nat.nft
Результат: С -c проверяет файл; без -c загрузка выполняет команды и может изменить действующие правила.

-c
Проверить допустимость команд, не применяя изменения.
Когда: Поймать ошибку перед загрузкой подготовленного файла.
Пример:
nft -c -f ./nat.nft
Результат: Успех означает прохождение поддерживаемой проверки, но не доказывает правильную доставку трафика или подходящий порядок политики.

Есть правило NAT, но соединение запрещено
Преобразование адреса и разрешение пересылки являются отдельными решениями.
Проследите hook, маршрут и filter-цепочку в правильном пространстве, затем проверьте обратный путь.

od
Показывает данные в явном числовом или символьном представлении. Внешняя программа GNU Coreutils помогает увидеть невидимые байты и точные границы.
Синтаксис: od [ПАРАМЕТРЫ] [--] [ФАЙЛЫ...]

-A n / -An
Не печатать адресное смещение слева.
Когда: Нужны только значения байтов небольшого фрагмента.
Пример:
printf 'AB\n' | od -An -tx1
Результат: Покажет 41 42 0a с форматными пробелами. -An — слитная запись -A n.

-A x / -Ax
Показывать смещения в шестнадцатеричном виде.
Когда: Сопоставить позицию с полем двоичного формата.
Пример:
od -Ax -tx1 packet.bin
Результат: Слева будут смещения, справа байты. Начало отсчёта — выбранный вход, а не обязательно заголовок IP.

-t x1 / -tx1
Показывать однобайтовые шестнадцатеричные значения.
Когда: Исследовать CR, LF, NUL и заголовок пакета без зависимости от порядка байтов CPU.
Пример:
printf 'A\r\n' | od -An -tx1
Результат: Покажет 41 0d 0a. Слитное -tx1 означает -t с аргументом x1.

-t c / -tc
Показать символьное представление и обозначения управляющих байтов.
Когда: Прочитать CR/LF и обратные черты в текстовом фрагменте.
Пример:
printf 'a\tB\n' | od -An -tc
Результат: Покажет символ a, обозначение табуляции, B и обозначение LF; это представление, не исходный поток.

-N БАЙТЫ
Прочитать не более выбранного числа байтов.
Когда: Посмотреть начало файла, не выгружая весь объём.
Пример:
printf 'abcdef' | od -An -tc -N 3
Результат: Будут показаны a b c.

-j БАЙТЫ
Пропустить выбранное число входных байтов.
Когда: Начать разбор с известного смещения.
Пример:
printf 'abcdef' | od -An -tc -j 2 -N 3
Результат: Будут показаны c d e. Пропуск относится к входу od.

-v
Не заменять повторяющиеся одинаковые строки одной звёздочкой.
Когда: Нужен полный дамп каждого участка.
Пример:
od -An -tx1 -v packet.bin
Результат: Повторяющиеся строки показываются явно. Без -v звёздочка может означать сокращённый повтор, а не байт 2a.

-w N / -wN
В GNU od задать число входных байтов на строку вывода.
Когда: Удобно видеть строки по 16 или 8 байтов.
Пример:
printf 'abcdef' | od -An -tx1 -w4
Результат: Первая строка покажет четыре байта, вторая — два. Учитывайте допустимость ширины для выбранного типа.

Без -t числа выглядят непривычно
По умолчанию od использует собственный исторический числовой формат, обычно восьмеричные единицы.
Для разбора байтов пишите явно od -An -tx1 -v.

-tx2 показала число в неожиданном порядке
Многобайтовые единицы интерпретируются с порядком байтов платформы или выбранной GNU-настройкой endian.
Для первого шага используйте x1 и собирайте поле по правилам изучаемого протокола; порядок CPU не равен сетевому.

Дамп копируется как исходные данные
В дампе есть пробелы, адреса и текстовые обозначения; это другая запись байтов.
Не подавайте человекочитаемый вывод в программу, ожидающую исходный двоичный файл без отдельного декодирования.

openssl
Набор криптографических инструментов. Здесь используется подкоманда s_client для наблюдения TLS-рукопожатия; соединение, SNI, доверие и проверяемое имя задаются раздельно.
Синтаксис: openssl s_client [ПАРАМЕТРЫ]

-connect АДРЕС:ПОРТ
Выбрать TCP-узел для соединения.
Когда: Соединиться с локальным учебным TLS-сервером.
Пример:
openssl s_client -connect 127.0.0.1:18443
Результат: Устанавливает TCP и TLS по адресу; сам адрес ещё не задаёт успешную проверку нужного имени.

-servername ИМЯ
Передать имя SNI в ClientHello.
Когда: Сервер выбирает сертификат среди нескольких служб.
Пример:
openssl s_client -connect 127.0.0.1:18443 -servername app.lab.test
Результат: Пошлёт app.lab.test как SNI; это отдельно от проверки, что сертификат разрешён для этого имени.

-verify_hostname ИМЯ
Проверить соответствие сертификата ожидаемому DNS-имени.
Когда: Проверка должна доказать именно личность нужной службы.
Пример:
openssl s_client -connect 127.0.0.1:18443 -servername app.lab.test -verify_hostname app.lab.test -CAfile ca.pem -verify_return_error
Результат: При несовпадении имени полный пример завершится ошибкой проверки.

-CAfile ФАЙЛ
Задать PEM-файл доверенных центров.
Когда: Использовать учебный CA без добавления в общее доверие ОС.
Пример:
openssl s_client -connect 127.0.0.1:18443 -servername app.lab.test -verify_hostname app.lab.test -CAfile ca.pem -verify_return_error
Результат: Проверяет цепь с указанным файлом доверия; относительный путь считается от текущего каталога.

-verify_return_error
Прерывать рукопожатие при ошибке проверки сертификата.
Когда: Код завершения должен отражать отказ проверки.
Пример:
openssl s_client -connect 127.0.0.1:18443 -verify_hostname wrong.lab.test -CAfile ca.pem -verify_return_error
Результат: Неправильное имя даст отказ. Без этого флага диагностический s_client способен продолжить обмен после сообщения об ошибке.

SNI верное, проверка имени не выполняется
Отправка имени серверу и проверка сертификата клиентом имеют разные задачи.
Задайте -servername и -verify_hostname, подходящее доверие и -verify_return_error.

pg_basebackup
Получает физическую базовую копию кластера через репликационное соединение. Это каталог серверных данных либо архивы, а не SQL одной базы; нужны совместимость версий и необходимые разрешения.
Синтаксис: pg_basebackup [ПАРАМЕТРЫ]

-D КАТАЛОГ
Указать каталог получения копии при обычном формате plain.
Когда: Сохранить базу в отдельном пустом месте.
Пример:
pg_basebackup -D ./book-base -X stream
Результат: Запишет физическую копию в book-base; это не подключение к базе с именем book-base и не автоматический запуск копии.

-X stream
Получать необходимый WAL параллельным потоком во время копирования.
Когда: Копия должна получить журнал для согласованного начала восстановления.
Пример:
pg_basebackup -D ./book-base -X stream
Результат: Использует дополнительное репликационное соединение и сохраняет нужный WAL вместе с копией.

-R
Подготовить настройки копии как будущей standby.
Когда: Собирать резервный сервер, который продолжит получать историю источника.
Пример:
pg_basebackup -D ./book-standby -X stream -R
Результат: В современных версиях создаёт standby.signal и дописывает сведения подключения; в PostgreSQL 11 использовался recovery.conf. Сервер ещё нужно отдельно запустить.

-S ИМЯ_СЛОТА
Использовать названный физический слот при потоковом получении WAL.
Когда: Связать копирование и будущую реплику с удержанием нужной истории.
Пример:
pg_basebackup -D ./book-standby -X stream -R -S book_standby
Результат: Без -C слот должен уже существовать. Сам слот может удерживать WAL после копирования и требует дальнейшего обслуживания.

Готовую копию удалили, а WAL растёт
Оставшийся постоянный слот продолжает удерживать историю.
Проверьте потребителей и restart_lsn; удалять слот допустимо только после отказа от нужды в его истории.

pg_config
Показывает сведения об установленной сборке PostgreSQL. Не подключается к работающему серверу; версия и пути этой команды могут относиться к другому комплекту, чем выбранное подключение psql.
Синтаксис: pg_config [ПАРАМЕТРЫ]

--version
Вывести версию установки этой утилиты.
Когда: Проверить комплект клиентских программ и заголовков.
Пример:
pg_config --version
Результат: Напечатает PostgreSQL и номер сборки; это не SHOW server_version подключённого экземпляра.

--bindir
Показать каталог исполняемых файлов данной установки.
Когда: Найти согласованный набор initdb, pg_ctl, psql и pg_waldump.
Пример:
pg_config --bindir
Результат: В stdout будет путь; при нескольких установках важно сначала выбрать нужный pg_config через PATH или полный путь.

--configure
Показать параметры конфигурирования этой сборки.
Когда: Проверить, какие возможности включались при сборке.
Пример:
pg_config --configure
Результат: Печатает сведения сборки, не текущие postgresql.conf и не фактически применённые серверные параметры.

Версия pg_config отличается от сервера
PATH выбрал утилиту другого установленного комплекта.
Используйте полный путь к согласованным программам и отдельно запросите версию сервера SQL-командой.

pg_ctl
Управляет жизненным циклом выбранного кластера: start, stop, restart, reload и status. Работает с каталогом данных; не выбирает базу SQL внутри сервера.
Синтаксис: pg_ctl ДЕЙСТВИЕ [ПАРАМЕТРЫ]

-D КАТАЛОГ
Указать каталог данных управляемого экземпляра.
Когда: Не остановить случайно другой учебный или рабочий сервер.
Пример:
pg_ctl -D ./book-pgdata status
Результат: Проверит состояние именно этого каталога; относительный путь считается от текущего места вызова.

-l ФАЙЛ
Записывать или дописывать вывод запускаемого сервера в журнал.
Когда: Сохранить причину успешного или неудачного старта.
Пример:
pg_ctl -D ./book-pgdata -l ./book-server.log -w start
Результат: Запустит сервер и направит его вывод в файл; разрешённые адреса и порт определяются серверными настройками.

-m fast
При остановке завершить соединения и откатить активную работу с корректным завершением сервера.
Когда: Остановить учебный кластер без ожидания добровольного выхода всех клиентов.
Пример:
pg_ctl -D ./book-pgdata -m fast -w stop
Результат: Клиенты будут отключены, сервер завершит предусмотренную очистку. Режим immediate имеет другие последствия и нужен только для отдельного опыта аварии.

-w
Дождаться завершения операции по правилам pg_ctl; в современных версиях обычно уже включён.
Когда: Последующая команда не должна стартовать сразу после отправки запроса запуска или остановки.
Пример:
pg_ctl -D ./book-pgdata -m fast -w stop
Результат: Ждёт предусмотренного состояния до тайм-аута. Готовность сервера ещё не доказывает успешность предметного SQL приложения.

reload не применил параметр
Часть настроек действует только при новом старте сервера.
Посмотрите pg_settings.context и pending_restart; отличайте перечитывание файла от фактического изменения значения.

pg_dump
Получает согласованную логическую копию одной базы. Сохраняет описание объектов и данные, а не побайтовую копию PGDATA; общие роли кластера требуют отдельного резервирования.
Синтаксис: pg_dump [ПАРАМЕТРЫ] [БАЗА]

-d БАЗА
Выбрать источник дампа через имя или строку подключения.
Когда: Не полагаться на имя базы по умолчанию из окружения.
Пример:
pg_dump -d book -Fc -f book.dump
Результат: Прочитает базу book и создаст архив book.dump; исходная база от этого не становится другой базой.

-Fc
Выбрать структурированный формат custom.
Когда: Нужны оглавление, выборочная обработка и pg_restore.
Пример:
pg_dump -d book -Fc -f book.dump
Результат: Создаст архив для pg_restore; это не текст SQL и не работающий каталог сервера.

-f ФАЙЛ
Задать место сохранения результата.
Когда: Сохранить дамп явно вместо выдачи в stdout.
Пример:
pg_dump -d book -Fc -f ./book.dump
Результат: Пишет файл в текущий каталог и может перезаписать имеющееся имя. Для формата directory аргумент обозначает каталог.

--schema-only
Сохранить определения объектов без табличных данных и статистики соответствующей версии.
Когда: Сравнить структуру или подготовить отдельную схему.
Пример:
pg_dump -d book --schema-only -f schema.sql
Результат: Получится текстовое описание схемы при обычном формате; это не полноценная резервная копия содержимого.

-Fp
Выбрать обычный текстовый SQL-формат.
Когда: Дамп надо читать и затем передавать psql.
Пример:
pg_dump -d book -Fp -f backup.sql
Результат: Результат — текст SQL с COPY либо INSERT. В отличие от -Fc его читает psql, а не pg_restore.

-s
Сохранить только определения объектов; краткая форма --schema-only.
Когда: Нужно изучить структуру без строк таблиц.
Пример:
pg_dump -d book -s -f schema.sql
Результат: Определения таблиц присутствуют; данные не включаются.

-a
Сохранить табличные данные без определений; краткая форма --data-only.
Когда: Структура целевой базы уже подготовлена отдельно.
Пример:
pg_dump -d book -a --column-inserts -f data.sql
Результат: В plain-дампе будут данные и необходимые команды их восстановления; создание таблиц исключено. Режим -s несовместим с -a.

-t ШАБЛОН_ТАБЛИЦЫ
Выбрать таблицы по шаблону имени; флаг можно повторить.
Когда: Нужно отдельно сохранить известные таблицы.
Пример:
pg_dump -d book -t public.documents -t public.users -f tables.sql
Результат: Выбранные таблицы сохраняются без автоматического включения всех зависимостей. При заданном -t ограничения -n не определяют выбор этих таблиц. Учебный терминал принимает точные имена без шаблонов.

-n ШАБЛОН_СХЕМЫ
Выбрать схему по имени или шаблону; флаг можно повторить.
Когда: Нужно отделить прикладную public от audit.
Пример:
pg_dump -d book -n audit -f audit.sql
Результат: Дамп содержит выбранную схему и относящиеся к ней объекты; зависимости за её пределами автоматически не гарантируются. Учебный терминал ограничен точными именами и своими таблицами.

-O / --no-owner
Убрать команды установки владельцев объектов.
Когда: Объекты при восстановлении должны принадлежать выполняющей восстановление роли.
Пример:
pg_dump -d book -O -f backup.sql
Результат: В plainSQL не будет ALTER OWNER или SET SESSION AUTHORIZATION для исходных владельцев. Флаг не удаляет права GRANT: это отдельное -x.

-x / --no-privileges
Не включать команды управления правами доступа.
Когда: При переносе права будут назначены отдельно.
Пример:
pg_dump -d book -O -x -f backup.sql
Результат: В дампе нет GRANT и REVOKE исходных объектов; определения и данные продолжают включаться по остальным параметрам.

-c / --clean
Включить удаление сохраняемых объектов перед их созданием при восстановлении.
Когда: Повторное восстановление plainSQL должно заменить выбранные объекты.
Пример:
pg_dump -d book -c --if-exists -f replace.sql
Результат: В текст добавятся DROP перед CREATE. Исходная база при создании дампа не очищается; DROP исполнится только при восстановлении этого файла.

--if-exists
Добавить IF EXISTS к удаляющим командам в режиме --clean.
Когда: Целевая база может не содержать часть удаляемых объектов.
Пример:
pg_dump -d book -c --if-exists -f replace.sql
Результат: DROP отсутствующего объекта не даст ошибки отсутствия. Требуется -c; флаг не подавляет все возможные ошибки восстановления.

--inserts
Выводить данные командами INSERT вместо COPY.
Когда: Нужен читаемый текст отдельных вставок или перенос в другую СУБД.
Пример:
pg_dump -d book -a --inserts -t public.documents
Результат: INSERT не перечисляет имена столбцов, поэтому порядок столбцов важен. Восстановление обычно медленнее COPY.

--column-inserts
Выводить INSERT с явным списком столбцов.
Когда: Нужно видеть соответствие каждого значения столбцу и меньше зависеть от порядка столбцов назначения.
Пример:
pg_dump -d book -a --column-inserts -t public.documents
Результат: Каждая строка представлена INSERT INTO ... (id,title,status) VALUES (...). Это не автоматическое согласование несовместимых типов или отсутствующих столбцов.

-C / --create
Включить создание самой базы и переключение подключения на неё.
Когда: Восстановление должно начинаться через административную базу.
Пример:
pg_dump -d book -C -O -x -f create-book.sql
Результат: В plainSQL появятся CREATE DATABASE и обратная команда psql для переключения базы. При -c добавится также DROP DATABASE; исходная база при создании дампа не удаляется.

Есть один дамп, значит сохранён весь кластер
pg_dump работает с одной базой и не сохраняет все глобальные роли как полную физическую историю.
Планируйте общие объекты отдельно и проверяйте восстановление в новом окружении.

pg_isready
Проверяет состояние приёма соединений PostgreSQL. Не доказывает успешную авторизацию прикладной роли и не выполняет предметный запрос; коды 0/1/2/3 различают приём, отказ, отсутствие ответа и неверный вызов.
Синтаксис: pg_isready [ПАРАМЕТРЫ]

-h УЗЕЛ_ИЛИ_КАТАЛОГ
Выбрать сетевой узел или каталог Unix-сокета.
Когда: Проверять отдельный учебный экземпляр.
Пример:
pg_isready -h /tmp/book-socket -p 55432
Результат: Обратится к сокету выбранного места; успешный ответ не проверяет сетевой путь с другого компьютера.

-p ПОРТ
Выбрать порт либо соответствующий номер Unix-сокета.
Когда: Отделить несколько кластеров на одном компьютере.
Пример:
pg_isready -h 127.0.0.1 -p 55432
Результат: Проверит TCP-порт 55432; это не порт приложения или имя базы.

-d БАЗА
Передать имя базы или conninfo для проверки состояния подключения.
Когда: Использовать адресные сведения конкретного приложения.
Пример:
pg_isready -d "host=127.0.0.1 port=55432 dbname=book"
Результат: Проверит состояние сервера по выбранным параметрам; результат не гарантирует вход именно в book с требуемыми правами.

-t СЕКУНДЫ
Ограничить ожидание попытки подключения; 0 отключает этот предел.
Когда: Проверка готовности должна завершаться за заданное время.
Пример:
pg_isready -h 127.0.0.1 -p 55432 -t 2
Результат: После результата или истечения ожидания завершится; код 2 означает отсутствие ответа, а не установленную причину отказа.

-q / --quiet
Скрыть сообщение о состоянии, оставив код завершения.
Когда: Сценарий проверяет готовность условием, не разбирая человекочитаемый текст.
Пример:
pg_isready -q -h /tmp/book-socket -p 5432 -d book
Результат: При доступном сервере статус0, без ответа —2. Отсутствие stdout не означает успешную готовность; проверяйте статус.

pg_isready успешна, приложение получает permission denied
Готовность сервера и разрешение конкретного SQL — разные этапы.
Проверьте вход прикладной ролью, выбранную базу, CONNECT/USAGE, таблицы, последовательности и RLS.

pg_restore
Читает архив pg_dump формата custom, directory или tar. С -d выполняет восстановление в сервере; без -d по умолчанию может выдавать SQL в stdout, не создавая работающую базу.
Синтаксис: pg_restore [ПАРАМЕТРЫ] АРХИВ

-d БАЗА
Подключиться к базе и выполнять восстановительные команды.
Когда: Восстановить архив в заранее созданную отдельную базу.
Пример:
pg_restore --exit-on-error -d book_restore book.dump
Результат: Изменит book_restore командами архива. Без -C указанная база является непосредственной целью.

-C
Создать базу с именем, записанным в архиве, затем восстановить её.
Когда: Нужно сохранить исходное имя базы, а не переименовать цель.
Пример:
pg_restore --exit-on-error -C -d postgres book.dump
Результат: postgres служит начальной административной базой; восстановление идёт в имя из архива. Это не восстановление в postgres только потому, что указан -d postgres.

--no-owner
Пропустить восстановление первоначальных владельцев объектов.
Когда: Исходные роли недоступны и новая модель владения выбрана заранее.
Пример:
pg_restore --exit-on-error --no-owner -d book_restore book.dump
Результат: Объекты создаются по правилам действующей роли; её прав должно хватать. Права GRANT этим флагом отдельно не отменяются.

--exit-on-error
Прервать восстановление на первой SQL-ошибке вместо обычного продолжения.
Когда: Сделать неполное восстановление заметным сразу.
Пример:
pg_restore --exit-on-error -d book_restore book.dump
Результат: Завершится ненулевым кодом при ошибке; уже выполненные ранее команды не обязаны откатиться одной общей транзакцией.

Передали backup.sql, pg_restore его не читает
Обычный текстовый дамп восстанавливается SQL-клиентом.
Используйте psql -X -v ON_ERROR_STOP=1 -d НОВАЯ_БАЗА -f backup.sql; тип архива устанавливайте до запуска.

pg_verifybackup
Проверяет физическую копию по манифесту и нужному WAL. Доступна начиная с PostgreSQL 13; не подключается к серверу и не исполняет прикладные запросы восстановленной базы.
Синтаксис: pg_verifybackup [ПАРАМЕТРЫ] КАТАЛОГ_КОПИИ

--exit-on-error
Остановиться на первой обнаруженной ошибке.
Когда: Автоматическая проверка должна сразу вернуть отказ.
Пример:
pg_verifybackup --exit-on-error ./book-base
Результат: Проверит локальную копию и завершится ненулевым кодом при ошибке; исходный кластер не запускается.

--wal-directory=КАТАЛОГ
Искать необходимый WAL в указанном месте.
Когда: Журнал копии сохранён отдельно от её стандартного pg_wal.
Пример:
pg_verifybackup --wal-directory=./book-wal ./book-base
Результат: Читает WAL выбранного каталога; само указание пути не восполняет отсутствующий сегмент.

--no-parse-wal
Пропустить разбор WAL, сохранив остальные предусмотренные проверки.
Когда: Отдельно исследовать файловую часть, понимая уменьшенную область проверки.
Пример:
pg_verifybackup --no-parse-wal ./book-base
Результат: Успех этой формы не подтверждает наличие и корректность всей необходимой WAL-цепи.

Проверка прошла, приложение после восстановления ошибается
Файловая целостность и прикладная работоспособность — разные свойства.
Выполните контрольный запуск отдельной копии, затем ограничения, владельцев, последовательности и предметные запросы.

pg_waldump
Разбирает записи WAL из локальных сегментов в текст. Не восстанавливает базу и не воспроизводит SQL; формат должен соответствовать версии утилиты и читаемого журнала.
Синтаксис: pg_waldump [ПАРАМЕТРЫ] [НАЧАЛЬНЫЙ_СЕГМЕНТ [КОНЕЧНЫЙ_СЕГМЕНТ]]

-p КАТАЛОГ
Указать место поиска файлов WAL или каталог данных с pg_wal.
Когда: Работать с сохранёнными сегментами отдельного опыта.
Пример:
pg_waldump -p ./wal-copy -n 10 000000010000000000000001
Результат: Читает локальные файлы и печатает записи; имя должно существовать в выбранной копии.

-s LSN
Начать чтение с указанной позиции журнала по правилам утилиты.
Когда: Найти участок конкретной операции.
Пример:
pg_waldump -p ./wal-copy -s 0/01CB1400 -n 10
Результат: Покажет записи начиная с доступной корректной границы; один LSN не заменяет требуемые файлы сегментов.

-e LSN
Задать границу окончания чтения.
Когда: Ограничить разбор известным участком потока.
Пример:
pg_waldump -p ./wal-copy -s 0/01CB1400 -e 0/01CB1600
Результат: Остановит вывод по указанной границе вместо чтения всей доступной дальнейшей истории.

-n ЧИСЛО
Ограничить число показанных записей.
Когда: Получить обозримый фрагмент вместо длинного вывода.
Пример:
pg_waldump -p ./wal-copy -s 0/01CB1400 -n 5
Результат: Выведет не более пяти подходящих записей; число относится к записям WAL, не к транзакциям или строкам таблицы.

Номер сегмента есть, байты не разбираются
Возможны другая версия формата, повреждение или неполный файл.
Сверьте версию pg_waldump, timeline, границы сегмента и сохранённые исходные файлы; не правьте рабочий WAL.

ping
Проверяет обмен ICMP Echo и измеряет время ответа на пробы. Проверка узла не доказывает доступность TCP-порта, DNS, TLS или операции приложения.
Синтаксис: ping [ПАРАМЕТРЫ] АДРЕС

-c ЧИСЛО
Ограничить число отправляемых эхо-запросов.
Когда: Сделать конечную проверку вместо непрерывного потока.
Пример:
ping -c 3 127.0.0.1
Результат: Отправит до трёх предусмотренных проб и напечатает сводку; отсутствие ответов разбирают отдельно.

-s БАЙТЫ
Задать размер данных эха без IP- и ICMP-заголовков.
Когда: Проверить прохождение выбранного размера пакета.
Пример:
ping -4 -c 3 -M do -s 1372 192.0.2.1
Результат: При обычных заголовках IPv4 получится 1372+8+20=1400 байт IP-пакета, без Ethernet.

-M do
Для iputils выбрать PMTU-режим с запретом фрагментации.
Когда: Проверить ограничение размера, не позволяя скрыть его дроблением IPv4.
Пример:
ping -4 -c 3 -M do -s 1372 192.0.2.1
Результат: Крупная проба может дать локальную ошибку либо ICMP о размере; молчание всё ещё не различает потерю и фильтр.

-4
Использовать IPv4.
Когда: Не смешивать IPv4- и IPv6-проверки одного имени.
Пример:
ping -4 -c 3 127.0.0.1
Результат: Проверит IPv4-эхо; IPv6 использует отдельную адресацию и механизмы ICMPv6.

Маленький ping проходит, файл зависает
Эхо малого размера ещё не проверило MTU полного пути или большие TCP-сегменты.
Сравните размеры проб и прохождение необходимых ICMP-ошибок; сопоставьте захваты и повторы TCP.

printf
Печатает данные по постоянному формату. В Bash обычно встроена. Формат — отдельный маленький язык; пользовательские значения передают после него.
Синтаксис: printf ФОРМАТ [ЗНАЧЕНИЯ...]

%s
Печатать значение как строку без дополнительного толкования процентов внутри него.
Когда: Почти любой буквальный пользовательский текст.
Пример:
value='100% ready'; printf '%s\n' "$value"
Результат: Выведет 100% ready и LF. Процент внутри value не станет командой формата.

%q
Вывести представление значения для повторного чтения Bash.
Когда: Показать пробелы, пустые строки и управляющие символы при отладке.
Пример:
printf '%q\n' 'two words'
Результат: Покажет форму с защитой пробела. Это представление, а не исходные байты имени.

-v ИМЯ
Присвоить отформатированное значение переменной вместо stdout.
Когда: Создать строку без подстановки команды и удаления конечных LF.
Пример:
printf -v label 'item-%03d' 7; printf '%s\n' "$label"
Результат: label станет item-007.

%b
Интерпретировать escape-последовательности в данных.
Когда: Только когда данные намеренно задают \n, \t и подобные записи.
Пример:
printf '%b' 'a\nb\n'
Результат: Выведет две строки. Для буквального текста вместо этого нужен %s.

Проценты в пользовательском тексте меняют вывод
Текст ошибочно передан как формат.
Пишите printf '%s\n' "$value", а не printf "$value".

ps
Показывает снимок сведений о процессах. Утилита procps имеет несколько семейств синтаксиса параметров; не смешивайте их без понимания.
Синтаксис: ps [ПАРАМЕТРЫ]

-p PID
Выбрать заданные номера.
Когда: Изучить известный собственный процесс.
Пример:
ps -p "$worker_pid" -o pid,ppid,stat,args
Результат: Покажет PID, родителя, состояние и командную строку на момент наблюдения.

-o СПИСОК
Задать поля вывода.
Когда: Получить нужную информацию вместо случайного оформления.
Пример:
ps -p "$$" -o pid=,ppid=,stat=,args=
Результат: Знаки = убирают заголовки выбранных столбцов.

-e
Выбрать все видимые процессы.
Когда: Общий обзор доступного пространства процессов.
Пример:
ps -e -o pid,ppid,stat,comm
Результат: Не является вечной таблицей: процессы могут измениться сразу после снимка.

Найденный по имени PID оказался не тем
Имена совпадают, PID повторно используется, а вывод является снимком.
Для детей сохраняйте $!, для служб используйте менеджер. Не превращайте случайный поиск по имени в сигнал.

psql
Клиент PostgreSQL: подключается к выбранной базе, отправляет SQL и обрабатывает свои обратные команды. Не является самим сервером; файл SQL и база подключения имеют разное назначение.
Синтаксис: psql [ПАРАМЕТРЫ] [БАЗА [РОЛЬ]]

-X
Не читать пользовательский файл запуска psql.
Когда: Повторяемый опыт не должен зависеть от настроек ~/.psqlrc.
Пример:
psql -X -d book
Результат: Откроет клиент выбранной базы без пользовательских команд запуска; само соединение всё равно требует доступного сервера и прав.

-d БАЗА_ИЛИ_CONNINFO
Выбрать базу; аргумент может быть строкой подключения libpq.
Когда: Явно задать имя базы и путь к учебному Unix-сокету.
Пример:
psql -X -d "host=/tmp/book-socket port=55432 dbname=book"
Результат: Подключится к базе book указанного сервера; это не путь к SQL-файлу и не создание базы.

-f ФАЙЛ
Выполнить команды из файла, затем завершиться.
Когда: Прочитать учебный SQL или восстановить текстовый дамп.
Пример:
psql -X -v ON_ERROR_STOP=1 -d book_restore -f backup.sql
Результат: Читает backup.sql, посылает SQL в book_restore. Файл не становится каталогом данных; ошибки видны в диагностике.

-v ON_ERROR_STOP=1
Задать переменную psql, останавливающую сценарий при ошибке.
Когда: Не получить незаметно частично выполненный набор команд.
Пример:
psql -X -v ON_ERROR_STOP=1 -d book -f check.sql
Результат: При ошибке сценария клиент прервёт обработку и вернёт соответствующий ненулевой код; это не автоматическая общая транзакция всех команд.

-h УЗЕЛ_ИЛИ_КАТАЛОГ
Выбрать TCP-узел либо каталог Unix-сокета сервера.
Когда: Явно подключиться к отдельному кластеру.
Пример:
psql -X -h /tmp/pgbook-example/socket -p 55432 -U book_admin -d book
Результат: Путь выбирает Unix-сокет; 127.0.0.1 выбрал бы TCP и потенциально другое правило HBA. Это адрес сервера, а не имя базы.

-p ПОРТ
Выбрать порт сервера; при Unix-сокете — номер в имени файла сокета.
Когда: Различить два кластера на одной машине.
Пример:
psql -X -h /tmp/pgbook-example/socket -p 55432 -d book
Результат: Ищет сервер с номером 55432 по выбранному способу соединения. Порт HTTP-приложения сюда не подходит.

-U РОЛЬ
Заявить роль PostgreSQL для входа.
Когда: Проверить работу под прикладными правами, а не случайной ролью по умолчанию.
Пример:
psql -X -h /tmp/pgbook-example/socket -p 55432 -U book_admin -d book
Результат: Сервер проверяет вход и права book_admin. Это роль базы, которая не обязана совпадать с пользователем ОС; флаг не выдаёт ей привилегии.

-c КОМАНДА
Выполнить строку SQL либо одну обратную команду psql, затем продолжить предусмотренный цикл параметров или завершиться.
Когда: Получить небольшой результат без интерактивного ввода.
Пример:
psql -X -d book -c "SHOW server_version;"
Результат: Отправит SHOW и выведет ответ. SQL и обратные команды psql нельзя произвольно смешивать внутри одного аргумента -c.

-A
Выводить таблицу без выравнивания пробелами.
Когда: Считать простое скалярное значение или подготовить машинный вывод.
Пример:
psql -X -A -t -d book -c "SELECT 1;"
Результат: stdout содержит 1 и завершающий перевод строки. Для нескольких полей обычный разделитель — |; это не автоматическое CSV-экранирование.

-t
Убрать заголовки столбцов и завершающую сводку числа строк.
Когда: В stdout нужны только значения результата.
Пример:
psql -X -A -t -d book -c "SELECT 1;"
Результат: Получится строка значения без имени столбца и подписи (1 row). Ошибки всё равно требуют проверки кода завершения.

-F РАЗДЕЛИТЕЛЬ
Выбрать разделитель полей невыравненного вывода.
Когда: Поля результата при -A нужны через запятую или другой знак.
Пример:
psql -A -t -F , -d book -c "SELECT id,title FROM documents ORDER BY id;"
Результат: Столбцы разделены запятой; значения с запятыми не получают автоматического CSV-экранирования. Для настоящего CSV используется отдельный режим psql, не эта комбинация.

-x
Выводить каждую запись вертикально: по одному имени столбца и значению на строку.
Когда: В строке много или очень широкие поля.
Пример:
psql -x -d book -c "SELECT * FROM documents WHERE id=1;"
Результат: Те же значения видны списком полей; запрос и данные таблицы не меняются.

psql --version совпадает, сервер ведёт себя иначе
Версия клиента не определяет версию подключённого сервера.
Выполните SELECT version() или SHOW server_version; проверьте адрес, порт и имя базы.

pwd
Показывает текущий каталог оболочки. Он не обязан совпадать с каталогом файла сценария.
Синтаксис: pwd [-L|-P]

-L
Показать логический путь с сохранением пройденных ссылок по правилам Bash.
Когда: Увидеть представление каталога оболочки.
Пример:
pwd -L
Результат: Путь может содержать имя символической ссылки.

-P
Показать физический путь без символических ссылок в компонентах каталога.
Когда: Получить расположение каталога-цели.
Пример:
pwd -P
Результат: Раскроются ссылки каталога; ссылка на сам файл сценария этим не разрешается.

python3
Запускает Python 3 для файла, текста программы или модуля. Переданный код разбирается уже по правилам Python.
Синтаксис: python3 [ПАРАМЕТРЫ] [ФАЙЛ|-c КОД|-m МОДУЛЬ|-] [АРГУМЕНТЫ...]

-c КОД
Исполнить программу из одного аргумента.
Когда: Наблюдать точные границы argv.
Пример:
python3 -c 'import sys; print(repr(sys.argv))' 'two words' ''
Результат: Будут видны отдельный аргумент с пробелом и отдельная пустая строка.

-m МОДУЛЬ
Найти модуль импортом и исполнить его как программу.
Когда: Использовать интерфейс установленного модуля.
Пример:
python3 -m json.tool input.json
Результат: При корректном JSON появится отформатированное представление.

-u
Отключить обычную буферизацию stdout/stderr Python.
Когда: Уменьшить задержку сообщений в конвейере.
Пример:
python3 -u worker.py
Результат: Записи не ждут обычного заполнения буфера Python; буферы следующей программы остаются отдельными.

-B
Не записывать .pyc при импортах.
Когда: Не оставлять новые кеши байткода в автономном комплекте.
Пример:
python3 -B linux_labs.py 01
Результат: Лаборатория выполнится без обычной записи новых .pyc её импортов.

read
Читает запись из ввода и присваивает поля переменным. На её поведение влияют IFS, обратные черты и разделитель записи.
Синтаксис: read [ПАРАМЕТРЫ] [ИМЕНА...]

-r
Не считать обратную черту экранированием.
Когда: Почти всегда при буквальном чтении пути или текста.
Пример:
IFS= read -r line <input.txt
Результат: Обратные черты внутри строки сохранятся.

-d ''
Использовать NUL как разделитель записи.
Когда: Читать имена из find -print0 без потери LF внутри имени.
Пример:
while IFS= read -r -d '' f; do printf '%q\n' "$f"; done <names.bin
Результат: Каждое нулём завершённое имя читается целиком; ноль в переменную не входит.

-u FD
Читать из выбранного дескриптора.
Когда: Отделить данные от общего stdin цикла.
Пример:
exec 3<input.txt; IFS= read -r -u 3 line; exec 3<&-
Результат: Строка взята через FD 3, а не через 0.

-t СЕКУНДЫ
Ограничить ожидание при подходящем источнике ввода.
Когда: Не ждать терминал или канал бесконечно.
Пример:
if IFS= read -r -t 2 line; then printf '%s\n' "$line"; fi
Результат: Ветка выполняется при успешном чтении; таймаут требует отдельной обработки статуса.

-a МАССИВ
Разделить прочитанную запись на элементы массива по IFS, начиная с нуля.
Когда: Простой формат действительно задаёт поля, а не произвольные строки.
Пример:
IFS=: read -r -a fields <<< 'a:b:c'; printf '%s\n' "${fields[@]}"
Результат: Получатся три элемента. Это не CSV-парсер; граничные пустые поля требуют проверки.

-d СИМВОЛ
Завершать запись на первом символе аргумента разделителя вместо LF.
Когда: У формата известен однозначный разделитель.
Пример:
IFS= read -r -d ':' value <<< 'alpha:beta'; printf '%s' "$value"
Результат: Прочитает alpha. Пустой аргумент -d отдельно означает NUL.

-n N
Остановиться после N символов, но раньше на разделителе.
Когда: Прочитать короткий ответ либо часть записи.
Пример:
IFS= read -r -n 3 value <<< 'abcdef'; printf '%s' "$value"
Результат: Значение abc. При UTF-8 число символов не тождественно числу байтов.

-N N
Читать ровно N символов, не завершаясь по обычному разделителю, кроме EOF/таймаута.
Когда: Нужен фиксированный символьный фрагмент, не произвольные двоичные данные.
Пример:
IFS= read -r -N 3 value < <(printf 'a\nb'); printf '%q' "$value"
Результат: В value три символа a, LF, b. Bash всё равно не хранит внутренний NUL.

-p ТЕКСТ
Показать приглашение без LF, если ввод из терминала.
Когда: Явный интерактивный вопрос.
Пример:
IFS= read -r -p 'Имя: ' name
Результат: При терминальном вводе покажет приглашение и прочитает строку. В автоматизации терминала может не быть.

-s
Не отображать набираемые символы, если stdin является терминалом.
Когда: Предусмотренный интерактивный ввод чувствительного значения.
Пример:
IFS= read -r -s -p 'Пароль: ' secret; printf '\n' >&2
Результат: Клавиши не отображаются терминалом; это не шифрование переменной и не защита последующей трассировки.

-e
Читать ввод с редактированием через Readline, если стандартный ввод подключён к терминалу. Readline — библиотека редактирования командной строки: курсор, удаление символов и привычные клавиши редактирования.
Когда: Человек вводит длинный ответ, который удобно исправлять до нажатия Enter.
Пример:
IFS= read -r -e -p 'Каталог: ' directory
Результат: Пользователь редактирует строку в терминале; после Enter ответ попадает в directory без завершающего LF. При чтении обычного файла интерактивное редактирование не включается.

-i ТЕКСТ
Поместить ТЕКСТ в редактируемую строку до начала ввода. Этот параметр действует при работе Readline, обычно вместе с -e.
Когда: Предложить значение по умолчанию, которое человек сможет изменить.
Пример:
IFS= read -r -e -i '/srv/data' -p 'Каталог: ' directory
Результат: После приглашения уже видно /srv/data. Если нажать Enter без правок, directory получит /srv/data; если отредактировать — итоговую строку. -i не читает файл и не заменяет включение -e.

-t 0
Проверить готовность ввода немедленно, не считывая данные.
Когда: Опросить доступность на поддерживаемом источнике.
Пример:
if read -t 0; then printf 'ввод доступен или достигнут EOF\n'; fi
Результат: Статус не доказывает наличие полной полезной записи; EOF и следующий реальный read требуют обработки.

Последняя строка без LF исчезла
Read возвращает отказ при EOF, даже если прочитала остаток.
Для обычного текстового файла используйте условие read ... || [[ -n $line ]], если незавершённая строка допустима.

-t не ограничил чтение обычного файла
В Bash таймаут относится к терминалу, pipe и другим подходящим специальным файлам; на обычном файле он не действует так же.
Ограничение всей операции проектируйте отдельно. Таймаут read не является общим таймаутом обработки.

Комбинация IFS= read -r означает три вещи
IFS= сохраняет краевые пробелы, read читает запись, -r сохраняет обратную черту.
Добавьте -d '' только для нулевого протокола. Не считайте стандартное read побайтовым копированием.

При таймауте переменная уже непустая
Bash может сохранить частично прочитанные символы и вернуть статус больше 128.
Оценивайте статус до использования: частичные данные не равны полной записи.

Один Bash понимает -N, другой инструмент read — нет
Это встроенная команда конкретной оболочки. POSIX-основа и Bash-возможности различаются.
Запускайте книгу Bash нужной версии; не проверяйте её флаги через произвольный /bin/sh.

readlink
Показывает текст ссылки либо разрешает путь с выбранными требованиями к существованию компонентов.
Синтаксис: readlink [ПАРАМЕТРЫ] ПУТЬ...

без параметров
Базовая форма: прочитать сохранённый текст ссылки.
Когда: Осмотреть ссылку пространства имён.
Пример:
readlink /proc/self/ns/net
Результат: Появится представление цели; обычная относительная ссылка не обязана стать абсолютной.

-f
Разрешить ссылки; все компоненты, кроме последнего, должны существовать.
Когда: Получить канонический путь с допустимым отсутствующим последним именем.
Пример:
readlink -f -- ./current/config.txt
Результат: При допустимом пути появится абсолютная форма с раскрытыми ссылками.

-e
Требовать существования всех компонентов.
Когда: Разрешить существующую конечную цель.
Пример:
readlink -e -- ./current/config.txt
Результат: Будет путь при успехе; последующая операция всё равно может увидеть изменение дерева.

readonly
Помечает переменную или функцию как доступную только для чтения в текущей области. После этого запрещены обычные изменения и удаление этой привязки. Это атрибут самой Bash, а не права доступа к файлу. Установленную метку readonly нельзя просто снять обратным флагом в той же привязке.
Синтаксис: readonly [ПАРАМЕТРЫ] [ИМЯ[=ЗНАЧЕНИЕ] ...]

ИМЯ[=ЗНАЧЕНИЕ]
При необходимости присвоить значение и запретить дальнейшее изменение выбранной переменной. Без значения существующее значение сохраняется.
Когда: Проверенная настройка не должна случайно поменяться в дальнейшем коде.
Пример:
bash -c 'readonly lesson_mode=check; printf "%s\n" "$lesson_mode"'
Результат: Печатает check. Последующее lesson_mode=other и unset lesson_mode будут отклонены; в неинтерактивной Bash ошибка присваивания readonly-переменной может также прекратить сценарий.

-p
Показать объявления переменных, отмеченных readonly. Это просмотр, а не установка атрибута всем переменным.
Когда: При отладке требуется увидеть, какие значения уже нельзя менять.
Пример:
bash -c 'readonly lesson_mode=check; readonly -p | grep "lesson_mode"'
Результат: Показывает объявление lesson_mode с меткой -r и значением check. Вывод включает значения, поэтому его содержимое следует учитывать при журналировании.

-f ИМЯ...
Пометить определения функций как доступные только для чтения: их нельзя переопределить или удалить обычным unset -f.
Когда: Зафиксировать определение известной функции в текущей оболочке.
Пример:
bash -c 'demo() { printf "%s\n" ok; }; readonly -f demo; demo'
Результат: Печатает ok. Защищено определение demo; значения переменных, к которым функция обращается, от этого автоматически не становятся readonly.

return
Заканчивает текущий вызов функции Bash или выполнение файла, подключённого через source/точку. Возвращает статус в вызывающий код и обычно не завершает всю оболочку. Это управление областью выполнения; return не передаёт произвольную строку как результат функции. Текст возвращают через stdout или согласованную переменную.
Синтаксис: return [КОД]

КОД
Прервать функцию или подключённый файл и вернуть указанный статус. Это аргумент управления, а не флаг.
Когда: Сообщить вызывающему коду об успехе или конкретном отказе, не останавливая его оболочку.
Пример:
bash -c 'f() { return 7; printf BAD; }; f; status=$?; printf "%s\n" "$status"'
Результат: BAD не печатается; после возврата вызывающий код печатает 7. Числовой статус ограничен одним байтом, как статус exit; он не заменяет вывод данных.

без аргумента
Вернуть статус последней команды, выполненной внутри функции или подключённого файла.
Когда: Результат последней операции должен стать результатом всей функции.
Пример:
bash -c 'f() { false; return; }; f; printf "%s\n" "$?"'
Результат: Печатает 1. Вне функции и вне подключённого файла return выдаёт диагностику и ненулевой статус; для обычного отдельного сценария нужен exit. Если у функции нет return, её обычный итоговый статус также определяется последней выполненной командой.

rm
Удаляет имена. Открытый файл может оставаться доступным по дескриптору после удаления последнего имени.
Синтаксис: rm [ПАРАМЕТРЫ] ФАЙЛ...

-i
Спрашивать подтверждение каждого удаления.
Когда: Вручную проверить конкретное имя.
Пример:
rm -i -- temporary.txt
Результат: Утвердительный ответ разрешает удаление; отрицательный сохраняет имя.

-r
Рекурсивно удалить каталог с содержимым.
Когда: Удалить своё определённое рабочее дерево.
Пример:
rm -r -- ./own-temporary-work
Результат: Удаляются имена внутри указанного дерева по текущему разрешению пути.

-f
Не спрашивать; не считать отсутствие указанных имён ошибкой.
Когда: Очистить собственный необязательный временный файл.
Пример:
rm -f -- "$pending"
Результат: Отсутствие допустимо; реальные ошибки прав или хранения всё равно могут дать отказ.

--
Закончить разбор опций.
Когда: Передать имя с начальным дефисом.
Пример:
rm -- -temporary.txt
Результат: Имя не будет разобрано как флаги.

sed
Потоковый редактор: читает записи и выполняет заданную программу преобразования. Программа sed и текст Bash — разные языки. Параметры -i, -z, -s и --follow-symlinks ниже описаны для GNU sed.
Синтаксис: sed [ПАРАМЕТРЫ] ПРОГРАММА [ФАЙЛЫ...]

-n
Отключить автоматическую печать каждой строки.
Когда: Печатать только выбранные адресами строки.
Пример:
sed -n '2,4p' input.txt
Результат: Выведет строки со второй по четвёртую.

-E
Использовать расширенные регулярные выражения.
Когда: Сделать группы и повторения выразительнее.
Пример:
printf 'x123\n' | sed -E 's/[0-9]+/NUM/'
Результат: Получится xNUM.

-e ПРОГРАММА
Добавить отдельную программу команд.
Когда: Применить несколько понятных преобразований.
Пример:
printf 'red blue\n' | sed -e 's/red/R/' -e 's/blue/B/'
Результат: Получится R B.

s/ОБРАЗЕЦ/ЗАМЕНА/g
Заменять все совпадения в строке вместо первого.
Когда: Преобразовать все повторения контролируемого образца.
Пример:
printf 'a a\n' | sed 's/a/b/g'
Результат: Получится b b. Амперсанд и обратная черта в замене имеют свой смысл.

-f ФАЙЛ
Читать программу sed из отдельного файла.
Когда: Несколько команд не помещаются в понятную строку.
Пример:
sed -f clean.sed input.txt
Результат: Данные читает из input.txt, команды — из clean.sed. Это разные файлы с разными ролями.

-i[СУФФИКС]
В GNU sed заменить файл результатом через временную запись; суффикс создаёт резервное имя.
Когда: Осознанное изменение собственных файлов после просмотра результата.
Пример:
sed -i.bak 's/old/new/g' ./sample.txt
Результат: sample.txt заменён, прежняя версия сохранена как sample.txt.bak. Это действие, не просмотр.

-s
Считать входные файлы раздельными потоками в GNU sed.
Когда: Нумерация и $ должны относиться к каждому файлу отдельно.
Пример:
sed -s -n '$p' a.txt b.txt
Результат: Выведет последнюю строку каждого файла. Без -s адреса обычно относятся к общему входу.

-z
Использовать NUL-разделённые записи в GNU sed.
Когда: Преобразовать контролируемые нулевые записи.
Пример:
printf 'old\0old\0' | sed -z 's/old/new/g'
Результат: Получатся new NUL new NUL; внутренние LF не завершают запись.

--follow-symlinks
С -i в GNU sed изменять конечную цель ссылки.
Когда: Это действительно выбранная политика редактирования.
Пример:
sed --follow-symlinks -i.bak 's/old/new/g' ./link.txt
Результат: Сохраняется роль ссылки, меняется цель. Без этой опции -i обычно заменяет саму запись ссылки обычным файлом.

-u
Уменьшить буферизацию чтения и вывода GNU sed.
Когда: Показать потоковые изменения с меньшей задержкой.
Пример:
producer | sed -u 's/old/new/g'
Результат: Sed старается выдавать результат раньше; это не управляет буфером producer.

АДРЕС d
Удалить выбранные строки из выходного потока.
Когда: Отфильтровать известные технические записи без изменения файла.
Пример:
printf 'keep\nDEBUG skip\n' | sed '/^DEBUG/d'
Результат: Выведет keep. Без -i исходный файл не редактируется.

s/ОБРАЗЕЦ/ЗАМЕНА/p
Печатать строку при успешной замене.
Когда: С -n выдавать только изменённые строки.
Пример:
printf 'old\nkeep\n' | sed -n 's/old/new/p'
Результат: Выведет new. Без -n автоматически печатаемые строки могут дублировать результат p.

s/ОБРАЗЕЦ/ЗАМЕНА/2
Заменять только второе совпадение в строке.
Когда: Нужна конкретная позиция повторения.
Пример:
printf 'a a a\n' | sed 's/a/b/2'
Результат: Получится a b a. Сочетание числового флага с g имеет правила реализации, не заменяйте его догадкой.

Произвольная строка сломала замену
Разделитель, &, обратная черта и образец имеют специальные правила sed.
Не вклеивайте произвольные данные в программу. Выберите обработчик с отдельными строковыми аргументами.

-i с -n неожиданно очистили файл
-n выключает обычную печать, а -i публикует оставшийся выход. Без явного p поток может быть пустым.
Сначала проверьте sed без -i. Для изменения выберите резервную копию и проверяемую публикацию; не запускайте sed -ni вслепую.

sed -iE и sed -Ei дают разное
У GNU sed -i принимает необязательный суффикс. В -iE буква E — суффикс резервной копии; в -Ei это -E и -i.
Пишите раздельно -E -i.bak, когда нужна ясность. Синтаксис -i отличается у GNU и BSD sed.

Знак & в замене стал старым текстом
В replacement-части & обозначает всё совпадение; обратные черты и разделитель тоже специальны.
Для произвольных значений лучше отдельный обработчик с прямой строковой заменой, а не вклейка в программу sed.

Короткий -r встречается в старой инструкции
В GNU sed -r — имя расширенных регулярных выражений, как -E; переносимость конкретной системы проверяется.
В новом понятном примере предпочитайте -E и указывайте проверенную реализацию.

set
Управляет параметрами оболочки и позиционными параметрами. Опции -e, -u и pipefail решают разные задачи и не создают универсальную транзакцию.
Синтаксис: set [ПАРАМЕТРЫ] [-- АРГУМЕНТЫ...]

-e
Завершаться при некоторых неуспешных командах с контекстными исключениями.
Когда: Дополнительное обнаружение необработанных отказов после понимания правил.
Пример:
bash -c 'set -e; false; printf BAD'
Результат: BAD не печатается. В if и проверяемой функции поведение другое.

-u
Сообщать о некоторых обращениях к незаданным параметрам.
Когда: Обнаруживать опечатки при явном договоре необязательных значений.
Пример:
bash -c 'set -u; printf %s "${optional-}"'
Результат: Допустимое отсутствие обработано через ${optional-}.

-o pipefail
Общий статус конвейера — крайний справа ненулевой или ноль.
Когда: Не скрывать отказ значимой ранней стадии.
Пример:
bash -c 'set -o pipefail; false | true'; printf '%s\n' "$?"
Результат: Покажет 1. Намеренный SIGPIPE требует отдельной политики.

-x
Включить трассировку: Bash печатает выполняемые команды и аргументы после раскрытий в stderr, обычно с префиксом PS4, равным «+ ».
Когда: Увидеть порядок выполнения и результат раскрытия переменных на данных без секретов.
Пример:
bash -c 'set -x; value=hello; printf "%s\n" "$value"'
Результат: В stdout появится hello, а в stderr — трасса присваивания и printf с раскрытым hello. Трасса может показать секреты и не является побайтовой записью argv.

+x
Выключить трассировку выполняемых команд. Уже напечатанные диагностические строки не исчезают.
Когда: Закончился исследуемый участок, дальнейшие значения не должны попадать в трассу.
Пример:
bash -c 'set -x; printf "%s\n" traced; set +x; printf "%s\n" plain'
Результат: В stdout будут traced и plain. В stderr видны первая printf и сама команда set +x; следующая printf уже не трассируется.

--
Заменить позиционные параметры следующими аргументами.
Когда: Сформировать проверенный набор $@.
Пример:
set -- 'a b' '' '*'; printf '%s\n' "$#"
Результат: Получится 3.

-E / -o errtrace
Наследовать ERR trap в функции, подстановки команд и подоболочки по правилам Bash.
Когда: Нужна диагностическая наследуемость обработчика.
Пример:
bash -c 'set -E; trap '''printf ERR >&2''' ERR; f() { false; }; f'
Результат: ERR может сработать на нескольких уровнях. Это не снимает исключения контекста if/&&/||.

-C / -o noclobber
Отклонять обычное > для существующего обычного файла по правилам Bash.
Когда: Дополнительная защита от случайного усечения.
Пример:
set -C; printf new >existing.txt
Результат: Если обычный файл существует, открытие обычно отказало. >| явно преодолевает режим; чужие программы им не защищены.

-m
Включить управление заданиями — режим monitor. Bash организует задания и группы процессов для управления запуском, остановкой и продолжением.
Когда: Исследовать управление заданиями; обычно оно уже включено в интерактивной оболочке.
Пример:
bash -c 'set -m; set -o | grep "^monitor"'
Результат: Строка monitor показывает on. Включённое управление заданиями препятствует работе lastpipe в текущей оболочке, даже если shopt -s lastpipe уже выполнен.

+m
Выключить управление заданиями — monitor становится off. Это условие для работы lastpipe, но само по себе lastpipe не включает.
Когда: В неинтерактивном учебном сценарии последняя стадия конвейера должна иметь возможность изменять переменные текущей оболочки.
Пример:
bash -c 'set +m; shopt -s lastpipe; printf "value\n" | read -r item; printf "%s\n" "$item"'
Результат: Сочетание выключенного monitor и включённого lastpipe позволяет read присвоить item в текущей оболочке; печатается value. В интерактивном сеансе +m также меняет привычное управление заданиями.

-f
Выключить раскрытие имён файлов по шаблонам *, ? и [...]. Это режим noglob. Разбиение незащищённых значений по IFS продолжает работать.
Когда: Исследовать отдельно разбиение полей и раскрытие шаблона, а не заменять необходимые кавычки.
Пример:
bash -c 'set -f; value="a *"; printf "<%s>\n" $value'
Результат: Печатает <a> и <*>: пробел всё ещё разделяет поля, но звёздочка не превращается в список имён. Вариант "$value" сохранил бы всё значение одним аргументом.

+f
Включить раскрытие имён файлов по шаблонам, выключив режим noglob. Дополнительные настройки nullglob, failglob, dotglob и другие остаются самостоятельными.
Когда: Закончился участок с намеренно отключёнными шаблонами, и требуется обычное раскрытие путей.
Пример:
bash -c 'set -f; set +f; printf "%s\n" [an]*.txt'
Результат: В каталоге учебных файлов будут выбраны подходящие names.txt, notes.txt и numbers.txt. Если совпадений нет и nullglob/failglob выключены, Bash оставляет буквальный шаблон. Плюс здесь отключает настройку noglob, а не сам glob.

-v
Печатать исходные строки оболочки в stderr по мере их чтения, до раскрытия переменных. Это режим verbose; он отличается от трассировки -x.
Когда: Увидеть, какой исходный текст читает Bash, и сравнить его с выполняемыми после раскрытий командами.
Пример:
bash -c 'set -v
value=hello
printf "%s\n" "$value"'
Результат: В stderr видны читаемые value=hello и printf с буквальной записью $value. В stdout — hello. Команда set -v должна быть прочитана раньше исследуемых строк, поэтому пример содержит реальные переводы строк.

+v
Перестать печатать читаемый исходный текст в stderr. Настройка -x от этого не меняется.
Когда: Закончить участок наблюдения за чтением исходника.
Пример:
bash -v -c 'set +v
printf "%s\n" quiet'
Результат: В stderr ещё появится прочитанная строка set +v, но следующая строка printf уже не выводится как исходник. В stdout остаётся quiet. Трассировка -x, если включена отдельно, продолжила бы работать.

-a
Автоматически помечать создаваемые или изменяемые переменные для экспорта в окружение будущих дочерних процессов. Это режим allexport.
Когда: На контролируемом участке подготовить набор скалярных переменных окружения.
Пример:
bash -c 'set -a; lesson_mode=check; set +a; env | grep "^lesson_mode="'
Результат: Будет lesson_mode=check: присваивание при -a поставило метку export. Это влияет на окружение запускаемых программ; случайно изменённые переменные тоже могут получить метку.

+a
Прекратить автоматическую установку метки export на последующих присваиваниях. Уже установленные метки у переменных сохраняются.
Когда: Завершить подготовку окружения, чтобы новые внутренние переменные не передавались потомкам автоматически.
Пример:
bash -c 'unset first second; set -a; first=yes; set +a; second=no; env | grep -E "^(first|second)="'
Результат: Вывод содержит first=yes, но не second=no. +a не отменяет экспорт first; чтобы снять конкретную метку, используют export -n first.

-o posix
Включить режим соответствия POSIX там, где Bash меняет стандартное поведение.
Когда: Исследовать совместимость, а не автоматически переписать программу.
Пример:
bash --posix -c 'shopt -q inherit_errexit; printf %s "$?"'
Результат: В Bash 5.2 inherit_errexit включён. Массивы и другой Bash-синтаксис не становятся переносимым кодом сами.

+o
Без имени настройки вывести команды set, которые восстанавливают текущее состояние параметров. С именем, например +o pipefail, выключить выбранную настройку.
Когда: Сохранить читаемое описание текущих режимов или явно отключить одну настройку.
Пример:
set +o
Результат: Печатает строки вида set -o ... и set +o ...; само перечисление режимов их не меняет. Это настройки set, а не полный список shopt. Автоматически исполнять произвольный полученный текст не требуется.

-o
Без имени настройки вывести список параметров set со значениями on/off. С именем, например -o pipefail, включить выбранную настройку.
Когда: Проверить действующие режимы или включить конкретный параметр по имени.
Пример:
set -o
Результат: Показывает, например, monitor, noglob и pipefail вместе с on/off. Команда без имени ничего не включает. Именованные -o pipefail и -o posix разобраны в отдельных карточках.

-P
Использовать физическую структуру при cd вместо логической цепочки ссылок.
Когда: Весь участок навигации должен следовать физическим каталогам.
Пример:
set -P; cd -- "$directory"; pwd
Результат: Вывод отражает выбранный физический режим. Критичный cd всё равно проверяется отдельно.

Функция с -e продолжила после false
Её вызов стоял в проверяемом контексте if/&&/||.
Проверяйте важные операции внутри функции явно; не полагайтесь на один строгий режим.

set -euo pipefail выглядит как один параметр
-e и -u — отдельные опции, а -o принимает имя pipefail. Договоры этих трёх настроек независимы.
Разберите каждый режим. Проверяйте критичные действия явно и не называйте сочетание универсальным строгим режимом.

Как выключить ранее включённую настройку?
Знак + обычно снимает соответствующий параметр, например set +e, set +x; именованный режим снимают set +o pipefail.
Не выключайте глобальное состояние библиотеки навсегда случайно. Восстановите договор вызывающего кода или изолируйте подоболочкой.

Сценарий без аргументов после set --
Set -- без следующих слов очищает позиционные параметры.
Если нужно сохранить исходный список, заранее сделайте original=("$@"); не заменяйте массив склеенной строкой.

Версии Bash по-разному ведут -u и пустые массивы
Особенности пустых массивов и отдельных раскрытий исправлялись между выпусками; поведение Bash 5.2 нельзя обещать всем Bash 4.x.
На целевом образе выполните пограничные опыты книги; не переносите конкретное исправление на весь ряд версий без проверки.

shift
Сдвигает позиционные параметры текущего контекста: удаляет начальные аргументы из $1, $2 и далее, уменьшает $# и перенумеровывает оставшиеся. $0 не меняется. Внутри функции изменяются аргументы этого вызова функции; после её возврата позиционные параметры вызывающего кода восстанавливаются.
Синтаксис: shift [N]

без аргумента
Удалить один начальный позиционный параметр. Прежний $2 становится $1.
Когда: Обработчик разобрал текущий аргумент и переходит к следующему.
Пример:
bash -c 'set -- alpha beta gamma; shift; printf "%s/%s\n" "$#" "$1"'
Результат: Печатает 2/beta. При исходном $#=0 сдвиг на один невозможен: shift возвращает ненулевой статус, поэтому условие цикла и количество аргументов нужно проверять.

N
Удалить N начальных аргументов за один шаг. N должен быть неотрицательным целым и не превышать $#; это числовой аргумент, а не флаг.
Когда: Пара параметр–значение уже обработана, например --output result.txt.
Пример:
bash -c 'set -- alpha beta gamma; shift 2; printf "%s/%s\n" "$#" "$1"'
Результат: Печатает 1/gamma. shift 0 ничего не удаляет и успешен. Если N больше числа аргументов или недопустим, сдвиг не выполняется и статус ненулевой.

shopt
Управляет дополнительными настройками Bash. Включение одной меняет семантику соответствующих конструкций.
Синтаксис: shopt [-s|-u|-q] ИМЯ...

-s nullglob
Удалять несовпавший шаблон имени.
Когда: Пустой набор файлов должен дать пустой массив.
Пример:
shopt -s nullglob; files=(./*.log)
Результат: При отсутствии совпадений files имеет ноль элементов.

-s lastpipe
При выключенном job control выполнять последнюю стадию в текущей среде.
Когда: Сознательно сохранить переменную последней стадии.
Пример:
set +m; shopt -s lastpipe; n=0; printf 'x\n' | read -r n; printf '%s' "$n"
Результат: Выведет x. Условие выключенного управления заданиями существенно.

-s inherit_errexit
Сохранять -e в подстановке команды.
Когда: Явно выбрать наследование с учётом исключений контекста.
Пример:
bash -c 'set -e; shopt -s inherit_errexit; x=$(false; printf BAD)'
Результат: Подстановка прервётся на false в этом последовательном контексте.

-q ИМЯ
Проверить настройку статусом без обычного вывода.
Когда: Не менять состояние при диагностике.
Пример:
if shopt -q nullglob; then printf enabled; fi
Результат: Печатает enabled только при включённой настройке.

-u ИМЯ
Выключить настройку shopt.
Когда: Восстановить ранее выбранное состояние.
Пример:
shopt -u nullglob
Результат: Несовпавший glob снова обычно остаётся буквальным словом. Это не команда удаления файлов.

-p [ИМЯ...]
Показать настройки в форме команд shopt.
Когда: Изучить включённое состояние и способ его восстановления.
Пример:
shopt -p nullglob failglob lastpipe
Результат: Покажет shopt -s/-u. Если проверяемая настройка выключена, общий статус может быть ненулевым; учитывайте -e.

-s failglob
Ошибка раскрытия при отсутствии совпадения шаблона.
Когда: Несуществующий набор — ошибка, а не пустой список.
Пример:
shopt -s failglob; printf '%s\n' ./missing*.xyz
Результат: При отсутствии совпадений printf не запускается; это ошибка подготовки слова.

-s dotglob
Разрешить обычным шаблонам выбирать скрытые имена с начальной точкой по правилам Bash.
Когда: Нужны скрытые записи в контролируемом наборе.
Пример:
shopt -s dotglob nullglob; files=(./*)
Результат: Скрытые имена могут попасть в массив. Правила . и .. отдельно зависят от версии/других настроек.

-s globstar
Включить рекурсивный смысл ** в шаблонах Bash.
Когда: Обойти известное дерево шаблоном в Bash 4+.
Пример:
shopt -s globstar nullglob; files=(./data/**/*.log)
Результат: Выберет .log на разных уровнях. Это не find с полноценной обработкой ошибок обхода.

-s nocaseglob
Не учитывать регистр при раскрытии имён.
Когда: Маска должна охватывать .LOG и .log.
Пример:
shopt -s nocaseglob nullglob; files=(./*.log)
Результат: Меняется выбор имён, а не регистр сохранённых строк.

-s nocasematch
Не учитывать регистр в case и [[-сопоставлениях по правилам Bash.
Когда: Управляемая нечувствительная к регистру классификация.
Пример:
shopt -s nocasematch; [[ READY == ready ]]; printf '%s' "$?"
Результат: Выведет 0. Эта настройка не заменяет nocaseglob для перечисления файлов.

-s extglob
Включить расширенные шаблоны ?, *, +, @, ! перед группой вариантов.
Когда: Нужен более выразительный шаблон Bash.
Пример:
bash -O extglob -c '[[ alpha == @(alpha|beta) ]]; printf %s "$?"'
Результат: Выведет 0. Для конструкций, влияющих на разбор, режим должен быть включён до чтения соответствующего кода.

-s expand_aliases
Включить раскрытие псевдонимов в подходящих контекстах.
Когда: Изучение alias в неинтерактивной Bash, где обычно выключено.
Пример:
shopt -s expand_aliases
alias hello='printf ready'
hello
Результат: Определение и использование должны быть прочитаны в нужные моменты; для сценария функция часто яснее.

-s globskipdots
В Bash 5.2 не допускать . и .. в результатах раскрытия имён.
Когда: Разобрать правила специальной пары точек.
Пример:
shopt -q globskipdots; printf '%s' "$?"
Результат: В обычной Bash 5.2 вернёт 0. На более старой версии такой настройки может не быть.

-s globasciiranges
Трактовать диапазоны шаблона как в C-локали.
Когда: Нужен технический диапазон [a-z], а не локальный порядок.
Пример:
shopt -s globasciiranges
Результат: Меняет диапазоны шаблонов Bash. Не является общим переключением кодировки всех программ.

-s varredir_close
Автоматически закрывать выделенные {var}-дескрипторы после команды в предусмотренных формах.
Когда: Осознанное управление сроком жизни временного перенаправления.
Пример:
shopt -s varredir_close; printf data {fd}>extra.txt
Результат: Опция влияет на выделение {fd}; долгоживущий exec-дескриптор требует понимания отдельного срока жизни.

Одинаковый сценарий по-разному считает строки
Различаются lastpipe и управление заданиями.
Закрепите настройки либо используйте ясное перенаправление ввода без зависимости от lastpipe.

Shopt неизвестна в /bin/sh
Это встроенная команда Bash. Переносимый POSIX shell не обязан поддерживать её.
Укажите Bash и нужную версию; при переносе алгоритм проверяется заново.

Lastpipe работает дома, не работает в окне объекта
Настройка действует при выключенном управлении заданиями и имеет ограничения по позиции/фону.
Проверьте set -o monitor и shopt -q lastpipe. Лучше выберите входное перенаправление, если не хотите зависеть от режима.

Старый Bash не знает lastpipe или inherit_errexit
Lastpipe доступна начиная с Bash 4.2, inherit_errexit — с Bash 4.4; globstar появился в Bash 4.0.
Зафиксируйте минимальную версию и проверьте фактическую реализацию. Globskipdots относится к Bash 5.2.

Комбинация nullglob и failglob непонятна
Обе настройки меняют отсутствие совпадений; включение всего сразу не создаёт более правильного режима.
Выберите политику: пустой набор допустим — nullglob; отсутствие является ошибкой — failglob. Проверьте сочетание на целевой версии, не надейтесь на название.

sleep
Просит приостановить выполнение на интервал. После ожидания процесс ещё должен получить CPU; пауза не подтверждает готовность другого процесса.
Синтаксис: sleep ИНТЕРВАЛ [ИНТЕРВАЛ...]

ЧИСЛО
Форма интервала в секундах; GNU sleep допускает дробь.
Когда: Небольшая пауза между ограниченными проверками.
Пример:
sleep 0.05
Результат: Запрошено 0,05 секунды, фактическое продолжение может быть позднее.

s, m, h, d
Суффиксы секунд, минут, часов и суток.
Когда: Явно обозначить единицу интервала.
Пример:
sleep 2m
Результат: Запрошены две минуты; прекращение по сигналу проверяют отдельно.

sort
Сортирует записи по выбранным правилам и ключам. Порядок зависит от локали и режима сравнения.
Синтаксис: sort [ПАРАМЕТРЫ] [ФАЙЛЫ...]

-n
Сравнивать числовое представление.
Когда: Поле действительно является числом.
Пример:
printf '2\n10\n' | LC_ALL=C sort -n
Результат: Выведет 2, затем 10; обычная текстовая сортировка дала бы обратный порядок.

-k ПОЛЕ,ПОЛЕ
Задать ключ сортировки.
Когда: Сортировать таблицу по выбранному столбцу.
Пример:
sort -k2,2n input.txt
Результат: Сравнивается второе поле численно; разделители и формат должны быть известны.

-u
Выдать уникальные результаты по правилам сравнения.
Когда: Удалить повторяющиеся ключи после сортировки.
Пример:
printf 'b\na\na\n' | LC_ALL=C sort -u
Результат: Получится a, затем b.

-z
Использовать NUL вместо LF между записями.
Когда: Сортировать нулевые списки имён в GNU sort.
Пример:
LC_ALL=C sort -z names.bin >ordered.bin
Результат: Перевод строки внутри имени не разбивает запись.

-r / --reverse
Обратить результат сравнения, получив обратный порядок.
Когда: Нужны большие значения или поздние строки в начале; с -n сравнение остаётся числовым.
Пример:
sort -nr numbers.txt
Результат: Для учебных 3,10,2,3 получится 10,3,3,2. Обращение порядка не устраняет повторы; за это отвечает отдельный -u.

Порядок отличается на двух машинах
Различаются локаль, ключи или режим сравнения.
Закрепите LC_ALL и смысл ключа. Для пользовательского алфавита выберите нужную локаль.

source
Читает доверенный файл как код текущей оболочки. Это не безопасный парсер произвольной конфигурации.
Синтаксис: source ФАЙЛ [АРГУМЕНТЫ...]

./ФАЙЛ
Явно указать относительный путь.
Когда: Не зависеть от поиска файла подключения по PATH.
Пример:
source ./library.sh
Результат: Функции и изменения выполняются в текущей среде.

АРГУМЕНТЫ
Задать позиционные параметры на время чтения.
Когда: Библиотека явно принимает параметры подключения.
Пример:
source ./setup.sh 'two words'
Результат: Внутри $1 — одно значение two words.

return
В подключённом файле вернуться к вызывающему коду.
Когда: Завершить чтение библиотеки без остановки всего сеанса.
Пример:
# внутри библиотеки: return 1
Результат: Вызывающий получает ненулевой статус; exit вместо этого завершил бы оболочку.

Файл настройки выполнил команду
Source интерпретирует полноценный код, включая $(...).
Недоверенные настройки читайте настоящим парсером данных с ограниченными ключами.

ss
Исследует сокеты Linux: локальные адреса, состояния и очереди. Показывает состояние на данном компьютере, а не факт прохождения пакетов на удалённом.
Синтаксис: ss [ПАРАМЕТРЫ] [ФИЛЬТР]

-l
Оставить слушающие сокеты.
Когда: Проверить, принял ли сервер нужный адрес и порт.
Пример:
ss -ltn
Результат: Покажет TCP-слушателей; без -l обычный вывод может их не включать.

-t
Выбрать TCP-сокеты.
Когда: Отделить TCP-службу от UDP и локальных Unix-сокетов.
Пример:
ss -tn
Результат: Покажет подходящие TCP-сокеты с числовыми адресами и портами.

-n
Не заменять числа портов именами служб.
Когда: Сравнить вывод с конкретным портом из настройки или захвата.
Пример:
ss -ltn
Результат: Порт 7000 останется числом; это не отключает DNS приложения, а меняет представление утилиты.

-p
Добавить доступные сведения о процессе-владельце.
Когда: Найти программу, которая действительно слушает порт.
Пример:
ss -ltnp
Результат: При достаточных правах появятся имя процесса, PID и FD; отсутствие этих полей при малых правах не доказывает отсутствие процесса.

Send-Q и Recv-Q похожи на размер буфера
Их смысл зависит от LISTEN или установленного соединения.
Сначала прочитайте состояние; для LISTEN смотрите очередь принятия, для ESTAB — непрочитанные или неподтверждённые данные.

stat
Показывает метаданные файлового объекта. Это наблюдение, а не фиксация содержимого или защита от подмены.
Синтаксис: stat [ПАРАМЕТРЫ] -- ПУТЬ...

-c ФОРМАТ
Задать формат GNU stat.
Когда: Получить конкретные метаданные.
Пример:
stat -c 'bytes=%s mode=%a type=%F' -- "$file"
Результат: Выведет размер, числовые права и тип. Формат не одинаков с BSD stat.

-L
Следовать символической ссылке.
Когда: Нужны свойства цели вместо самой ссылки.
Пример:
stat -L -- "$file"
Результат: Исследует разрешённую цель; для оборванной ссылки возможна ошибка.

--
Закончить параметры.
Когда: Имя начинается с дефиса.
Пример:
stat -- ./-leading
Результат: Путь рассматривается как операнд.

Размер изменился между stat и чтением
Файл менялся или путь заменён.
Для согласованности нужен удержанный объект/снимок/протокол; предварительный stat не гарантирует будущие байты.

strace
Наблюдает системные вызовы и сигналы процесса. Вычисления и подстановки внутри языка не видны как отдельные вызовы ядра.
Синтаксис: strace [ПАРАМЕТРЫ] КОМАНДА [АРГУМЕНТЫ...]

-f
Следовать за создаваемыми потомками.
Когда: Увидеть внешние программы сценария.
Пример:
strace -f bash -c 'printf "%s\n" ready'
Результат: Будут события Bash и отслеженных потомков; встроенный printf может исполниться без отдельного execve.

-e trace=СПИСОК
Отобрать системные вызовы или группы.
Когда: Сузить наблюдение до файловых операций.
Пример:
strace -e trace=openat,read,close cat /etc/os-release
Результат: Трасса будет ограничена выбранными вызовами и сопутствующими событиями.

-o ФАЙЛ
Записать трассу отдельно в файл.
Когда: Не смешивать наблюдение с выводом программы.
Пример:
strace -o own-trace.txt cat /etc/os-release
Результат: Трасса окажется в own-trace.txt, содержимое файла — в stdout cat.

-T
Показать длительность вызовов.
Когда: Найти долгие ожидания на границе ядра.
Пример:
strace -T -e trace=read,write cat /etc/os-release
Результат: Появятся длительности с накладными расходами самого наблюдения.

-yy
Подробно декодировать сведения о дескрипторах.
Когда: Связать номер с файлом или сокетом.
Пример:
strace -yy -e trace=openat,read,close cat /etc/os-release
Результат: Рядом с номерами будут доступные сведения об объектах; формат зависит от версии.

sysctl
Читает и меняет параметры ядра, часто представленные в /proc/sys. Здесь показаны формы чтения без изменения настроек.
Синтаксис: sysctl [ПАРАМЕТРЫ] [КЛЮЧ...]

КЛЮЧ
Базовая форма: прочитать указанный параметр.
Когда: Проверить одно известное значение.
Пример:
sysctl vm.overcommit_memory
Результат: Появятся имя и значение при доступности ключа.

-n
Печатать значения без имён.
Когда: Получить значение для предметной проверки.
Пример:
sysctl -n vm.overcommit_memory
Результат: Будет только значение; смысл 0/1/2 задаёт договор именно этого ключа.

-a
Перечислить доступные параметры.
Когда: Осмотреть интерфейс конкретного ядра.
Пример:
sysctl -a
Результат: Вывод большой; отдельные ключи могут дать диагностику доступа.

-r ВЫРАЖЕНИЕ
Отобрать имена регулярным выражением в procps.
Когда: Ограничить обзор ветвью параметров.
Пример:
sysctl -a -r '^vm\.'
Результат: Останутся совпадающие имена vm.; значения не устанавливаются.

systemctl
Читает состояние и управляет единицами systemd. Здесь показаны только формы наблюдения за службой и её фактической конфигурацией.
Синтаксис: systemctl [ПАРАМЕТРЫ] ДЕЙСТВИЕ [ЕДИНИЦА...]

status
Действие: краткое состояние и доступные последние сообщения.
Когда: Начать расследование службы.
Пример:
systemctl status example.service --no-pager
Результат: Появятся состояние и PID; ненулевой статус может отражать неактивную единицу.

cat
Действие: показать файлы единицы и дополнения.
Когда: Найти ExecStart и drop-in.
Пример:
systemctl cat example.service
Результат: Будет конфигурационный текст, а не все вычисленные свойства менеджера.

show
Действие: показать свойства единицы у менеджера.
Когда: Прочитать эффективные значения.
Пример:
systemctl show example.service -p MainPID -p WorkingDirectory
Результат: Появятся пары свойство=значение для выбранных имён.

-p ИМЯ
Выбрать свойство для поддерживающего действия, например show.
Когда: Не просматривать весь список свойств.
Пример:
systemctl show example.service -p MainPID
Результат: Появится выбранное свойство; -p можно повторять.

--no-pager
Не запускать постраничный просмотрщик.
Когда: Получить обычный поток вывода.
Пример:
systemctl --no-pager status example.service
Результат: Вывод пойдёт непосредственно в терминал или перенаправление.

tail
Выводит конец файла или наблюдает добавление данных. Слежение по открытому объекту и по имени различается при ротации журнала.
Синтаксис: tail [ПАРАМЕТРЫ] [ФАЙЛ...]

-n ЧИСЛО
Вывести последние указанное число строк.
Когда: Прочитать недавние сообщения.
Пример:
tail -n 20 -- service.log
Результат: Появятся последние 20 строк либо весь более короткий файл.

-f
Продолжать слежение, по умолчанию за открытым описанием.
Когда: Наблюдать дописываемый файл.
Пример:
tail -f -- service.log
Результат: Новые байты будут выводиться; после rename может продолжиться чтение старого объекта.

-F
Сочетание --follow=name --retry: следить по имени и повторять попытки.
Когда: Наблюдать журнал с заменой файла при ротации.
Пример:
tail -F -- service.log
Результат: При обнаруженной замене будет открыт текущий файл по имени; это не гарантия доставки каждой записи.

tc
Исследует и настраивает очереди обработки трафика Linux. Приведённые формы show только читают состояние; скорость интерфейса и политика очереди — разные параметры.
Синтаксис: tc [ПАРАМЕТРЫ] ОБЪЕКТ КОМАНДА [АРГУМЕНТЫ]

qdisc show dev ИНТЕРФЕЙС
Показать дисциплины очередей данного интерфейса.
Когда: Установить, какой алгоритм реально обслуживает отправку.
Пример:
tc qdisc show dev enp1s0
Результат: В stdout появятся root/дочерние qdisc и их параметры; команда не включает новое ограничение скорости.

-s
Добавить статистику пакетов, байтов, потерь и очереди, где поддерживается.
Когда: Сравнить состояние до и во время нагрузки.
Пример:
tc -s qdisc show dev enp1s0
Результат: Покажет счётчики и backlog; они относятся к данному объекту, а не ко всем потерям пути.

-d
Показать дополнительные подробности объекта.
Когда: Разобрать параметры очереди вместо одного названия алгоритма.
Пример:
tc -d qdisc show dev enp1s0
Результат: Выведет доступные детали реализации; набор полей зависит от qdisc и версии iproute2.

Увеличение очереди убрало потери, но всё стало медленным
Дополнительный запас способен увеличить время ожидания под нагрузкой.
Сопоставьте backlog, скорость обслуживания и RTT; исследуйте bufferbloat и подходящую политику AQM.

tcpdump
Захватывает пакеты либо читает готовый pcap. Точка наблюдения и аппаратные оптимизации влияют на увиденное; выбор интерфейса не является проверкой всего пути.
Синтаксис: tcpdump [ПАРАМЕТРЫ] [ВЫРАЖЕНИЕ ФИЛЬТРА]

-i ИНТЕРФЕЙС
Выбрать интерфейс живого наблюдения.
Когда: Знать, с какой стороны шлюза получены пакеты.
Пример:
tcpdump -i lo -nn tcp port 7000
Результат: Печатает подходящие события loopback до остановки Ctrl+C; для захвата нужны разрешения системы.

-nn
Сохранить числовые адреса и порты.
Когда: Не тратить время на разрешение имён и сопоставить адреса с байтами.
Пример:
tcpdump -nn -r labs/document-flow-http.pcap
Результат: Прочитает локальный файл и выведет сводку без подстановки имён узлов и служб.

-r ФАЙЛ
Читать ранее сохранённый захват вместо сетевого интерфейса.
Когда: Разбирать разговор без сети и прав захвата.
Пример:
tcpdump -nn -r labs/document-flow-http.pcap
Результат: Пакеты берутся с диска; программа ничего из файла в сеть не отправляет.

-w ФАЙЛ
Записывать двоичный захват вместо обычной текстовой расшифровки.
Когда: Сохранить исходные данные для повторного анализа.
Пример:
tcpdump -i lo -nn -w loopback.pcap tcp port 7000
Результат: Создаст или перезапишет loopback.pcap; служебная сводка идёт в stderr. Остановите Ctrl+C после нужного обмена.

-s ЧИСЛО
Ограничить сохраняемую часть каждого пакета заданным числом байтов.
Когда: Нужны заголовки и тело, а короткая запись могла обрезать данные.
Пример:
tcpdump -i lo -nn -s 0 -c 50 tcp port 7000
Результат: -s 0 выбирает большое стандартное значение snaplen этой версии, а не математически бесконечный размер; в распространённых современных версиях это 262144 байта.

-c ЧИСЛО
Завершить захват или чтение после указанного числа обработанных подходящих пакетов.
Когда: Сделать ограниченную запись небольшого разговора.
Пример:
tcpdump -nn -c 10 -r labs/document-flow-http.pcap
Результат: Выведет до десяти пакетов, затем завершится; при живом захвате без подходящего трафика предел числа сам по себе не задаёт срок ожидания.

-X
Добавить дамп байтов в шестнадцатеричном виде и ASCII без канального заголовка.
Когда: Разобрать IPv4/TCP и прикладной текст одновременно.
Пример:
tcpdump -nn -X -r labs/document-flow-http.pcap
Результат: После текстовой сводки покажет байты начиная после Ethernet-заголовка в этом захвате; для дампа вместе с ним используется -XX.

-xx
Показать шестнадцатеричные байты вместе с канальным заголовком.
Когда: Сопоставить Ethernet MAC и EtherType с последующими полями IP.
Пример:
tcpdump -nn -xx -r labs/document-flow-http.pcap
Результат: Дамп включает Ethernet в данном pcap; в отличие от -X правая ASCII-колонка этой формой не запрашивается. Другой тип канала имеет иной заголовок.

-XX
Показать шестнадцатеричные байты и ASCII вместе с канальным заголовком.
Когда: Повторить полный байтовый разбор кадра из практикума.
Пример:
tcpdump -nn -XX -r labs/document-flow-http.pcap
Результат: Удобен для чтения Ethernet и текста в одном дампе. Двойная заглавная X добавляет канальный заголовок к представлению -X.

-v
Добавить подробности разбора протоколов; -vv и -vvv повышают подробность дальше.
Когда: Увидеть TTL, длины, флаги и содержимое поддерживаемых управляющих протоколов.
Пример:
tcpdump -nn -vvv -r labs/control-samples/control-packets.pcap "port 53"
Результат: Даст расширенный текстовый разбор DNS-пакетов. Не увеличивает автоматически сохранённый snaplen и не возвращает ранее обрезанные байты.

В файле нельзя найти преамбулу или FCS
Адаптер обычно не передаёт их в стандартную точку захвата.
Различайте кадр на линии и сохранённое представление; проверяйте тип канала и длину захвата.

tee
Копирует stdin в stdout и дополнительные файлы. Добавляет отдельную стадию со своими возможными ошибками.
Синтаксис: tee [ПАРАМЕТРЫ] [ФАЙЛЫ...]

-a
Добавлять к файлу вместо усечения.
Когда: Дополнить простой журнал.
Пример:
printf 'new\n' | tee -a run.log
Результат: Строка видна в stdout и добавлена в run.log.

--output-error=warn
Предупреждать об ошибках любого выхода, продолжая запись в оставшиеся доступные выходы; итоговый статус отражает ошибку.
Когда: Осознанно определить реакцию на отказ одного выхода.
Пример:
producer | tee --output-error=warn copy.log | consumer
Результат: При отказе одного выхода tee сообщает ошибку и продолжает другие. Успех consumer не скрывает нужду проверить статус tee.

--
Закончить параметры.
Когда: Путь файла не должен стать опцией.
Пример:
printf data | tee -- ./-log
Результат: Создаст или усечёт указанный файл с буквальным именем.

На экране всё было, но журнал неполный
Отказ записи отдельного выхода или непроверенный статус tee.
Оцените PIPESTATUS/pipefail и гарантию журнала; видимость stdout не доказывает сохранность файла.

test
Команда проверки, возвращающая статус. Форма [ требует отдельного последнего аргумента ]. Все аргументы строятся обычными правилами Bash.
Синтаксис: [ ВЫРАЖЕНИЕ ]  или  test ВЫРАЖЕНИЕ

-n СТРОКА
Успех при непустой строке.
Когда: Проверить наличие текста.
Пример:
value=; [ -n "$value" ]; printf '%s\n' "$?"
Результат: Вернёт 1. Без кавычек число аргументов может измениться.

-z СТРОКА
Успех при пустой строке.
Когда: Проверить явно пустое значение.
Пример:
[ -z "${value-}" ]
Результат: Успешна и для отсутствующего value, поскольку форма подстановки дала пустоту.

-f ПУТЬ
Успех для обычного файла по правилам разрешения пути.
Когда: Ранняя проверка ожидаемого типа.
Пример:
[ -f "$input" ]
Результат: Не фиксирует файл от последующей замены; реальное чтение всё равно проверяют.

ЧИСЛО -eq ЧИСЛО
Числовое равенство.
Когда: Сравнить допустимые числовые значения, не строки.
Пример:
[ 2 -eq 02 ]
Результат: Оба значения обозначают два в данном интерфейсе test; форма проверяемого ввода должна быть известна.

Пустое значение внезапно признано непустым
Незащищённая подстановка изменила набор аргументов test.
Используйте [ -n "$value" ] или осознанную конструкцию [[ ... ]].

touch
Обновляет временные метки, обычно создавая отсутствующий файл. Содержимое существующего файла не обнуляет.
Синтаксис: touch [ПАРАМЕТРЫ] ФАЙЛ...

-c
Не создавать отсутствующие файлы.
Когда: Обновить только существующий объект.
Пример:
touch -c -- report.txt
Результат: Отсутствующее имя не появится; существующий файл получит новые выбранные времена.

-r ФАЙЛ
Взять временные метки из эталона.
Когда: Согласовать времена двух файлов.
Пример:
touch -r reference.txt -- result.txt
Результат: Изменятся времена result.txt, а не содержимое.

-m
Менять только mtime из выбираемых atime/mtime.
Когда: Обновить время изменения содержимого.
Пример:
touch -m -- report.txt
Результат: mtime изменится; ctime также отражает изменение метаданных по правилам ФС.

tr
Преобразует или удаляет выбранные символы потока по правилам реализации и локали. Принимает данные из stdin.
Синтаксис: tr [ПАРАМЕТРЫ] НАБОР1 [НАБОР2]

-d
Удалить символы из набора.
Когда: Заведомо текстовый формат требует удаления выбранных байтов.
Пример:
printf 'a1b2\n' | tr -d '0-9'
Результат: Выведет ab и LF.

-s
Сжать повторы выбранного набора.
Когда: Нормализовать контролируемый текстовый разделитель.
Пример:
printf 'a   b\n' | tr -s ' '
Результат: Получится a b; значимые пробелы при этом теряются.

НАБОР1 НАБОР2
Заменить соответствующие символы.
Когда: Простое контролируемое преобразование.
Пример:
printf 'abc\n' | LC_ALL=C tr 'a-z' 'A-Z'
Результат: Выведет ABC. Не обещает полноценное преобразование всех Unicode-букв.

Удаление CR испортило двоичный файл
Tr не знает смысл формата.
Сначала подтвердите текст и кодировку; не удаляйте байты из произвольных данных.

traceroute
Посылает пробы с возрастающим TTL/Hop Limit и сопоставляет ответы промежуточных узлов. Методы и флаги относятся к реализации traceroute для Linux; наборы других систем отличаются.
Синтаксис: traceroute [ПАРАМЕТРЫ] АДРЕС

-n
Не выполнять обратное разрешение адресов узлов в имена.
Когда: Измерять маршрут без дополнительного ожидания DNS.
Пример:
traceroute -n 198.51.100.20
Результат: Покажет числовые адреса ответивших узлов и времена; звёздочка означает отсутствие ответа на пробу, а не доказанный обрыв.

-I
Использовать ICMP Echo вместо обычных UDP-проб.
Когда: Сравнить прохождение разных видов диагностического трафика.
Пример:
traceroute -n -I 198.51.100.20
Результат: Промежуточные ответы ищутся по ICMP; права и фильтрация могут отличаться от UDP-метода.

-T
Использовать TCP SYN-пробы.
Когда: Исследовать путь для выбранного TCP-порта.
Пример:
traceroute -n -T -p 443 198.51.100.20
Результат: Пробы ориентированы на TCP/443, но не выполняют полноценный HTTP-запрос или TLS-проверку.

-p ПОРТ
Задать порт с учётом выбранного метода.
Когда: Для TCP проверить порт нужной службы.
Пример:
traceroute -n -T -p 7000 198.51.100.20
Результат: В TCP-методе задаст порт назначения 7000; в обычном UDP-методе это начальный порт последовательности, поэтому трактовка зависит от метода.

Две трассировки дают разные узлы
Балансировка, тип пробы, обратный путь и политика ответов могут различаться.
Сравнивайте одинаковый метод и условия; задержка ICMP-ответа не равна времени обработки каждого пользовательского пакета.

trap
Назначает команды событиям Bash и перехватываемым сигналам. Очистка должна сохранять исходный статус и учитывать стадию операции.
Синтаксис: trap 'КОМАНДЫ' СОБЫТИЕ...

EXIT
Выполнить при завершении текущей оболочки.
Когда: Убрать собственный временный ресурс.
Пример:
tmp=$(mktemp -d) || exit; trap 'rm -rf -- "$tmp"' EXIT
Результат: Удаляется только созданный этим запуском каталог. SIGKILL и питание обходят обработчик.

ERR
Обработчик некоторых ненулевых результатов.
Когда: Дополнительная диагностика, не замена явных проверок.
Пример:
trap 'printf "status=%s\n" "$?" >&2' ERR
Результат: Печатает статус в поддерживаемых контекстах; if и другие исключения существенны.

- СОБЫТИЕ
Снять установленное действие.
Когда: Восстановить стандартную обработку или избежать рекурсивной очистки.
Пример:
trap - EXIT
Результат: Предыдущий EXIT обработчик больше не вызывается.

'' СИГНАЛ
Игнорировать сигнал в рамках правил запуска и наследования.
Когда: Только при осознанном протоколе остановки.
Пример:
trap '' HUP
Результат: Текущая оболочка игнорирует HUP; это не защита от TERM или KILL.

После очистки исчез исходный отказ
Последняя успешная команда заменила статус.
Сохраните $? первым действием и завершитесь выбранным исходным кодом; код очистки не должен врать о стадии.

true
Встроенная команда с успешным статусом 0. Не выполняет предметную проверку внешнего ресурса.
Синтаксис: true

true
Базовая форма: вернуть 0.
Когда: Явно задать успешный результат.
Пример:
true; printf "%s\n" "$?"
Результат: Будет напечатан 0; готовность службы этим не проверялась.

true && КОМАНДА
Форма списка: правый участник && выполнится после 0.
Когда: Изучить короткое замыкание.
Пример:
true && printf '%s\n' ready
Результат: Будет ready. && принадлежит Bash и не является флагом true.

type
Встроенная команда Bash показывает, как текущая оболочка разрешит имя: псевдоним, ключевое слово, функцию, встроенную или внешний файл. Она знает контекст текущей Bash.
Синтаксис: type [-aftpP] ИМЯ...

-a
Показать все подходящие варианты, включая функции/встроенные и найденные внешние пути по правилам Bash.
Когда: Есть подозрение на одноимённую функцию или старую программу в PATH.
Пример:
type -a printf
Результат: Обычно видны встроенная printf и внешние варианты; пути зависят от системы.

-t
Показать один классификатор alias, keyword, function, builtin или file.
Когда: Нужен тип разрешения, а не подробная фраза.
Пример:
type -t cd
Результат: В Bash 5.2 выведет builtin.

-p
Вывести путь внешнего файла, который был бы выполнен, либо ничего, если имя разрешается иначе.
Когда: Имя уже ожидается как внешняя команда.
Пример:
type -p bash
Результат: Обычно покажет путь Bash. Для встроенной cd вывода пути не будет.

-P
Принудительно искать внешний файл в PATH, даже при функции или встроенной с тем же именем.
Когда: Сравнить внешний исполняемый файл с внутренним разрешением.
Пример:
type -P printf
Результат: Выведет найденный путь внешней printf, если она установлена. Ничего не запускает.

-f
Не учитывать функции при разрешении.
Когда: Исследовать, что находится под обёрткой-функцией.
Пример:
type -f printf
Результат: Не выберет одноимённую функцию; остальные категории продолжают учитываться.

Which и type дали разные ответы
Внешняя which может не знать функции и псевдонимы текущей Bash.
Для вопроса о текущем исполнении используйте type -a. Для фактической версии запускайте проверенный конкретный путь.

Type нашла несколько имён — какое выполнится?
Обычное разрешение выбирает подходящую категорию и первый путь по правилам Bash; -a показывает альтернативы, не последовательный запуск.
Проверьте первый результат, PATH и функцию. Не считайте наличие новой версии где-то на диске доказательством её вызова.

umask
Показывает или меняет маску снятия начальных прав у новых файлов процесса и потомков. В Bash это встроенная команда; отдельный дочерний процесс не изменит маску родителя.
Синтаксис: umask [-p] [-S] [РЕЖИМ]

без аргумента
Показать текущую маску восьмерично.
Когда: Установить исходное состояние перед созданием файла.
Пример:
umask
Результат: Например, 0022. Значение зависит от среды; оно не является правами уже существующего файла.

0077
Установить числовую восьмеричную маску, снимающую разрешения группы и остальных.
Когда: Создавать собственные закрытые рабочие файлы.
Пример:
(umask 0077; : >private.tmp; stat -c '%a' -- private.tmp)
Результат: На обычной локальной ФС новый файл обычно получит 600; подоболочка не меняет маску родительского окна. Пример создаёт файл в текущем каталоге.

0022
Обычно снимать запись для группы и остальных.
Когда: Новые объекты должны быть читаемы другими согласно договору.
Пример:
(umask 0022; : >public.tmp; stat -c '%a' -- public.tmp)
Результат: При обычном исходном 0666 новый файл получит 644, а не исполняемые права. ACL и программа создания могут добавлять особенности.

-S
Показать разрешённые классы символически.
Когда: Увидеть, какие разрешения маска позволяет, а не только снятые биты.
Пример:
(umask 0022; umask -S)
Результат: В Bash обычно u=rwx,g=rx,o=rx. Буква x здесь не обещает x у обычного файла: программа могла не запрашивать его.

-p
Показать команду восстановления текущей маски.
Когда: Записать контролируемое исходное состояние для диагностики.
Пример:
(umask 0077; umask -p)
Результат: Напечатает umask 0077 в подходящей форме Bash.

u=...,g=...,o=...
Задать маску символической формой разрешаемых прав.
Когда: Нужен читаемый эквивалент выбранного режима.
Пример:
(umask u=rwx,g=rx,o=; umask -S)
Результат: Разрешены указанные классы; это политика для новых объектов, а не chmod существующего дерева.

Файл не стал закрытым после umask 077
Umask ограничивает создание, а существующий объект сохраняет свои права; открытие > могло лишь усечь его.
Различайте безопасное создание нового объекта и изменение атрибутов существующего. Для временного объекта используйте mktemp.

Маску вычли как обычное число
Права снимаются побитово из режима, который запросила программа, а не арифметическим вычитанием.
Для 0666 и маски 0022 получается 0644; запрос без x не получает x от маски.

Функция изменила маску всего сценария
Она выполнялась в текущей Bash; local для обычных переменных не локализует umask.
Восстановите исходное состояние или используйте подоболочку, если наружу нужны только поток и статус.

uniq
Объединяет соседние одинаковые записи. Не ищет все повторы по всему неотсортированному входу.
Синтаксис: uniq [ПАРАМЕТРЫ] [ВХОД [ВЫХОД]]

-c
Показать число соседних повторений.
Когда: Подсчитать группы после согласованной сортировки.
Пример:
printf 'a\nb\na\n' | LC_ALL=C sort | uniq -c
Результат: Покажет две a и одну b.

-d
Вывести только повторяющиеся соседние группы.
Когда: Найти дубли по полному ключу после сортировки.
Пример:
printf 'a\na\nb\n' | uniq -d
Результат: Выведет a.

-u
Вывести только группы, встреченные один раз.
Когда: Выбрать одиночные записи в подготовленном потоке.
Пример:
printf 'a\na\nb\n' | uniq -u
Результат: Выведет b.

-z
Разделять записи NUL.
Когда: Работать с именами, содержащими LF, в GNU uniq.
Пример:
sort -z names.bin | uniq -z
Результат: Сохраняет нулевой протокол.

Повтор a остался дважды
Между одинаковыми строками была другая запись.
Если исходный порядок не важен, сначала сортируйте; иначе нужен алгоритм с памятью ключей.

unset
Удаляет переменную вместе с её значением и атрибутами либо удаляет определение функции. Отсутствующая переменная отличается от заданной пустой строкой: это влияет на ${name-default}, ${name:-default} и проверки наличия. Явные -v/-f устраняют неоднозначность имени. Переменную readonly удалить нельзя.
Синтаксис: unset [-v|-f|-n] [ИМЯ...]

-v ИМЯ...
Удалить именно переменные, а не функции с совпадающими именами.
Когда: Требуется сделать параметр отсутствующим или очистить временные переменные текущей оболочки.
Пример:
bash -c 'value=; unset -v value; printf "%s\n" "${value-missing}"'
Результат: Печатает missing. До unset значение value было пустым, но переменная существовала; после unset параметр отсутствует. Кавычки вокруг имён элементов массива защищают их от раскрытия шаблонов.

-f ИМЯ...
Удалить определения функций с указанными именами. Переменные с такими именами остаются.
Когда: Временная функция больше не нужна либо нужно убрать переопределение команды в текущей оболочке.
Пример:
bash -c 'demo() { :; }; unset -f demo; declare -F demo; printf "%s\n" "$?"'
Результат: declare -F уже не находит demo, поэтому выводится статус 1. Удаление функции не меняет файлы сценариев, из которых её определение было прочитано.

-n ИМЯ...
Если имя имеет атрибут ссылки по имени, удалить саму переменную-ссылку. Без -n unset обычно действует на её цель.
Когда: Удалить вспомогательную ссылку, сохранив данные переменной, на которую она указывала.
Пример:
bash -c 'value=kept; declare -n ref=value; unset -n ref; printf "%s/%s\n" "$value" "${ref-missing}"'
Результат: Печатает kept/missing: value сохранена, ref удалена. Флаг -n здесь не означает отрицание и не совпадает по смыслу с declare -n.

wait
Ожидает собственных асинхронных детей и получает их статус. Возврат после сигнала не всегда означает завершение ребёнка. Описаны возможности Bash 5.2; версии появления отдельных флагов отмечены в случаях.
Синтаксис: wait [ПАРАМЕТРЫ] [PID...]

PID
Дождаться конкретного собственного ребёнка.
Когда: Проверить результат сохранённого $!.
Пример:
bash -c 'exit 7' & p=$!; wait "$p"; printf '%s' "$?"
Результат: Выведет 7.

-n
Дождаться одного из подходящих детей.
Когда: Организовать ограниченный пул задач на поддерживаемой версии.
Пример:
sleep 0.1 & sleep 0.2 & wait -n
Результат: Возвратит результат одного завершения, а не автоматически всех детей.

-p ИМЯ
Сохранить идентификатор завершённой задачи при подходящем режиме ожидания.
Когда: Связать wait -n с таблицей рабочих процессов.
Пример:
sleep 0.1 & wait -n -p finished; printf '%s' "$finished"
Результат: В Bash 5.2 finished указывает ожидавшееся завершение; доступность проверяется по версии.

без PID
Дождаться всех текущих асинхронных детей и вернуть ноль по этому режиму Bash.
Когда: Барьер окончания, когда отдельные результаты уже не нужны.
Пример:
sleep 0.01 & sleep 0.02 & wait
Результат: Все учтённые дети завершатся. Нулевой общий результат такого wait не доказывает успех каждого работника.

-n PID...
Дождаться одного из указанных подходящих детей.
Когда: Ограниченный пул, где важно обслужить ближайшее завершение.
Пример:
sleep 0.02 & a=$!; sleep 0.03 & b=$!; wait -n -p done "$a" "$b"
Результат: Done получает завершившийся идентификатор на Bash 5.2. Оставшихся детей требуется дождаться отдельно.

-f
При включённом job control ждать завершения, а не просто смены состояния.
Когда: Остановка SIGSTOP/SIGTSTP не должна считаться окончанием.
Пример:
# В осознанной интерактивной сессии:
wait -f "$worker_pid"
Результат: Остановленный, но живой ребёнок не удовлетворяет ожидание завершения. Это не таймаут и не сигнал.

-p ИМЯ вместе с -n
Узнать идентификатор, результат которого возвращён.
Когда: Сопоставить ближайшее завершение с входной задачей.
Пример:
sleep 0.02 & wait -n -p finished; printf '%s' "${finished-}"
Результат: Перед ожиданием переменная снимается; при отсутствии результата не читайте её без проверки, особенно с set -u.

Живой процесс есть, но wait его не принимает
Это не ребёнок данной оболочки либо результат уже не относится к её учёту.
Не используйте wait как опрос любого PID. Управляйте службой через её менеджер.

Старый Bash не знает -n или -p
Wait -n появилась в Bash 4.3; -p для идентификатора результата — в Bash 5.1.
Для более старой системы храните PID и ждите их явно. Проверяйте help wait, а не возможности другой оболочки.

Wait -n вернула 127
Может не быть неотобранных подходящих детей; неверный идентификатор тоже требует диагностики.
Ведите собственный набор активных PID и не вызывайте wait -n на пустом множестве как ожидание будущего запуска.

Перехваченный сигнал прервал wait, а ребёнок ещё жив
Bash может вернуть статус больше 128 и затем выполнить trap, не подтверждая окончания ребёнка.
Обработчик должен реализовать пересылку сигнала и нужное повторное ожидание; отправка kill сама по себе тоже не подтверждает конец.

Wait с несколькими PID скрыла ранний отказ
Итоговый статус соответствует последнему указанному идентификатору, а не логическому И всех результатов.
Для оценки всех детей выполняйте if wait "$pid" для каждого, сохраняйте ошибки и возвращайте общий выбранный итог.

wc
Подсчитывает LF, слова, байты и символы по выбранному режиму. Обычно это внешняя программа GNU Coreutils, а не встроенная команда Bash. Единицу счёта выбирают явно.
Синтаксис: wc [ПАРАМЕТРЫ] [--] [ФАЙЛЫ...]

-l
Подсчитать байты перевода строки LF.
Когда: Нужна численность завершённых строк текстового протокола.
Пример:
printf 'a\nb' | wc -l
Результат: Выведет 1. Визуальных строк две, но завершающий LF у b отсутствует.

-c
Подсчитать байты.
Когда: Измерить размер потока, файла или сетевой записи.
Пример:
printf 'Я\n' | wc -c
Результат: В UTF-8 выведет 3: два байта буквы и один LF.

-m
Подсчитать символы по текущей локали.
Когда: Сравнить символьную длину UTF-8 с байтовой.
Пример:
printf 'Я\n' | LC_ALL=C.UTF-8 wc -m
Результат: При установленной C.UTF-8 выведет 2. Это не число визуальных графем сложного Unicode-текста.

-w
Подсчитать слова по правилам разделения wc и локали.
Когда: Простая оценка текстового объёма.
Пример:
printf 'one  two\nthree\n' | wc -w
Результат: Выведет 3. Слово здесь не является аргументом Bash или полем CSV.

-L
В GNU wc показать максимальную ширину отображения строки.
Когда: Оценить ширину строк с учётом табуляций и ширины символов.
Пример:
printf 'a\tb\n' | LC_ALL=C wc -L
Результат: Выведет 9: табуляция продвигает позицию до следующего шага 8. Это не байтовая длина строки.

--files0-from=ФАЙЛ
В GNU wc прочитать нулём завершённые имена из файла, а не из длинного argv.
Когда: Обработать большой список или имена с LF.
Пример:
find ./data -type f -print0 >names.bin
wc -c --files0-from=names.bin
Результат: Размеры считаются для каждого перечисленного файла. Имена в текстовом выводе всё ещё требуют осторожности при машинном разборе.

Wc печатает имя файла или строку total
Когда файлы переданы операндами, вывод включает их имена и может содержать общий итог.
Для одного числового результата подайте один файл через stdin: wc -c <"$file". Не разбирайте произвольные имена пробелами.

-c и -m расходятся
Байт, кодовая точка/символ локали и визуальный знак — разные единицы.
Укажите кодировку и выбранную единицу; для пакетов и двоичного формата обычно нужны байты.

На другой системе нет -L или --files0-from
Описаны дополнительные возможности GNU wc; набор BSD/BusyBox может отличаться.
Проверьте локальную помощь и нужный режим до офлайн-работы.

xargs
Собирает аргументы из входного потока и запускает команду пакетами. Формат входа должен быть выбран явно.
Синтаксис: xargs [ПАРАМЕТРЫ] КОМАНДА [ПОСТОЯННЫЕ_АРГУМЕНТЫ...]

-0
Разделять записи нулём, не трактовать обычные пробелы и кавычки как разделители.
Когда: Читать find -print0.
Пример:
find ./data -type f -print0 | xargs -0 -r printf '<%s>\n'
Результат: Каждое имя остаётся отдельным аргументом.

-r
В GNU xargs не запускать команду при пустом вводе.
Когда: Пустой набор должен означать отсутствие действий.
Пример:
printf '' | xargs -r printf 'called\n'
Результат: Ничего не выведет.

-n N
Ограничить число входных аргументов на запуск.
Когда: Получатель работает с небольшими независимыми пакетами.
Пример:
printf 'a\0b\0c\0' | xargs -0 -n 2 printf '[%s]\n'
Результат: Будет несколько запусков, каждый максимум с двумя входными значениями.

-P N
Разрешить до N параллельных запусков.
Когда: Задачи независимы и допускают перемешанный вывод.
Пример:
find ./data -type f -print0 | xargs -0 -r -n 1 -P 2 wc -c --
Результат: До двух wc работают одновременно. Порядок вывода не гарантирован исходным списком.

-a ФАЙЛ
В GNU xargs читать список из файла вместо stdin.
Когда: Команде-получателю нужен собственный stdin.
Пример:
xargs -0 -r -a names.bin printf '<%s>\n'
Результат: Список читается из names.bin; stdin дочерней команды не заменяется обычным способом xargs на /dev/null.

-d РАЗДЕЛИТЕЛЬ
В GNU xargs выбрать однобайтовый разделитель; кавычки и обратные черты данных буквальны.
Когда: Формат гарантирует, что разделитель не встречается внутри значения.
Пример:
printf 'a:b:c:' | xargs -d ':' -n 1 printf '<%s>\n'
Результат: Три отдельных значения. Для произвольных имён предпочтительнее -0.

-I МАРКЕР
Заменять маркер в аргументах каждым входным элементом по режиму -I.
Когда: Нужно поставить значение не в конце argv.
Пример:
printf 'a\nb\n' | xargs -I '{}' printf 'name=%s\n' '{}'
Результат: Будет отдельный вызов для каждого элемента. -I подразумевает свои правила строк и лимитов; не комбинируйте наугад с -n.

-L N
Использовать не более N непустых строк на запуск с обычными правилами xargs.
Когда: Известный построчный список без произвольных имён.
Пример:
printf 'a\nb\nc\n' | xargs -L 2 printf '<%s>\n'
Результат: Разделит запуск по двум строкам. Это не безопасная замена -0 для имён с LF.

-s БАЙТЫ
Ограничить размер собираемой командной строки по правилам xargs.
Когда: Получателю нужны небольшие пакеты по объёму.
Пример:
printf 'alpha\0beta\0' | xargs -0 -s 128 printf '%s\n'
Результат: Пакет учитывает также постоянную команду и её аргументы; слишком маленький лимит вызовет отказ.

-t
Перед запуском напечатать запускаемую команду в stderr.
Когда: Посмотреть пакетирование на несекретных данных.
Пример:
printf 'a\0b\0' | xargs -0 -t printf '<%s>\n'
Результат: Данные останутся в stdout, диагностическое представление вызова — в stderr. Может раскрыть аргументы.

-p
Спрашивать подтверждение перед каждым запуском.
Когда: Ручной просмотр плана, когда есть терминал.
Пример:
printf 'a\0' | xargs -0 -p printf '<%s>\n'
Результат: Ожидает человека; для безоператорной автоматизации непригодно.

-P 0
В GNU xargs запускать столько параллельных процессов, сколько возможно.
Когда: Редкий заранее ограниченный набор с рассчитанными ресурсами.
Пример:
# Обычно выбирают предел, например:
find ./data -type f -print0 | xargs -0 -r -n 1 -P 2 wc -c --
Результат: Пример ограничен двумя процессами. -P 0 способен исчерпать ресурсы и не означает автоматическую оптимизацию.

Вывод параллельных задач перемешан
-P запускает процессы одновременно.
Сохраняйте результаты отдельно и объединяйте в заданном порядке, если порядок важен.

-I, -L и -n изменили пакетирование неожиданно
Некоторые режимы взаимно исключаются; GNU xargs сообщает о конфликте и применяет определённые правила последнего режима.
Выберите один способ группировки. Для произвольных имён начинайте с -0, затем осознанно добавляйте -n или -P.

Команда-получатель не прочитала нужный stdin
Обычно xargs сама читает поток и запускает команду со stdin из /dev/null.
Используйте -a для файла списка или отдельный договор ввода. Интерактивным программам GNU xargs предоставляет -o для открытия /dev/tty.

Один работник отказал, итоговый статус не равен его коду
GNU xargs сводит результаты в собственные статусы: например, 123 при отказах работников 1–125; 124 при статусе 255, который останавливает чтение.
Читайте договор xargs. Отдельные ошибки записывайте с идентификатором задачи, не ожидайте прозрачной передачи любого кода.
