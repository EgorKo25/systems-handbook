# Systems Handbook

Интерактивная библиотека о сетях, Linux, Bash, PostgreSQL, кэшировании, Git и сборке на русском языке.

**[Открыть учебник](https://egorko25.github.io/systems-handbook/)**

- Сети — от Ethernet и байтов пакета до TCP, DNS и NAT.
- Linux — процессы, память, файловые системы, устройства и службы.
- Bash — разбор команд, аргументы, дескрипторы и управление процессами.
- PostgreSQL — SQL, планы, MVCC, страницы, WAL и восстановление.
- Кэширование — расчёт пользы, свежесть данных, Redis и Memcached.
- Git и сборка — объекты, история, совместная работа, воспроизводимость, Jenkins и семь связанных опытов.
- Дополнительные главы — DNS, Kerberos и FreeIPA.

В томах есть пошаговые схемы, поиск, словари, тренажёры, справочник команд и лабораторные материалы. Страницы работают без сборки и внешних библиотек.

## Читать без интернета

Скачайте репозиторий через **Code → Download ZIP**, распакуйте его целиком и откройте `index.html`. Для чтения сервер не нужен. Требования к запуску лабораторных опытов указаны рядом с ними.

## Изменять и публиковать

Рабочая ветка — `main`. Каждый пуш в неё запускает проверки и публикацию GitHub Pages. Для pull request выполняются проверки без публикации. Если проверка не проходит, остаётся доступной предыдущая успешно опубликованная редакция. Состояние запуска видно во вкладке **Actions → Check and publish handbook**.

Для томов V и VI исходниками служат `cache/sources/` и `git/sources/`: главы HTML, словари, справки и модели. После правки пересоберите страницы и сохраните полученные изменения вместе с исходниками:

```sh
python3 scripts/build_library.py
python3 -m unittest discover -s tests -v
python3 scripts/check_site.py . --node-check
node cache/labs/test-eviction.cjs
node cache/labs/test-resources.cjs
node cache/labs/test-resp.cjs
python3 git/labs/check_lab.py
node git/labs/check-reader.cjs
python3 scripts/update_checksums.py
```

Нужны Python 3.10+ и Node.js для проверки JavaScript; для чтения они не нужны. Проверяются локальные ссылки и якоря, встроенные данные, синтаксис JavaScript и учебные модели. Эти проверки не запускают серверы Redis/Memcached, Git-лаборатория проверяется настоящими операциями в изолированных временных каталогах. Jenkins и Maven не запускаются. Проверки не заменяют вычитку текста и проверку интерфейса в браузере.

После регистрации новых файлов в Git обновите `SHA256SUMS` и включите его в коммит. Он покрывает публичные материалы для чтения; служебные исходники сборки в этот перечень не входят. Экспорт для Pages и флэшки получает собственный перечень с файлом версии публикации.

В Pages отправляется отдельный набор публичных страниц, иллюстраций и лабораторий. Git, настройки сборки, исходные фрагменты тома и незарегистрированные локальные файлы в него не попадают. Тот же набор можно подготовить для флэшки:

```sh
python3 scripts/prepare_site.py _site --revision "$(git rev-parse HEAD)"
python3 scripts/check_site.py _site --node-check
```

Экспорт берёт текущие версии файлов, зарегистрированных в Git: новые файлы предварительно добавьте через `git add`. Для замены предыдущего экспорта используйте `--replace`; проверяется его `site-version.json` и целостность всех файлов по `SHA256SUMS`. Изменённую копию или каталог с добавленными файлами скрипт сохранит, предложив выбрать другой путь. В `site-version.json` указан коммит публикации. Откройте `_site/index.html` или перенесите содержимое `_site` на флэшку целиком.
