# Systems Handbook

Интерактивная техническая энциклопедия на русском языке: от устройства компьютера и операционной системы до сетей, разработки на Go, баз данных и доставки приложений.

**[Открыть книгу](https://egorko25.github.io/systems-handbook/)** · [Как читать](КАК-ЧИТАТЬ.txt) · [Проверки и ограничения](ПРОВЕРКИ-БИБЛИОТЕКИ.txt)

## Начать читать

В браузере откройте [главную страницу](https://egorko25.github.io/systems-handbook/), выберите том и главу. Для чтения не нужны Docker, виртуальная машина или установленные инструменты из примеров.

Чтобы читать без интернета, клонируйте репозиторий или скачайте **Code → Download ZIP**, распакуйте его целиком и откройте корневой `index.html`. Все каталоги книги должны оставаться рядом с ним. Текст, словари, справки и встроенные модели входят в копию; внешние первоисточники и загрузка программ требуют интернета.

Первое получение:

```sh
git clone https://github.com/EgorKo25/systems-handbook.git
cd systems-handbook
```

Обновление существующей копии — из каталога `systems-handbook`:

```sh
git pull --ff-only
```

После обновления откройте `index.html` заново или обновите вкладку. Пересобирать книгу для чтения не требуется. Если Git сообщает о локальных изменениях или расхождении истории, сохраните свою работу и разберите сообщение перед обновлением.

Открыть книгу из PowerShell на Windows:

```powershell
Start-Process .\index.html
```

Открыть книгу из терминала Ubuntu с графическим рабочим столом:

```sh
xdg-open index.html
```

Заметки, положение чтения и настройки сохраняет браузер. Git не переносит их между компьютерами: перед переносом экспортируйте заметки через интерфейс книги. Возможности локального хранилища для `file://` зависят от браузера; при смене пути или переходе между локальной копией и Pages прежние записи могут быть недоступны.

## Что есть внутри

- Оглавление, поиск и общий словарь с переходами к объяснениям. Выделенное слово можно отправить в словарь из текста.
- Карточки команд: назначение, параметры, условия применения и примеры. Поддерживаемые команды можно исследовать во встроенном учебном терминале.
- Пошаговые схемы, предметные рисунки и модели; в Bash — тренажёр регулярных выражений.
- Общие темы оформления, размер и шрифт текста, теплота страницы, мобильная навигация, оценка времени до конца главы.
- Локальные заметки, текстовые версии томов и справочники команд.

Браузерный терминал моделирует выбранные команды в памяти страницы. Он не выполняет их в операционной системе читателя и не подключается к настоящим серверам. Для настоящих лабораторий требования, подготовка и рабочий каталог указаны в главе и соответствующем `labs/README.txt`.

## Практика

Для первого знакомства достаточно текста и встроенных моделей. Настоящие упражнения выполняются в отдельной учебной среде с программами нужных версий; их установщики, образы ОС и личные данные не включены в книгу.

Материалы практики лежат внутри томов. Например, [`go/labs/README.txt`](go/labs/README.txt) описывает Go-службу, а [`go/labs/compiler-runtime/README.txt`](go/labs/compiler-runtime/README.txt) — сохраняемый каталог опытов с компилятором и исполнением. Для последнего проверен профиль Go 1.27.3 на Linux amd64; это не универсальный запуск на любой ОС.

Сквозной практикум и код управления стендом развиваются. Клонирование книги не выдаёт готовую виртуальную машину. Наличие сценария или сохранённого результата не означает, что весь маршрут уже проверен на Windows, с RDP/VNC и всеми связанными заданиями.

Публичная редакция не содержит рабочих инструкций развёртывания на объектах. Имена и адреса в примерах условные. Замечания по объяснениям и примерам можно оставить в **Issues**.

## Изменять и публиковать

Рабочая ветка — `main`. Каждый пуш в неё запускает [**Check and publish handbook**](.github/workflows/pages.yml): проверки, сборку и публикацию GitHub Pages. Для pull request выполняются проверки без публикации. При ошибке проверки остаётся доступна предыдущая успешно опубликованная редакция. Ход запуска виден во вкладке **Actions**.

Общий вход сборки:

```sh
python3 scripts/build_library.py
python3 -m unittest discover -s tests -v
python3 scripts/check_site.py . --node-check
```

Для этих команд нужны Python 3.10+ и Node.js. Полный CI дополнительно запускает проверки учебных моделей и настоящие ограниченные лабораторные опыты с Git и Go; список команд и опорная версия Go находятся в [workflow](.github/workflows/pages.yml). Сборка книги не запускает все описанные серверы и виртуальные машины. Успешный CI не заменяет вычитку, проверку интерфейса и испытание конкретной среды.

Исходники поддерживаемых томов находятся в их `sources/` и конфигурациях; для части прежних томов используется отдельная сборка. После правок запускайте общий сборщик и включайте в коммит исходники, полученные страницы и актуальный `SHA256SUMS`. Корневой перечень содержит зарегистрированные в Git файлы, кроме самого перечня; у экспорта отдельные контрольные суммы.

Чистую копию для автономного чтения готовит только штатный экспорт:

```sh
python3 scripts/prepare_site.py _site --revision "$(git rev-parse HEAD)"
python3 scripts/check_site.py _site --node-check
```

Откройте `_site/index.html`. Экспорт берёт текущие версии зарегистрированных в Git файлов и исключает служебные исходники, незарегистрированные тома и приватные данные. Новые проверенные файлы сначала добавьте в Git. В `site-version.json` записывается указанная ревизия; для локально изменённой копии она ещё не удостоверяет содержимое будущего коммита.

Для замены предыдущего экспорта предусмотрен `--replace`: скрипт проверяет его маркер и контрольные суммы. Изменённую копию следует сохранить и выбрать другой путь экспорта.
