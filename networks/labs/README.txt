Учебные материалы к главам «Байтовый разбор» и «Практикум»

document-flow-http.pcap — искусственно созданный классический PCAP с Ethernet II,
IPv4 и TCP. 10 кадров, 951 байт файла. Это не захват с объекта и не запись ДО.
Место наблюдения — Ethernet-сегмент клиента 192.0.2.10. Один маршрутизатор,
сервер 198.51.100.20:7000, без NAT. FCS и преамбула не включены, Ethernet-дополнение
коротких кадров включено. TCP options отсутствуют.

document-flow-http.txt — ожидаемые числа, описание и шестнадцатеричный дамп кадра 4.
packet-map.json — 127 байтов кадра 4, карта полей со смещениями, размерами,
значениями, ролями, отправителями, читателями и диагностическими пояснениями.

make-example-pcap.py — воспроизводимый генератор этих трёх файлов, без сети.
Запуск без аргументов создаёт НОВЫЙ временный каталог и печатает его путь:
python3 make-example-pcap.py
Для своего НОВОГО, ещё не существующего каталога:
python3 make-example-pcap.py --output-dir ./my-generated-example
Если каталог существует, программа откажется работать; эталоны не перезаписывает.

inspect-pcap.py — учебный читатель без сторонних пакетов, без сетевых обращений.
Из этого каталога: python3 inspect-pcap.py --verify-example
Режим проверки предназначен именно для приложенного эталона. Поддерживаются
classic PCAP с микросекундами, linktype=1, Ethernet без VLAN, IPv4 без фрагментации,
TCP. Неподдерживаемый формат не означает неисправность сети.

loopback-framing.py — сервер и клиент на 127.0.0.1, без повышения прав, случайный
свободный порт, два сообщения с 4-байтным полем длины и завершение одного направления.
Запуск: python3 loopback-framing.py
Программа проверяет значения и порядок байтов, не предполагая соответствия
между вызовами sendall, recv и TCP-сегментами.

namespace-lab.sh — НЕОБЯЗАТЕЛЬНЫЙ опыт Linux. Сам не запускается, при вызове без
аргумента --run только печатает справку. Прочитайте весь сценарий перед выполнением.
Нужны права root и поддержка сетевых пространств имён/veth; ip, python3, sysctl.
sudo bash namespace-lab.sh --run
Дополнительно при наличии tc и netem:
sudo bash namespace-lab.sh --run --loss
Адреса, маршруты, sysctl пересылки и правило искусственных потерь применяются
только в трёх НОВЫХ пространствах с уникальным префиксом dfbook-. Физические
интерфейсы, основной маршрут, общий sysctl и общий межсетевой экран не меняются.
Сценарий удаляет созданные им пространства при обычном завершении и прерывании.
В живом опыте начальные SEQ, сегментация и параметры TCP определяются ядром:
точного совпадения с искусственным PCAP не предполагается.

Проверено при подготовке:
- детерминированное создание PCAP, повторная генерация даёт тот же SHA-256;
- все 10 IPv4- и TCP-контрольных сумм, длины, SEQ/ACK и содержимое HTTP;
- полная карта полей кадра 4 без пропущенных и пересекающихся байтов;
- изменение одного байта HTTP временной копии сохраняет IP checksum и нарушает TCP;
- loopback-framing.py выполнен успешно;
- namespace-lab.sh проверен командой bash -n; создание сети и искусственные потери
  при подготовке книги на компьютере автора не запускались.

PCAP SHA-256:
5955356b0c4ca3afbd6d8bbb5486a8f5d48cdff15b765b48584401c987f03c88

Ключевые числа:
GET: HTTP73, TCP93, IPv4 113, Ethernet127 без FCS.
IPv4 checksum: 0x3c01; TCP checksum: 0xdf89.
SEQ запроса1001, следующий ACK1074.
HTTP-ответ106, тело16; SEQ ответа9001, после данных9107, после FIN9108.


Дополнение: полный ARP-запрос и ответ
------------------------------------
arp-request-reply.pcap — два Ethernet-кадра длиной 60 байт каждый, без FCS.
Клиент 192.0.2.10 / 02:00:00:00:00:10 определяет MAC шлюза 192.0.2.1.
Шлюз отвечает MAC 02:00:00:00:00:01.
Самостоятельный разбор из каталога книги:
  python3 labs/inspect-arp.py
или с tcpdump, если установлен:
  tcpdump -enn -r labs/arp-request-reply.pcap arp
Эти команды читают файл и не обращаются к сети.
Для записи нового примера без перезаписи имеющихся файлов:
  python3 labs/inspect-arp.py --write-example /tmp/arp-example-new.pcap
Последний путь должен быть новым: скрипт откажет, если файл уже существует.
Полная карта смещений, длины и действия участников находятся в главе 4.


Расширенный сетевой том: дополнительные практикумы
-------------------------------------------------
1. DHCP и DNS, синтетические эталонные сообщения:
   python3 labs/control-packets.py --self-test
   Готовые файлы находятся в labs/control-samples/.
2. ICMP/IPv6, синтетические пакеты:
   python3 labs/icmp-examples.py --inspect labs/icmp-generated/echo-request.bin
   Готовые файлы, тип канального формата и команды — labs/icmp-generated/README.txt.
3. Настоящие DHCP и DNS в изолированной сети:
   bash labs/isolated-control-lab.sh --run
   Фактическая запись подготовки книги — labs/actual-control-run/.
4. Настоящие SNAT, DNAT, внутренний разворот и фильтрация:
   bash labs/nat-lab.sh --help
   bash labs/nat-lab.sh --run
   Семь фактических проверок подготовки — labs/nat-lab-tested.txt.
5. Настоящая TLS1.3 проверка доверия и имени:
   python3 labs/tls-local.py
   Создаются временные учебные ключи и сертификаты; хранилище доверия ОС не меняется.

Для всех реальных опытов используются новые изолированные сети Linux.
Автоматического подключения к интернету и установки пакетов нет.
Наличие программ и поддержка пространств имён проверяются сценарием.
Весь текст и готовые разборы можно читать без запуска этих программ.
