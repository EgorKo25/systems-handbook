Инженерный практикум. Проверка от 27.10.2026

ПРОВЕРЕНО ФАКТИЧЕСКИ
HTML открывается через file://, без сервера и внешних ресурсов.
Chrome: все семь страниц, ширина 1500 и 390 пикселей, нет общего
горизонтального переполнения и необработанных JavaScript-ошибок.
Проверены поиск, шаги диаграмм, калькулятор /0 /25 /32 и неверный адрес,
формирование 31-байтного DNS запроса, кеш и истечение TTL, модели RC/RR.
Просмотрены снимки светлой/тёмной темы, схемы Kerberos и узкого экрана.

Одноразовый Debian bookworm контейнер, только учебные адреса:
- три BIND: primary, secondary, resolver, A-ответы на трёх портах;
- NXDOMAIN, NODATA для AAAA, обратный PTR, AXFR по TCP;
- увеличение SOA serial и обновление secondary;
- остановка своих процессов, отказ перезаписывать каталог;
- отдельный MIT KDC LAB.TEST на loopback: AS/TGS, TGT, service ticket;
- проверка расшифрования билета keytab;
- отказ для неизвестной службы, пустого кеша и устаревшей keytab;
- восстановление после согласованного обновления keytab и билета.

Одноразовый PostgreSQL 17, без опубликованных портов:
- создание из postgres-lab.sql;
- reader читает, запись reader отклоняется;
- writer создаёт строку и получает номер serial;
- default privileges применяются к объекту нужного владельца;
- объект, созданный администратором, не получает это право автоматически;
- реальные два сеанса: Read Committed и Repeatable Read;
- повторный setup отклонён без перезаписи;
- custom dump восстановлен в отдельную course_restore, число строк сверено.

Python 3.7: синтаксис и запуск генераторов DNS/KDC/pcap проверены отдельно.
Синтетический pcap содержит один 73-байтный Ethernet кадр без FCS;
IPv4 и UDP checksum рассчитаны и проверены, трафик не отправлялся.

НЕ ВЫДАЁТСЯ ЗА ПРОВЕРЕННОЕ
Сетевая лаборатория namespaces/NAT не выполнена целиком: текущий Docker
отклонил mount --make-shared /run/netns. Для неё нужна отдельная Linux ВМ
с соответствующими полномочиями. Bash-синтаксис файлов проверен.
VLAN/trunk-опыт требует отдельной ВМ и настроенного лабораторного порта.
Полный новый FreeIPA domain по главе не переустанавливался в рамках этой
работы. Команды сверены с первичными руководствами; нужна подходящая ОС,
пакеты, DNS, время и отдельные машины.
Нативные MAC-механизмы PostgreSQL/Astra и bsign этой учебной проверкой
не подтверждаются. Реальный сервер подписи и ключи не использовались.
PostgreSQL 17 проверяет общие SQL-сценарии; это не проверка восстановления
конкретной PostgreSQL 11 Astra с мандатными метками.
