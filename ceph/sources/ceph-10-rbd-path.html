Как адрес блока становится объектом RADOS

RBD предоставляет блочное представление, а не общую файловую систему. Проследим адресацию и границы совместного доступа.

Image и адрес

RBD image — логическое блочное устройство с именем и размером. Программа обращается к диапазонам байтов этого устройства. Файловая система, если она нужна, создаётся поверх него отдельным клиентом. Увеличение image ещё не увеличивает автоматически раздел или файловую систему внутри.

Библиотека librbd переводит диапазоны image в обращения к внутренним объектам RADOS. Для простого layout с размером объекта 4 MiB и без сложного чередования адрес 10 MiB относится к объекту с индексом floor(10/4)=2 и смещению 2 MiB внутри него. Запись диапазона, пересекающего границу, затрагивает несколько объектов. Это арифметика выбранного layout, не полный алгоритм каждого варианта striping.

У image есть метаданные: имя, идентичность, layout и свойства. Логический размер 16 GiB не означает, что сразу выделено 16 GiB полезных данных на носителях. Учитываются фактически записанные области, защита пула, снимки и зависимости.

Два клиента

Userspace-клиент использует librbd; kernel client — драйвер ядра. Одинаковое имя image не делает их поддерживаемые возможности и CephX-ключи одинаковыми. В этом томе первые операции выполняются через userspace. Подключение драйвером ядра допускается после проверки конкретного ядра, backports, image features и типа ключа.

Exclusive-lock помогает защищать внутреннее состояние image и координировать клиентов. По умолчанию он может передаваться между клиентами, которые по очереди пишут. Поэтому наличие этого feature не делает обычную файловую систему пригодной для одновременной записи с двух машин. Нужны предназначенная для этого файловая система и координация приложения.

Снимок и резервная копия

Snapshot сохраняет выбранное состояние image в том же хранилище. Clone может зависеть от снимка родителя. Trash откладывает удаление и сохраняет ограничения существующих зависимостей. Ни один из этих механизмов сам по себе не создаёт независимой копии за пределами отказа кластера.

Приёмка backup требует импорта на другое имя или в отдельную целевую среду, проверки размера, байтов и использования приложением. Возврат к старому snapshot отменяет более поздние записи image; их судьба должна быть согласована до rollback. Для базы данных дополнительно нужна согласованная прикладная точка, а не только блочный снимок.

Первоисточники: RBD image и layout, cooperative exclusive-lock, snapshot, trash и зависимости. Расчёт адреса и договор восстановления — авторские.

Состав format 2 и одна операция диапазона

В format 2 имя image разрешается через каталог RBD в идентификатор image. Header хранит его размер, порядок размера объекта, features и сведения о снимках. Data objects именуются с префиксом данного image и индексом объекта. Object map — отдельное описание наличия объектов для ускорения операций; это не CRUSH map и не единственное место хранения payload.

Зафиксируем stripe_count=1, stripe_unit=object_size=4194304 байт. Запись 1048576 байт начиная с 3984588 пересекает границу 4194304. В объект 0 попадают 209716 байт, в объект 1 — 838860 байт. Две операции RADOS могут принадлежать разным PG и primary. Атомарность одной операции RADOS не делает эту многoобъектную запись транзакцией произвольного размера. Приложение и файловая система должны сами обеспечивать восстановимость своих структур.

Для проверки адреса без кластера разделите каждый диапазон по границам размера объекта: object_index=floor(offset/object_size), within=offset%object_size, chunk=min(remaining,object_size−within). Увеличивайте offset на chunk до remaining=0. Результат нельзя применять без изменений к layout с несколькими полосами чередования: там stripe_unit и stripe_count меняют последовательность объектов.

Где заканчивается write и начинается durability

Librbd может иметь собственный кэш в памяти клиента. При write-back успех отдельного write может означать приём данных этим кэшем. Flush заставляет передать грязные данные OSD и дождаться требуемого завершения. Грязными называют изменённые данные, ещё не сохранённые на нижнем уровне. Снятие питания с клиента до flush может потерять неотправленный кэш, хотя кластер исправен.

В выбранном учебном userspace-профиле ниже кэш отключается параметром rbd_cache=false для client.admin — удостоверения административной Bash этой отдельной лаборатории. Это не меняет автоматически кэш других клиентов. Это упрощает наблюдение границы записи и не объявляется настройкой высокой производительности. Запросы RADOS дальше проходят описанные в главе 05 primary и реплики. Для VM нужны корректные flush на всём пути: гостевая файловая система → виртуальный диск → librbd → OSD → BlueStore → устройство.

Первый userspace image без kernel map

Этот опыт выполняется только после четырёхузловой приёмки и достаточного свободного места, в ceph1 из Bash с source reenter.bash. B — функция запуска rbd, c — ceph того же FSID. Новый пул rbdstudy создаётся по host-правилу с size=3/min_size=2, его восемь PG должны достичь active+clean. Одноузловой пул cephstudy не переиспользуется.

c config set client.admin rbd_cache false
c osd pool create rbdstudy 8 8 replicated --rule=cephstudy-host --autoscale-mode=off
c osd pool application enable rbdstudy rbd
c osd pool get rbdstudy all
c pg ls-by-pool rbdstudy
b pool init rbdstudy
b create --size 64M --object-size 4M --image-feature layering rbdstudy/report-disk
b info rbdstudy/report-disk --format json

Перед первой командой проверьте отсутствие rbdstudy через c osd pool ls, а перед create — отсутствие image через b ls rbdstudy. Существующий объект означает повторный вход, а не разрешение пересоздать. 64M здесь — размер image 64 MiB, а не резервирование такой физической ёмкости. Info должен показать размер 67108864 байта, object_size=4194304, format=2 и выбранные features. Init создаёт метаданные использования пула RBD, а application rbd только помечает назначение пула.

Сначала на ceph1 подготовьте новый собственный каталог rbd-01, небольшой raw-файл и его SHA-256. Для импорта имя назначения должно отсутствовать: команда import создаёт image. Не импортируйте этот файл поверх report-disk и не считайте нули невыделенных областей случайными данными. Полный перенос и проверка байтов приведены в главе 12.

Проверка понимания

Приложение пишет 8 KiB по смещению 4 MiB−4 KiB. При выбранном layout оно затрагивает два объекта по 4 KiB. Если один объект уже подтверждён, а второй вернул ошибку, нельзя объявить откат всей записи только потому, что приложение получило ненулевой результат. Чтение и прикладной журнал определяют дальнейшее восстановление.

RBD format, striping, create/import; librbd cache и flush. Числовой разрез диапазона — авторский расчёт; реальная трасса OSD не получалась.
