Принять первый OSD и проверить доступ

Добавление host, назначение диска и готовность PG — разные этапы. Первый участник проверяется через собственную VM-консоль, а контрольные данные его приёмки сохраняются до расширения в главе09.

Ключи и сети относятся к разным ролям

SSH cephops управляет гостевой ОС, CephX client.admin управляет Ceph, S3 user управляет разрешёнными API-объектами RGW. Ни один из этих секретов не заменяет другой. В bootstrap выбран собственный SSH key из access-01; появление /etc/ceph/ceph.pub не предполагается. Cephadm хранит daemon state под /var/lib/ceph/FSID, а минимальный /etc/ceph/ceph.conf не содержит все пользовательские данные.

Public network — закрытая клиентская сеть 10.77.0.0/24. MON использует TCP3300/6789, OSD и другие daemon listeners — выбранные порты диапазона TCP6800–7568, SSH управления — TCP22. Firewall ограничивают требуемыми узлами и источниками, не отключают целиком. Правила гипервизора и гостя проверяются отдельно. RGW позже получает свой HTTPS8443, а не право открыть всю рабочую LAN.

Первый отдельный диск

В ceph1 после bootstrap и source reenter.bash принят один MON/MGR, OSD ещё отсутствуют. Отдельный новый data disk VM должен быть однозначно сопоставлен с устройством Linux. /dev/vdb ниже — выбранный пример только после сверки serial, размера и конфигурации гипервизора. В консоли этой VM выполните чтение инвентаря:

lsblk --output NAME,PATH,SIZE,TYPE,FSTYPE,MOUNTPOINTS,SERIAL,MODEL
sudo wipefs --no-act /dev/vdb
sudo pvs

На data disk не должно быть разделов, файловой системы, LVM, mountpoints или найденных сигнатур. Wipefs --no-act только показывает сведения; здесь нет zap или стирания. Неизвестное устройство не разрешается «почистить» ради следующего шага. На ceph1 через c дополнительно проверьте:

c orch device ls --hostname=ceph1 --wide --refresh
c osd tree

Только если именно ceph1:/dev/vdb имеет Available без reject reasons и выбранный пустой диск подтверждён владельцем:

c orch daemon add osd ceph1:/dev/vdb
c orch ps --daemon-type osd --refresh
c osd tree
c osd df tree

Cephadm создаёт OSD и размещает его daemon. Запишите фактический OSD ID, его host, устройство, image и состояние up/in; он не обязан быть 0. До принятия должны отсутствовать неожиданные вторые OSD. Это разрешает малый опыт главы 09, но не даёт HA: единственная копия погибнет вместе с этим устройством.

Граница первого этапа

На этом установка первого OSD заканчивается: ceph2–ceph4 пока не добавляйте. В главах05–08 разберите размещение и восстановление, затем в главе09 выполните опыт1/1 и read-probe-01. Подготовка новых VM и расширение стоят там после этой проверки; дальше тот же объект будет прочитан при защите3/2.

Приёмка и остановка

При нехватке RAM, OOM, full/backfillfull, clock skew, недоступном host или unexpected device следующий этап не начинается. Запишите c quorum_status,c mgr dump,c osd tree,c pg stat,c health detail и сравнение контрольных данных. Число работающих процессов само по себе не подтверждает нужную защиту или допустимую историю PG.
