Официальная поставка, установка и первое доказательство работы

От проверенной загрузки до постоянного процесса в собственной VM

Выбор начинается до команды запуска

Откройте официальную страницу Download, выберите Linux x86-64, зафиксируйте полное имя nexus-3.97.3-01-linux-x86_64.tar.gz, дату, URL и SHA-256. На 1 ноября 2026 страница указывает 3.97.3; notes ветки 3.97 датируют исправление 27 октября. Бинарная CE подходит для Go hosted/proxy/group и raw. Поддержку HA, high availability — работы нескольких узлов с согласованным состоянием, здесь не предполагаем. Открытый проект Core ограничивает набор форматов; самостоятельная сборка из него не эквивалентна CE.

Поставка содержит рекомендуемую JVM, Java Virtual Machine — среду исполнения Java; ветка требует Java 21. Установка случайной системной Java 17 не удовлетворяет этому условию. По официальным требованиям размер выбирают по профилю нагрузки. Для небольшого учебного опыта резервируем, как собственное допущение, 4 vCPU, 16 GiB RAM, 50 GiB свободного локального SSD и место под отдельный резерв. Это стартовый бюджет, не минимальная гарантия. Этот бюджет VM требует отдельной машины либо хоста с запасом сверх 16 GiB: домашний компьютер с 8–16 GiB RAM не сможет одновременно выделить его гостевой ОС и себе. На таком компьютере сначала выполните реальную локальную Go-часть, а сервер перенесите на подходящее личное железо; меньший профиль не объявляется поддержанным без проверки требований именно версии. Размер всех артефактов и копий должен в него помещаться; рост request queue при свободном CPU может указывать на диск, сеть или внешнее ожидание.

curl --fail --show-error --location \
  --output nexus-3.97.3-01-linux-x86_64.tar.gz \
  https://download.sonatype.com/nexus/3/nexus-3.97.3-01-linux-x86_64.tar.gz
curl --fail --show-error --location \
  --output nexus-3.97.3-01-linux-x86_64.tar.gz.sha256 \
  https://download.sonatype.com/nexus/3/nexus-3.97.3-01-linux-x86_64.tar.gz.sha256

--fail делает HTTP-ошибку ошибкой процесса; без него тело страницы 404 можно сохранить как архив. --location разрешает перенаправление, --output выбирает имя файла, --show-error сохраняет объяснение отказа. При проверке происхождения переходы должны оставаться в доверенной цепочке источника. SHA-256, криптографический хеш, сравнивают с ожидаемым значением из доверенно полученного официального источника. Сумма, которую злоумышленник свободно заменяет рядом с архивом, происхождения не доказывает. MD5/SHA-1 на странице не выбираем как современное доказательство целостности. Подпись проверяют только если для выбранного артефакта действительно опубликованы подпись и проверенный ключ; нельзя придумывать файл ASC по аналогии с migrator.

sha256sum nexus-3.97.3-01-linux-x86_64.tar.gz
cat nexus-3.97.3-01-linux-x86_64.tar.gz.sha256
tar -tzf nexus-3.97.3-01-linux-x86_64.tar.gz

Первые две команды дают сравнимые хеши. Если checksum-файл содержит одну сумму без имени, его нельзя слепо подавать в sha256sum --check: сначала сформируйте запись «ожидаемая сумма, два пробела, точное имя». tar -t показывает состав без распаковки; -z включает gzip, -f задаёт файл. На этом этапе смотрят корневой каталог, архитектуру, комплект JVM и отсутствие неожиданного пути. Распаковку выполняют только после совпадения суммы, в выделенный каталог своей VM.

Что подготовить в отключённой сети

В комплект переноса включите архив и проверенную сумму, release notes и инструкции точной версии, ОС-пакеты и зависимости для VM, средства TLS, CA — certificate authority, удостоверяющую сторону доверия, установочный Go и его checksum, исходники labs, необходимые внешние модули и данные checksum database, если она используется. Для контейнерного варианта понадобились бы также daemon, образы и их digest, а не одна команда pull. Перенос файлов позволяет установить программное обеспечение без загрузки; политика базовой телеметрии CE 3.97.3 остаётся отдельной границей. Не отключайте проверку суммы и TLS ради офлайна.

Пользователь и два вида каталогов

Следующие команды — рецепт только для собственной VM. Создайте системного пользователя nexus без интерактивного входа, каталоги приложения и данных. Например, администратор VM выполняет useradd --system --home /srv/nexus-data --shell /usr/sbin/nologin nexus, затем install -d -o nexus -g nexus -m 0750 /srv/nexus-data. Имя группы и путь nologin сверяют с ОС. --system выбирает служебную учётную запись; её UID не должен совпасть с случайной личностью при восстановлении на другую VM.

Распакуйте проверенный архив в /opt/sonatype, создайте ссылку nexus на каталог этой версии. Распределение прав должно позволять launcher писать нужные служебные файлы; data-dir доступен на запись пользователю nexus. Не применяйте рекурсивное chmod 777. Зафиксируйте владельцев, режимы и фактические каталоги. В bin/nexus.vmoptions задайте согласованные абсолютные пути -Dkaraf.data=/srv/nexus-data, -Dkaraf.log=/srv/nexus-data/log, -Djava.io.tmpdir=/srv/nexus-data/tmp, создайте эти каталоги с нужным владельцем. Не добавляйте дубли параметров в конец: измените существующие строки и сохраните исходный файл. Комплектная JVM и фактические аргументы процесса проверяются после запуска.

В /srv/nexus-data/etc/nexus.properties положите учебную конфигурацию: приложение слушает только 127.0.0.1:8081. application-host ограничивает адрес HTTP connector; application-port задаёт порт, nexus-context-path=/ — корень URL. Каталог etc создайте до первого запуска. Не редактируйте defaults поставки ради постоянной настройки: при обновлении они принадлежат новой версии.

Последовательность команд в личной VM

Предполагается, что проверенный архив уже находится в текущем каталоге VM, служебная учётная запись создана, путь /opt/sonatype ранее не использовался другим экземпляром. Эти операции исполняет администратор своей VM. sudo здесь лишь явная граница прав; команды не предназначены для рабочего хоста.

sudo install -d -o root -g root -m 0755 /opt/sonatype
sudo tar -xzf nexus-3.97.3-01-linux-x86_64.tar.gz -C /opt/sonatype
sudo ln -s /opt/sonatype/nexus-3.97.3-01 /opt/sonatype/nexus
sudo chown -R nexus:nexus /opt/sonatype/nexus-3.97.3-01
sudo install -d -o nexus -g nexus -m 0750 \
  /srv/nexus-data/etc /srv/nexus-data/log /srv/nexus-data/tmp
sudo -u nexus /opt/sonatype/nexus/bin/nexus run

tar -x извлекает выбранный архив, -C меняет каталог назначения. ln -s создаёт ссылку без принудительной замены существующего пути. Владение launcher-каталогом у nexus в этом простом стенде даёт возможность записи PID; в более строгой поставке разделяют неизменяемое приложение и отдельный PID-dir по документации. Перед последней командой уже должны быть отредактированы vmoptions и nexus.properties, как описано выше. Повторная распаковка поверх работающей версии не является обновлением. На первом запуске Ctrl+C запрашивает завершение foreground; дождитесь остановки JVM, проверьте status и отсутствие слушателя перед запуском systemd.

На компьютере читателя ssh -N -L 18081:127.0.0.1:8081 vm-user@nexus-vm создаёт туннель до своей VM с проверенным SSH host key. -N не запускает удалённую shell, -L связывает локальный 18081 с loopback-портом на VM. Условные vm-user/nexus-vm заменяют собственными именами. Откройте http://127.0.0.1:18081 локально; HTTP-участок до VM защищён SSH. Туннель не открывает backend всем клиентам. Для удалённых автоматических Go-клиентов далее нужен общий проверенный HTTPS.

Запуск и служба

Предыдущая команда sudo -u nexus ... run уже заняла один терминал VM. Не вводите второй run. Пока первый процесс работает, откройте второй SSH-сеанс к той же VM и выполните наблюдения:

sudo -u nexus /opt/sonatype/nexus/bin/nexus status
curl --fail --show-error http://127.0.0.1:8081/service/rest/v1/status

Первый запуск выполняется от nexus в foreground, переднем плане, для наблюдения bootstrap — первоначальной подготовки приложения и данных; он меняет data-dir, создаёт БД и первоначальное состояние. Не запускайте параллельно службу над теми же данными. status исследует launcher/process, HTTP endpoint — способность приложения ответить. Оба результата слабее успешной загрузки и скачивания пакета. Если процесс исчез, смотрят log/nexus.log, JVM logs, права на tmp/db, свободное место и занятой порт. Молчание до появления журнала часто означает проблему launcher/доступа, не ошибку repository format.

После штатной остановки foreground настройте systemd unit по официальному контракту службы. Type=forking согласуется с bin/nexus start, который запускает фоновой процесс. WorkingDirectory фиксирует контекст относительных путей, User/Group задают права, TimeoutSec=600 оставляет время на bootstrap/остановку, LimitNOFILE=65536 — бюджет открытых файлов, а не настройка throughput. В VM администратор выполняет systemctl daemon-reload, затем systemctl start nexus. enable включает будущую автозагрузку и является отдельным решением. journalctl -u nexus -n 100 --no-pager ограничивает просмотр, а прикладной журнал всё равно находится в data-dir.

В этом стенде итоговый unit сохраняется как /etc/systemd/system/nexus.service на VM, а не остаётся только файлом в копии книги. Посмотрите systemctl show nexus --property=FragmentPath --value: он должен назвать этот файл. Вывод параметров systemd не сообщает, какие приложения запущены вручную вне unit; не оставляйте такой второй launcher после перехода к службе.

Первый вход и приёмка

Первоначальный пароль admin находится в $data-dir/admin.password. Читайте его только в частном терминале или через защищённый способ VM; не помещайте в командную строку, screenshot и историю CI. Для первого входа до TLS используйте SSH-туннель с локальным браузером, затем настройте HTTPS по следующей главе. Войдите через этот защищённый маршрут, смените пароль, завершите onboarding, прочитайте и подтвердите обязательные условия телеметрии как осмысленное административное действие. Anonymous access — анонимный доступ — пока отключите; позднее выдадим конкретное чтение. Создайте личного администратора и отдельного обычного читателя. Сохраните аварийный путь входа локального realm — источника установления личности.

Приёмка состоит из четырёх наблюдений: экземпляр сообщает выбранную версию; обычный пользователь читает разрешённый тестовый asset — адресуемый файл; тот же пользователь не публикует без права; после systemctl stop nexus и start сохранены репозиторий, учётные записи и checksum файла. Не удаляйте data-dir, чтобы получить «чистый» вход. Реальные ответы записывайте в журнал стенда, включая дату и версию. Авторская проверка этого тома установку Nexus не выполняла; её пределы перечислены в протоколе.
