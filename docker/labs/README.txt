ПРАКТИКУМ DOCKER

index.html#16-integrated-lab в корне тома — последовательный маршрут.
Теоретические команды 02–15 показывают варианты конфигурации: подряд с одним
именем/портом их не выполняют. Основной сервер и данные продолжают историю.

models.py — два ограниченных алгоритма (видимость слоёв и бюджет CPU) плюс
ближайший ранг перцентиля. Никаких запросов к Docker, сетевых/хостовых изменений:
  python3 models.py
  python3 -m unittest -v test_models.py
Слои представлены строковыми логическими файлами, без tar, ссылок, владельцев
и реальной OverlayFS. Whiteout/opaque удаляют только нижние записи до добавления
новых файлов слоя. Модель не стирает исходные нижние байты.
Квота — идеальные постоянно готовые задачи, один период, без накладных расходов,
заимствования и детализации Linux bandwidth slices. Она не предсказывает p99.

echo/ — реальные Go-исходники, Dockerfile и Compose. Их тесты проверены отдельно.
Для Docker нужны собственная разрешённая среда, подготовленные образы и Engine.
Открытие HTML не устанавливает и не запускает Docker. Основной том study-data
не очищается при переходе к следующему упражнению.

Специфические границы: rootful Linux/Engine29 — основной сценарий; rootless,
Desktop/Windows и иное storage/firewall окружение требуют проверки отличий.
Никаких обещаний отсутствия следов установки на рабочем компьютере нет.
