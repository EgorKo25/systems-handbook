Резерв маленького Go-счётчика: программа проверки поколения

Читайте вместе с главой14 Docker. Это узкая учебная проверка набора файлов
для собственного echo из labs/echo, а не средство резервирования произвольной
БД. Рабочий каталог команд главы — каталог тома docker в личной Ubuntu-VM.
Реальный Engine, его образы, GNU tar и права готовятся по главам04/06/08.
На компьютере для чтения книги ничего устанавливать не требуется.

bundle.py требует Python3.8 или новее и только стандартную библиотеку.
seal дополнительно использует Linux fsync каталога; показанный путь рассчитан
на Linux-файловую систему в собственной Ubuntu-VM. Работа этого пути на
Windows/FAT/exFAT и поведение конкретного накопителя здесь не подтверждены.

  python3 -B labs/backup14/bundle.py --help
  python3 -B labs/backup14/bundle.py seal "$BACKUP_DIR"
  python3 -B labs/backup14/bundle.py verify "$BUNDLE" --expected-manifest "$KNOWN_MANIFEST_SHA"

BACKUP_DIR — уже подготовленный новый каталог gen.XXXXXX. BUNDLE — выбранное
своё поколение после переноса. KNOWN_MANIFEST_SHA — отдельно сохранённый SHA256
manifest.json; сумма, заново взятая из неизвестного файла на той же цели,
не является независимой проверкой. Не вводите произвольные пути из примера.

seal принимает только полный набор:
  counter.tar             несжатый USTAR остановленного собственного каталога
  app-image.tar           результат docker image save приложения
  tools-image.tar         результат docker image save подготовленного помощника
  image.id, tools.id      полные sha256: идентификаторы этих образов
  platform.txt            Linux-платформа
  version.expected        строка ответа своего /version
  counter.expected        обычные десятичные цифры uint64 и один перевод строки
  stopped.at              UTC YYYY-MM-DDTHH:MM:SSZ
  runtime.txt             выбранные несекретные параметры запуска
  container.id            полный ID исходного контейнера

Программа отвергает незавершённые *.partial, необычные имена/ссылки/устройства
в counter.tar, повторения, неверные UID/GID10001, режимы0700/0600 и расхождение
counter с counter.expected. Разрешены «.» и обычные counter/.counter-<цифры>.
Ограничения именно учебного data-архива:16MiB,128 членов,1MiB данных,4096 байт
на обычный файл. Архивы образов читаются потоком для SHA; программа не разбирает
их внутренний Docker/OCI-формат. Успешный load и image ID проверяет Engine.

Затем seal вычисляет длины и SHA256, синхронизирует свои экспортированные
файлы и создаёт manifest.json один раз с O_EXCL. Синхронизируются каталог поколения и его
родитель (новая запись gen.XXXXXX); верхняя учебная папка готовится заранее. При ошибке файлы остаются;
повторно перезаписывать manifest она отказывается. verify только читает,
не распаковывает на диск, не подключается к Docker, не открывает сеть.
SHA256 обнаруживает изменение относительно доверенного значения, но не
заменяет подпись или защиту ключа. Во время проверки никто параллельно
не изменяет каталог: это не защита от атакующего писателя тех же путей.

Тесты:
  python3 -I -B labs/backup14/test_bundle.py

Тесты создают и удаляют только собственные TEMP-каталоги. В них16 проверок
формата, сохранения исходной копии, границ, ошибок и отказа перезаписи.
Image payloads — явно подставные байты, НЕ настоящие образы Docker/OCI.
UID10001 записан в синтетические заголовки tar; chown на хосте не вызывается.
Успех этих тестов не проверяет Engine, настоящие volumes, восстановление
привилегированным tar, отключение питания, независимый носитель или GUI.

Глава продолжает прежний основной study-data. Восстановление получает новый
том и проверяет запись отдельно. Старые поколения и неудачные цели не стираются.
Автоматического запуска, сброса стенда, удаления томов или prune здесь нет.
