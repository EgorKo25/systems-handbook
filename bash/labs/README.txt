Bash: автономные опыты и проект

Проверенная среда: GNU Bash 5.2.21, Python 3.12.3, Linux x86_64.
Интернет, службы, sudo и доступ к реальному ДО не нужны.
Флэшку и файлы проекта опыты не изменяют: рабочие данные находятся
в отдельно созданных временных каталогах.

Запуск всех 18 опытов:
  bash run-labs.sh

Выбор отдельных опытов:
  bash run-labs.sh 3 6 10

Машинный отчёт:
  bash run-labs.sh --json

Прочитать исходники можно любым текстовым редактором.
verified-results.json — сохранённый итог проверки автора: 137 проверок,
18 опытов, все PASS. Это результат конкретной среды, а не гарантия
одинаковой сборки Bash и системных стартовых файлов на любой машине.

Дополнительный проект:
  python3 test-collect-report.py

Тест проекта создаёт сложные имена и проверяет dry-run, JSON,
сохранность прежнего отчёта при отказе и два параллельных запуска.

Учебный инструмент для собственного доверенного каталога:
  bash collect-report.sh --dry-run КАТАЛОГ ОТЧЁТ.json
  bash collect-report.sh КАТАЛОГ ОТЧЁТ.json

Нужны python3 и flock. Каталог назначения должен существовать.
Будет создан стабильный файл ОТЧЁТ.json.lock; его намеренно не удаляют
при завершении, чтобы согласованные запуски блокировали один объект.
В отчёт входят обычные .log без следования символическим ссылкам.
Пример не создаёт согласованный снимок изменяющегося дерева и
не является резервным копированием живой базы PostgreSQL.

atomic_publish.py демонстрирует запись → fsync файла → replace →
fsync каталога в доверенном каталоге обычной локальной файловой системы.
Не сохраняет атрибуты прежнего файла: режим нового 0600.

argv_dump.py показывает точные границы, длины и hex-байты аргументов.

psql-example.sh НЕ запускается общим набором: нужен ваш PostgreSQL,
настроенное подключение и осознанный запуск. Пример делает только SELECT
для демонстрации SQL-литерала psql. Общий комплект к базе не подключается.

Если flock отсутствует, опыт 15 и проект сообщат о зависимости.
Заранее проверьте комплект перед отъездом: интернет для установки
недостающих системных программ в офлайн-режиме не появится.

Конечный дополнительный проход глав 08–18 (1 ноября 2026)

Сначала прочитайте remaining_lab.py. Это 11 конечных групп с собственными
файлами, pipe, FD и детьми; новая группа 18 проверяет collect-report без
исходных запусков Bash, унаследовавших личный HOME. Словарь — текстовый
scope, не дополнительный исполняемый опыт.

Стенд читателя сохраняется между днями. Выберите свой абсолютный каталог,
например $HOME/handbook-lab/bash. HOME здесь только источник выбранного
пути; настройки домашнего каталога не меняются. Обычный пользователь,
права r/w/x в своём каталоге, без sudo. Из каталога labs самой книги:

  work_root="$HOME/handbook-lab/bash"
  mkdir -p -- "$work_root" || exit
  chmod 700 -- "$work_root" || exit
  if env -u BASH_ENV -u ENV python3 remaining_lab.py \
       --work-root "$work_root" >"$work_root/result.next.json"; then
      mv -fT -- "$work_root/result.next.json" "$work_root/result.json" || exit
  else
      status=$?
      printf 'Опыт не завершён: %s; прежний result.json сохранён\n' "$status" >&2
  fi

Параметр --work-root задаёт существующий собственный каталог. Внутри него
каждый запуск создаёт отдельный временный подкаталог и убирает его.
result.json остаётся и содержит argv/cwd, статусы, hex stdout/stderr,
версии и проверенные утверждения. Временные пути из старого JSON уже
не существуют. Для сравнения дней скопируйте result.json под новым
собственным именем до повторного запуска. Набор не выполняет startup-
опыт 02, не читает dotfiles и не требует TTY/SSH/psql/служб/сети.
Внутри дочерних процессов окружение задаётся явно без HOME/BASH_ENV/ENV;
все запускаемые Bash используют --noprofile --norc.

Проверены Bash 5.2.21, Python 3.12.3, coreutils 9.4, findutils 4.9.0,
grep 3.11, sed 4.9, mawk 1.3.4 (20240123), flock util-linux 2.39.3.
Node-проверка ERE использует node ere-engine-tests.js и установленный
GNU grep в C.UTF-8; собственный renderer браузера при этом не проверяется.

Разделяйте реальные и искусственные сбои: before-replace и второй fsync
моделируются явным исключением на собственном файле. Успех опыта не
доказывает устойчивости после отключения питания. TERM получает только
свой конечный ребёнок после ready. Проверок управления настоящим TTY,
cron/systemd, удалённой машины или PostgreSQL в этом проходе нет.

Источники версии: локальные bash(1) GNU Bash 5.2 от 19 сентября 2022,
help trap/set/wait, mawk(1), flock(1) util-linux 2.39.3; execve(2)
Linux man-pages 6.7. Внешние протоколы в тексте сверены по psql PostgreSQL18
и ssh(1) OpenBSD7.4. Новые версии этих программ не предполагаются автоматически.
