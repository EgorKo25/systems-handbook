59. Лаборатория компилятора: от проверяемого вопроса до машинной инструкции

Сохраним исходники, реальные команды стадий, SSA и код одного executable. У каждого наблюдения будут свои входы и свой результат; отказ команды не сотрёт удачный предыдущий файл.

Продолжить свой стенд и проверить входы

Подготовка выполнена в главе 48: Python3 скопировал поставленные fixtures в личный постоянный каталог. Для нового опыта выберите другой корень в prepare.py; для продолжения достаточно собственного env.sh. Повторная подготовка существующего пути отказывает. В следующих блоках обычный пользователь работает в Bash без профилей, Go 1.27.3 linux/amd64/v1, CGO_ENABLED=0. GO, VOLUME и LABROOT обозначают выбранный инструмент, каталог тома в клоне и личный стенд; VOLUME при новом входе задайте из текущего корня клона библиотеки.

VOLUME="$PWD/go"
. "$HOME/handbook-lab/go-runtime/env.sh" || exit 1
cd "$LABROOT/projects/compilerlab" || exit 1
"$GO" version || exit 1
"$GO" test -count=1 -timeout=30s ./... || exit 1
"$GO" build -trimpath -buildvcs=false -o "$LABROOT/out/compiler" . || exit 1
"$LABROOT/out/compiler" || exit 1

Ожидается 0; TestValues проверяет арифметику, closure, перестановку, безопасные границы, намеренную panic у Unchecked и ABI0 AddAsm. Программа выводит значения 42,9,4,22,55,49,5,9,2,8,9,3, нулевой байт, массив 42/0/0/0 и dev. Полная строка помогает обнаружить запуск другого файла. При отказе не переходите к диагностике как с проверенными входами.

В projects/compilerlab есть go.mod, main.go, lab/lab.go, lab/lab_test.go, lab/add_amd64.s и cmd/gc/main.go. Модуль не имеет внешних зависимостей. Кэши, tmp, out и reports находятся внутри LABROOT; настройки GOENV/GOTOOLCHAIN/GOWORK/GOPROXY и telemetry ограничены средой текущей оболочки. Выходы опыта сохраняются после завершения.

Холодная компиляция в отдельном кэше и сохранённый WORK

Драйвер go build выбирает файлы, строит зависимости и вызывает compile/asm/pack/link. Флаг -x печатает команды, -work сохраняет рабочий каталог и печатает WORK=… в stderr. При тёплом кэше отдельной команды compile может не быть; для наблюдения выбираем ещё не существующий кэш work-observation01. Если он уже есть, строка проверки возвращает 1: прочитайте старый отчёт либо выберите новое имя 02, сохранив прежний опыт. Глобальный go clean не нужен.

cd "$LABROOT/projects/compilerlab" || exit 1
test ! -e "$LABROOT/cache/work-observation01" || exit 1
GOCACHE="$LABROOT/cache/work-observation01" "$GO" build -work -x \
  -o "$LABROOT/out/compiler-work" . 2>"$LABROOT/reports/work01.log" || exit 1
"$LABROOT/out/compiler-work" || exit 1

Ожидается 0. При ошибке полный stderr остаётся в work01.log; на его первой строке ищут WORK. В этом каталоге importcfg описывает packagefile-архивы, importcfg.link — входы linker, _pkg_.a — архив пакета, symabis — соглашения символов .s, go_asm.h — подготовленные константы/смещения для ассемблера. Для нашего AddAsm драйвер сначала делает asm -gensymabis, передаёт результат compile -symabis и -asmhdr, затем обычный asm создаёт объект, который попадает в пакет. Это связь производителей и потребителей файлов, а не список файлов, обязательных у любого пакета.

Встраивание: сообщение, код, затем выделения

Ptr(v) возвращает &v. Use(v), помеченная noinline, возвращает *Ptr(v). Самостоятельная Ptr должна сохранить v после возврата; после встраивания её тела в Use наружу выходит только число. Поэтому moved to heap для Ptr и RET в Use совместимы. NoInline у Use запрещает встроить саму Use, но не запрещает ей получить встроенное тело Ptr.

cd "$LABROOT/projects/compilerlab" || exit 1
"$GO" build '-gcflags=example.org/compilerlab/lab=-m=2' ./lab 2>"$LABROOT/reports/m2.txt" || exit 1
"$GO" tool objdump -s 'example.org/compilerlab/lab.Use$' "$LABROOT/out/compiler" || exit 1
"$GO" test -run='^$' -bench='^BenchmarkUse$' -benchmem -benchtime=50ms -count=3 ./lab || exit 1
"$GO" test -run='^$' -bench='^BenchmarkUse$' -benchmem -benchtime=50ms -count=3 \
  '-gcflags=example.org/compilerlab/lab=-l' ./lab || exit 1

Все команды ожидают 0. В нативном опыте обычная Use — байт c3/RET,0 B/op,0 allocs/op; с -l у собственного lab —8 B/op,1 allocs/op. Результат сохраняется как int, указатель глобально не удерживается. Флаг -m=2 относится к сообщениям компилятора, -benchmem к выполнению benchmark. У -gcflags шаблон до = ограничивает пакет; all=-l затронул бы и стандартную библиотеку. -N отключил бы дополнительные оптимизации и изменил вопрос, поэтому его здесь нет.

SSA: одинаковый индекс и доказанное условие

Select выбирает j=i либо i+1, затем возвращает−1 при j<0 или j≥len(xs), иначе xs[j]. Переполнение int у i+1 сохраняет обычные правила Go: проверяется уже полученный j. Дамп build содержит Phi по ветвям и повторный IsInBounds перед Load. Prove использует обе установленные границы и снимает эту повторную проверку. Контроль Unchecked(xs,i) её сохраняет.

cd "$LABROOT/projects/compilerlab" || exit 1
"$GO" tool compile -d=ssa/help
mkdir -p "$LABROOT/reports/ssa59" || exit 1
GOCACHE="$LABROOT/cache/ssa59" GOSSAFUNC=Select GOSSADIR="$LABROOT/reports/ssa59" \
"$GO" build '-gcflags=example.org/compilerlab/lab=-d=ssa/build/dump=Select,ssa/prove/dump=Select,ssa/check_bce/debug=1' ./lab

Справочный вызов печатает возможности внутреннего инструмента; финальная компиляция должна дать 0. При заданном GOSSADIR текстовые Select_01__build.dump и Select_02__prove.dump сохраняются в $LABROOT/reports/ssa59; HTML — там же, по пути example.org/compilerlab/lab.Select,1.html. Номера v/b принадлежат диагностике этой версии. Если каталог кэша уже тёплый и новые дампы не появились, сохраните опыт и выберите новый личный каталог; пустой stderr не доказывает снятие проверки. Предшествующая глава разбирает реальные поля и выбор Phi по предшественнику.

Прямые compile/link с существующими входами

Не исполняйте строки неизвестного журнала через eval. Для самостоятельного повтора здесь есть простой projects/flaglab с main.go без asm; его imports подготавливает go list. Этот опыт намеренно отделён от пакета с AddAsm: одиночный compile не добавил бы его .o в архив.

cd "$LABROOT/projects/flaglab" || exit 1
"$GO" list -deps -export -f '{{if .Export}}packagefile {{.ImportPath}}={{.Export}}{{end}}' . >"$LABROOT/out/replay.importcfg" || exit 1
"$GO" tool compile -p main -pack -importcfg "$LABROOT/out/replay.importcfg" \
  -o "$LABROOT/out/replay.a" main.go || exit 1
"$GO" tool link -importcfg "$LABROOT/out/replay.importcfg" -o "$LABROOT/out/replay" "$LABROOT/out/replay.a" || exit 1
"$LABROOT/out/replay" || exit 1

Ожидается dev 22 и код 0. -p задаёт идентичность пакета, -pack — архив, -importcfg — реальные архивы этой версии/цели, -o — отдельный выход. Без importcfg компилятор не находит fmt, linker — runtime-зависимости. Исправление возвращает подготовленный вход; оно не требует установки стороннего пакета. Равный вывод драйверного и прямого вариантов не доказывает побайтового равенства: build ID, пути и дополнительные флаги могут отличаться.

Ассемблерный переход и контроль свежести

AddAsm в lab/add_amd64.s использует ABI0: a+0(FP),b+8(FP),ret+16(FP); $0-24 задаёт нулевой локальный кадр и 24 байта аргументов/результата. Драйвер согласует это с Go-объявлением. В objdump символ AddAsm.abi0 читает 8(SP),прибавляет 16(SP),пишет 24(SP) и делает RET: ещё 8 байт на входе занимает адрес возврата. TestValues требует 5 для 2+3. Успех этой функции не проверяет произвольный рукописный указательный asm при GC.

У objdump -s фильтрует символ; у compile -S печатает листинг создаваемого кода; asm -S относится к самостоятельному ассемблеру. Сначала создайте тот binary, который затем читаете: build ./lab не переписывает старый out/compiler. В reports сохраняйте точный argv, версию, исходный SHA, имя выхода и проверенный результат. Временной сдвиг или хеш старого файла нельзя выдавать за новую компиляцию.

Первичные исходники закреплены tag go1.27.3: SSA diagnostics, SSA emission, ABI, benchmark loop. Сохранённая справка находится в labs/toolchain-reference; чужую версию автоматически эта лаборатория не загружает.
