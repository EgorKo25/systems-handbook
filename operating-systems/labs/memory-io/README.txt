ПАМЯТЬ И I/O — МОДЕЛИ И СВОЙ СОХРАНЯЕМЫЙ ОПЫТ

Первый путь: index.html. Откройте обычным браузером из локальной копии книги.
Интернет, Python, служба и установка не нужны. models.js не обращается к сети,
процессам или устройствам. Числа в моделях не являются измерениями компьютера.
Формат M32-2L-v1: учебные 32 бита, страницы 4 KiB, уровни 10/10/12,
записи по 4 байта little-endian. P/W/U/X/A/D/C: биты 0–6; резерв 7–11; PFN 12–31.
PDE запрещает D/C; отсутствующая запись должна быть нулём. Права U/W/X
требуются на обоих уровнях. Калькулятор переводит начало 4-байтного диапазона;
если он пересёк страницу, следующая PTE здесь не подставляется автоматически.
counter.bin: беззнаковое 32-битное число, младший байт первым: 2a000000=42→2b000000=43.
VA 0x00403124→VPN 0x403/offset 0x124→PFN 0x12a→PA 0x0012a124.

Дополнительный нативный путь только после подготовки Python 3 в личном Linux/
POSIX стенде. Он не является обязательной предпосылкой чтения. Исходный код
доступен рядом, зависимости только стандартной библиотеки Python. Windows-
нативный запуск с fcntl/O_DIRECTORY не обещан. Для Windows используйте браузер
либо собственную ранее подготовленную Linux VM; ничего на работе не ставьте.

Впервые, из каталога operating-systems/ своей копии:
  OS_MEMORY_TOOLS="$PWD/labs/memory-io"
  OS_MEMORY_ROOT="$HOME/os-learning/memory-io"
  python3 "$OS_MEMORY_TOOLS/native.py" prepare --root "$OS_MEMORY_ROOT"
prepare создаёт новый отсутствующий каталог с marker; существующий отвергает.
Сохраните оба абсолютных пути, версию Python, тип файловой системы и результаты
в собственном паспорте. Это постоянный каталог, не mktemp. Не копируйте туда
исходники заново при каждом упражнении и не удаляйте его после ошибки.

Продолжение в том же или новом терминале:
восстановите OS_MEMORY_TOOLS/OS_MEMORY_ROOT из паспорта, затем:
  python3 "$OS_MEMORY_TOOLS/native.py" status --root "$OS_MEMORY_ROOT"
  python3 "$OS_MEMORY_TOOLS/native.py" advance --root "$OS_MEMORY_ROOT"
Первый advance: 43; следующий: 44. counter.bin остаётся четырёхбайтным. Старые версии
сохранены в history/before-N.bin. Дескрипторы проверки — отдельный опыт:
  python3 "$OS_MEMORY_TOOLS/native.py" descriptors --root "$OS_MEMORY_ROOT"
read_first=2a00,read_duplicate=0000,read_independent=2a00;
общая позиция 4; pwrite со смещением 0 не меняет её; после unlink своего отдельного проверочного файла
открытая ссылка ещё читает 2b000000. Основной counter этим опытом не меняется.

Смысл параметров: prepare/status/advance/descriptors — выбранное действие;
--root задаёт ТОЛЬКО свой явно подготовленный каталог, а не файл книги/устройство.
prepare не является reset. advance держит локальную flock-блокировку своих
писателей, сохраняет предыдущую версию с O_EXCL, пишет новый файл, fsync,
replace и fsync каталога; затем пишет диагностический observations.jsonl.
Это журнал наблюдений, НЕ атомарная транзакция вместе со счётчиком. Ошибка
после replace может оставить уже новое значение при неполном журнале.
status показывает pending_files, значение и число сохранённых версий.

Если остались counter.next.N или before-N.bin после неуспеха, сохраните всё,
сверьте четыре байта/current/history и выясните, до какой границы дошёл запуск.
Повтор с тем же именем не перезаписывает следы: O_EXCL откажет. Для новой
попытки перемещение признанных ненужными следов — только отдельное явное
решение владельца с сохранением копии; сценарий этого автоматически не делает.
Не редактируйте marker для превращения чужой папки в учебную.

Нативный опыт проверяет обычное fsync/rename/перечитывание. Не отключает питание,
не доказывает корректность контроллера/FS после аварии, не измеряет IOPS.
Нет mount/losetup/fsck/drop_caches/sysctl, OOM, служб и чужих процессов.

Другие модели браузера: buddy на 32 кадра, пошаговый CLOCK, журнал OSJ1.
У CLOCK подтверждение записи старой версии не стирает новую dirty-версию.
У OSJ1 DATA без совпадающей COMMIT не применяется; переключатель порчи
изменяет только копию для проверки checksum. Префикс из 160 действий сохраняется
в собственном ключе os-memory-io-lab-v1. Сброс делается явной кнопкой;
повреждённое сохранение не перезаписывается до явного сброса.

Авторские проверки, из корня репозитория (создают только свои temp fixtures):
  node operating-systems/tests/memory_io_models.cjs
  node operating-systems/tests/memory_io_browser.cjs
  PYTHONDONTWRITEBYTECODE=1 python3 operating-systems/tests/memory_io_native.py
Они не выбирают OS_MEMORY_ROOT читателя. Контроль моделей не равен аппаратному
тесту MMU, DMA или настоящему отключению накопителя.

ОФОРМЛЕНИЕ БРАУЗЕРНОЙ ЛАБОРАТОРИИ
Страница читает только три общих параметра: library-theme-v1,
library-reader-preset-v1 и library-reader-appearance-v1 (только warmth).
Она не меняет эти ключи, заметки или настройки других книг. Поддерживаются
те же восемь палитр и согласованная теплота 0–100. Цвет надписей на основных
кнопках выбирается для контраста с текущим, уже смешанным цветом кнопки.
При запрете хранения используются встроенные значения, работа моделей доступна.

Для file:// браузер может разделить localStorage между файлами. Поэтому ссылка
из читателя может передать readerTheme (один из paper/night/white/black/sepia/
graphite/midnight/forest) и warmth (конечное число 0–100) в query страницы:
  index.html?readerTheme=night&warmth=60#translation
Эти два явных значения имеют приоритет над общими сохранёнными параметрами;
прочие или некорректные значения игнорируются. Их автоматическая передача
ссылкой зависит от общего читателя и проверяется при интеграции книги.
Никакие данные query не исполняются и не вставляются как HTML.

Тест memory_io_browser.cjs исполняет настоящий inline-код на небольшом DOM-stub,
включая формы, восстановление событий и read-only оформление. Он считает
контраст из заданных CSS-переменных всех восьми палитр при теплоте 0/50/100,
но не проверяет настоящий рендер, Safari, мобильную раскладку или сглаживание.
