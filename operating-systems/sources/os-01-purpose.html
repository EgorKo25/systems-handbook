Зачем скрипту операционная система

Скрипт прочитал из файла 42 и записал 43, но при следующем запуске снова получил 42. Разберём, куда попали новые байты.

Счётчик сборок в файле

После удачной сборки скрипт открывает counter.bin, читает число, прибавляет единицу и записывает результат. Просмотрщик открывает тот же файл и читает число с начала. Они видят одни и те же байты файла, но каждый может читать их со своей позиции. Операционная система (ОС) запоминает эту позицию отдельно для каждого самостоятельного открытия.

Какие байты должны измениться

В начале опыта в файле ровно четыре байта: 2a 00 00 00. Скрипт и просмотрщик договорились читать их как беззнаковое целое, начиная с младшего байта. 2a в шестнадцатеричной записи означает 42, 2b означает 43. Старшие три байта в обоих случаях нулевые. Как один и тот же байт читают в разных форматах, разобрано в главе о байтах в памяти.

Почему запись попала в конец

Скрипт открывает существующий файл для чтения и записи. ОС находит его по имени, проверяет доступ и ставит текущую позицию файла для этого открытия на 0. Скрипт просит прочитать четыре байта в свой буфер. В следующих схемах буфер начинается с адреса 0x00403124. Это место в памяти скрипта, а позиция 0 указывает на первый байт файла.

Чтение возвращает четыре байта и продвигает позицию с 0 на 4. Скрипт прибавляет единицу в своей памяти и просит записать 2b 00 00 00. ОС записывает эти байты с позиции 4, сразу после прежнего содержимого. Теперь в файле восемь байтов. Когда просмотрщик открывает его заново, чтение начинается с позиции 0 и снова даёт 42. Для перезаписи нужно вернуть позицию скрипта к началу перед записью.

Проверить на четырёх байтах

Выполните блок целиком в sh или Bash на Linux или macOS с Python 3.8 или новее. Он создаёт счётчик во временном каталоге. Режим r+b открывает существующий файл для чтения и записи без обрезания. С buffering=0 Python не добавляет свой буфер поверх файлового ввода-вывода.

python3 - <<'PY'
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    path = Path(directory) / "counter.bin"
    path.write_bytes(bytes.fromhex("2a 00 00 00"))
    with path.open("r+b", buffering=0) as counter:
        raw = counter.read(4)
        if len(raw) != 4:
            raise ValueError("Ожидались четыре байта")
        print("Позиция после чтения:", counter.tell())
        value = int.from_bytes(raw, "little") + 1
        counter.seek(0)
        if counter.write(value.to_bytes(4, "little")) != 4:
            raise OSError("Записана лишь часть числа")
    print("Байты файла:", path.read_bytes().hex(" "))
PY

tell() покажет позицию 4 после чтения. Затем seek(0) вернёт её к первому байту, и в конце останется 2b 00 00 00. Уберите только строку counter.seek(0) и повторите запуск. Скрипт начнёт со свежего файла и выведет 2a 00 00 00 2b 00 00 00. Сравните первые четыре байта двух результатов.

Как редактор получает процессор во время сборки

Вы нажали клавишу, пока компилятор считает. Пусть у машины один логический процессор, компилятору осталось 50 мс работы, а готовому обработчику клавиши нужна 1 мс. Если сначала закончить сборку, обработчик завершится через 51 мс. Если уступить ему процессор сейчас, он закончит через 1 мс, а компилятор через 51 мс. Это расчёт без затрат на переключение.

Чтобы сделать паузу посреди вычисления, ОС сохраняет регистры компилятора и место, с которого тот продолжит работу. Вернуть управление ядру может прерывание от аппаратного таймера. Планировщик выбирает редактор, ядро восстанавливает его состояние, и редактор обрабатывает ввод. Позже ОС вернёт компилятору его регистры. Где хранится это состояние и что сохраняется у всего процесса, разберём в главе о процессах и потоках.

Почему скрипт может изменить именно этот файл

Допустим, у скрипта есть право менять счётчик, а общую документацию он может только читать. Когда скрипт попытается открыть существующий файл документации для записи, ОС проверит его полномочия и откажет. Проверка доступа к counter.bin пройдёт успешно и при записи с позиции 4. Правило «первые четыре байта содержат число сборок» задаёт сам скрипт, поэтому и позицию для перезаписи выбирает он.

Когда правильной позиции мало

Две сборки могут закончиться одновременно. Если оба скрипта прочитают 42 до первой записи, оба вычислят 43 и перезапишут начало. В файле останется 43, хотя ожидается 44. Этот случай разберём в главе об одновременной работе. Что нужно сделать, чтобы запись пережила потерю питания, показано в главе о сохранности данных.

А пока вернёмся к самому чтению. Скрипту разрешено писать в свой буфер. Кто берёт байты файла и переносит их туда? С этого начинается глава о работе ядра.

Поведение последовательного ввода-вывода на Linux описано в open(2), read(2) и write(2). Методы файлового объекта объясняет документация Python по FileIO. Числа и адреса для следующих схем собраны в локальном файле условий опыта.
