DEVICES · как читать и повторить модели

Для опыта нужен браузер с JavaScript. Установка пакетов, Linux, Bash, Go и
права администратора не требуются. Откройте model.html или boundaries.html
из этой папки. Скрипты загружаются локально: нет fetch, CDN, ES modules и
HTTP-сервиса. Модели не обращаются к настоящим устройствам или прошивке.

model.html — М32-I/O1

Сектор LBA 7 содержит 512 байт: 2A 00 00 00 и 508 нулей. Входная область
RAM 2000..21FF и выходная 2200..23FF первоначально нулевые. Адреса здесь
шестнадцатеричные. Основная кнопка выполняет один следующий переход:

  1. Подготовка READ: LBA=7, length=512, address=2000, owner=host.
  2. Публикация: поля видимы устройству, owner=device, записан doorbell.
  3. DMA READ: 512 байт поступают во входную RAM; completion ещё нет.
  4. READ completion: success, 512 байт, IRQ pending=1.
  5. Доставка IRQ: savedPC=1000, PC=1800, режим handler.
  6. Наблюдение completion: результат READ проверен.
  7. ACK и возврат: pending=0, PC=1000, режим U.
  8. CPU-урок: 42→43; SW записывает только четыре байта по адресу 2200.
     EBREAK завершает показ. Этот шаг — интерфейс к CPU-уроку, не ISA-эмулятор.
  9. Отдельная подготовка 512 байт: сохранить исходный хвост и результат 43.
 10. Подготовка WRITE из выходного буфера 2200..23FF.
 11. Новая публикация описателя WRITE.
 12. DMA WRITE: энергозависимый кэш устройства содержит 43, носитель — 42.
 13. WRITE completion: success; устойчивое значение всё ещё 42.
 14. Запрос FLUSH: ожидание, устойчивое значение 42.
 15. FLUSH completion: устойчивое значение 43; грязного кэша больше нет.

Смысловой шаг не равен аппаратному такту. Время и IOPS эта модель не измеряет.
Маска IRQ и потеря питания доступны рядом с основной кнопкой. Раскрываемый
раздел «Другой порядок и ошибки» содержит все отдельные действия и редактор
адреса; он нужен для самостоятельного изменения порядка.

После READ completion маскируйте IRQ. Pending и данные сохранятся, доставка
откажет, а «Наблюдать completion» найдёт результат опросом. Затем разрешите
IRQ и отдельно сравните вход/ACK/возврат. Попытка наблюдать completion до её
публикации отказывает, даже если DMA уже изменила RAM. ACK требует именно
доставленного ожидающего IRQ. Обычный ошибочный переход не меняет байты.

IOMMU включают до подготовки. IOVA 4000→PA 2000 разрешает устройству 1 писать
RAM при READ накопителя; IOVA 4200→PA 2200 разрешает читать RAM при WRITE.
Оба отображения покрывают 512 байт. CPU VA 00402000 относится к другой
таблице и сюда автоматически не переводится. После owner=device редактировать
описатель нельзя. Проверяются весь диапазон, направление, requester и конец
32-битного адресного диапазона. Плоская таблица служит для этого опыта;
двоичные таблицы RISC-V IOMMU она не реализует.

Потеря питания здесь относится только к устройству. Его кэш и очереди
исчезают, носитель сохраняется, RAM оставлена для сравнения. До завершения
FLUSH останется 42; после завершения — 43. Продолжение прежнего нормального
пути после неисправности не предлагается: откройте свой JSON или явно начните
другой опыт. Сохранение настоящей DRAM после потери питания не предполагается.
Тест хвоста использует ненулевой узор: неверное заполнение нулями тогда видно.
В исходном читательском секторе хвост состоит из 508 нулей.

Сохранение и восстановление

Модель хранится в localStorage под ключом handbook-m32-devices-v1. Открытие
или перезагрузка страницы не сбрасывает прогресс. «Скачать JSON» сохраняет
полные байты, состояние и журнал. «Открыть свой JSON» проверяет схему, версию,
диапазоны и связанные поля, затем явно заменяет текущее состояние. Чужая
версия, повреждённые байты и невозможное состояние IRQ отвергаются.
«Начать заново» требует отдельного подтверждения.

Для сравнения двух ветвей скачайте JSON перед неисправностью, выполните её,
затем откройте тот же файл и выполните другой вариант. Если браузер не может
сохранять localStorage, работа остаётся в памяти страницы; скачайте JSON до
закрытия. При повреждённом прежнем содержимом ключ не перезаписывается,
страница показывает новое состояние в памяти и сообщает об этом. Его экспорт
не является копией старого повреждённого содержимого. Старое значение можно
извлечь средствами экспорта хранилища браузера; эта страница его не экспортирует.
Темы и теплота общие с книгой; собственный ключ состояния модели отдельный.

boundaries.html — M32-BOUND1

Здесь две независимые сцены с журналами. Загрузка проходит подготовку памяти,
обнаружение, образ загрузчика, GetMemoryMap, ExitBootServices и вход ядра.
Дополнительное выделение после получения карты меняет символический ключ
5→6. Exit со старым ключом 5 отказывает и сохраняет restricted=true: уже первая
попытка могла остановить часть Boot Services. После неё обычный вызов служб
консоли/устройств отклоняется. Получить актуальную карту, при необходимости
выполнить разрешённые Memory Allocation Services и повторить Exit с ключом 6 —
допустимый путь. Реальный буфер EFI_MEMORY_DESCRIPTOR здесь не строится.

Вторая сцена использует профиль М32-VM1: GVA 00402200→GPA 2200→HPA 5200,
память host — 1 MiB. Гостевая root PTE по GPA 8004 читается через HPA 18004,
leaf PTE по GPA 9008 — через HPA 19008. Затем проверяется запись по GPA 2200.
До начала можно убрать отображение root или запретить запись данных: отказ
возникает на нужном шаге, итоговый адрес не публикуется. Массив RAM в этой
сцене отсутствует: показаны адреса и разрешение записи. Вторая ступень
абстрактна, полной эмуляции Sv32x4 нет. Пары страниц фиксированы и проверяются
при импорте. Каждый уже пройденный адресный шаг должен соответствовать наличию
отображения и использованному праву: чтению root, затем чтению leaf, затем
записи данных. JSON с успешным результатом и запрещённой записью отвергается
до замены текущего состояния. Право для ещё не выполненного шага может быть
запрещено: такой вариант загружается, а следующий доступ получает отказ.
Ключ — handbook-m32-boundaries-v1; экспорт/импорт работают так же.

Дополнительные функции кодирования

nvme_layout.js кодирует выбранные 64-байтные Read/Write SQE и 16-байтные CQE,
проверяет размещение PRP при MPS=4096 и LBA размером 512 байт. PRP2 указывает
вторую страницу данных либо список. Первый указатель списка кратен 8 байтам
и может иметь смещение в странице. Продолжение списка на другой странице
не поддерживается и даёт явный отказ. CID, phase и status проверяются.
Контроллер, SGL и большинство дополнительных возможностей не реализованы.
formats.js кодирует выбранные заголовки MRd/CplD PCIe 2.1 из трёх слов и поля
RX LAN743x. Байты примеров глав 25/26 сверяются тестами. Сетевые пакеты эти
функции не отправляют.

Необязательные проверки исходников для разработчика

Они не нужны для чтения книги. Предпосылка: уже доступен Node.js с модулем
node:assert/strict. Пользователь ОС — обычный, без повышенных прав. Текущий
каталог — computer-architecture. Файлы tests/devices*.js и labs/devices/*.js
доступны для чтения; дополнительных зависимостей нет. Команды вычисляют
состояния в памяти и печатают отчёт, не создавая служб и не обращаясь к аппаратным контроллерам:

  node tests/devices_model.js
  node tests/devices_boundaries.js
  node tests/devices_nvme_layout.js
  node tests/devices_formats.js

Каждая команда должна завершиться с кодом 0 и числом успешных проверок.
Исключение или assertion даёт ненулевой код. Другие успешные команды не
исправляют упавшую проверку. Проверяются хвост данных, ownership, masked IRQ,
DMA-range/requester/permissions, переполнение адреса, импорт состояния,
обычный путь, stale MapKey с изменением restricted-state, вложенные переводы,
байты форматов, выравнивания, CID/phase/status. Это проверки выбранных функций,
а не испытание соответствия настоящего устройства стандарту.
