Запись: какая копия изменилась и когда можно её вытеснить

Два независимых выбора политики, очередь и точные 16 байт результата

Одно слово меняет часть линии

В предыдущей главе адреса 0x2000 и 0x2200 выбирали одно место набора 0 с разными тегами, 0x80 и 0x88. Теперь запишем 43 по 0x2200, а затем прочитаем 42 по 0x2000. Чтение заставит освободить место, если там находится выходная линия. В этот момент важно знать, где хранится новая версия 43.

Запись по 0x2200 меняет первые четыре байта 16-байтовой линии на 2B 00 00 00. Остальные 12 байтов сохраняются. В таблице кэша valid отмечает пригодную копию, а dirty — ещё не переданное дальше изменение. Адрес начала линии хранится в поле base. При вытеснении он указывает, куда отправить прежние данные.

Write-through и write-back отвечают за распространение

При write-back (отложенной обратной записи) обновление сначала остаётся в изменённой линии. Следующий уровень получает её, например, при вытеснении. При write-through (сквозной записи) каждое обновление передаётся следующему уровню, при необходимости через очередь. Пригодная копия текущего уровня тоже обновляется, если она есть.

В упражнении следующим уровнем служит массив RAM. Появление 43 в этом массиве само по себе не меняет файл counter.bin на устройстве. В аппаратуре следующим уровнем может быть другой кэш.

Write-allocate отвечает на другой вопрос

Правило write-allocate определяет, что делать при промахе записи. С ним кэш получает линию, размещает её и затем меняет нужные четыре байта. При no-write-allocate промах отправляет обновление вниз без заполнения линии. Это отдельное решение от выбора между сквозной и отложенной записью.

Политика в опытеПосле записи 43 по PA2200Чтение из RAM / запись в RAM за обе операции
WB/WAКэш 43, dirty=1, RAM 032 / 16 байтов
WT/WAКэш 43, dirty=0, RAM 4332 / 4 байта
WT/noWAНабор 0 пуст, RAM 4316 / 4 байта

Во всех трёх вариантах кэш сначала пуст, за записью по PA2200 следует чтение PA2000. Чтение входа приносит 16 байтов при любой политике. Выделение при записи добавляет ещё 16 байтов для выходной линии. Обратная запись отправляет 16 байтов при её вытеснении, а сквозная передаёт четыре байта самого обновления до завершения запроса. Поэтому трафик сравнивают за обе операции, включая вытеснение.

Полный путь dirty-вытеснения

В WB/WA запись по PA2200 начинается с заполнения нулевой линии с тегом 0x88. После изменения первых четырёх байтов копия содержит 43 и получает dirty=1. Запрос завершается, а строка состояния всё ещё показывает RAM[2200]=0.

Чтение PA2000 обнаруживает другой тег в том же наборе и переводит запрос в этап evict. Следующий переход «Write-back старой линии» переносит её 16 байтов по старой базе 0x2200 и снимает dirty. Именно здесь RAM получает 43. В таблице набора ещё виден тег 0x88. Лишь затем заполнение по 0x2000 устанавливает тег 0x80, и чтение возвращает 42. Контроллеру нужно сохранить изменённые данные и адрес прежней линии до передачи. Реальный контроллер может передать их в буфер вытеснений и освободить место после того, как буфер примет ответственность за запись.

Очередь записи и точка завершения

В обоих сквозных профилях сначала в очереди появляется адрес 0x2200 и четыре байта 2B 00 00 00. При WT/WA к этому моменту кэш уже содержит 43, при WT/noWA промах оставляет набор без новой линии. Пока этап равен drain, RAM ещё содержит 0. Переход «Очередь передала запись» переносит четыре байта в RAM. После отдельного finish модель разрешает следующий запрос.

У реального ядра может быть собственный буфер записей (store buffer). Пока данные в нём ждут передачи, зависимая загрузка этого ядра может получить их напрямую. Как буфер меняет порядок обращений, разберём в главе о порядке памяти.

Выровненная запись четырёх байтов помещается внутри 16-байтовой линии. Адрес 0x2201 в учебном коде проверяется до обращения и отклоняется как невыровненный, оставляя данные и счётчики прежними. Реальная обработка невыровненных обращений зависит от архитектуры и среды исполнения.

Что проверить и что изменить

В модели памяти выберите «Кэш: линия16 B». Чтобы сохранить прежний опыт, скачайте JSON перед сбросом сцены. Для каждого прогона выберите одну из кнопок «Новый опыт: WB/WA», «Новый опыт: WT/WA» или «Новый опыт: WT/noWA» и подтвердите сброс. Нажмите «Записать 43 PA2200». Нажимайте «Следующий переход» до этапа idle. Затем так же завершите «Читать PA2000».

До и после каждого перехода сверяйте RAM[2200] в строке состояния, пару чисел в колонке «Пригодность /изменённость» и тег набора 0. В деталях сравните readBytes, writeBytes и writebacks с таблицей. Эти счётчики относятся к логическим переносам модели. Она обслуживает один запрос за раз. Переходы показывают порядок действий без длительности, а запись в её RAM завершается без моделирования отказов следующего уровня.

Чтобы увидеть выделение отдельно от сквозной записи, сначала прочитайте PA2000, затем запишите 43 по PA2200. В WT/noWA тег 0x80 уцелеет. При WT/WA появится тег 0x88. В следующей главе добавим второй кэш и проследим, как он получит актуальное значение, пока изменённая линия ещё у первого ядра.
