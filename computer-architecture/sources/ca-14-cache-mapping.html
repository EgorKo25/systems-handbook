Кэш: где искать копию и почему два адреса конфликтуют

Линия 16 B, четыре набора и точные биты учебной М32

Зачем хранить ещё одну копию

В предыдущей главе чтение доходило до контроллера DRAM. Здесь ядро сначала ищет копию в кэше. Когда оно впервые читает четыре байта по 0x2000, кэш загружает 16 соседних байтов 0x2000…0x200F. Такая порция называется линией кэша (cache line). Следующее слово начинается с 0x2004. Все его байты уже находятся в загруженной линии.

Использование соседних байтов называют пространственной локальностью. Повторное чтение того же места даёт временную локальность, если копия ещё хранится. В учебной М32 кэш держит четыре линии по 16 байтов. Помимо 64 байтов данных он хранит адресные признаки, по которым распознаёт каждую копию.

Смещение, набор и тег

Физический адрес в этой модели занимает 16 бит. Четыре младших бита PA[3:0] дают смещение (offset) от 0 до 15 внутри линии. Следующие два бита PA[5:4] выбирают набор (cache set) от 0 до 3. Старшие десять битов PA[15:6] образуют тег (cache tag). Тег указывает, какую из линий, относящихся к этому набору, сейчас хранит кэш. В скобках указаны номера битов, младший имеет номер 0.

Прочитаем двоичный 0x2004 = 0010000000 | 00 | 0100 слева направо. Тег 0010000000 равен 0x80, набор 00 равен 0, смещение 0100 равно 4. Обнуление смещения даёт базу линии 0x2000. Слово занимает позиции 4…7. У 0x2200 = 0010001000 | 00 | 0000 тот же набор 0, но тег 0x88. Оно начинает другую линию.

В кэше с прямым отображением (direct-mapped) каждый набор имеет одно место. Кэш сначала выбирает его по индексу набора, затем проверяет бит пригодности valid и совпадение тега. Только при выполнении обоих условий он выбирает нужные байты по смещению. Это попадание (hit). Если хотя бы одна проверка не проходит, происходит промах (miss).

Холодный промах и замещение

При первом чтении 0x2000 набор 0 ещё пуст. Кэш заполняет его байтами 0x2000…0x200F, выставляет valid=1 и тег 0x80. Из первых четырёх байтов получается число 42. Чтение 0x2004 видит тот же тег и берёт соседние четыре байта. В начальных данных там 0. Программа получает два слова, а нижний уровень передаёт одну линию из 16 байтов.

При чтении 0x2200 тег 0x88 не совпадает с сохранённым 0x80. В единственное место набора 0 приходит новая линия, а старая вытесняется, даже если соседние наборы свободны. Следующее чтение 0x2000 снова промахнётся. Первое чтение каждой линии в этом опыте даёт холодный промах. Повторный промах по 0x2000 вызван конфликтом размещения.

При той же ёмкости данных можно организовать два набора по два места. Тогда индекс занимает один бит, тег получает ещё один бит, а смещение сохраняет четыре. Обе линии нашего примера попадут в набор 0 и смогут остаться там одновременно. Восемь чередующихся чтений 0x2000 и 0x2200 изначально пустого кэша с прямым отображением дадут восемь заполнений и 128 байтов трафика. При двух местах это расчётно два заполнения, 32 байта и шесть попаданий. Для нескольких мест нужна политика выбора кандидата при заполненном наборе. Например, LRU выбирает линию, к которой дольше всего не обращались.

Что происходит во время промаха

Запрос следующему уровню не завершает чтение мгновенно. Нужно помнить адрес недостающей линии, ожидающую операцию и место будущего результата. Современный неблокирующий кэш может одновременно ожидать несколько линий; для этого существуют отдельные записи учёта промахов. Если они заняты, новый запрос ждёт даже при наличии свободного места для данных. Две загрузки той же отсутствующей линии могут объединяться в один перенос, сохраняя несколько ожидающих читателей.

Учебный кэш принимает по одному запросу. Кнопка «Следующий переход» проводит проверку тега, заполнение при промахе, выбор слова и завершение. У этих событий нет заданной длительности. Перекрытие нескольких запросов, MLP, будет рассчитано в главе эффективности.

Наблюдаемый опыт и границы

В модели памяти выберите «Кэш: линия16 B». Чтобы повторить опыт с пустым кэшем, при необходимости скачайте JSON текущего состояния. Затем нажмите «Новый опыт: WB/WA» и подтвердите сброс сцены кэша. По очереди выполните «Читать PA2000», «Читать PA2004», «Читать PA2200» и ещё раз «Читать PA2000». После каждого запроса нажимайте «Следующий переход», пока этап в строке состояния не станет idle.

При проверке каждого адреса журнал пишет набор, смещение и требуемый тег. В таблице «Тег /база PA» у набора 0 после первого чтения будет 0x0080 /0x2000. Второе чтение оставит запись прежней. Третье заменит её на 0x0088 /0x2200, а последнее вернёт первый тег и базу. В деталях проверьте hits=1, misses=3 и readBytes=48. Модель считает 16 байтов на каждое заполнение. Доля промахов 3/4 относится к четырём выбранным чтениям. Для оценки трафика её сопоставляют с объёмом переносов.

В опыте используется один уровень кэша с физическим индексом, физическим тегом и одним местом на набор. Оценка для двух мест выше рассчитана вручную. У реальных кэшей геометрия и способ выбора набора зависят от реализации. В следующей главе запишем 43 в выходную линию и проследим, что должно произойти с изменённой копией перед её вытеснением.
