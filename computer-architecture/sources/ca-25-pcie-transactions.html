PCI Express: запрос, маршрут и completion

Связь с устройством состоит из пакетов и отдельных подтверждений. Приём пакета соседом ещё не доказывает завершение команды накопителя.

Дерево соединений

PCI Express, PCIe, — семейство интерфейсов соединения контроллеров с системой. Root complex связывает процессорную/памятную часть с деревом PCIe. Root port — порт начала такой ветви. Endpoint — конечная функция устройства, например сетевого контроллера. Switch, «коммутатор», пересылает пакеты между портами по адресным/идентификационным правилам. Несколько endpoints за одним uplink делят его пропускную способность, даже если каждый нижний порт выглядит быстрым.

Link — двунаправленное соединение двух соседних портов. Lane — пара направлений передачи с физическими линиями для каждого направления. Запись x4 означает четыре согласованные lanes; это не четыре независимых блока данных приложения и не четыре ядра. Скорость задают в GT/s, гигапередачах в секунду, а полезные bytes/s зависят от кодирования, заголовков, подтверждений, размера payload и режима. Версия спецификации, согласованный режим link и скорость самого накопителя — разные сведения.

Обнаружение функции не равно разрешению DMA

У функции есть configuration space — пространство конфигурационных полей, по которым обнаруживают идентификаторы, классы, возможности и окна доступа. BAR, base address register, описывает ресурсное окно устройства. Привилегированная программа/firmware назначает подходящее размещение; CPU MMIO к этому окну маршрутизируется функции. Изменить BAR случайной обычной программе нельзя считать безопасной операцией. Наличие BAR не делает отображённую область обычной cacheable RAM.

Bus/device/function идентифицируют функцию в принятой области PCI. Requester ID сопровождает инициированные запросы и помогает сопоставить источник, completion и проверки IOMMU. Разрешение bus mastering, корректные DMA mappings и готовая очередь являются отдельными условиями. Устройство, видимое при enumeration, ещё не обязано иметь право писать в буфер приложения. Назначение ресурсов и подключение драйвера — программная политика; аппаратная маршрутизация применяет результат.

Три уровня, три разных вопроса

Physical layer кодирует и восстанавливает физический сигнал, согласует link. Data link layer контролирует передачу между соседями: обнаруживает ошибки, управляет повтором и flow control в рамках соответствующей версии. Transaction layer формирует TLP, transaction layer packet: запросы чтения/записи, completion и сообщения. Успешный link-level обмен отвечает «сосед принял пакет», а не «SQL-транзакция сохранена» и даже не «команда NVMe закончена».

Для конкретного формата ниже прочитаны доступные разделы PCI Express Base Specification Revision 2.1, размещённой Intel. Более новые 6.x/7.x используют иные физические/канальные возможности; их подробный бинарный формат здесь не реконструируется из старой редакции. Public PCI-SIG сообщает о 7.0/128 GT/s, но полный 7.0 base standard, доступный членам, не был прочитан. Нельзя назвать изображение старого TLP точным форматом каждого поколения.

Memory Read требует результата

Endpoint хочет получить 512 B из host RAM. Он отправляет Memory Read Request с адресом и длиной, Requester ID и tag. Tag — локальный идентификатор незавершённого запроса в предусмотренных пределах, не адрес данных. Получатель выполняет доступ и возвращает Completion with Data. Completion связывается с запросом по идентификаторам, несёт статус и часть/все запрошенные bytes согласно ограничениям. Большой read может дать несколько completion packets; первый пакет не обязательно содержит весь 512 B результат.

Такие запросы называют non-posted: инициатор должен получить completion. Ошибка Unsupported Request или timeout отличается от успешного completion. Таймаут означает отсутствие ожидаемого завершения к сроку, а не математическое доказательство, что нигде не произошло побочного действия. Если устройство после reset повторно использует tags без корректного завершения/сброса старого состояния, оно может неверно связать ответы — защита от этого входит в протокол и процедуру recovery.

Буквальный заголовок Memory Read в выбранном формате 2.1

Возьмём 32-bit Memory Read: 512 байт от 2000h, Requester ID=0100h, Tag=5Ah. Предположим разрешённый Max Read Request Size не менее 512 B, доступный tag, отсутствие пересечения границы 4 KiB и успешное сопоставление RAM. Адрес и число байтов кратны 4; все byte enables, биты выбора действительных байтов первого/последнего слова, включены. Это отдельный пример endpoint→host, а не запись пакета в RAM модели. Код DEVICES-FORMATS1 проверяет ровно этот выбранный выровненный формат с тремя словами заголовка, а не все законные варианты PCIe.

Один запрос, восемь Completion with Data

Для изменяемого примера выберем поддержанную границу разбиения ответов Read Completion Boundary, RCB=64 байта, и допустимые размеры полезной порции. Получатель может вернуть 512 B восемью CplD по 64 B. В первом CplD Fmt=010/Type=01010, Length=16 DW, Completer ID=0000, успешный статус, BCM=0 и ByteCount=512. BCM — специальный признак изменения ByteCount мостом; в нашем обычном ответе он сброшен. Requester ID=0100 и Tag=5A прежние. LowerAddress, младшие 7 бит адреса первого возвращённого байта, равен 00. Его 12-байтный заголовок по тому же правилу:

CplD #0: 4A 00 00 10 |00 00 02 00 |01 00 5A 00
           16DW       BC=512       ID/tag/low7

ByteCount показывает число байтов, ещё подлежащие возврату, включая текущий completion, а не всегда размер его payload. Для наших восьми порций он 512,448,384,320,256,192,128,64; LowerAddress, младшие 7 бит первого возвращённого byte address, чередуется 00,40,00,40,00,40,00,40. Один это поле из 7 бит не восстанавливает полный адрес: инициатор хранит исходную заявку и прогресс. Успех первой порции 64 B не даёт права читать оставшиеся 448 B как завершённые. После ошибок/несовпадения tag или сборки ответа нельзя выдать результат за успешное чтение 512 байт.

Разбиение ограничивают MPS, максимальный размер полезных данных TLP, а также границы и правила completion; наши 64 B не единственный законный выбор. Восемь пакетов несут восемь заголовков. При допустимом разбиении на более крупные порции их было бы меньше. Именно поэтому одни и те же 512 байт полезных данных даёт разный объём транзакционного трафика. Размеры получены из формата; настоящий link для примера не захватывался.

ACK и credits не заменяют CplD

В рассматриваемой 2.1 схеме номер последовательности и link CRC, LCRC, принадлежат link-передаче; соседняя сторона подтверждает принятый диапазон ACK, отрицательное подтверждение NAK или таймер может потребовать повторную передачу. Такой ACK способен прийти задолго до transaction completion от конечной цели за несколькими коммутаторами. LCRC обнаруживает определённые повреждения, не является криптографической проверкой и не подтверждает сохранение данных на носителе.

Flow-control credits описывают доступные приёмные ресурсы link: header/data и классы posted/non-posted/completion учитываются раздельно. Нулевой credit приостанавливает соответствующую передачу, даже если логически запрос готов; освобождение credit означает возможность принять пакет, не завершённый DMA. Outstanding tags, credits и глубина NVMe SQ — три разных ограничителя. Пример с одним разрешённым tag сериализует reads даже при свободной полосе; увеличение credits не создаёт дополнительные tags автоматически.

Memory Write является posted

Endpoint передаёт DMA payload в host RAM Memory Write Request. Такой posted request не получает обычного transaction completion как ответ на read. Это не означает отсутствие любой проверки передачи: соседний link всё ещё имеет свои гарантии, а ошибка может сообщаться другим механизмом. Программное подтверждение результата создаётся на другом уровне, например записью status descriptor или NVMe CQE. Нельзя ждать выдуманный Completion with Data в ответ на каждый posted Memory Write.

Похожая цепочка у CPU doorbell: write к BAR формирует MMIO-транзакцию, которая может быть принята/буферизована раньше фактического дальнейшего исполнения устройства. Порядок регулируют правила PCIe attributes, CPU memory type и платформа. Чтение документированного регистра иногда применяется для согласованной проверки/продвижения предыдущих writes; произвольный read любого endpoint не является универсальным flush всей системы. Спецификация допускает ordering exceptions, включая Relaxed Ordering; фраза «PCIe всегда исполняет всё в порядке программы» неверна.

Стоимость сериализации и общего узкого места

Для явно выбранного примера Gen3, x4,8 GT/s на lane, кодирование 128b/130b даёт верхнюю оценку до transaction overhead:8·10⁹ передач/с ×4 ×128/130 ÷8 ≈3.938·10⁹ B/s в одном направлении. Деление 8 переводит биты в байты; коэффициент 128/130 учитывает только этот способ кодирования. Реальная скорость полезных 512 B ниже из-за headers, flow control, размера запросов и получателей. Формула не переносится на Gen6/7 FLIT/PAM4 простым удвоением без изучения overhead.

Для очереди небольших reads важны также число outstanding запросов и round-trip: очень широкий link не поможет, если разрешён единственный маленький read и каждый ждёт полный ответ прежде следующего. Для DMA в RAM ограничителем могут стать IOMMU walk, память или общий uplink switch. Диагностика должна различать negotiated link, retries/errors и полезный поток, не только название PCIe на коробке.
