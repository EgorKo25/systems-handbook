Транзакции PCI Express

Проследим, как запрос доходит до памяти, как возвращаются данные и что именно подтверждает соседний порт.

Дерево соединений

В ca‑24 контроллер прочитал LBA 7 и перенёс 512 байт в RAM. Если такой перенос идёт по PCIe, контроллер посылает Memory Write с данными в буфер хоста. Ответ на команду накопителя публикуется отдельно. Чтобы увидеть именно обратный путь данных в PCIe, ниже пройдём другую операцию: контроллер сам читает 512 байт из RAM через Memory Read. Это направление пригодится, например, когда устройство забирает буфер для записи на накопитель.

PCI Express, PCIe, — семейство интерфейсов соединения контроллеров с системой. Root complex связывает процессорную/памятную часть с деревом PCIe. Root port — порт начала такой ветви. Endpoint — устройство на конце ветви. Оно может предоставлять одну или несколько функций, например функции сетевого контроллера. Switch, «коммутатор», пересылает пакеты между портами по адресным/идентификационным правилам. Несколько endpoints за одним uplink делят его пропускную способность, даже если каждый нижний порт выглядит быстрым.

Link — двунаправленное соединение двух соседних портов. Lane — пара направлений передачи с физическими линиями для каждого направления. Запись x4 означает четыре согласованные lanes; это не четыре независимых блока данных приложения и не четыре ядра. Скорость задают в GT/s, гигапередачах в секунду, а полезные bytes/s зависят от кодирования, заголовков, подтверждений, размера payload и режима. Версия спецификации, согласованный режим link и скорость самого накопителя — разные сведения.

Обнаружение функции не равно разрешению DMA

При обнаружении функции программа читает её конфигурационное пространство, configuration space. Регистры BAR описывают ресурсные окна, для которых прошивка или ОС назначает адреса. Например, CPU пишет в отображённый регистр дверного звонка, а сеть PCIe направляет обращение к функции, которой принадлежит диапазон BAR.

Когда инициатором выступает устройство, ему нужно отдельно разрешить bus mastering, то есть право выдавать транзакции. Для передачи также нужны подготовленная очередь и допустимый DMA-адрес буфера. Если включён IOMMU, его настройки должны разрешать этому инициатору нужное направление доступа и весь используемый диапазон. Именно это условие проверяли в ca‑24. Обнаружение функции и размещение её окна BAR этих разрешений не выдают.

Три уровня, три разных вопроса

Физический уровень кодирует сигнал и согласует соединение двух портов. Канальный уровень отслеживает передачу между соседями и повторяет пакеты по правилам выбранной версии. Транзакционный уровень формирует TLP, пакет запроса, ответа или сообщения. В рассматриваемом формате канальные пакеты переносят подтверждения приёма и обновления сведений о доступном месте в приёмных буферах.

Ниже используется учебный профиль PCIe 2.1 с трёхсловными заголовками. Он фиксирует поля запроса и ответа. Для оценки полосы в конце отдельно взят канал Gen3.

Memory Read требует результата

Пусть контроллер с Requester ID=0x0100 получает 512 байт из разрешённого для чтения буфера хоста. В обычной кодировке bus/device/function это функция 01:00.0. Устройство занимает Tag=0x5A и запоминает адрес и длину заявки. Поле Tag позволяет отличить этот незавершённый запрос от других запросов того же инициатора.

У Memory Read маршрут выбирается по адресу. В нашем примере запрос направляется вверх, к корневому комплексу, через корневой порт. Если между портами стоит коммутатор, он сверяет адрес с настроенными окнами. На стороне хоста проверяется доступ DMA к RAM. Ответ с данными, Completion with Data (CplD), возвращается по Requester ID, а инициатор находит ожидающий запрос по паре ID и Tag. Поэтому адрес полезных данных и идентификатор обратного маршрута выполняют разные роли.

Memory Read — запрос с обязательным ответом, non-posted. Помимо успешного ответа с данными возможен ответ со статусом отказа, например Unsupported Request. При истечении времени ожидания инициатор фиксирует незавершённое чтение. Дальнейшее использование Tag зависит от процедуры обработки ошибки или сброса устройства.

Буквальный заголовок Memory Read в выбранном формате 2.1

Для MRd32 зададим 512 байт от DMA-адреса 0x2000, Requester ID=0x0100 и Tag=0x5A. В этом отдельном примере разрешённый для чтения DMA-адрес совпадает с адресом RAM. Отображение ca‑24 с IOVA 0x4000 разрешало устройству запись в другой постановке опыта. Предположим доступный Tag и допустимый Max Read Request Size не меньше 512 байт. Диапазон 0x2000…0x21FF целиком лежит внутри одной границы 4 KiB. Адрес и число байтов кратны 4; все byte enables, биты выбора действительных байтов первого/последнего слова, включены. Это отдельный пример endpoint→host, а не запись пакета в RAM модели. Один запрос, восемь Completion with Data

В учебном примере корневой комплекс использует границу разбиения ответов Read Completion Boundary, RCB = 64 байта. Предположим, что размер полезной порции 64 байта допустим. Получатель может вернуть 512 B восемью CplD по 64 B. В первом CplD Fmt=010/Type=01010, Length=16 DW, Completer ID=0000, успешный статус, BCM=0 и ByteCount=512. BCM — специальный признак изменения ByteCount мостом; в нашем обычном ответе он сброшен. Requester ID=0100 и Tag=5A прежние. LowerAddress, младшие 7 бит адреса первого возвращённого байта, равен 00. Его 12-байтный заголовок по тому же правилу:

CplD #0: 4A 00 00 10 |00 00 02 00 |01 00 5A 00
           16DW       BC=512       ID/tag/low7

На схеме переходите кнопкой «Дальше →». В кадре «Приём соседним портом» у инициатора всё ещё 0 из 512 байт. «Первый CplD» даёт 64 байта. ByteCount=512 здесь включает текущие 64 байта и оставшиеся 448. «Второй CplD» доводит собранный ответ до 128 байт и показывает ByteCount=448. В этой порции младшие семь бит адреса 0x2040 дают LowerAddress=0x40. Для следующего адреса 0x2080 поле снова будет нулевым. Полный адрес инициатор восстанавливает по сохранённому запросу и уже полученному объёму.

Между кадрами «Второй CplD» и «Последняя порция» схема сворачивает пять промежуточных ответов. Полный ряд значений ByteCount равен 512, 448, 384, 320, 256, 192, 128, 64. В восьмом пакете осталось вернуть ровно его 64 байта. После проверки статуса, идентификаторов и всех 512 байт инициатор может завершить запрос и освободить Tag. Кадр «Отказ или timeout» показывает альтернативный исход запроса. Схема переключает заранее подготовленные состояния, а проверка заголовков в formats.js вычисляет байты. Обмена по реальной шине здесь нет.

Разбиение ограничивают MPS, максимальный размер полезных данных TLP, а также границы и правила completion; наши 64 B не единственный законный выбор. Восемь пакетов несут восемь заголовков. При допустимом разбиении на более крупные порции их было бы меньше. Именно поэтому одни и те же 512 байт полезных данных даёт разный объём транзакционного трафика. Размеры получены из формата; настоящий link для примера не захватывался.

ACK и credits не заменяют CplD

В рассматриваемой 2.1 схеме номер последовательности и link CRC, LCRC, принадлежат link-передаче; соседняя сторона подтверждает принятый диапазон ACK, отрицательное подтверждение NAK или таймер может потребовать повторную передачу. При наличии коммутатора этот ACK относится только к соединению с ним. К этому моменту отправитель может получить подтверждение соседнего порта, пока конечная цель ещё готовит ответ. LCRC обнаруживает определённые повреждения, не является криптографической проверкой и не подтверждает сохранение данных на носителе.

Flow-control credits описывают доступные приёмные ресурсы link: header/data и классы posted/non-posted/completion учитываются раздельно. Нулевой credit приостанавливает соответствующую передачу, даже если логически запрос готов; освобождение credit означает возможность принять пакет, не завершённый DMA. Outstanding tags, credits и глубина NVMe SQ — три разных ограничителя. Пример с одним разрешённым tag сериализует reads даже при свободной полосе; увеличение credits не создаёт дополнительные tags автоматически.

Memory Write является posted

Вернёмся к READ накопителя из ca‑24. На участке контроллер → RAM запись данных идёт в Memory Write. Этот тип запроса называется posted: обычного TLP Completion для него нет. Соседний порт всё ещё может подтвердить приём пакета на канальном уровне. Сам контроллер накопителя сообщает хосту результат READ отдельной записью завершения команды, например NVMe CQE. Таким образом, момент приёма пакета соседним портом, ответ PCIe на чтение RAM и результат команды накопителя видны в разных местах.

Похожая цепочка у CPU doorbell: write к BAR формирует MMIO-транзакцию, которая может быть принята/буферизована раньше фактического дальнейшего исполнения устройства. Порядок регулируют правила PCIe attributes, CPU memory type и платформа. Чтение документированного регистра иногда применяется для согласованной проверки/продвижения предыдущих writes; произвольный read любого endpoint не является универсальным flush всей системы. Спецификация допускает ordering exceptions, включая Relaxed Ordering; фраза «PCIe всегда исполняет всё в порядке программы» неверна.

Стоимость сериализации и общего узкого места

Для явно выбранного примера Gen3, x4,8 GT/s на lane, кодирование 128b/130b даёт верхнюю оценку до transaction overhead:8·10⁹ передач/с ×4 ×128/130 ÷8 ≈3.938·10⁹ B/s в одном направлении. Деление 8 переводит биты в байты; коэффициент 128/130 учитывает только этот способ кодирования. Реальная скорость полезных 512 B ниже из-за headers, flow control, размера запросов и получателей. Формула не переносится на Gen6/7 FLIT/PAM4 простым удвоением без изучения overhead.

Для очереди небольших reads важны также число outstanding запросов и round-trip: очень широкий link не поможет, если разрешён единственный маленький read и каждый ждёт полный ответ прежде следующего. Для DMA в RAM ограничителем могут стать IOMMU walk, память или общий uplink switch. При диагностике сверяют согласованную ширину и скорость соединения, ошибки, повторы и полезный поток. В следующей главе посмотрим, как сетевой контроллер пользуется этим путём для доставки принятого кадра в RAM.

Спецификация выбранной редакции указана в каталоге PCI‑SIG. Раздельные ACK и CplD и границы RCB показаны в Intel/Altera AN 456. Смысл полей ответа сверяется по документации AMD о приёме Completion. Это описание интерфейса блока, а не побайтовая карта TLP на проводе. Для PCIe 7.0 здесь используется только публичное сообщение PCI‑SIG.
