Компьютер: состояние, правило и следующий шаг

С нуля строим путь от различимых физических состояний к исполнению маленькой программы.

Что должно измениться

Пусть на устройстве хранения есть четыре байта 2A 00 00 00, представляющие число 42. Наша задача — получить 43 и сохранить его. Байт — группа из восьми двоичных разрядов; бит — один разряд с двумя допустимыми значениями, 0 или 1. Почему именно эти байты обозначают 42, разберём до первой инструкции. Пока важно различить сведения и способ их изменения: наличие числа в памяти само по себе не заставляет его увеличиться.

Состояние — сведения о выбранных частях системы в определённый момент. В маленьком примере к нему относятся байты памяти, содержимое внутренних ячеек процессора и место следующей команды. Правило перехода определяет, какое состояние получится из данного состояния при допустимом входе. Программа — сохранённая последовательность таких команд. Вход, правило и результат имеют конкретное представление; компьютер не читает человеческое намерение «сделай полезно».

Минимально нужны хранилище состояния, механизм выбора команды, механизм преобразования и пути передачи. Процессор, CPU, — устройство, выполняющее кодированные инструкции. Система команд, ISA, определяет доступные инструкции, регистры и видимые результаты их исполнения. Память удерживает различимые значения в выбираемых местах. Устройство ввода-вывода связывает вычисление с внешними данными: например, переносит байты с накопителя. Эти роли могут быть объединены в одном кристалле; прямоугольники схемы означают ответственность, а не обязательно отдельные коробки на столе.

Данные и управление идут разными путями

Передача числа требует информационного пути: по нему движутся его разряды. Выбор места требует адресного пути: он указывает, какую ячейку читать. Сигнал «записать сейчас» относится к управлению: он разрешает изменение. Совпадение чисел на разных путях не объединяет их смысл. Адрес 0x2000 не является значением 42, а команда чтения не является самими прочитанными данными. Префикс 0x обозначает шестнадцатеричную запись, которую введём в главе о числах.

Сигнал — изменяемая физическая величина, используемая для передачи состояния. В электронной схеме это часто напряжение относительно общей точки отсчёта. Человеческий 0 не летит по проводу как печатный знак: передаётся величина, которую принимающая схема при заданных условиях распознаёт как один из уровней. Состояния ячеек памяти также имеют физический носитель.

Какие ячейки есть в М32

В учебной машине М32 память содержит 65536 байт, то есть 64 KiB; приставка Ki означает множитель 1024. RAM, random access memory, означает память с выбором ячейки по адресу; дальше так подписан массив байтов модели. Внутренние регистры — небольшие именованные хранилища процессора — имеют ширину 32 бита. Они называются x0…x31; x0 читается как ноль. Отдельный PC, program counter, хранит адрес инструкции, которую предстоит выбрать в текущем шаге; во время её выполнения это адрес текущей инструкции. Инструкция — одна кодированная команда процессора. Сначала мы даём вход уже подготовленным в памяти; его перенос с устройства — отдельный следующий механизм.

Код начинается с адреса 0x1000, входной буфер — с 0x2000, результат — с 0x2200. Буфер — выделенная область хранения передаваемых данных. Эти места не меняются молча между главами. Первая фаза использует физические адреса — места в аппаратной области памяти модели. Виртуальные адреса появятся явно позже, после объяснения аппаратного преобразования адресов.

Состояние должно быть достаточно полным

Для однозначного следующего шага недостаточно записать только «в памяти 42». Надо знать PC, байты команды по этому адресу и значения её источников. Если при одинаковой RAM PC=1000, сначала создаётся адрес входа; если PC=1008 при x6=42, следующим действием станет увеличение. Указатель и данные — разные части одного состояния. Если программа остановлена событием отладки, ещё одно нажатие не выбирает следующую инструкцию. Отладка — наблюдение программы по выбранным событиям; в нашем интерфейсе точка останова подписана breakpoint. Другой вид остановки, trap, хранит причину отказа; подробнее виды событий разберём при исполнении команд.

Архитектурный результат определяется первыми частями, а журнал помогает его проверить. В реальном устройстве дополнительно есть множество внутренних состояний: например, ожидающий запрос памяти. Позднее увидим, почему одинаковая видимая программа может занимать разное время. Последовательная М32 намеренно выполняет один логический переход целиком; она не вводит скрытое время ожидания, которое якобы было измерено.

Участники обмена и условие готовности

Чтение памяти в нашей модели задаёт инициатор CPU: «нужны 4 байта начиная с 2000». Память отвечает 2A 00 00 00; CPU собирает число и принимает его в регистр. Адрес не переписывает память, чтение не увеличивает число, наличие ответа не записывает выход. Для записи CPU отдельно передаёт «адрес 2200, длина 4, байты 2B 00 00 00, разрешить запись». Смена только информационного пути без разрешения не должна изменять состояние хранения.

В аппаратном обмене ответ может прийти не сразу. Требуется различить «запрос подан», «принят получателем», «данные готовы» и «потребитель их принял». Дополнительные сигналы готовности и подтверждения устанавливают, когда можно двигаться дальше; ширина адресного/информационного пути сама этого не сообщает. В первой браузерной модели ответ возвращается в том же логическом шаге. Более сложные очереди/шины будут введены после того, как смысл одного обмена понятен.

Изменяемый пример: оставим программу прежней, но подготовим вход 41 вместо 42. После загрузки будет 41, после сложения 42, выходные байты станут 2A 00 00 00. Адреса и роли участников останутся прежними. Если вместо этого изменить только место входа на 2004, а команду/базу не менять, CPU всё ещё читает 2000: человеческое пояснение не перенаправляет аппаратное обращение. Поэтому расположение входа должно совпасть с адресом, который вычисляет программа.

М32 последовательно меняет регистры и массив памяти. Здесь реализованы только пять выбранных инструкций; электрические переходы и работу ОС прослеживаем в отдельных разделах.

Как наблюдать, не устанавливая программы

Откройте локальную модель М32 обычным браузером. Для чтения и первого опыта не нужны Linux, терминал, язык программирования или сеть. «Следующая инструкция» меняет состояние на один логический шаг. «До события» ограничивает число шагов; автоматического бесконечного исполнения нет. Неизвестная инструкция и неподдержанный адрес останавливают показ с объяснением. Кнопка явного начала заново требует осознанного выбора; повторное открытие продолжает сохранённое состояние, если браузер разрешает локальное хранение. Состояние можно скачать в JSON — текстовый файл с именованными полями, числами и массивами — и позже загрузить обратно. JavaScript внутри локальной страницы выполняет эти операции в браузере; писать его для опыта не требуется.

До подробного исполнения пройдём три основания: как физическое различие становится битом; как разряды представляют числа и текст; как схема хранит состояние между изменениями входа. Только затем одинаковые байты смогут быть прочитаны как команды, по их полям и выбранному действию.
