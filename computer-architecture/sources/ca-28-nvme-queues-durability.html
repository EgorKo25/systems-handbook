NVMe: очередь команды, очередь результата и граница устойчивости

Разберём конкретные поля Read/Write, роль doorbell и то, почему успех команды не всегда означает пережитую потерю питания.

Интерфейс контроллера и носитель

NVM Express, NVMe, определяет интерфейс взаимодействия host с контроллером и его ресурсами. NAND является возможным носителем SSD, а PCIe — одним из транспортов; NVMe также имеет другие транспорты. Роли можно проследить в одном чтении: NAND выдаёт данные контроллеру, NVMe задаёт команду и результат, PCIe переносит транзакции к памяти host. Namespace в NVMe — набор адресуемых ресурсов с идентификатором NSID и форматом логических блоков. Это не namespace CPU/OS и не каталог файлов.

Для этой главы выбраны NVMe Base 2.1 и NVM Command Set 1.1 от 5 августа 2024. Прочитаны разделы настройки контроллера, регистров, очередей, PRP и команд Read/Write/Flush; их перечень и доступность документов указаны в карте источников. Официальные структуры Microsoft nvme.h дополнительно помогают сверить размеры полей. Архив NVMe содержит более новые редакции; здесь разобрана выбранная версия.

Как очереди соединяют host и контроллер

Submission queue, SQ, — очередь описаний команд, подготовленная host. Completion queue, CQ, — очередь результатов, которые публикует контроллер. Они размещаются в доступной согласно transport памяти; настройка сообщает адреса/размеры и связь очередей. Для типичного NVMe over PCIe memory-based пути host заполняет SQE, submission queue entry, делает содержимое видимым и обновляет SQ tail doorbell через MMIO. Контроллер узнаёт новый tail, забирает доступные задания и выполняет их.

Он не обязан завершать все независимые команды в том порядке, в котором host их поставил. Completion содержит идентификатор команды и очереди; host связывает результат с нужным запросом. CQ head doorbell сообщает, какие результаты уже обработаны и какие слоты можно повторно использовать. Для кольцевой CQ phase bit позволяет отличать новую запись после оборота от прежней; это конкретный протокол, а не общая гарантия любого кольца.

В выбранном формате описание команды занимает 16 слов по 4 байта, всего 64 байта. Запись результата состоит из четырёх слов, 16 байт. Данные сектора размером 512 байт находятся в отдельном буфере. Поле PRP/SGL указывает страницы/сегменты буфера данных в поддержанном формате. PRP, physical region page, — механизм указания областей данных; SGL, scatter-gather list, — описание нескольких сегментов. Наивно поместить CPU VA в PRP не означает настроить DMA mapping. Отображение DMA-адресов и согласование размеров страниц выполняются по правилам транспорта и платформы.

До первой SQE: как контроллер получает административные очереди

Рассмотрим только memory-based NVMe over PCIe и уже выполненную подготовку транспорта: функция обнаружена, MMIO BAR доступен, разрешён корректный DMA, отображения памяти созданы, буферы остаются выделенными до окончания обращения. Числа ниже описывают подготовленный учебный профиль. Properties — поля управления и состояния интерфейса. Смещение ниже считается от начала окна регистров. Привилегированная программа записывает настройки, контроллер сообщает статус готовности.

До EN=1 выбираем CSS=0, MPS=0, AMS=0 и CRIME=0 в поддержанном режиме готовности. Сначала CC=0, затем устанавливаем EN=1; ждём RDY=1, проверяя CFS и предел времени выбранного режима. CAP.TO имеет единицу 500 ms; Base 2.1 также имеет регистр CRTO и режимы готовности с носителем/независимо от носителя, поэтому старую простую формулу нельзя безусловно применять к любому новому контроллеру. Если срок истёк, настройка останавливается: следующие команды не публикуются.

Через административную очередь выполняются Identify Controller и нужные Identify Namespace: по их ответам проверяем размеры записей, активный NSID 1, формат 512 байт без отдельных метаданных и поддержку используемых возможностей. Только после проверки этих ответов задаём IOSQES=6, IOCQES=4, то есть 64 B/16 B, до создания очередей I/O. При сохранении остальных выбранных битов CC=00460001h. Set Features Number of Queues согласует доступное число очередей; затем Create I/O CQ создаёт CQ 2 по DMA-адресу 5000. После её успешного завершения Create I/O SQ создаёт SQ 2 по адресу 6000 и связывает её с CQ 2. Обе базы выровнены по 4 KiB, очереди имеют по четыре слота. Здесь разобраны порядок и поля настройки по Base 2.1 §3.5.1; двоичные записи административных команд не реализованы helper-функцией.

Попытка Create SQ до существующей CQ, неподдержанный MPS или неверные размеры записей имеют ветку отказа; нельзя переходить к Read после ошибочного результата административной команды. Успех EN/RDY сам по себе не подтвердил формат namespace. Политика выбора числа очередей и их привязки к CPU выполняется ОС; аппаратная причина последовательности — контроллер должен знать, где брать команды, куда возвращать результаты и как читать каждую запись.

Конкретная команда Read

В общем формате команды CDW0 содержит код операции opcode и идентификатор команды CID, NSID выбирает namespace, указатель данных задаёт буфер, CDW10/11 содержат начальный LBA, CDW12 — число блоков и управляющие биты. Dword — 32-битное слово, не обязательно логический сектор. В NVM Command Set Read имеет opcode=02h, Write — 01h. NLB, number of logical blocks, в этих командах кодируется нулевой базой: NLB=0 означает один блок, NLB=1 — два, а не запрос нулевой длины.

Буквальные 64 B одной заявки

Выберем отдельный конкретный профиль очередей в памяти: namespace 1, данные LBA по 512 байт без метаданных, страница памяти контроллера 4096 байт, адресация PRP, READ одного блока LBA 7, CID 0011h, DMA-адрес 2000h уже отображён на нужную RAM. FUA меняет момент, когда контроллер вправе сообщить успешный результат.

PRP1, PRP2 и граница страницы

Размер страницы памяти контроллера задаётся CC.MPS и может отличаться от страницы виртуальной памяти CPU. У PRP1 допускается смещение в первой странице при требуемом выравнивании. В примере 2200 смещение 200h=512 B, до конца 4 KiB страницы остаётся 3584 B, поэтому весь выходной буфер 512 байт помещается. Для отдельного примера PRP1=2F00 при передаче 512 байт первая страница даёт 100h=256 B, ещё 256 B нужны из второй: PRP2=7000 может указать другую выровненную страницу. Две порции данных размещены в разных страницах: непрерывность физического диапазона 2F00..30FF не требуется.

Если после первой частичной страницы нужно больше одной полной страницы, PRP2 представляет указатель на PRP List, массив 64-битных адресов следующих страниц данных. Указатель списка должен быть кратен 8 байтам; первый список может начинаться с ненулевым смещением в странице. Адреса самих страниц данных выровнены по размеру страницы контроллера. Если список продолжается за пределами страницы, последний предусмотренный элемент связывает следующую страницу списка по правилам стандарта. Нельзя одновременно читать PRP2 как адрес второй страницы данных и адрес массива адресов.

Пример дополнительного профиля размещения: PRP1=2F00, длина 8704 байта →256 B первой страницы, затем 8448 B =4096+4096+256. PRP2=6010 указывает выровненный по 8 байтам список с адресами 7000, 9000, B000. Страницы списка и данных должны оставаться доступными для DMA до конца обращения. Поставить CPU VA 00402000 вместо подготовленного DMA-адреса нельзя. Включённый IOMMU может преобразовывать IOVA устройства, но использует отдельные таблицы, а не обход CPU satp по умолчанию.

Буквальные 16 B completion и оборот кольца

Для успешной Read CID 0011 в SQ2, голова очереди после извлечения равна 1, phase=1. Получатся следующие байты CQE. DW0/DW1 — поля результата конкретной команды, здесь 0; SQHD, SQID, CID и status находятся по указанным смещениям. Status=01h означает phase=1 при SC=0/SCT=0 в выбранном минимальном примере; phase не является признаком ошибки.

offset00: 00 00 00 00 00 00 00 00 01 00 02 00 11 00 01 00
         DW0         DW1         SQHD  SQID  CID   STATUS

SQHD показывает продвижение головы submission queue, но одно это поле не завершает все более ранние команды: очередность извлечения и завершения различаются. Пара SQID/CID идентифицирует конкретный результат. SC — status code, SCT — его категория; статус ошибки проверяется до использования буфера. DNR, do not retry, ограничивает повтор по указанному статусу, а не доказывает успешность ранее совершённых эффектов.

Для CQ из 4 слотов host сначала ожидает phase=1 при исходных phase=0 в памяти. После прохождения слотов 0..3 он возвращается к 0 и ожидает phase=0. Пока в старом слоте 0 phase=1, эта запись ещё не новая; содержимое CID само по себе не годится как признак нового результата. Обработав записи, host публикует новую CQ head doorbell, освобождая место. Если не продвигать head, controller исчерпает место в CQ и новые результаты/работа могут остановиться даже при свободной NAND.

На карте ниже выбран тот же Read CID 0011h. Буфер, SQ и CQ — отдельные участки host RAM. Снимок показывает состояние после DMA и публикации первой CQE, когда host ещё не сообщил CQ head=1. Байты SQE остаются в памяти, хотя контроллер уже извлёк их и сообщил SQHD=1. Это значение головы SQ на момент создания CQE; позднее голова могла продвинуться дальше. Host сопоставляет SQID=2/CID=0011h, проверяет phase и статус, использует данные, затем освобождает обработанный слот CQ записью CQ head. Поля doorbell находятся в отдельном MMIO-окне контроллера; в них записывают индексы, а не сектор.

Два doorbell и время жизни буфера

В явном очередном примере SQ 2 имеет базу 6000 и четыре записи по 64 байта: адреса 6000, 6040, 6080, 60C0. CQ 2 имеет базу 5000 и четыре записи по 16 байт: 5000, 5010, 5020, 5030. Эти очереди созданы после административной настройки. Host записал слот SQ 0 → обеспечил видимость полей/data mapping → tail=1 в doorbell → извлечение команды контроллером → DMA → публикация CQE в слоте 0 со статусом и phase → IRQ или polling → host проверил phase/SQID/CID/status → обработал байты → head=1 в CQ doorbell. Адреса очередей используются дополнительными действиями настройки; пять исходных CPU-инструкций их не записывают.

Нельзя освободить/переиспользовать буфер и CID после одного лишь tail doorbell или host timeout. Пока незавершённый DMA не остановлен/не завершён по правилам транспорта/контроллера, контроллер ещё может писать в прежний адрес, уже отданный другому владельцу. Отмена ожидания приложения и принятие abort/reset устройством различаются. Восстановление включает прекращение старого DMA, согласованное состояние очередей, инвалидацию отображений по необходимости и только затем повторное использование памяти. Отмена ожидания сама по себе старый DMA не останавливает.

Файл NVMe-LAYOUT32 кодирует только выбранные поля/PRP-граничные случаи и читает CQE; тесты сверяют байты, несовпадение phase/CID, error/DNR, выравнивания и отказ при неподдержанном продолжении списка. Функции кодируют данные и не отправляют команды накопителю.

У выбранной Read контроллер логически считывает 64 байта SQE, передаёт 512 байт данных и записывает 16 байт CQE: сумма этих трёх областей равна 592 байтам. Doorbell, чтения CPU, обходы IOMMU и протокольные заголовки сюда не включены. Это счёт описанных операций интерфейса памяти, а не измеренный трафик DRAM или NAND. Увеличение payload уменьшает долю фиксированных 80 байт SQE/CQE, но требует большего буфера и может дольше занимать контроллер.

От числа 42 в RAM к буферу записи с числом 43

Контроллер читает LBA 7 и DMA-пишет вход. После completion CPU получает 42, прибавляет 1, записывает 2B000000 по PA 2200..2203 и доходит до EBREAK. Пять инструкций не подготовили PA 2204..23FF. Поэтому перед Write одного 512 B блока отдельная операция копирует исходные 508 байт хвоста в output и сохраняет первые 4 B результата. Затем WRITE descriptor читает PA 2200..23FF; лишь после публикации/доступного DMA устройство вправе забрать содержимое.

Четыре точки вместо одного «готово»

Acceptance — контроллер принял запрос или байты по определённому интерфейсу. Data transfer complete — нужные байты DMA уже переданы. Command completion — опубликован результат с успехом/ошибкой по правилам команды и настроек. Durable — данные и необходимые для их нахождения метаданные находятся в предусмотренном энергонезависимом хранилище. Например, FUA сближает успешное завершение Write и сохранение её данных; обычная Write с энергозависимым кэшем может разделять эти события.

При включённом энергозависимом кэше записи обычная Write может завершиться, пока новая версия находится в памяти контроллера. Сразу следующий read может вернуть 43 из этого кэша, хотя после потери питания останется 42. Поэтому «прочитал обратно» проверяет текущую видимость, но не достаточен как power-fail test. Power-loss protection, PLP, — аппаратные средства и средства firmware для сохранения принятых данных/метаданных при исчезновении питания; наличие одного конденсатора на фотографии ещё не доказывает заявленную область гарантии.

Flush с opcode=00h — отдельная NVM команда для выбранной области namespace/controller, доводящая соответствующие данные и метаданные до энергонезависимого состояния. Для примера выбираем поддержанный NSID 1; значение FFFFFFFFh имеет отдельные правила всех namespaces и не подставляется вместо 1 без проверки. Flush не является командой очистки содержимого кэша и не обещает сделать атомарной группу разных Write. Чтобы связать её с предыдущей Write, сначала нужно дождаться завершения той Write и соблюдать требуемый порядок публикации; иначе «ранний flush» может не охватить ещё не принятую запись. FUA, force unit access, в NVM Write требует завершить именно данные/метаданные этой команды на энергонезависимом носителе до её completion. FUA не означает общий барьер порядка всех других команд.

Вызов fsync — программный контракт OS/файловой системы с данными и метаданными файла. Между ним и командой устройства могут быть журнал, несколько Write, несколько namespaces/устройств, RAID и кэши нижних уровней. Для реализации fsync вся эта последовательность должна довести нужные данные до требуемой точки сохранения. Один бит FUA в отдельной команде ещё не показывает, что сохранены все файловые метаданные. Успех Read из кэша, успешная обычная Write и успешный нужный Flush отвечают на разные вопросы.

Изменяемый опыт и ошибки

В М32-I/O1 после DMA WRITE и WRITE completion носитель остаётся 42, кэш содержит 43. Скачайте JSON. Потеря питания устройства до flush возвращает видимое устойчивое 42; загрузка своего сохранённого JSON и завершение flush позволяет сравнить вариант с устойчивым 43. RAM оставлена в модели как контрольное изображение; настоящая host DRAM не объявлена переживающей питание. В опыте задан кэш, теряющий содержимое при отказе; свойства настоящего SSD проверяются по его документации.

Completion может содержать error: неверный namespace, LBA вне диапазона, media/integrity error, неподдержанный формат. Timeout host означает отсутствие принятого результата к deadline. Команда могла уже изменить устройство, поэтому слепой повтор не является универсальной recovery-процедурой. Сброс очередей меняет состояние незавершённых команд; повторное использование CID/буфера требует завершения старой возможности DMA. Восстановление драйвера и гарантии файловых операций рассматривает том об ОС.

Глубина очереди скрывает latency за параллельными запросами, но не создаёт бесконечную полосу NAND/PCIe. Большая очередь увеличивает ожидание и tail latency при насыщении. Команды flush/FUA могут менять возможное переупорядочение и цену подтверждения; сравнивать IOPS до/после без одинаковой durability-гарантии — сравнивать разные услуги.
