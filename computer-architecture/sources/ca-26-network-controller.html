Сетевой контроллер: от сигнала до буфера RAM

Кадр проходит физический приём, аппаратную проверку, очередь и DMA прежде, чем программный сетевой стек сможет прочитать его байты.

PHY и MAC делают разную работу

Сетевой контроллер, NIC — network interface controller, соединяет компьютер с сетевой средой. PHY, physical layer transceiver, преобразует электрический/оптический сигнал в поток цифровых символов и обратно по конкретному стандарту. MAC, media access control, разбирает границы Ethernet-кадра, адреса и предусмотренные проверки. Кадр — единица канального обмена с заголовком и payload, а не сразу HTTP-запрос и не строка файла.

Полученный сигнал может иметь ошибку; восстановленные bytes проходят проверку кадра, включая FCS — поле контрольной суммы кадра, вычисленной алгоритмом CRC. CRC — код обнаружения определённых ошибок передачи, не криптографическая подпись отправителя. Неверный кадр может быть отброшен раньше DMA по настройкам контроллера. Верный FCS не доказывает, что содержимое безопасно для приложения. VLAN, virtual local area network, — виртуальная локальная сеть; метка VLAN в кадре указывает его принадлежность к такой логической сети. Аппаратный фильтр адресов и VLAN определяет часть принимаемых кадров, а правила доступа протоколов и приложения находятся выше.

Внутренняя очередь поглощает разницу скоростей

Пока Ethernet приносит кадр, PCIe или RAM могут быть заняты. Контроллер использует FIFO — first in, first out, буфер с последовательным изъятием. Его конечная ёмкость означает, что поток нельзя бесконечно принимать без доступных host buffers. Пример реального чипа LAN7430/LAN7431 из datasheet DS00002631D имеет отдельные RX/TX DMA пути и каналы; его конкретные четыре RX-канала приёма и один TX-канал передачи не являются правилом любого NIC. PHY, MAC, FIFO и DMA могут быть частями одной микросхемы, но их функции остаются различными.

Host заранее выделяет буферы, создаёт receive descriptors с адресами/размерами и передаёт их контроллеру. Контроллер выбирает пригодный descriptor, переносит данные и возвращает status/length. Если кадр больше одного буфера, поддержанный формат может использовать несколько descriptors и признак последней части. CPU должен обработать все нужные части прежде, чем назвать кадр полным. Длина DMA-буфера и длина полезного кадра не обязаны совпадать.

Реальный RX descriptor: LAN743x, AN2948 revision B

Рассмотрим 16-байтный описатель принимаемых данных LAN743x по Microchip AN2948 DS00002948B, таблицы 378–381. Четыре слова DWORD размером 32 бита начинаются со смещений 0, 4, 8 и 12 байт. OWN в бите 15 слова DWORD0 передаёт владение: 1 — контроллеру приёма RX DMAC, 0 — host. BUFLENGTH в битах 13:0 задаёт вместимость буфера перед передачей, а после возврата — число использованных байтов. Байты 4..7 содержат RADDRL, 8..11 RADDRH; 12..15 зарезервированы до передачи. После возврата описатель без дополнительной extension-записи содержит FS в бите 31, LS в бите 30, FRMLENGTH в битах 29:16, OWN=0 в бите 15 и EXT=0 в бите 14. FS/LS обозначают первую/последнюю часть кадра. Вместо адресов в DWORD1/2 появляются статус, контрольная сумма и данные VLAN; DWORD3 содержит RSS hash — хеш, число, вычисленное из выбранных полей заголовков. Receive-side scaling, RSS, использует его для выбора очереди приёма; подробнее этот путь разобран ниже.

Для первоначального буфера вместимостью 512 байт и DMA-адресом 6000h получатся показанные ниже 16 байт little-endian. DW0=00008200h: OWN=1 и BUFLENGTH=0200h. Старшие биты адреса нулевые. Данные кадра хранятся отдельно по 6000..61FF; эти 16 B не содержат сам кадр.

offset00  00 82 00 00  00 60 00 00  00 00 00 00  00 00 00 00
          OWN/len      RADDRL      RADDRH       reserved

Учебный одиночный 128 B кадр помещается целиком. В этом примере не добавляются байты выравнивания, VLAN/FCS не удаляются, extension-записи нет; размер 128 B в этом профиле включает сохранённый FCS. Тогда при успешном приёме FS=1, LS=1, FRMLENGTH=128, BUFLENGTH=128 и OWN=0 дают DWORD0=C0800080h. Это число описывает только DWORD0. До чтения кадра host проверяет также статус RXSTATUS в другом слове и соответствующие флаги ошибок. Один флаг OWN не доказывает исправность кадра. Для 512 B кадра при вместимости буфера 256 байт нужны описатели первой и последней частей; первая часть сама по себе ещё не полный кадр.

Host хранит отдельное соответствие «slot→buffer». При извлечении адреса из уже возвращённого DWORD1 получится статус вместо адреса. Перед повторным использованием адреса снова записываются вместе с capacity и затем корректно публикуются. В AN2948 отдельно предупреждено: чтение RX_HEAD CSR может обогнать descriptor writes; продвижение регистра нельзя единолично объявить видимостью всех DMA bytes. Нужно дождаться предусмотренной интерфейсом записи описателя/головы в память и обеспечить видимость DMA для CPU по правилам платформы.

Один оборот ring и исчерпание буферов

Возьмём канал RX 0, длину кольца 4, расстояние DSPACE=16 байт и базу 3000h. Четыре слота находятся по адресам 3000/3010/3020/3030. Выбранное поле поддерживает такую малую длину. RX_CFG_B0.RX_RING_LEN задаёт 4; RX_BASE_ADDRH/L задают 0/3000. Поля меняют в исходном состоянии DMA, разрешающем настройку, не поверх работающего канала. Аппаратура использует HEAD/TAIL как индексы, не байтовые адреса; address(slot)=base+slot×DSPACE.

При HEAD=TAIL интерфейс считает ring пустым. Публикация сразу всех четырёх слотов с TAIL 0 выглядела бы пустотой: один слот оставлен различителем. Уменьшить TAIL и забрать уже аппаратные descriptors назад нельзя; остановка/reset канала имеют свой протокол. Объединение уведомлений IRQ может объединить несколько completions в одно уведомление; счётчик IRQ не равен числу кадров.

Полный receive-путь

Сигнал приходит в PHY → MAC получает границы/байты и проверяет допустимость → classifier выбирает RX queue → FIFO хранит принятую часть → DMA читает доступные descriptors → выдаёт Memory Write в host buffers → публикует completion/status → IRQ/polling сообщает host о работе. Для non-coherent платформы host дополнительно выполняет cache maintenance по правилам платформы. Только затем программный сетевой стек разбирает сетевые/транспортные заголовки. В этом порядке «пакет уже на кабеле», «кадр принят MAC», «bytes в RAM» и «приложение получило данные» — разные наблюдения.

На передаче host создаёт payload, описатели и публикацию. DMA читает host RAM, контроллер готовит кадр и передаёт через PHY. Возврат TX descriptor означает установленный datasheet этап; его нельзя без проверки назвать подтверждением получения удалённым приложением. Даже факт отправки последнего символа не доказывает доставку кадра соседу, а кадр соседу не доказывает подтверждение TCP. Прикладная надёжность потребует других уровней.

Разделение очередей и аппаратная помощь

Распределение RSS направляет входные потоки между очередями по хешу выбранных заголовочных полей. Hash — вычисляемое число для выбора, не гарантия равного количества работы и не криптографическая защита. Очереди дают возможность параллельной обработки, но один поток может остаться в одной очереди, и skew нагрузит её сильнее остальных. Привязка очередей к CPU и политика обработки — операционная система; аппаратный механизм лишь предоставляет выбор и идентификаторы.

Checksum offload передаёт контроллеру расчёт/проверку определённых контрольных сумм. Segmentation offload позволяет host передать крупный логический набор для аппаратного формирования нескольких кадров. Поэтому захват данных в разных точках пути может показывать разные размеры и незаполненные checksum до offload. Успех одного offload не доказывает корректность остальных; формат descriptor и supported capabilities читают у конкретного устройства.

Где теряются данные и время

Нет свободных host descriptors — аппаратуре некуда DMA-писать следующий кадр. Заполнен FIFO — возникают потери или предусмотренное управление потоком, которое зависит от среды/настроек. Драйвер долго не возвращает buffers — очередь исчерпывается, хотя line rate и PCIe исправны. Ошибка IOMMU блокирует DMA, даже если PHY link up. Много маленьких кадров даёт высокий packets/s при умеренных bytes/s и большую стоимость descriptors/IRQ на каждый полезный байт.

Для отдельного примера 1 Gb/s Ethernet выберем полный дуплекс: обе стороны могут передавать одновременно. Минимальный кадр занимает 64 B. Перед ним передаются 7 B preamble, преамбулы для синхронизации приёмника, и 1 B SFD, Start Frame Delimiter, маркера начала кадра. Между кадрами нужен IFG, Inter-Frame Gap, интервал длительностью 96 времён передачи одного бита. Это время соответствует 12 байтам при той же скорости; оно не означает передачу ещё 12 байт кадра. Поэтому временной бюджет равен (64+7+1)×8+96=672 битовым временам, или 84 байтовым временам. Получаем 1·10⁹ bit/s ÷672≈1.488·10⁶ кадров/с. Устройство и приложение имеют дополнительные ограничения; в 64 B уже входят канальные поля, а заголовки высших уровней уменьшают полезные данные. Размеры преамбулы и SFD показаны в Microchip AN1120, DS01120A, рис. 3–4. Это расчёт выбранного режима, а не измерение сетевого порта.
