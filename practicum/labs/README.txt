ПОМОЩНИКИ СКВОЗНОГО ПРАКТИКУМА
Редакция 1 ноября 2026. Они не создают готовую инфраструктуру.

observe.py — небольшой ограниченный HTTP-измеритель своего учебного сервиса.
Выполнять из копии labs внутри гостя либо с разрешённого учебного клиента:
python3 observe.py http://127.0.0.1:8087/healthz --count 200 --concurrency 2 --timeout 3
Полный смысл границ и отчёта: ../index.html#P13-observability.
Это замкнутый поток: каждый работник ждёт ответ до следующего запроса.
Тайм-аут относится к операции сокета, не ко всей серии; нет нагрузки
по независимому расписанию. Redirect не становится успехом. Читается
до 64 KiB тела, большие/потоковые ответы требуют другого договора.
statuses учитывает полученный HTTP-код даже при последующей ошибке тела;
failure_kinds хранит причину неудачи. Квантили только по успешным ответам.

verify_go_release.py — проверка уже собранного настоящего handbook-service.
Скопируйте в собственный service/tools/verify-release.py И СОХРАНИТЕ КОММИТ
до сборки. Он проверяет manifest, чистый Git HEAD, версию Go и бинарника,
параметры, размер, хеш и происхождение, не собирая новый артефакт.
Из корня личного service:
python3 tools/verify-release.py --expected-version 1.0.0
Если Go вне PATH, задайте HANDBOOK_GO с абсолютным путём к настоящему go.
Это проверка согласованности собственного выпуска, не подпись издателя.
Основной пример: ../index.html#P15-jenkins-delivery.

ПРОВЕРКИ ДЛЯ АВТОРА
Из корня репозитория:
python3 -m unittest discover -s practicum/labs -p 'test_*.py' -v
python3 -m unittest discover -s labs-personal/tests -v
Для Go-проверок необходим реальный Go; при отсутствии набор явно skipped.
Без сети никакие инструменты автоматически не загружаются.

test_observe.py использует временные локальные HTTP/TCP-серверы.
test_verify_go_release.py — временный Git-проект и настоящий Go-бинарник.
test_curriculum.py проверяет маршрут, ссылки и сохранность чужого состояния;
не запускает QEMU/Docker и не ставит пакеты. Общий приёмочный запуск
настоящих машин — отдельная следующая работа, см. ../ПРОВЕРКИ.txt.
