Pod Security, capabilities, seccomp и доверие к node

Контейнерная изоляция составляется из нескольких ограничений и доверия к ядру. Namespace не является границей защиты от произвольного кода на node.

Restricted как воспроизводимый baseline

Pod Security Standards задаёт профили Privileged/Baseline/Restricted; Pod Security Admission применяет enforce/audit/warn на namespace согласно labels. Это встроенный admission-механизм, а не старый PodSecurityPolicy: PSP удалён с Kubernetes 1.25. Наш lab pin enforce-version=v1.36, чтобы изменение cluster minor не меняло правила молча. Audit/warn помогают видеть нарушения, enforce отклоняет неподходящий Pod. Labels не настраивают NetworkPolicy и не шифруют volume.

ledger-api запускается runAsNonRoot с uid65532, не допускает privilege escalation, drop ALL capabilities, readOnlyRootFilesystem и seccomp RuntimeDefault. Linux capability — разделённое привилегированное полномочие, например NET_ADMIN; uid0 без capabilities слабее полного root, но его не следует считать достаточной защитой. allowPrivilegeEscalation=false препятствует соответствующему получению дополнительных privileges при exec, а не исправляет уже выданный privileged режим. Seccomp фильтрует системные вызовы, RuntimeDefault выбирает runtime-профиль; это не proof того, что любое Go-приложение безопасно.

Почему нужен именно такой image

Scratch image содержит только статически собранный Go binary. Поэтому отсутствуют shell/curl/package manager и CA trust bundle. Наш сервис не делает внешний HTTPS, но если добавится такой клиент, потребуется осознанно доставить CA roots либо иной доверенный механизм; отсутствие /bin/sh не должно внезапно ломать exec probe. HTTP probes выполняет kubelet снаружи контейнера, так что curl внутри не нужен. Read-only rootfs требует отдельные writable mounts для программ, которые пишут tmp/cache; ledger-api этого не делает.

Image provenance — свидетельство происхождения от source/build/release. Digest закрепляет содержимое, но сам не говорит, кто его собрал и прошёл ли review. Подпись/attestation проверяется доверенным policy/controller по конкретному формату и issuer identity; встроенный imagePullPolicy=Always не выполняет такую проверку. Always означает resolve/pull policy по правилам kubelet/runtime и допускает content cache, а не «безопасный image». Private registry credentials ограничиваются scope и хранятся как чувствительные данные.

Где проходит node trust

Кластер доверяет kubelet/runtime узла исполнять назначенные Pods и обращаться к нужным Secrets/volumes. Компрометированный node может наблюдать colocated workloads и их данные; RBAC одного namespace не устраняет этот риск. Node authorizer/NodeRestriction ограничивают некоторые API-действия kubelet, но не превращают root на node в слабого пользователя. Не запускайте взаимно недоверенные privileged workloads вместе без отдельного threat model; нужны dedicated nodes/VM/runtime isolation и policy.

hostPath даёт доступ к файловой системе node, hostNetwork/hostPID/hostIPC разделяют host namespaces, privileged расширяет доступ к устройствам/ядру. Это функции для инфраструктурных агентов с повышенным доверием, а не быстрый fix PermissionDenied. Наш local PV лабораторный путь подготовлен администратором и ограничен topology; произвольный mount / в приложение полностью меняет границу. Не выдавайте cluster-admin CI, который нужен только для изменения одного Deployment.

Разобрать отказ admission

Создайте отдельный dry-run пример Pod без runAsNonRoot/seccomp/drop capabilities в lab. API должен сообщить, какие Restricted требования нарушены. Добавьте поля согласно смыслу и повторите server dry-run. Если после admission Pod всё равно Waiting из-за permission на volume, это уже runtime/filesystem, а не RBAC. Добавлять privileged, чтобы «заработало», значит убрать проверяемую гарантию вместо исправления ownership/mount mode. Для каждого исключения запишите нужный syscall/device/path, narrow privilege и способ контроля.

Измерение overhead security также предметное: latency syscalls, CPU, memory runtime sandbox, startup, число отклонений admission и time-to-fix. Снимайте baseline с одинаковой программой/нагрузкой. Гипотеза «seccomp тормозит» не заменяет профиль, а выключение защиты без измерения не является оптимизацией. Самый дешёвый первый шаг для нашей службы — не монтировать API token, не иметь writable rootfs и не включать лишние network listeners.
