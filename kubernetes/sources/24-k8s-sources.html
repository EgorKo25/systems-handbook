Источники, версии и границы доказательств

Версионный факт связан с первичным источником и датой. Работающая синтаксическая проверка не превращается в обещание промышленной эксплуатации.

Зафиксированная редакция

Проверка 01.11.2026: latest Kubernetes 1.37.2, выбранный kubeadm baseline 1.36.6; kind 0.33.0 с опубликованным node 1.36.4 digest; containerd 2.4.2/runc 1.5.2; CNI reference plugins1.9.1; Calico 3.33.0; Gateway API latest1.7.0. Встроенные workload APIs: apps/v1, batch/v1, autoscaling/v2, policy/v1, networking.k8s.io/v1, discovery.k8s.io/v1. kubeadm config v1beta4, kubelet config v1beta1 и kube-proxy config v1alpha1 имеют собственные жизненные циклы; номер config API не равен уровню стабильности всего продукта.

Машиночитаемый журнал первичных источников входит в офлайн-набор. Он сохраняет официальные адреса и даты сверки, а для полученных исходных ответов — размер и SHA-256, если эти сведения были зафиксированы. Контрольная сумма связывает запись с конкретными байтами; она не обещает, что живая веб-страница с тех пор не изменилась, и сама по себе не подтверждает доверие к издателю. У новых записей, проверенных по тексту документации без сохранения сырого ответа, hash не выдумывается.

Для чтения объяснений, словаря, карточек и схем сеть не нужна. Внешние ссылки предназначены для дополнительной проверки и получения дистрибутивов. Проверенные свойства API и опубликованные версии отделены от опыта исполнения: документация описывает поведение, но не доказывает, что конкретный CNI, Gateway, HPA или восстановление уже сработали на вашем стенде. Исторические результаты локальных тестов и ещё не выполненные кластерные проверки перечислены ниже.

API и исполнение

  • Kubernetes API concepts: identity, resourceVersion, list/watch и concurrency.
  • Server-side apply: managedFields, merge и conflict.
  • Kubernetes source tag1.36.6: точный код выбранного patch; cmd/kubeadm/app/constants содержит pause3.10.2, etcd 3.6.8-0 и CoreDNSv1.14.2.
  • containerd CRI config2.4.2: version3, runtime plugin path, systemd cgroups и pinned sandbox.
  • CNI spec, OCI runtime spec: разные границы sandbox networking и запуска process.

Сеть, данные и эксплуатация

  • Versioned Service proxy1.36: iptables/nftables/IPVS и traffic policies.
  • Calico requirements3.33 и точный Calico manifest: совместимость и вход локальной трансформации.
  • Gateway API: CRD/controller/conformance boundaries; latest не автоматически поддерживается любым controller.
  • CSI spec: controller/node volume operations; PV/PVC: binding/access/reclaim.
  • etcd 3.6 recovery: new logical cluster, revision bump и mark-compacted для Kubernetes caches.
  • Skew policy и deprecated API migration: допустимые переходы и удалённые формы.

Что доказано этой поставкой

Исходники, локальные Go tests/race/vet, graceful active-request drain, YAML parse/OpenAPI shape/negative fixtures, bundle integrity и metadata/schema diagrams — проверяемые локальные факты. Кластер не создавался: kubeadm init/join, CNI packet path, network enforcement, CSI, actual HPA/drain/upgrade/etcd restore — рецепты с критериями, не результаты исполнения. В ПРОВЕРКИ.txt сохраняются точные границы. Ресурсные числа условны, capacity не измерена на пользовательских 8/16GiB. Это честный фундамент для следующего собственного опыта.
