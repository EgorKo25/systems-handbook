Получить дистрибутив, выбрать среду и собрать офлайн-набор

Установка начинается с происхождения байтов, совместимости и бюджета машины. Копия kubeadm без образов и зависимостей не является офлайн-кластером.

Выбор, который можно воспроизвести

kubeadm создаёт предусмотренный upstream Kubernetes control plane и присоединяет nodes; он не создаёт VM, не устанавливает за вас containerd и не выбирает CNI. CNI, Container Network Interface, — договор передачи runtime сетевому плагину параметров sandbox и получения сетевого результата. Calico реализует IP-связность и NetworkPolicy. CRI, Container Runtime Interface, — gRPC-интерфейс kubelet к runtime, через который запрашиваются sandbox, образы и контейнеры. CSI, Container Storage Interface, относится к управлению хранилищем и не участвует в выборе IP Pod.

При 8 GiB всей машины начните с kind одним node и лимита памяти VM/container engine около 3–4 GiB, если ОС и IDE помещаются в остаток. Это начальная гипотеза, а не гарантия. При 16 GiB можно выделить cp1 2 vCPU/2.5 GiB и wk1 2 vCPU/2.5 GiB, оставив примерно 11 GiB до учёта гипервизора и прочих программ. На каждую VM планируем диск 25 GiB thin, затем измеряем фактически занятое. Нельзя складывать виртуальные размеры файлов и считать их свободной RAM. Одновременные image pulls и сборки могут исчерпать диск или вызвать memory pressure при маленьком приложении.

Фиксируем версии и происхождение

На 01.11.2026 stable.txt показал Kubernetes v1.37.2, stable-1.36.txt — v1.36.6. Для VM выбран второй; kubeadm, kubelet и kubectl фиксируем одним patch. Официальные release endpoints дали containerd v2.4.2, runc v1.5.2, reference CNI plugins v1.9.1, Calico v3.33.0 и kind v0.33.0. Calico 3.33 официально тестируется с Kubernetes 1.35/1.36/1.37. Это проверка опубликованной совместимости, не выполненный интеграционный тест нашей пары VM. Аппаратная архитектура amd64/arm64 должна совпадать у ОС, бинарника и образа.

curl -fL -o kubectl https://dl.k8s.io/release/v1.36.6/bin/linux/amd64/kubectl
curl -fL -o kubectl.sha256 https://dl.k8s.io/release/v1.36.6/bin/linux/amd64/kubectl.sha256
printf '%s  kubectl
' "$(cat kubectl.sha256)" | sha256sum -c -
chmod +x ./kubectl
./kubectl version --client -o yaml

-f завершает curl ошибкой на HTTP-ошибке, -L следует redirect, -o задаёт файл. Сумма проверяет целостность относительно доверенно полученного значения; если атакующий заменил и бинарник, и сумму, арифметика не докажет происхождение. Сохраняйте TLS-цепочку доверия, официальный URL, release notes, опубликованные подписи/attestations там, где они предоставлены, и отдельно подтверждённую сумму. Не запускайте скачанное до проверки. На Windows используют официальный kubectl.exe той же версии, Get-FileHash -Algorithm SHA256 и собственный kubeconfig; кластер остаётся Linux-кластером.

Что должно доехать без сети

Офлайн-набор содержит Ubuntu ISO с суммами и подписью поставщика, все .deb зависимости выбранного ОС/архитектуры, kubelet/kubeadm/kubectl и kubernetes-cni/cri-tools в согласованной версии, containerd/runc и systemd unit, CNI binaries, точный Calico manifest, все его images, control-plane/CoreDNS/pause/etcd images из kubeadm config images list --config vm/kubeadm.yaml, собственный Go binary/image, диагностический образ, исходники, Python wheels при необходимости и документацию. Kubernetes пакеты получают из отдельного minor-репозитория pkgs.k8s.io; legacy apt.kubernetes.io не используем.

Собирать .deb нужно на отдельной staging-VM с тем же Ubuntu 24.04 и архитектурой: чистая машина выявляет транзитивные зависимости. apt-get --download-only на машине, где всё уже установлено, может не скачать нужные зависимости. Запишите версии через apt-cache policy и dpkg-query; перенесите подписанные repository metadata либо сформируйте проверяемый локальный набор. Точный суффикс Debian package revision выбирается из реального репозитория, не угадывается по версии upstream.

kubeadm config images list --config vm/kubeadm.yaml > kubeadm-images.txt
python3 bundle_manifest.py create /path/to/staged-bundle
python3 bundle_manifest.py verify /path/to/staged-bundle

Первый вызов перечисляет ожидаемые ссылки конкретной конфигурации, а не скачивает images. В VM ctr --namespace k8s.io images export сохраняет подготовленные образы, images import загружает их на каждый нужный node. namespace containerd k8s.io — пространство metadata runtime, оно не равно Kubernetes namespace lab. OCI archive и Docker save не следует считать одним форматом без проверки импортера. Наш bundle_manifest.py записывает размер и SHA-256 каждого файла и обнаруживает повреждение, но не подтверждает подпись издателя. Реальный критерий полноты — повторить bootstrap и запуск приложения на изолированной VM с отключённым внешним доступом; здесь этот опыт не выполнен.
