Чтение и изменение: точный предикат важнее короткого запроса

CRUD, атомарный переход и сохранение прикладного смысла

Что является запросом

CRUD сокращает Create, Read, Update, Delete — создание, чтение, изменение, удаление. Предикат — условие, которое должен выполнить документ; сервер проверяет его при выборе записи. {tenant:"tenant-01",state:"open"} связывает условия логическим И. Проекция выбирает возвращаемые поля: {title:1,_id:0} оставляет title и исключает _id. Курсор — серверный и клиентский механизм порционного получения результата. Find не обязан сразу получить все документы: следующая порция может потребовать getMore, а ошибку проверяют и после чтения курсора.

Условие сортировки определяет порядок до limit. Сортировать лишь по createdAt недостаточно, если даты совпадают; добавляем _id как однозначное разрешение равенства. Limit=20 ограничивает число результатов, но не гарантирует, что сервер исследовал только 20 документов. Пропуск через skip на дальних страницах стоит всё больше: для продолжения по последней паре (createdAt,_id) строят range-предикат и сохраняют тот же порядок.

Операторы обновления и защита от потери изменения

$set меняет указанные поля, $unset удаляет поле, $inc увеличивает числовое значение, $push добавляет элемент массива. Оператор — именованное правило изменения, которое исполняет сервер. replaceOne заменяет весь документ, кроме требований к _id; забытые приложением поля могут исчезнуть. Upsert означает создать документ, если предикат никого не нашёл; это не «всегда update». Несколько конкурирующих upsert без уникального ключа могут создать логические дубликаты.

Наш HTTP close отправляет предикат {_id:id,state:"open",version:1} и одновременно {$set:{state:"closed"},$inc:{version:1}}. Успешный первый вызов даёт version=2; второй не соответствует предикату и modified=0. Сравнение версии — optimistic concurrency: клиент меняет только известное ему состояние. Чтение версии в Go, потом update лишь по _id оставляет окно гонки и способно затереть конкурента. Атомарность одиночного update закрывает окно только для проверки внутри самого предиката.

matchedCount — сколько документов подошло, modifiedCount — сколько реально изменено. Ноль modified не всегда ошибка: новое значение уже могло совпадать со старым. updateMany атомарен по каждому документу, но между документами могут вклиниться другие операции. После отказа часть уже изменена. Миграция нашего сервиса фильтрует schemaVersion=1 и ставит 2 вместе с priority=0; повтор обрабатывает остаток. Он не возвращает старые значения и не является обратной миграцией.

Валидация и массовое исполнение

Серверный validator задаёт правила формы; $jsonSchema может требовать строковый tenant, дату createdAt и целочисленную version. Он проверяет будущие записи согласно validationLevel/action, а не переписывает существующие документы. Backfill — дозаполнение ранее созданных документов по новому договору формы. Вводить жёсткую обязательность priority до backfill сломает старое приложение. Сначала код читает обе версии и пишет новую, затем порциями преобразуются старые, проверяются остатки и только потом ужесточается правило.

BulkWrite позволяет передать драйверу несколько операций одним вызовом. Драйвер делит их на команды и пакеты по ограничениям сервера; один вызов не гарантирует один сетевой пакет. По умолчанию ordered-пакет останавливается на первой ошибке записи; уже исполненные не отменяет. Unordered позволяет продолжать независимые операции и требует разобрать ошибки по индексам входа. В seed используем batches по 500 и deterministic _id: $setOnInsert добавляет документ только при первом upsert, повтор не меняет ранее принятые данные. Это конкретная идемпотентность начального наполнения, а не гарантия exactly once для любой бизнес-операции.

Практика CRUD выполняется через собственный HTTP-сервис в книге IV: сначала он будет собран и запущен. Сейчас полезно прочитать InsertOne, обработку DuplicateKey, предикат close и cur.All в исходнике. Для каждого отказа определите, известно ли, что изменение не состоялось, или ответ потерян и результат ещё надо сверить по ID. Не выполняйте удаление данных ради «чистого повторения».
