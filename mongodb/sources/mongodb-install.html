Версии и происхождение

Воспроизводимая линия тома — MongoDB Community 8.0.34, патч поддерживаемой основной ветки 8.0 от 13 октября 2026. Это выбранная учебная ветка, а не утверждение, что 8.0 — новейшая основная версия. На 1 ноября 2026 отдельно получены mongosh 2.14.1, Database Tools 100.20.0 и Go-драйвер v2.9.2. Номера этих продуктов независимы. Актуальные предупреждения и путь обновления проверяют перед новой установкой по release notes 8.0 и реестру поставки.

Community — доступная в исходниках самостоятельная редакция под SSPL-1.0; это не лицензия Apache и не обозначение OSI-approved open source. Enterprise Advanced — отдельная коммерческая подписка; Atlas — управляемый сервис. Самостоятельное использование Community, распространение программы и предоставление её функциональности как сервиса — разные случаи текста лицензии. Сам текст сохранён в licenses/; юридические обязательства определяет он. Бесплатный учебный стенд не получает автоматически Enterprise audit, встроенное шифрование at rest или управляемый Atlas PIT restore. Приложение с Apache-2.0 драйвером не меняет лицензию сервера.

У закреплённой ветки есть также требования к ядру Linux: актуальные release notes предупреждают о несовместимости TCMalloc с ядрами 6.19…7.0.13; исправление указано для 7.0.14 и новее. Названия Ubuntu 24.04 недостаточно для проверки этого условия. На затронутом ядре не обходите startup-отказ флагами; выберите отдельно подготовленное совместимое личное окружение. Эта лаборатория ядро и host-пакеты не меняет.

Подготовка каталога до скачивания

Следующий блок — Bash обычного пользователя, cwd mongodb/, Python и GnuPG уже установлены; каталог LAB ещё не существует. umask 077 ограничивает права новых файлов. prepare.py создаёт только новый личный каталог, случайный межузловой ключ, два пароля и конфигурацию YAML (текст вложенных ключей с отступами) с абсолютными путями. Код 0 и строка prepared означают подготовленные файлы, но не запущенный сервер. При отказе не удаляйте старый стенд: выберите новое имя или исследуйте существующее состояние.

set -euo pipefail
umask 077
export LAB="$HOME/handbook-lab/mongodb"
python3 labs/prepare.py "$LAB"
python3 labs/install.py "$LAB"
export PATH="$LAB/tools/server/bin:$LAB/tools/shell/bin:$LAB/tools/dbtools/bin:$PATH"
export MONGOSH_CONFIG_DIR="$LAB/shell-config"
export MONGOSH_DISABLE_TELEMETRY=1
mongod --version
mongosh --version
mongodump --version

install.py рассчитан только на Ubuntu 24.04 x86-64, скачивает закреплённые tgz в downloads/, сравнивает SHA-256 и проверяет подпись сервера до распаковки. SHA-256 — отпечаток байтов, его совпадение проверяет целостность относительно доверенного ожидаемого значения. Подпись связывает архив с ключом выпуска. Для этого релиза фактически подтверждён fingerprint 4B07 52C1 BCA2 38C0 B4EE 14DC 41DE 058A 4E7D CA05. В старом примере документации встречается другой fingerprint: не заменяйте проверку под копируемый вывод. Новая ротация ключа требует отдельной проверки официального объявления, а не автоматического принятия любого ключа по URL.

Архивы распаковываются в tools/server, tools/shell, tools/dbtools, не в /usr/bin. Ожидаются версии из начала главы, modules: [] у Community и код 0. Ошибка загрузчика, CPU или OpenSSL — остановка; нельзя считать скачанный файл установленной программой. Для другой ОС выбирают её официальный вариант и заново фиксируют хеши. Server tarball содержит mongod и mongos; shell и dump/restore получены отдельно.

Запуск до первого пользователя

Primary — ведущая роль участника набора, принимающая обычные записи. URI — строка адреса с параметрами подключения; наш URI указывает только loopback. В том же Bash и cwd mongodb/ выполните блок по частям. --config читает созданный YAML; --fork оставляет процесс в фоне после успешного первоначального запуска, с журналом в LAB. Код 0 не заменяет последующую приёмку. Если порт занят или путь недоступен, читайте $LAB/log/mongod.log; не переходите к bootstrap. Локальное исключение — временная возможность создать первого пользователя на ещё не инициализированном сервере с access control; оно не действует после создания пользователя.

set -euo pipefail
mongod --config "$LAB/mongod.yml" --fork
PHASE=init mongosh 'mongodb://127.0.0.1:27117/admin?directConnection=true' --quiet --norc --file labs/bootstrap.js
mongosh 'mongodb://127.0.0.1:27117/admin?directConnection=true' --quiet --norc --eval 'if (!db.hello().isWritablePrimary) { throw Error("STOP: wait for primary, repeat only this probe") }'
PHASE=users mongosh 'mongodb://127.0.0.1:27117/admin?directConnection=true' --quiet --norc --file labs/bootstrap.js
ACTION=accept mongosh 'mongodb://127.0.0.1:27117/admin?directConnection=true' --quiet --norc --file labs/admin.js

После init первичные выборы могут ещё не закончиться: probe с кодом 1 означает остановить последовательность и повторить только чтение готовности через несколько секунд. PHASE=users создаёт operator в admin с MongoDB-ролью root (полное администрирование БД, не OS-пользователь root), затем app с ролью readWrite только в workshop. Не запускайте его повторно при частичном успехе: сначала выясните, какой пользователь уже создан. --norc запрещает стартовый пользовательский JavaScript, --quiet сокращает приветствие, --file исполняет конкретный файл. Скрипт принимает у db.auth и старое число 1, и реальный ответ mongosh {ok:1}. Приёмка записывает пробный документ с write concern majority — подтверждением нужного большинства участников с данными — и j:true, ожиданием дискового журнала. В одном участнике это он сам; распределённые условия разобраны в книге III. Приёмка выводит версию, primary, bind и writeRead: true, код 0; пароли не печатаются.
