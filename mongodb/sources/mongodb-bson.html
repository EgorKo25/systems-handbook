BSON: какие байты получает сервер

Тип, порядок полей, идентификатор и отсутствие значения

От объекта к последовательности байтов

BSON — двоичное представление упорядоченных пар «имя–типизированное значение». JSON — текстовый формат именованных значений; в HTTP это текстовый вход, BSON в драйвере — другой формат. Длина документа записана int32 в little-endian: младший байт первым. Далее для каждого поля идут байт типа, UTF-8 имя с нулевым окончанием и значение по правилам типа; весь документ заканчивается нулём. Строка хранит свою длину в байтах вместе с конечным нулём. Это объясняет, почему число букв не равно длине BSON.

В -mode=bson сервис сериализует упорядоченный bson.D с int32(42) и строкой «я». Результат: 16 00 00 00 10 6e 00 2a 00 00 00 02 73 00 03 00 00 00 d1 8f 00 00. Первые четыре байта означают 22 байта всего; 10 — int32, имя n занимает два байта, число 42 — четыре. 02 — строка; имя s — два; её длина 3 означает два UTF-8 байта d1 8f и завершающий 00. Последний 00 закрывает документ. Это собственный минимальный пример по грамматике BSON, не перехват реального пакета.

Структура Go с тегами bson:"createdAt" задаёт имена полей, time.Time превращается в BSON Date, int64 версии — в 64-битное целое. bson.D сохраняет заданный порядок и нужен для compound key и команд, где порядок значим. bson.M — карта Go без обещанного порядка обхода. Дублирующиеся имена полей не допускайте: инструменты могут интерпретировать их неодинаково. Сервер может перемещать _id первым, а операции — менять расположение полей; BSON-порядок не является контрактом форматирования ответа HTTP.

Числа, время и ObjectId

Int32 — целое со знаком на 32 бита, int64 — на 64; double — двоичная плавающая точка, decimal128 — десятичное представление на 128 бит. Не храните денежные копейки как случайно декодированный JSON double: задайте int64 минимальных денежных единиц либо decimal128 с договором округления. Разные числовые типы сравниваются численно в предусмотренных операциях, но остаются разными BSON-типами для проверки схемы и сериализации. В JavaScript Number не представляет точно все int64: в mongosh используйте NumberLong("9007199254740993"), а не уже округлённый числовой литерал.

BSON Date — int64 миллисекунд UTC от эпохи Unix, без исходного часового пояса. Нужный локальный пояс хранится отдельно. BSON Timestamp — внутренний тип времени и порядкового счётчика для репликации, не замена дате задания. ObjectId — 12 байт: четыре байта секунд времени, пять случайных байтов процесса и трёхбайтовый счётчик. В отличие от большинства BSON-чисел компоненты timestamp/counter ObjectId имеют big-endian порядок. Это удобный уникальный ID, но не строгие часы завершения операций и не последовательный глобальный номер заказа.

Упорядоченная форма важна и при сравнении вложенного документа целиком: равенство встроенному объекту учитывает порядок его полей; для независимых условий используйте dotted paths. При большинстве сравнительных предикатов сервер ограничивает сравнение подходящими типами (type bracketing), объединяя числовые типы по установленным правилам: строка "42" не становится автоматически числом42. Порядок BSON-типов при sort и правила сравнения чисел нужно отличать от автоматического преобразования входа JSON.

Null, missing и массив

null — присутствующее поле с пустым значением; missing означает, что пары с таким именем нет. Запрос {a:null} подходит обоим случаям. {a:{$type:10}} выбирает BSON null, {a:{$exists:false}} — отсутствие поля. Go-тег omitempty способен удалить нулевое значение при сериализации: решите, должно ли отсутствие означать default, «не известно» или ошибку. Для миграции не заменяйте все missing на null без анализа читателей.

Массив хранится как вложенный документ с именами 0,1,… . Условие {a:{$gt:5,$lt:3}} может совпасть с [1,8]: разные элементы удовлетворяют разным частям. $elemMatch требует один элемент, удовлетворяющий обеим частям. Условие {"address.city":"Тула"} проходит по пути вложенного поля; имя с точкой внутри данных создаёт неоднозначность для части инструментов. В примерах избегаем таких имён.

После приёмки, Bash/cwd тома: ACTION=types mongosh 'mongodb://127.0.0.1:27117/admin?directConnection=true' --quiet --norc --file labs/admin.js. Оно создаёт отдельную коллекцию semantics, ожидает nullOrMissing=[missing,null], differentElements=[array], sameElement=[] и код 0. Порядок первых двух ID не важен. Второй запуск намеренно откажет, если коллекция уже наполнена: исходное состояние нужно изучить, а не автоматически стереть.
