MongoDB: от документа до восстановленного сервиса

Том XXI · самостоятельный маршрут с одним сохраняемым стендом

MongoDB — серверная система хранения документов. В этом томе документ означает именованные поля с типизированными значениями: заказу можно дать номер, время и массив позиций, сохранив их одним объектом. Документ не отменяет проектирование данных: сначала решают, что должно изменяться вместе, затем выбирают представление, индексы и гарантии ответа.

Наш сервис — программа, принимающая запросы клиентов по HTTP, протоколу запроса и ответа, — хранит задания мастерской. У задания есть клиент tenant, заголовок, состояние open/closed, дата создания и версия изменения. Данные переживают остановку приложения и сервера. Начальное наполнение, или seed, создаёт собственные воспроизводимые данные. Первая поставка создаёт документы версии 1; следующая добавляет приоритет и индекс; затем мы разбираем повтор запроса, транзакцию с журналом действий и восстановление в отдельный экземпляр. Это учебные имена и данные, без реальных заказчиков.

Что подготовить и что считается успехом

Для исполнения нужен личный Linux Ubuntu 24.04 x86-64 с уже доступными Python 3.12+, GnuPG, подходящей системной OpenSSL и Go 1.25+. Никакая команда не требует root или установки службы. На рабочем Windows путь этой книги — чтение; для практики выделяют собственную Linux VM и переносят туда исходники. Установка VM меняет состояние компьютера и не является «работой без следов».

Постоянный каталог читателя — $HOME/handbook-lab/mongodb. В нём живут данные, журналы, конфигурация и приватные пароли. Книга и её переносимая копия содержат только исходники. Все команды выполняет ваш обычный пользователь в каталоге тома mongodb/, если явно не написано иначе. Сначала откройте Bash и выполните set -euo pipefail: отказ останавливает зависимую последовательность. Каждое новое окно требует повторного выбора LAB, MONGOSH_CONFIG_DIR и прочих переменных, показанных в лаборатории.

Нужны свободные порты 127.0.0.1:27117 для данных, 127.0.0.1:18089 для HTTP сервиса и позднее 127.0.0.1:27118 для восстановления. Loopback — адрес только этой машины. Он ограничивает сетевую достижимость, но процессы того же пользователя читают ваши файлы. Проверка занятости и отказ запуска лучше смены чужой службы. Все службы книги одновременно на 8–16 GiB не нужны: один небольшой MongoDB и один Go-процесс достаточны для основного пути.

Replica set — набор реплик: экземпляров, согласующих роль ведущего и историю изменений; вначале у нас один участник. Restore — восстановление сохранённой копии на отдельную цель. Native-проверка означает настоящее исполнение установленной программы, а не модель. Приёмка — подтверждённая версия и конфигурация, аутентификация (проверка личности), успешная запись/чтение, сохранение после перезапуска и отдельный restore. Открытый TCP-порт доказывает только приём соединения. Один узел такого replica set позволяет изучать связанные операции, но не даёт резервной копии или защиты от потери машины.

Порядок чтения

Не копируйте административные выражения из поздних глав в неизвестную БД. Выполняемые исходники лежат в labs/prepare.py, bootstrap.js, admin.js и Go-сервисе. Порядок, постоянное состояние и точный состав внешнего офлайн-комплекта собраны в README лабораторий. Полные границы реально выполненных проверок перечислены в ПРОВЕРКИ.txt: native означает настоящий процесс, статическая проверка — чтение исходников, схема — объяснительную модель.
