Получение и сборка клиента

Соберём программу из известных исходников и подготовим приватные каталоги для её конфигурации, входных данных и результатов.

Подготовка Linux-стенда

Статус лаборатории: исходники object-study предоставлены; native-сборка и приёмка на выбранном endpoint должны быть завершены до сетевых упражнений. Чистые Python-модели работают отдельно.

Выбран Linux AMD64: 64-разрядная платформа, для которой предназначен архив Go. Go toolchain — компилятор, стандартная библиотека и команда go. Сервера Amazon S3 локально не устанавливают: это служба AWS. Для локального MinIO или удалённого RGW сначала выполняют установку и TLS-приёмку соответствующего тома. Клиент не создаёт сервер и не открывает ему сеть.

Новый постоянный каталог

Откройте терминал в корне своей полной копии книги, где есть s3/labs/object-client. Следующий Python-код создаёт новый каталог object-study-lab в домашнем каталоге пользователя. Уже существующее имя вызывает отказ; исходники копируются в отдельное дерево, прежние секреты не перезаписываются. Umask 077 запрещает доступ группы и остальных к новым файлам.

python3 -B - <<'PY'
import os, shutil
from pathlib import Path
os.umask(0o077)
root = Path.home() / "object-study-lab"
root.mkdir(mode=0o700)
for name in ("downloads", "tools", "source", "config", "secrets",
             "certs", "receipts", "outputs", "fixtures", "cache", "bin"):
    (root / name).mkdir(mode=0o700)
shutil.copytree("s3/labs/object-client", root / "source/object-client")
with (root / "fixtures/hello-v1.bin").open("xb") as f:
    f.write(b"object-lab v1\n")
print(root)
PY

-B запрещает Python записывать кэш bytecode, а одиночный - выбирает программу из стандартного ввода. Последняя строка печатает только путь. Файл hello-v1.bin должен иметь 14 байтов. Каталоги config и secrets имеют разные роли: в первом — endpoint и пути, во втором — credentials. Receipt, квитанция операции, — строка JSON с разрешёнными результатами, без Authorization и токенов.

Go и происхождение зависимостей

На официальной странице Go выберите go1.27.3.linux-amd64.tar.gz и сохраните в downloads. Для выбранного выпуска ожидаемый SHA-256 — 65efbc80fdc1fa2cd2631cad5b481777a68e8725f34e89f50fc6ac714e379b40. SHA-256 — хеш полученных байтов; доверие к ожидаемому значению начинается с происхождения страницы.

Каждый блок ниже запускает дочернюю оболочку в круглых скобках и сам задаёт LAB — путь лаборатории; HOME не меняется. set -euo pipefail действует только внутри блока: -e останавливает его при ошибке команды, -u отвергает незаданную переменную, pipefail передаёт ошибку любого участника конвейера. Поэтому после отказа проверки или mkdir извлечение не начинается. sha256sum -c читает строку «хеш имя» из stdin, обозначенного -. tar -xzf извлекает gzip-архив, а -C выбирает новый каталог назначения.

(
  set -euo pipefail
  LAB="$HOME/object-study-lab"
  printf '%s  %s\n'   '65efbc80fdc1fa2cd2631cad5b481777a68e8725f34e89f50fc6ac714e379b40'   "$LAB/downloads/go1.27.3.linux-amd64.tar.gz" | sha256sum -c -
  mkdir -m 700 "$LAB/tools/go-1.27.3"
  tar -C "$LAB/tools/go-1.27.3" -xzf "$LAB/downloads/go1.27.3.linux-amd64.tar.gz"
  "$LAB/tools/go-1.27.3/go/bin/go" version
)

Проверьте код завершения всего блока: только ноль позволяет перейти к сборке. Последний вывод должен назвать go1.27.3 linux/amd64. Это ещё не проверка работы клиента. В архиве верхний каталог go, поэтому путь содержит go-1.27.3/go/bin/go. Ошибка извлечения может оставить частично заполненный каталог; повторный блок остановится на mkdir, сохранив его для разбора.

go.mod описывает модуль и минимально требуемые версии. Выбор build list, набора реально выбранных модулей, выполняется алгоритмом MVS: для каждого пути берётся наибольшая из требуемых минимальных версий. go.sum хранит проверки .mod/.zip и не является самостоятельным lock-файлом. Исходный go.mod закрепляет core SDK v1.47.1, S3 v1.114.0 и smithy-go v1.28.1 из snapshot release-2026-10-02. Первое получение полного графа требует сети; go.sum в исходной поставке не выдуман.

Перейдите в копию helper. GOTOOLCHAIN=local запрещает автоматическую загрузку другого Go; GOWORK=off исключает чужой workspace; GOENV=off отключает пользовательский go env-файл; GOFLAGS= очищает унаследованные флаги команды go. Кэши направляются в свою лабораторию. tidy может дополнить go.mod косвенными требованиями и создаёт go.sum: сохраните оба файла вместе с build list. После этого readonly запрещает сборке незаметно менять описание модуля.

(
  set -euo pipefail
  LAB="$HOME/object-study-lab"
  cd "$LAB/source/object-client"
  export GOTOOLCHAIN=local GOWORK=off GOENV=off GOFLAGS=
  export GOMODCACHE="$LAB/cache/mod" GOCACHE="$LAB/cache/build"
  GO="$LAB/tools/go-1.27.3/go/bin/go"
  "$GO" mod tidy
  "$GO" list -m all
  "$GO" build -mod=readonly -o "$LAB/bin/object-study" ./cmd/object-study
)

Сохраняйте фактический build list и SHA-256 бинарника; без успешной сборки следующие команды не выполняются. Полностью автономная сборка требует заранее полученных зависимостей: повторяют build с GOPROXY=off на подготовленном кэше. Из HTML-книги они не появляются. Vendor, если его отдельно распространяют, требует лицензий и сведений о происхождении. Здесь полный SDK/vendor/runtime в публичные исходники не включён.

Каталоги и программа готовы к настройке. Перейдите к выбору endpoint, CA и профиля; первое сетевое действие находится там, после создания обоих JSON-файлов.

Go modules/MVS; выбранный SDK snapshot. Сборка, проверка типов, доверие TLS и реальные ответы каждого endpoint принимаются отдельно.
