Получение и сборка клиента

Соберём программу из известных исходников и подготовим приватные каталоги для её конфигурации, входных данных и результатов.

Подготовка Linux-стенда

Сборка object-study проверена на Go 1.27.3 для Linux AMD64. Исходники включают версии и контрольные суммы зависимостей, а также их лицензии. В этой главе вы соберёте свою копию; подключение к серверу начнётся в следующей. Работа с настоящими S3, MinIO и Ceph RGW пока не проверена. Подробности выполненной проверки приведены в README клиента.

Дальше работаем в 64-разрядном Linux на процессоре x86-64 (то же обозначение — amd64). Архив для ARM64 содержит программу для другого процессора и здесь не подходит.

Новый постоянный каталог

Откройте терминал в корне своей полной копии книги, где есть s3/labs/object-client. Следующий Python-код создаёт новый каталог object-study-lab в домашнем каталоге пользователя. Уже существующее имя вызывает отказ; исходники копируются в отдельное дерево, прежние секреты не перезаписываются. Umask 077 запрещает доступ группы и остальных к новым файлам.

python3 -B - <<'PY'
import os, shutil
from pathlib import Path
os.umask(0o077)
root = Path.home() / "object-study-lab"
root.mkdir(mode=0o700)
for name in ("downloads", "tools", "source", "config", "secrets",
             "certs", "receipts", "outputs", "fixtures", "cache", "bin"):
    (root / name).mkdir(mode=0o700)
shutil.copytree("s3/labs/object-client", root / "source/object-client")
with (root / "fixtures/hello-v1.bin").open("xb") as f:
    f.write(b"object-lab v1\n")
print(root)
PY

-B запрещает Python записывать кэш bytecode, а одиночный - выбирает программу из стандартного ввода. Последняя строка печатает только путь. Файл hello-v1.bin должен иметь 14 байтов. Каталоги config и secrets имеют разные роли: в первом — адрес API и пути, во втором — учётные данные. Receipt, квитанция операции, — строка JSON с разрешёнными результатами, без Authorization и токенов.

Go и происхождение зависимостей

На официальной странице Go выберите go1.27.3.linux-amd64.tar.gz и сохраните в downloads. Для выбранного выпуска ожидаемый SHA-256 — 65efbc80fdc1fa2cd2631cad5b481777a68e8725f34e89f50fc6ac714e379b40. SHA-256 — хеш полученных байтов; доверие к ожидаемому значению начинается с происхождения страницы.

Выполняйте блоки в Bash. Круглые скобки запускают подоболочку. Каждый блок задаёт LAB — путь лаборатории; HOME не меняется. set -euo pipefail действует только внутри блока: -e останавливает его при ошибке команды, -u отвергает незаданную переменную, pipefail передаёт ошибку любого участника конвейера. Поэтому после отказа проверки или mkdir извлечение не начинается. sha256sum -c читает строку «хеш имя» из stdin, обозначенного -. tar -xzf извлекает gzip-архив, а -C выбирает новый каталог назначения.

(
  set -euo pipefail
  LAB="$HOME/object-study-lab"
  printf '%s  %s\n'   '65efbc80fdc1fa2cd2631cad5b481777a68e8725f34e89f50fc6ac714e379b40'   "$LAB/downloads/go1.27.3.linux-amd64.tar.gz" | sha256sum -c -
  mkdir -m 700 "$LAB/tools/go-1.27.3"
  tar -C "$LAB/tools/go-1.27.3" -xzf "$LAB/downloads/go1.27.3.linux-amd64.tar.gz"
  "$LAB/tools/go-1.27.3/go/bin/go" version
)

Проверьте код завершения всего блока: только ноль позволяет перейти к сборке. Последний вывод должен назвать go1.27.3 linux/amd64. Это ещё не проверка работы клиента. В архиве верхний каталог go, поэтому путь содержит go-1.27.3/go/bin/go. Ошибка извлечения может оставить частично заполненный каталог; повторный блок остановится на mkdir, сохранив его для разбора.

Проект уже задаёт версии зависимостей в go.mod, а проверяемые суммы хранит в go.sum. При подготовке поставки получен граф из 11 модулей через Go proxy и базу контрольных сумм. Чтобы заполнить собственный кэш, нужна сеть либо заранее полученные модули. Как Go выбирает версии, описывает статья «MVS / go.sum» в словаре.

Перейдите в каталог исходников учебного клиента. GOTOOLCHAIN=local запрещает автоматическую загрузку другого Go; GOWORK=off исключает настройки из внешнего файла go.work; GOENV=off отключает пользовательский файл настроек go env; GOFLAGS= очищает унаследованные флаги команды go. Кэши направляются в каталог лаборатории. tidy сверяет зависимости с импортами в исходниках и при необходимости дополняет go.mod/go.sum: сохраните оба файла вместе со списком выбранных версий. После этого readonly запрещает сборке незаметно менять описание модуля.

(
  set -euo pipefail
  LAB="$HOME/object-study-lab"
  cd "$LAB/source/object-client"
  export GOTOOLCHAIN=local GOWORK=off GOENV=off GOFLAGS=
  export GOMODCACHE="$LAB/cache/mod" GOCACHE="$LAB/cache/build"
  GO="$LAB/tools/go-1.27.3/go/bin/go"
  "$GO" mod tidy
  "$GO" list -m all
  "$GO" build -mod=readonly -o "$LAB/bin/object-study" ./cmd/object-study
)

Сохраните вывод go list -m all и SHA-256 полученной программы. Если зависимости уже есть в подготовленном кэше, повторный go build можно запустить с GOPROXY=off: при отсутствующем модуле он остановится. Архив компилятора и содержимое кэша в поставку книги не входят.

Каталоги и программа готовы к настройке. Перейдите к выбору endpoint, CA и профиля; первое сетевое действие находится там, после создания обоих JSON-файлов.
