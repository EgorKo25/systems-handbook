Список объектов: префиксы, страницы и изменяющийся набор

Разберём ответ ListObjectsV2 и построим обход, который не перепутает размер страницы с размером всей корзины.

Какие строки входят в список

ListObjectsV2 выбирает текущие объекты корзины. Для general purpose bucket AWS возвращает ключи в лексикографическом порядке; это не обещание всех типов bucket. Prefix ограничивает начало ключа, delimiter группирует дальнейшие фрагменты имени. Группы CommonPrefixes помогают рисовать дерево в UI, хотя каталог как самостоятельный объект от этого не возникает.

Возьмём ключи a/1, a/2, a/sub/3, b. Без delimiter и с prefix=a/ видны три объекта. С delimiter=/ первые два находятся в Contents, а a/sub/ — в CommonPrefixes. Размер группы не сообщает, сколько объектов спрятано внутри. Пустой объект с ключом a/ может дополнительно существовать; он не является обязательным основанием остальных ключей.

Запрос и ответ страницы

MaxKeys задаёт верхний предел числа возвращаемых элементов, до 1000 для выбранного AWS API. Сервис может вернуть меньше. KeyCount — количество в этой странице, не в корзине. IsTruncated сообщает необходимость продолжить; NextContinuationToken передаётся следующему запросу как continuation-token. Token непрозрачен и не обязан быть последним ключом.

list-type=2&prefix=a%2F&max-keys=2
Contents: a/1, a/2
KeyCount: 2
IsTruncated: true
NextContinuationToken: TOKEN

list-type=2&prefix=a%2F&max-keys=2&continuation-token=TOKEN
Contents: a/sub/3
KeyCount: 1
IsTruncated: false

Это объяснение query и ответов, не неподписанная рабочая команда. При продолжении сохраняются bucket, prefix, delimiter и прочие параметры той же задачи. Token URL-кодируется как исходная строка. Печатать его как «проверенное имя следующего объекта» неверно. StartAfter — начальная позиция нового обхода, а не универсальная замена continuation-token.

Потребитель страницы

Алгоритм хранит набор параметров задачи, текущий token и обработанные результаты. Для каждой успешной страницы он разбирает весь XML, проверяет элементы и передаёт их обработчику. Затем, если IsTruncated=true, требует следующий token и продолжает. Если token повторяется без продвижения, задача останавливается с диагностикой, а не входит в вечный цикл. Завершением служит последняя корректно разобранная страница, а не пустой Contents сам по себе: страница с CommonPrefixes всё ещё может требовать продолжения.

Даже HTTP 200 не гарантирует корректного XML-тела ListObjectsV2. Ошибка разбора не становится пустым списком. При временном сбое повторяется та же страница с сохранёнными параметрами и token. Обработчик должен выдерживать повтор элементов: например, добавлять в локальный индекс по key, а не безусловно прибавлять стоимость ещё раз. Прежде чем удалять локальные «лишние» записи, требуется успешный полный обход.

Список не является замороженной транзакцией

Между страницами другой клиент может добавить, заменить или удалить объект. Сильная согласованность отдельных операций AWS не создаёт один snapshot на весь многостраничный обход. Для строгого прикладного набора используйте сохранённый manifest выбранных ключей/версий или отдельную процедуру инвентаризации. Перечисление текущих ключей также не содержит все noncurrent версии, delete markers и незавершённые multipart части.

Модель python3 -B s3/labs/storage_models.py listing сначала обходит фиксированные ключи страницами по два. Затем она вставляет ключ перед уже прочитанной позицией в простой индексной модели: повтор либо пропуск показывает, почему номер позиции не является настоящим S3 token. Эта часть намеренно не эмулирует внутренний token AWS; она проверяет необходимость явных условий стабильности набора.

Что означает отсутствующий результат

Нет Contents для prefix=a/ может означать отсутствие текущих объектов с таким началом, но не отсутствие старой истории. AccessDenied — ошибка разрешения списка, а не пустая корзина. В AWS действие для текущего списка называется s3:ListBucket и относится к ARN корзины. Для истории требуется s3:ListBucketVersions. Для bodies нужны отдельные GetObject/GetObjectVersion.

Чтобы вывести сумму размеров текущих объектов, сложите Size Contents после полного успешного обхода. Результат имеет единицы байт и не равен оплачиваемому объёму хранения: старые версии, multipart parts, служебные минимумы классов хранения и срок хранения учитываются отдельно. Размер сжатого объекта также не равен размеру исходного распакованного архива.
