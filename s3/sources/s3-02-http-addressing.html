Как имя объекта становится сетевым запросом

Корзину можно указать в имени узла или в начале пути. От этого меняются имя сервера, проверка сертификата и поля, которые подписывает клиент.

Запрос и ответ

Чтобы получить сохранённый отчёт, клиент отправит серверу HTTP-запрос. В нём он укажет действие GET и адрес выбранной версии. Сервер вернёт код результата, поля ответа и при успехе — байты отчёта.

Поменяем действие: PUT запишет переданное тело, GET вернёт содержимое, HEAD запросит сведения без тела объекта. DELETE удаляет по правилам выбранной S3-операции. Для списка имён клиент вызывает отдельную операцию интерфейса.

В ответе на чтение нашего примера Content-Type: text/plain поможет обработать текст, а Content-Length: 14 задаст ожидаемую длину тела. Названия полей HTTP не чувствительны к регистру. Значения подчиняются правилам своего поля: переводить их все в нижний регистр нельзя.

При ответе 200 на GET клиент продолжит читать тело; при 403 разберёт отказ в доступе, при 412 — невыполненное условие запроса. Одного числа недостаточно для всех S3-операций. CompleteMultipartUpload, сборка загруженных частей, может начать ответ HTTP 200, а затем сообщить ошибку в XML-теле; этот путь разобран в главе multipart.

Для одной загрузки различайте три момента: соединение установлено, пришёл код ответа, дочитано тело. Если чтение оборвалось после заголовков, клиент уже знает код, но ещё не получил весь объект.

В нашем клиенте AWS SDK for Go v2 строит HTTP-запрос, подписывает его и разбирает ответ. Программа передаёт библиотеке адрес службы и явно выбранный профиль.

Из чего состоит адрес

Адрес сообщает библиотеке, куда подключаться и какой ресурс запрашивать. В наших примерах достаточно разделить схему, узел и порт, путь и параметры запроса; формальные термины URI и URL есть в словаре.

В записи https://storage.example.test:9443/study-s3/lessons/2026-11/hello%20%2B%25.txt?versionId=V1 схема — https, узел — storage.example.test, порт — 9443, путь — /study-s3/lessons/2026-11/hello%20%2B%25.txt, параметр — versionId=V1. Если V1 — сохранённый идентификатор первой версии из предыдущей главы, параметр выбирает её; без него запрос обращается к текущему состоянию имени. Это учебный разбор адреса; он не утверждает существование такого сервера.

В настройках учебного клиента endpoint задаёт адрес API без имени корзины. По этому имени клиент запросит у DNS сетевой адрес. Сертификат и разрешения к корзине проверяются уже после этого.

Region, или регион, — область размещения и обслуживания ресурса в модели провайдера. В AWS регион участвует также в выборе точки обращения и области подписи. У совместимого сервера строка региона может иметь другое эксплуатационное значение. Подставлять произвольное значение только потому, что SDK требует строку, нельзя: нужно согласовать его с конфигурацией конкретной цели.

Два способа указать корзину

Для сравнения способов возьмём короткий ключ report.txt. Имя корзины study-s3 можно поместить в путь (path-style) или в имя узла (virtual-hosted style). В рисунке выделено только то, что переезжает. Ключ report.txt остаётся в пути.

Во втором варианте клиент запрашивает у DNS другое имя и проверяет сертификат для него. При подписывании изменятся сразу два входа: Host и путь. Поэтому перенос имени корзины после подписи меняет смысл уже подписанного запроса.

Документация AWS на дату проверки описывает оба способа для корзин общего назначения. Это не универсальное правило для всех типов корзин: например, directory buckets требуют предусмотренных для них конечных точек и не поддерживают path-style. Данный том не использует их как базовый учебный профиль.

Для собственного сервера virtual-hosted style требует соответствующего разрешения имён и TLS-конфигурации. Одного параметра SDK недостаточно, чтобы имя study-s3.storage.example.test появилось в DNS или в сертификате. В лабораториях MinIO и RGW способ адресации задаётся явно после установки самого сервера.

Что защищает HTTPS

Когда адрес начинается с HTTPS, клиент проверяет сертификат выбранного сервера и устанавливает защищённое TLS-соединение. Передаваемый отчёт будет зашифрован; принимающая сторона проверит целостность защищённых записей.

Сертификат связывает удостоверяемое имя с открытым ключом. Соответствующий закрытый ключ сервер хранит у себя. В полном сертификатном рукопожатии TLS 1.3 сервер подтверждает владение им подписью CertificateVerify. Клиент проверяет имя и доверенную цепочку. Удостоверяющий центр, CA, участвует в цепочке доверия. У личного учебного сервера может быть собственный CA, который нужно явно передать клиенту. Выключение проверки сертификата не является настройкой доверия.

TLS не решает, имеет ли приложение право перезаписать отчёт. Эту проверку выполняет объектная служба по своей модели доступа. И наоборот: корректная подпись S3-запроса не скрывает его тело от наблюдателя незашифрованного соединения. Для удалённых целей наш клиент требует HTTPS; незашифрованный транспорт допускается только как явно выбранное исключение на loopback учебного стенда.

Кодирование байтов ключа в пути запроса

Вернёмся к ключу lessons/2026-11/hello +%.txt. В адресе байты пробела, плюса и процента должны быть представлены по правилам кодирования. Для рассматриваемого пути получится окончание hello%20%2B%25.txt.

Для первой редакции из предыдущей главы в учебном примере полный путь и параметр имеют вид /study-s3/lessons/2026-11/hello%20%2B%25.txt?versionId=V1. При этом V1 передаётся как параметр версии, а не входит в ключ. Фактический идентификатор версии и конечный адрес выдаются и определяются выбранной службой.

Запись %20 в таком адресе представляет байт пробела. Но если исходный ключ содержит три буквальных символа %20, процент нужно закодировать ещё как данные: получится %2520. Поэтому контракт нашего клиента принимает исходный ключ и поручает построение запроса SDK. Пользователь не должен предварительно «подготавливать URL» в аргументе ключа.

Аналогично, ключи a/b и a%2Fb различаются. У второго в имени присутствуют процент, цифра и буква. Кодирование их пути нельзя заменять общим исправлением строк или повторным декодированием.

У S3 есть ещё существенная граница: путь объекта не нормализуется как обычный файловый путь. Ключ a//b не следует превращать в a/b. Вызов функции очистки пути способен обратиться к другому имени ещё до того, как начнётся проверка подписи.

Почему перенаправление требует внимания

Если первоначальный адрес не соответствует региону корзины, ответ может предложить перейти по другому адресу. Но подпись уже связана с методом, ресурсом и полями запроса. Перенос старого заголовка аутентификации на произвольный новый узел может раскрыть его получателю и не создаёт корректную подпись нового запроса.

Для AWS клиент получает регион и endpoint из описания выбранной цели; SDK применяет к ним правила адресации корзины. Для MinIO и RGW он получает разные явные endpoints. В учебном HTTP-клиенте автоматический переход по HTTP-перенаправлению запрещён; такой ответ становится наблюдаемым результатом. Исправление региона или адреса происходит до нового подписывания, а не подменой уже отправленного запроса.

Порядок соединения и чтения

После ответа DNS клиент устанавливает TCP-соединение с выбранным IP-адресом и портом. Закэшированный ответ DNS можно использовать в пределах его TTL. Затем TLS согласует защиту и проверяет сервер. После этого передаются HTTP-поля и тело. Ошибка DNS не является отказом S3 в доступе; ошибка сертификата не является HTTP 403.

127.0.0.1 — loopback сетевого окружения самого клиента. Если RGW работает в другой VM, это не его адрес. Для HTTPS по IP сертификат должен удостоверять этот IP, а не только постороннее доменное имя. Добавление CA не выключает проверку имени.

В HTTP/1.1 начальная строка и заголовки заканчиваются CRLF: возврат каретки (CR, 0D) и перевод строки (LF, 0A). Пустая строка отделяет их от тела. Наше тело имеет собственный LF 0A; он входит в Content-Length: 14. HTTP/2 использует фреймы и не передаёт заголовки в таком текстовом виде. Канонические строки SigV4 разделяются LF по отдельным правилам: менять ради них CRLF сетевого сообщения нельзя.

GET предоставляет поток тела; получение заголовков ещё не завершает получение объекта. HEAD тела объекта не передаёт, хотя Content-Length для такого ответа указывает размер тела, которое вернул бы соответствующий GET. Подробный путь до принятого файла находится в главе операций.
