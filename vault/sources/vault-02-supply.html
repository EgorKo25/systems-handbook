Получение: доверие появляется до запуска

Закрепим версию, проверим подписанный список хешей и установим исполняемый файл в собственный каталог.

Три разные проверки поставки

Версия — текст о выпуске. SHA-256 — вычисляемый отпечаток байтов; совпадение с ожидаемым хешем обнаруживает замену содержимого, но не доказывает происхождение самого ожидаемого значения. Подпись — проверяемая связь списка хешей с закрытым ключом издателя. Доверие начинается с заранее проверенного полного fingerprint публичного ключа, а не с короткого key ID и не с произвольного ключа, лежащего рядом с архивом.

Для этого опыта официальный Linux amd64 архив — vault_1.21.4_linux_amd64.zip. SHA-256 принятого архива: 889b681990fe221b884b7932fa9c9dd0ee9811b9349554f1aa287ab63c9f3dae. Подписан файл vault_1.21.4_SHA256SUMS, а не текст, напечатанный этой страницей. Проверенный primary fingerprint: C874 011F 0AB4 0511 0D02 1055 3436 5D94 72D7 468F; подпись выпуска сделана signing subkey 374E C75B 4859 1360 4A83 1CC7 C820 C6D5 CD27 AB87. Проверка полного primary связывает актуальные подключи с ожидаемым владельцем. GPG может отдельно сообщить отсутствие локального web-of-trust и старые истёкшие self-signatures; нельзя превращать любое «Good signature» с неизвестным ключом в принятую поставку.

Один воспроизводимый способ установки

Среда: собственная Linux amd64, обычный владелец; рабочий каталог vault/labs перенесённого комплекта. До запуска уже доступны Python 3.11+ (hashlib.file_digest в helper требует 3.11), gpg, openssl и системные CA для HTTPS. Комплект не устанавливает пакеты и не вызывает sudo. При отсутствии инструмента сначала готовят личную VM по правилам её ОС; рабочий компьютер остаётся режимом чтения. Для другой архитектуры выбирают иной официальный архив и проверяют соответствующую строку списка, а не запускают amd64 бинарник наугад.

set -euo pipefail
umask 077
stand="$HOME/handbook-vault"
python3 get_vault.py --root "$stand"
"$stand/bin/vault" version
"$stand/bin/vault" -help

--root у helper выбирает частный каталог доставки, не адрес сервера. Загрузка идёт только с официальных URL по HTTPS; gnupg/ — отдельное хранилище ключей, системное не меняется. Helper требует успешный VALIDSIG ожидаемого primary и совпадение SHA-256, затем извлекает только vault, назначает ему mode 0700 и печатает проверенный номер. Ожидается код 0 и Vault v1.21.4 (...). Ошибка сети, проверки подписи, fingerprint или хеша завершает программу до установки бинарника. Не продолжайте с частично полученным архивом; удалять весь сохраняемый стенд для повторной загрузки не требуется.

Полученные downloads/, bin/ и gnupg/ не входят в книгу. Переносимая HTML-копия содержит код получения и лицензии, но наличие её на флэшке не доказывает, что дистрибутив доступен в offline-день. Для автономного запуска заранее сохраняют проверенный архив, подписанный список, подпись, нужный ключ и запись о принятом fingerprint на разрешённом частном носителе. Заново проверяют подпись и хеш после переноса.

CLI, сервер, Agent и встроенные plugins могут иметь разные точки совместимости. Мы используем CLI и Agent из одного проверенного 1.21.4 файла. PostgreSQL — отдельная поставка 18.6, Go — отдельный toolchain 1.27.3. Это закреплённые входы теста, не обещание поддержки любой комбинации будущих версий.
