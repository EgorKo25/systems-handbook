Чарт как проверяемый интерфейс

Проследим, как файл из каталога чарта попадает в ConfigMap и что меняет одно правило .helmignore.

Состав нашего пакета

chart/
  Chart.yaml
  values.yaml
  values.schema.json
  .helmignore
  files/operator-note.txt
  templates/
    _helpers.tpl
    deployment.yaml
    configmap.yaml
    service.yaml
    secret.yaml
    pvc.yaml
    tests/http.yaml
    NOTES.txt

Chart.yaml задаёт name, SemVer version, строковое appVersion, type, kubeVersion и dependencies. SemVer — Semantic Versioning, соглашение major.minor.patch с дополнительными частями. Chart version относится к интерфейсу и содержимому пакета; appVersion — информативная строка приложения и сама не меняет image Deployment. Image tag — отдельный указатель registry, digest — идентификатор содержимого манифеста. Одинаковые цифры 0.1.0 не делают эти три сущности одним объектом.

Values задают defaults, но сами не запрещают произвольный ввод. Schema — JSON Schema, контракт типов и ограничений. Templates проходят через engine; файл с начальным подчёркиванием содержит helpers и не печатается как отдельный ресурс. NOTES.txt выводит пояснение, не исполняется как shell. Files — включённые обычные bytes, доступные .Files.Get. CRD размещается отдельно и имеет особый lifecycle.

Что исключает .helmignore

Шаблон templates/configmap.yaml переносит файл files/operator-note.txt в данные ConfigMap. .Files.Get берёт содержимое как строку из уже загруженного чарта. nindent 4 добавляет перевод строки и четыре пробела отступа, чтобы текст оказался внутри блока |-. Этот блок задаёт строку YAML без конечного перевода строки.

  operator-note.txt: |-
    {{- .Files.Get "files/operator-note.txt" | nindent 4 }}

Начните в рабочей копии из главы 01, где есть ./chart/Chart.yaml. Скопируйте чарт во временный каталог и дважды выведите только ConfigMap. Между запусками добавьте точный путь к заметке в .helmignore временной копии. Для команд нужны Helm и право записи во временный каталог. Флаг --dry-run=client оставляет оба запуска локальными.

(
  scratch=$(mktemp -d) || exit 1
  cp -R ./chart "$scratch/chart" || exit 1
  cd "$scratch" || exit 1
  helm template ledger ./chart --dry-run=client --kube-version 1.36.6 \
    --show-only templates/configmap.yaml
  printf '\nfiles/operator-note.txt\n' >> chart/.helmignore
  helm template ledger ./chart --dry-run=client --kube-version 1.36.6 \
    --show-only templates/configmap.yaml
)

В первом выводе под ключом operator-note.txt есть строка из файла.

data:
  MESSAGE: "Hello from Helm"
  operator-note.txt: |-
    This note is packaged as bytes, not executed as a template.

Во втором выводе остаётся operator-note.txt: |- с пустым телом. Файл всё ещё лежит на диске. Правило в .helmignore велит Helm пропустить его при загрузке чарта, поэтому .Files.Get возвращает пустую строку. Сам ключ шаблон печатает без условия. Значение MESSAGE осталось прежним, потому что оно берётся из параметров чарта.

Тот же фильтр действует для helm package. Проверяйте состав готового архива через tar -tzf и сохраняйте архив снаружи каталога чарта. Правила .gitignore относятся к Git, поэтому секретные файлы храните за пределами каталога чарта. Широкое правило *.tgz может заодно скрыть архив зависимости из charts/: после успешного helm dependency build рендеринг тогда остановится на отсутствующей зависимости.

Schema — входная граница, а не scheduler

{"type":"object", "properties": {
  "replicaCount":{"type":"integer","minimum":1,"maximum":6},
  "config":{"type":"object","required":["message"],
    "properties":{"message":{"type":"string","minLength":1}}}
}}

Это сокращённый пример; полный файл в labs/chart. Schema проверяет объединённые values; overlay — файл частичных переопределений поверх предыдущих параметров — может не содержать key, предоставленный defaults. В JSON Schema required проверяет наличие свойства, а minLength: 1 запрещает пустую строку. При рендеринге в Helm 4.3.1 одноимённая функция шаблона останавливает рендеринг для nil и пустой строки, пропускает false и 0. Schema не узнает свободную память nodes, существование Secret или подлинность registry digest.

Внутри image/config/service и других interfaces additionalProperties=false ловит опечатки. Корень оставлен расширяемым для отдельного dependency-упражнения: при строгом корне нужно перечислить global и subchart keys. CPU/memory оставлены строковыми quantity; API проверит их грамматику и соотношение requests/limits. Самодельная regex редко воспроизводит все правила Kubernetes.

helm lint ./chart --strict --kube-version 1.36.6
helm lint ./chart --strict --kube-version 1.36.6 -f fixtures/wrong-replicas.yaml

Первый запуск проходит, второй отвергает строку "3" вместо integer. --strict превращает lint warnings в ошибки, но не запускает Pod. --skip-schema-validation отключил бы защиту, не исправив ввод. Такие флаги допустимы как точный диагностический опыт или управляемая миграция, а не обход неизвестной ошибки CI.

Capabilities и версии API

.Capabilities.KubeVersion сообщает версию, .Capabilities.APIVersions.Has — наличие API. Локальный --kube-version меняет модель версии, --api-versions добавляет моделируемую capability; CRD или controller они не устанавливают. Для Gateway API номер Kubernetes сам по себе не доказывает наличие CRD. Наш chart использует стабильные apps/v1 и v1. При удалении key, изменении типа, selector или dependency повышают chart version и документируют миграцию. Уже опубликованную 0.1.0 нельзя перезаписать другими bytes: кэши, provenance и журнал выпуска рассчитывают на неизменность.

В следующей главе проследим второй вход того же ConfigMap. Выясним, из каких файлов и флагов Helm выбирает значение для MESSAGE.
