Как передать готовый чарт

Упакуем ledger-api в архив и проверим, что из него и из исходного каталога получаются одинаковые манифесты.

Как проверить архив ledger-api

Оставайтесь в корне рабочей копии из главы 01, где chart/ — вложенный каталог. Команды выполняйте в одном Bash, где доступен helm. Отдельная копия с библиотекой из предыдущей главы остаётся в своём временном каталоге. Новый каталог пакета нужен, чтобы сохранить уже подготовленные архивы.

helm_dist=$(mktemp -d) &&
  helm package ./chart --destination "$helm_dist"

После успешной упаковки в том же терминале выполните команды с архивом ledger-api-0.1.0.tgz.

helm show chart "$helm_dist/ledger-api-0.1.0.tgz"
helm show values "$helm_dist/ledger-api-0.1.0.tgz"
(set -C
helm template ledger ./chart \
  --namespace helm-lab --kube-version 1.36.6 > "$helm_dist/from-directory.yaml" &&
helm template ledger "$helm_dist/ledger-api-0.1.0.tgz" \
  --namespace helm-lab --kube-version 1.36.6 > "$helm_dist/from-archive.yaml" &&
cmp "$helm_dist/from-directory.yaml" "$helm_dist/from-archive.yaml"
)

set -C сохраняет прежние YAML при повторе блока; для нового сравнения повторите упаковку в новый каталог. Для исходного чарта cmp завершится с кодом 0 без вывода. При различиях откройте оба файла и проверьте, какие параметры или шаблоны изменились.

helm package упаковывает описание релиза. Сборка Go-приложения и получение образа идут отдельными шагами. Имя архива содержит name/version метаданных. --version меняет версию пакета, --app-version — информативное поле, но ни один не меняет автоматически тег образа шаблона. Каталог назначения вне чарта исключает самовложение архивов. Show читает пакет, template исполняет его. Тесты сравнивают разобранные объекты каталога и tgz, отдельно точные байты включённого файла.

HTTP chart repository

HTTP-репозиторий чартов — каталог HTTP(S) с index.yaml и архивами по URL. Repo add сохраняет имя и адрес у клиента, repo update скачивает индекс, search repo ищет в локальном индексе. Старый индекс способен показывать устаревшую версию; обновление индекса не доказывает неизменность архива по URL. Такой сервер не является API Kubernetes или хранилищем истории релиза.

helm repo add handbook https://charts.example.invalid
helm repo update handbook
helm search repo handbook/ledger-api --versions
mkdir -p "$helm_dist/from-repo"
helm pull handbook/ledger-api --version 0.1.0 --destination "$helm_dist/from-repo"

Example.invalid — намеренный заполнитель адреса своего сервера, а не рабочее публичное хранилище. --version фиксирует пакет вместо выбора последней подходящей версии. Pull без --untar сохраняет архив, с --untar распаковывает, но доверия не добавляет. Для публикации своего HTTP-репозитория helm repo index "$helm_dist" --url https://charts.example.invalid создаёт индекс в личной промежуточной папке; его публикуют согласованно с архивами. --merge существующего индекса не восстанавливает неизвестные версии сервера.

OCI registry

В OCI-реестр можно отправить архив чарта и затем получить его командой helm pull. Для запуска приложения узлам по-прежнему нужен контейнерный образ. Дайджест чарта и дайджест образа определяют разные манифесты. Тег удобен как версия, дайджест связывает запрос с содержимым; доверие к издателю остаётся отдельной задачей.

printf '%s' "$REGISTRY_PASSWORD" | \
  helm registry login registry.example.invalid \
  --username "$REGISTRY_USER" --password-stdin
helm push "$helm_dist/ledger-api-0.1.0.tgz" \
  oci://registry.example.invalid/handbook
helm pull oci://registry.example.invalid/handbook/ledger-api \
  --version 0.1.0 --destination ./downloaded

В Helm 4 registry login принимает domain[:port], а не полный URL со схемой и путём. --password-stdin уменьшает утечку в argv, но файл учётных данных надо защищать. Push получает созданный tgz; конечные имя и версия берутся из метаданных, поэтому к адресу назначения не дописывают произвольный тег как у docker push. В 4.x чарт можно установить по OCI-дайджесту: его берут из ответа своего реестра или доверенного описания, а не из учебного фиктивного хеша. --plain-http и --insecure-skip-tls-verify ослабляют транспортную проверку и не исправляют неизвестную причину ошибки TLS.

Provenance и доверие

Рядом с архивом можно передать файл .prov: подписанный OpenPGP-документ с метаданными чарта и хешем архива. Проверка связывает подпись с выбранным ключом и байтами; право ключа выпускать боевой пакет задаёт политика доверия. Подпись не анализирует шаблоны, обработчики, полномочия и уязвимости образа.

helm package ./chart --destination ./signed \
  --sign --key 'HANDBOOK SIGNER' --keyring ./private-signing-keyring.gpg
helm verify ./signed/ledger-api-0.1.0.tgz --keyring ./trusted-public.gpg
helm pull handbook/ledger-api --version 0.1.0 --verify \
  --keyring ./trusted-public.gpg --destination ./verified

Это рецепт со своими подготовленными ключами; подпись редакцией не выполнялась. --verify требует доступного .prov и успешной проверки, а не наличия файла рядом. Закрытый ключ не кладут в чарт, журнал конвейера или переносимую книгу. Подписывающий ключ и доверенное кольцо открытых ключей — разные материалы и права. OCI способен переносить слой происхождения, но поведение конкретного реестра проверяют отдельно: произвольная подпись реестра не обязана поддерживаться helm verify.

Комплект offline и журнал promotion

Создайте опись комплекта: версия и архитектура Helm, хеш; имя/хеш/подпись чарта и отпечаток ключа; версии и хеши зависимостей; файлы и хеши параметров; образы и неизменяемые дайджесты приложения и тестов; договор Kubernetes API. Саму опись подпишите или доставьте доверенно. Отключённый интернет и успешный template не доказывают наличие образов, CNI, DNS и хранилища на узлах. Для kind загрузите свой образ локально, для VM доставьте в личный реестр или CRI по соседнему тому.

Продвижение релиза переносит тот же чарт и содержимое образа между окружениями с явно различными параметрами. Не пересобирайте приложение после теста под тем же тегом. Хеш параметров и итоговые манифесты сохраняйте защищённо вместе с временем, пространством имён, контекстом и ревизией. Сеть измеряют по реальным переданным байтам и попаданиям в кэш: локальная упаковка за 20 мс не определяет передачу 2GiB образа нескольким узлам.
