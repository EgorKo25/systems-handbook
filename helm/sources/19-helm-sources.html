Текст и лаборатория авторские; версии и механика сверены с документацией и исходниками фиксированного выпуска.

Как читать источники

Ссылки в конце каждой главы привязаны к её механизму. Страницы официальной документации были проверены с индикатором 4.3.1 1 ноября 2026; ссылки source закреплены tag v4.3.1 и позволяют отличить фактическую реализацию от общей строки help. Если будущая документация по тому же URL показывает новую версию, повторно проверьте флаг своего binary через help. Ни текущая ветка main, ни поисковый snippet не заменяют выбранный release source.

Ключевые факты

  • Официальный release4.3.1 и SHA Linux amd64 — release page; реально скачанный executable сообщил v4.3.1+gc0d08d0.
  • Текущая major4 и срок security-only ветки 3 — overview и EOL.
  • Порядок семейств --set — MergeValues, дополнительно реальный fixture.
  • Условия reset/reuse/default upgrade — reuseValues; cluster upgrade не выполнялся.
  • Граница install dry-run — RunWithContext; возврат до изменения обычных ресурсов объяснён отдельно.
  • JSON→gzip→base64 release storage — encoding source; кодирование не названо шифрованием.
  • Контекст языка — спецификация text/template, расширения — engine Helm.

Что не доказано этой редакцией

Реального Kubernetes-кластера не было: не исполнены admission, install/upgrade, wait watcher на настоящих workloads, запуск hooks, rollback, PVC binding/attach и lifecycle CRD. Не выполнены remote OCI push/login, подпись chart собственным key и GPG-проверка binary. Их рецепты имеют явные входы и критерии, но не выдуманный журнал успеха. Полный список выполненного и ограничений — в ПРОВЕРКИ.txt и машинном отчёте.

Разумное продолжение

Первый следующий эксперимент — тот же ledger release на личном kind/kubeadm по соседнему тому: последовательно установить, нарушить readiness, исправить, проверить test hook и rollback. Только после этих наблюдений стоит добавлять operator, CRD, admission policies или непростую БД. GitOps-controller позже может вызывать Helm render и иметь собственную историю применения; такая история не автоматически равна обычному release storage Helm. Это отдельная модель ownership и согласования состояния, а не дополнительный флаг текущего CLI.
