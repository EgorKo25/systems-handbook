Как Helm добавляет зависимость к чарту

Добавим библиотеку lab-labels к копии чарта. Helm запишет выбранную версию в Chart.lock, затем восстановит по нему архив в каталоге зависимостей.

Что входит в чарт вместе с зависимостью

Зависимость чарта — включаемый пакет со своими шаблонами, исходными параметрами и схемой. Дочерний чарт приложения создаёт ресурсы, библиотечный чарт предоставляет вспомогательные шаблоны без собственных рабочих нагрузок. Они входят в одну операцию релиза; ошибка одной зависимости блокирует рендеринг или оставляет частично изменённый набор. Umbrella chart, чарт-оболочка нескольких зависимостей, удобен только при действительно связанных жизненных циклах. Сборка БД, брокера сообщений и API в один релиз не создаёт общую транзакцию данных.

Основной чарт ledger-api уже работает без зависимостей. Временная копия позволит добавить библиотеку и проверить её отдельно. file://../lab-labels отсчитывается от каталога чарта, поэтому chart-copy и lab-labels должны оказаться рядом.

Подготовить копию и собрать зависимость

Продолжайте в рабочей копии из главы 01: в текущей папке должны лежать chart и dependency, а команда helm должна быть доступна. Все блоки выполняйте в одном Bash. После ошибки остановитесь; для полного повторения опыта начните с нового временного каталога первым блоком.

helm_dep=$(mktemp -d) &&
  cp -R chart "$helm_dep/chart-copy" &&
  cp -R dependency/lab-labels "$helm_dep/lab-labels" &&
cat >> "$helm_dep/chart-copy/Chart.yaml" <<'YAML'

dependencies:
  - name: lab-labels
    version: 0.1.0
    repository: file://../lab-labels
YAML
helm dependency update "$helm_dep/chart-copy" &&
  test -s "$helm_dep/chart-copy/Chart.lock" &&
  helm dependency list "$helm_dep/chart-copy"

В списке ожидается lab-labels 0.1.0 со статусом ok. Теперь переместите каталог архивов в сторону и восстановите его из файла блокировки.

test ! -e "$helm_dep/charts-before-build" &&
  test ! -L "$helm_dep/charts-before-build" &&
  mv "$helm_dep/chart-copy/charts" "$helm_dep/charts-before-build" &&
  helm dependency build "$helm_dep/chart-copy" &&
  helm dependency list "$helm_dep/chart-copy"

В копии снова появится charts/lab-labels-0.1.0.tgz. Проверка перед mv откажет, если резервный путь уже существует. Наличие архива ещё не показывает работу библиотеки: родитель должен вызвать её шаблон. Добавьте в ту же временную копию отдельный ConfigMap.

(set -C; cat > "$helm_dep/chart-copy/templates/library-proof.yaml" <<'YAML'
apiVersion: v1
kind: ConfigMap
metadata:
  name: library-proof
  labels:
    {{- include "lab-labels.owner" . | nindent 4 }}
data:
  result: "library included"
YAML
) &&
helm template ledger "$helm_dep/chart-copy" \
  --namespace helm-lab --kube-version 1.36.6 \
  --show-only templates/library-proof.yaml

В выводе ожидается handbook.example/owner: "reader" под metadata.labels. Строку печатает шаблон lab-labels.owner из библиотеки; nindent 4 помещает её внутрь меток. Повтор создания файла остановится благодаря set -C. Каталог исходного чарта и его параметры не менялись. Рабочая папка терминала осталась прежней, поэтому из неё можно сразу перейти к упаковке основного чарта.

В чём разница между update и build

update выбирает версию, подходящую под ограничение из Chart.yaml, и записывает её в Chart.lock. build при наличии Chart.lock использует закреплённую версию. Если файла нет, команда может выбрать зависимости заново. Поэтому в опыте сначала проверяем наличие файла, а затем перемещаем только каталог с архивом.

Дайджест в Chart.lock связывает описание с выбранным набором версий. Архивы проверяют отдельно по их контрольным суммам и подписям. Если сервер позволит заменить архив по прежнему адресу, закреплённая версия сама по себе не обнаружит подмену. Для автономной сборки нужны и версии, и файлы.

Scoped values и global

Родитель передаёт параметры дочернему чарту под ключом имени зависимости; внутри дочернего пакета это поддерево становится собственным .Values без родительского префикса. Произвольные параметры родителя ему недоступны. Явно выделенное поддерево global доступно нескольким чартам по договорённости. Global не является переменной ОС или настройкой всего кластера — это область параметров одного рендеринга.

# Parent values для условного child с именем cache:
cache:
  replicaCount: 1
global:
  imageRegistry: registry.example.invalid

Дочерний пакет увидит .Values.replicaCount=1 и .Values.global.imageRegistry, но обязан сам использовать global при формировании ссылки образа. Дублирование одной настройки в родителе, дочернем пакете и global порождает неочевидный приоритет; документируйте один источник. Имена вспомогательных шаблонов общие для дерева, поэтому библиотечный префикс и версия важны даже при отдельных параметрах.

Alias, conditions и tags

Alias, псевдоним, позволяет включить один пакет под двумя именами с отдельными поддеревьями параметров; ресурсы всё равно должны избегать фиксированных имён. Condition, условие включения, — путь логического значения в параметрах. Tags, теги группировки, объединяют зависимости. При заданном применимом condition оно имеет приоритет над tags; в списке путей условий существенен первый найденный подходящий путь по правилам Helm. Это не произвольное правило «любой false выключает всё».

# Пример metadata отдельного зависимого chart, не основной ledger:
- name: worker
  alias: reports
  version: 1.2.3
  repository: https://charts.example.invalid
  condition: reports.enabled
  tags: [background]

В параметрах родителя нужен reports.enabled логического типа. Tags размещают на предусмотренном верхнем уровне, не в произвольном global. Import-values переносит экспортированные дочерние значения либо выбранный путь в путь родителя до рендеринга. Это преобразование интерфейса, а не возврат данных уже работающего приложения. Импорт может конфликтовать с исходными значениями или схемой; фиксируйте путь и проверяйте итоговое дерево.

Практический выбор

В опыте библиотека добавила одну метку и не создала собственных рабочих нагрузок. Зависимый чарт с БД изменил бы и набор ресурсов, и порядок обновления. Если БД и приложение обслуживают разные владельцы, отдельные релизы дадут каждому свой цикл обновления. Для переноса нашего примера сохраните Chart.lock, архив lab-labels-0.1.0.tgz и результат рендеринга: без архива автономная сборка должна была бы снова получить библиотеку из источника.
