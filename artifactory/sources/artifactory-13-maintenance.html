Поиск, сроки хранения, корзина и сборка мусора

Сначала определить безопасный набор, потом менять ссылки, затем измерять освобождение байтов.

Поиск отвечает на поставленный вопрос

Сведения о файле, результаты поиска пакетов и статистика хранилища имеют разные единицы. Один Go module включает несколько артефактов; один OCI image — манифест и множество blobs; один build-info связывает несколько выходов и зависимостей. Свойство stage=approved — метаданные, установленные уполномоченным процессом, а не автоматически неизменяемая подпись. Если издатель может менять свойство, фильтр по нему не является самостоятельным запретом удаления принятого выпуска.

AQL, Artifactory Query Language, — язык запросов к данным Artifactory. Он работает с локально известными объектами, связями и свойствами; не обходит весь внешний registry, чтобы вернуть все существующие пакеты. Его API даёт фильтры, выбираемые поля, порядок и порции результатов. Поиск может увидеть объекты кэша, но отсутствие результата не всегда означает отсутствие объекта upstream. Доступ зависит от личности, а не от длины запроса. По текущей матрице AQL доступен Pro X и выше, среди бесплатных — JCR, а не OSS/CE C/C++.

Прочитать небольшой собственный набор

Администратор уже создал репозиторий кандидатов, издатель сохранил собственные файлы, а читатель с правом чтения этого набора имеет свой профиль CLI. Из labs можно вызвать jf rt curl с ограниченным запросом. Файл receipt-query.aql заранее существует: это не обещание результата несуществующего файла.

jf rt curl -X POST /api/search/aql --server-id=lab-publisher \
  --fail --silent --show-error -H 'Content-Type: text/plain' \
  --data-binary @fixtures/receipt-query.aql

POST здесь выполняет запрос поиска, а не удаление. Content-Type text/plain относится к языку AQL; это не JSON-телу обычного REST метода. Limit100 ограничивает порцию, не полную численность репозитория. Для полной описи нужен устойчивый порядок и контролируемая пагинация с учётом изменений между запросами. Результат, прочитанный в 10:00, не блокирует чужую публикацию в 10:01. Поля фактической суммы называются actual_sha1/actual_sha256 в AQL; не путайте их с произвольным пользовательским свойством sha256.

Локальная проверка файла подтверждает синтаксически сохранённую задумку, но AQL-запрос к живому серверу автор не исполнял. При 400 сначала проверяют грамматику/поддержку полей выбранной версии, при 403— права; не дают администраторский токен вместо понимания отказа. Запрос archive.entries из старых руководств больше не подходит: archive domain исключён из текущего поддержанного интерфейса.

Решение удалить и механизм удаления

Retention, политика сроков и условий хранения, должна учитывать поддерживаемые выпуски, возможность возврата, юридические ограничения и наличие независимого резерва. «Не скачивали 30 дней» не означает ненужность редкого аварийного инструмента. Для нашего стенда сначала составьте список только собственных устаревших кандидатов, исключите generic-releases и текущую версию модуля. Сохраните эту опись в журнал, сравните её с фактическим namespace путей и выполните предварительный просмотр выбранной поддержанной операции. Удаление не запускается автоматически из результатов поиска без отдельного принятия списка.

Новые Package Cleanup Policies лицензируются отдельно: на Self-Hosted поддержка Enterprise+ появилась с 7.98.7, Enterprise X — с 7.146.7; наш Pro X не обещает эту автоматизацию. Build cleanup и Release Bundle policies имеют свои условия, не наследуют право от похожего имени. Для Pro X малый ручной опыт работает только с выделенной собственной областью и обычными поддержанными delete-операциями. Отсутствие платного планировщика не повод использовать rm в filestore.

Почему delete не вернул весь размер

Trash Can — корзина отложенного удаления. Пока объект или его сохранённая ссылка остаётся в корзине, требование восстановления может сохранять байты. После удаления последней необходимой ссылки Garbage Collection, сборка мусора, находит неиспользуемое содержимое и удаляет его по своим правилам. По документации расписание по умолчанию обычно 4 часа; фактическое расписание своей версии проверьте в Maintenance. Сокращение интервала усиливает фоновую работу и не обязано ускорять пользовательские запросы.

После удаления одного имени два одинаковых логических файла могут всё ещё ссылаться на один blob. Размер освобождения отличается от суммы размеров удалённых путей. Дополнительно влияют незавершённые загрузки, снимки и версии объектов внешнего хранилища и резервные копии. Массовое удаление может одновременно нагружать SQL, журналы и backend; на заполненном диске это ухудшит ситуацию. Сначала ограничьте ненужную запись, исследуйте файловые системы, свободные inode и рост журналов, сохраните диагностику и резерв. Не удаляйте произвольный объект по его большому размеру.

Проверить восстановление до расширения уборки

На отдельном собственном маленьком объекте проверьте: что видит прежний читатель после удаления, доступно ли восстановление из корзины, какая сумма возвращается и что произойдёт после истечения её срока. Наличие GC-кнопки не делает каждый удалённый объект необратимо потерянным сразу, но успешный запуск GC также не доказывает, что резерв пригоден. После опыта верните согласованную политику, не полный reset стенда. Реальные серверные delete/trash/GC автором не выполнялись; модель reference-count в labs специально не воспроизводит корзину и сроки.
