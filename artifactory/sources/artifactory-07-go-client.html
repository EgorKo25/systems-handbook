Чистый Go client, секрет отдельно от URL и управляемый fallback

Маршрут приватного модуля должен быть понятен до первого сетевого запроса.

Параметры решают разные задачи

GOPRIVATE задаёт префиксы частных модулей и служит умолчанием для GONOPROXY/GONOSUMDB. GONOPROXY управляет обходом module proxy; GONOSUMDB — обходом публичной checksum database. Если просто поставить GOPRIVATE=example.invalid и забыть GONOPROXY, Go может попытаться получить частный модуль напрямую из VCS, минуя Artifactory. Для маршрута через свой proxy задаём GONOPROXY=none, а GONOSUMDB=example.invalid. Это не выключение sumdb для всего интернета. GOAUTH управляет получением HTTP-материалов аутентификации, а не разрешением доступа на сервере.

Здесь example.invalid — собственный единственный частный префикс, а не рекомендация копировать его в production. Заменяйте область на свою утверждённую. Никогда не ставьте GONOSUMDB=* или GOSUMDB=off как универсальное исправление checksum mismatch. Несовпадение с сохранённым проверенным go.sum надо расследовать: версию могли переписать, компрометировать источник или выбрать другой неправильный модуль. Замена ожидаемой суммы результатом повторного скачивания уничтожает саму проверку.

Сохранённое рабочее окружение

Личный Linux-клиент либо сама VM уже имеют проверенный Go и доверенный ca.crt из главы об адресах и TLS. Публичный ca.crt переносится из своей VM по уже проверенному SSH-каналу в $LAB_WORK/private/ca.crt; приватный ca.key клиенту не передаётся. Скопируйте labs в постоянную папку до выполнения блока. GO_BIN указывает на проверенный исполняемый файл, а LAB_WORK — на созданный work. Никакой go env -w не изменяет общий профиль. Подоболочка ниже действует только до закрывающей скобки. Перед командой получения проверьте, что HTTPS-имя разрешается и ca.crt принадлежит принятой CA.

export LAB_WORK="$HOME/artifactory-handbook/work"
mkdir -p "$LAB_WORK/client" "$LAB_WORK/cache/go-build" "$LAB_WORK/cache/go-mod"
# Скопируйте service/ из labs в новый "$LAB_WORK/client/receipt" один раз.
(
  set -euo pipefail
  export GOENV=off GOWORK=off GOTOOLCHAIN=local GOAUTH=netrc
  export GOPROXY=https://aft.lab.example/artifactory/api/go/go-virtual
  export GOPRIVATE=example.invalid GONOPROXY=none GONOSUMDB=example.invalid
  export GOCACHE="$LAB_WORK/cache/go-build" GOMODCACHE="$LAB_WORK/cache/go-mod"
  export SSL_CERT_FILE="$LAB_WORK/private/ca.crt" NETRC="$LAB_WORK/private/go.netrc"
  cd "$LAB_WORK/client/receipt"
  "$GO_BIN" mod download -json example.invalid/BuildLab/checkdigit@v1.0.0
)

Go env off отключает сохранённый пользовательский GOENV-файл, GOWORK off — влияние случайного родительского workspace, GOTOOLCHAIN local запрещает автоматическое скачивание другой toolchain. До первой команды создайте private/go.netrc в частном редакторе с mode0600 и строкой machine aft.lab.example login ИМЯ_ЧИТАТЕЛЯ password ЕГО_ТОКЕН. Имя и токен создаёт администратор модели прав главы о правах; пока подходящего читателя нет, блок получения откладывается. NETRC — путь только этого клиента, не обязательная перезапись общего ~/.netrc. В URL нет username:token, в опубликованном репозитории нет настоящего netrc.

Почему хороший токен ещё способен дать 401

Учитываются адрес, способ передачи, истечение и реальные полномочия. Настоящий Go с GOAUTH=netrc использует Basic credentials из подходящей записи; CLI bearer-token и native client Basic — разные транспортные формы. Для identity/reference token JFrog рекомендует задавать username; токен без распознаваемой JWT-личности способен не дать CLI нужный login для Go. JWT — подписанный структурированный токен, не просто длинная строка. Он не становится доверенным от декодирования payload без проверки подписи и правил Access.

Настоящий Go1.27.3 в нашем HTTPS-fixture не сопоставил запись machine127.0.0.1 с URL127.0.0.1:случайный_порт и получил 401. Запись с тем же host:port сработала; это подтверждено настоящим клиентом и его реализацией сопоставления префиксов. На стандартном 443 наш URL не содержит явного порта, поэтому выбранная machine aft.lab.example совпадает. При нестандартном порте не переносите привычки другого netrc-клиента автоматически: проверьте фактическую версию Go и точное имя обращения. Отдельный отрицательный опыт GOAUTH=off с чистым кэшем снова получил 401, не ложный успех из старого GOMODCACHE.

Запятая и вертикальная черта — политика выхода

GOPROXY может содержать несколько элементов. Запятая разрешает переход к следующему после 404/410; вертикальная черта разрешает его после любой ошибки, включая 403, ошибку TLS или тайм-аут. Direct означает получение из системы контроля версий, а off — запрет получения. Поэтому PRIVATE_PROXY,direct всё равно допускает выход наружу после ответа об отсутствии объекта, а PRIVATE_PROXY|direct способен обойти отказ доступа или проверки TLS. Для фиксированного стенда частных модулей используем один proxy без direct; отсутствие версии должно быть ошибкой.

На Artifactory это отдельный слой относительно remote negative cache: сервер сначала решил, что ответить, а затем Go выбирает следующий элемент своей цепочки. Нельзя называть обе цепочки «приоритетом репозиториев» и ждать одинакового поведения. Jf go также умеет VCS fallback по умолчанию; в учебной сборке явно ставится --no-fallback. Простая установка GOPROXY в shell не гарантирует его сохранения внутри wrapper, который сам задаёт источник.

Принять результат без раскрытия секрета

После успешного download-json проверьте Version, Sum и GoModSum, затем выполните verify и build теми же входами. JSON может включать локальные абсолютные пути; они не являются частью provenance и не публикуются автоматически в CI. Код завершения проверяется независимо от наличия stdout: критический checksum mismatch может завершить Go до JSON. Не включайте trace с credentials в публичный журнал. Зафиксируйте только обезличенный protocol path, код и контрольные суммы. Для приёмки новым клиентом создайте новый cache каталог и повторите чтение выпущенной версии, сохранив доверенный go.sum.
